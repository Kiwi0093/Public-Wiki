# MS SQL-Server docker-compose.yml

```yml
# Docker-compose.yml
version: '3'
services:
  mssql
    image:  mcr.microsoft.com/mssql/server:2019-latest
    container_name: sql-server
    environment:
      - PUID=1000
      - ACCEPT_EULA=Y
#     - MSSQL_PID=<your_product_id | edition_name> (default: Developer)"
      - SA_PASSWORD=<your@Passw0rd>
    ports:
      - 1433:1433
    volumes:
      - /var/lib/docker/volumes/mssql:/var/lib/mssqlql
    restart: always
```

> [!info] Updated 2026-11-27
> 此封存設定檔存在多處語法錯誤與過時參數，保留原文供歷史對照：
> - **YAML 語法錯誤**：`mssql` 服務名稱後方缺少冒號（應為 `mssql:`）。
> - **掛載路徑錯誤**：微軟官方 SQL Server 容器的資料目錄為 `/var/opt/mssql`（原文誤植為 `/var/lib/mssqlql`），且建議使用 Docker named volume 而非直接寫死 `/var/lib/docker/volumes/...`。
> - **Compose V2 規範**：使用新版 `docker compose` 時已不需宣告頂層 `version: '3'`。
> - **環境變數與版本**：`2019-latest` 已屬舊版，SQL Server 2022 起已改用 `MSSQL_SA_PASSWORD` 取代 `SA_PASSWORD`。

### 基本說明

* <span style="color:#e06c75"><del>PUID=1000 因為SQL-Server不能用root運作所以要另外指定一個USER不然容易會有問題,但是我看一堆教學都沒放所以若是沒放也可以正常跑就不用這行</del></span> *(Updated 2026-11-27: 微軟官方 `mcr.microsoft.com/mssql/server` 映像檔並不支援 `PUID` 環境變數（此為 LinuxServer.io 映像檔慣例）；若需以非 root 身分執行，應於 Compose 使用 `user:` 並搭配目錄權限設定。)*
* `ACCEPT_EULA=Y`：這個其實是廢話，因為不同意就不能跑，不過這個 Image 是微軟官方做的所以也沒辦法改。
* `MSSQL_PID`：這個其實是最重要的一個參數，因為它決定了你在跑的這個 SQL Server 是什麼版本，若是公司在用的，就要在這裡放入購買的序號（或版本名稱）。
* `SA_PASSWORD`：就如字義，等於 MySQL 的 root 密碼定義。
