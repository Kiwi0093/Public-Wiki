Some graphical user interface (GUI) applications (such as SonicWall NetExtender) provide an operation interface, but require root privileges when invoking underlying system core tools in the background (such as `pppd`, network routing configuration, etc.). Running them directly as a regular user often results in connection failure due to insufficient permissions.

> [!warning] Updated 2026-11-27
> When using the following methods in modern Linux desktop environments, please note these compatibility limitations:
> 1. **Wayland Environment Limitations**: In modern Wayland desktops like KDE Plasma 6 and GNOME, launching GUI programs directly with `su`, `sudo`, or `pkexec` usually fails due to inability to access the user's Wayland socket; if the program runs via XWayland, running `xhost +SI:localuser:root` beforehand is often required (it is recommended to revert with `xhost -SI:localuser:root` afterwards).
> 2. **`pkexec` GUI Launching**: `pkexec` clears environment variables like `DISPLAY` and `XAUTHORITY` by default; you must create a corresponding `.policy` configuration file under `/usr/share/polkit-1/actions/` with `<annotate key="org.freedesktop.policykit.exec.allow_gui">true</annotate>` to open windows normally.
> 3. **`kdesu` Path Differences**: Most modern KDE distributions no longer place `kdesu` in `$PATH` (often located at `/usr/lib/kf6/kdesu` or `/usr/lib/kf5/kdesu`).
> 4. **Polkit Group Names**: `subject.isInGroup("wheel")` in the example below applies to Arch / Fedora / RHEL families; if using Debian / Ubuntu families, change it to the `"sudo"` group.

## Command Line Interface (CLI) Execution Methods

- **Switch identity via `su`:** Directly switch to the root account and then launch the application.

  ```bash
  su -
  netExtenderGui
  ```

- **Temporary privilege escalation via `sudo`:** Requires ensuring that the current user is added to the `sudoers` list.

  ```bash
  sudo netExtenderGui
  ```

## Desktop Shortcut and Menu Modification Method (.desktop)

If you want the system to automatically pop up a password prompt and run as root when clicking the application menu or desktop shortcut, you must modify the corresponding `.desktop` file (usually located in `/usr/share/applications/` or `~/.local/share/applications/`).

- **KDE Desktop Environment (`kdesu`)** Open the `.desktop` file with a text editor and modify the `Exec=` field to use `kdesu`:

  ```ini
  # Before modification
  Exec=/usr/bin/netExtenderGui

  # After modification
  Exec=kdesu /usr/bin/netExtenderGui
  ```

- **GNOME / XFCE / Generic Desktop Environments (`pkexec`)** For non-KDE environments, it is recommended to use the modern Linux standard PolicyKit privilege escalation tool `pkexec`:

  ```ini
  # After modification
  Exec=pkexec /usr/bin/netExtenderGui
  ```

  *(After modification, if it does not take effect immediately, run the following command to refresh the desktop database:)*

  ```bash
  update-desktop-database ~/.local/share/applications/
  ```

## Advanced Application: Passwordless Execution via Polkit

If you do not want to manually input the root password every time you launch the GUI software, you can establish an authorization whitelist through PolicyKit rules.

1. Create a configuration file under the `/etc/polkit-1/rules.d/` directory (e.g., `49-netextender.rules`):

   ```bash
   sudo nano /etc/polkit-1/rules.d/49-netextender.rules
   ```

2. Write the following rule content (allowing users belonging to the `wheel` or `sudo` group to run passwordlessly):

   ```javascript
   polkit.addRule(function(action, subject) {
       if (action.id == "org.freedesktop.policykit.exec" &&
           action.lookup("program") == "/usr/bin/netExtenderGui" &&
           subject.isInGroup("wheel")) {
           return polkit.Result.YES;
       }
   });
   ```
