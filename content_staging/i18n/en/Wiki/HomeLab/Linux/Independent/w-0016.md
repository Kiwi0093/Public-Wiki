## I. Getting Started: The Immutable `/nix/store` and Generations

In the world of Nix, there are no traditional `/usr/bin` or `/lib` directories. All software installations, dependencies, and configuration files are assigned a content-derived Hash value and uniformly dumped into `/nix/store/` (e.g., `/nix/store/1a2b3c...-python-3.10`).

This brings two massive benefits:

1. **No Dependency Hell:** Software A needs Python 3.9, and Software B needs Python 3.10; both can coexist perfectly in the system without interfering with each other.
2. **Painless Rollback:** Every system modification generates a new "Generation". Did an upgrade break something? Instantly switch back to the previous generation in a second.

_(Note: The commands below are categorized into two scenarios: "Standalone Nix Package Manager" and "NixOS Operating System".)_

## II. Basic Maintenance: Installing and Updating Systems

In Nix, we are currently in a transition period between the legacy `nix-env` command and the new `nix` command; this guide focuses on the most stable and commonly used syntax.

**1. System-wide Updates and Application for NixOS** If you use NixOS, you rarely install software manually via commands; instead, you modify the declarative configuration file `/etc/nixos/configuration.nix` and let the system "realize" it:

```bash
# Edit your system configuration file and add required packages
sudo vim /etc/nixos/configuration.nix

# Let the system compile/download and switch to the new state based on the configuration file
sudo nixos-rebuild switch

# If you only want to test the state temporarily, rebooting will revert to the previous state (great for testing high-risk settings):
sudo nixos-rebuild test
```

**2. Daily Package Management for Standalone Nix** If you are simply using Nix as a package manager on Ubuntu or macOS:

```bash
# Search for packages (recommended to use the web version search.nixos.org for speed)
nix-env -qaP <keyword>

# Install a package (strongly recommended to use the -A flag to install from attribute paths for speed and precision)
nix-env -iA nixpkgs.<package_name>

# Upgrade all installed user packages
nix-env -u
```

## III. Environment Cleanup and Garbage Collection

This is the **most important** maintenance action in Nix! Due to Nix's immutable nature, by default it **never deletes any old software** (to allow you to roll back at any time). If left unmanaged, `/nix/store` will quickly fill up your hard drive.

**1. Manually Trigger Garbage Collection (GC)**

```bash
# Find and delete orphan files in the current system that are "not referenced by any generation"
nix-collect-garbage

# ⚠️ Ultimate Cleanup (Deep Clean): Delete all old generations, keeping only the version "currently in use"
# Note: After running this, you will no longer be able to roll back to previous states!
nix-collect-garbage -d

# Requires root privileges to clean system-level waste (Mandatory for NixOS)
sudo nix-collect-garbage -d
```

**2. Configure Automatic Garbage Collection (NixOS Only)** Add this block to your `configuration.nix` to let the system automatically collect garbage weekly and prune old generations older than 7 days:

```nix
nix.gc = {
  automatic = true;
  dates = "weekly";
  options = "--delete-older-than 7d";
};
```

## IV. Lifesaving Tools: Time Machine and Generation Rollbacks

This is Nix's super killer feature. When you update the system or install new software and services fail to start or the system crashes, the recovery method is extremely simple and brutal.

**1. System-wide Rollback for NixOS**

```bash
# List all system generations and timestamps
sudo nix-env --list-generations --profile /nix/var/nix/profiles/system

# If the newly applied configuration is broken, mindlessly revert to the previous generation
sudo nixos-rebuild switch --rollback
```

_(Even if your system fails to boot, the NixOS bootloader menu (GRUB/systemd-boot) lists all historical generations by default; simply select the previous generation to boot up fully restored!)_

**2. User Package Rollbacks (Standalone Nix)**

```bash
# List the package modification history of the current account
nix-env --list-generations

# Revert to the state before the last operation
nix-env --rollback
```

## V. Advanced Magic Weapon: Nix Shell (A Feature You Won't Want to Live Without)

For those who frequently develop and test different environments or manage IaC automation pipelines, `nix-shell` is an absolute divine tool. It helps you create a "clean, disposable environment".

**Scenario: I just want to temporarily run a Python script requiring Ansible without installing them globally and messing up my environment!**

```bash
# Temporarily spin up a virtual terminal environment containing python3 and ansible
nix-shell -p python3 ansible
```

Once inside this shell, you can use `python3` and `ansible` normally. As soon as you type `exit` to leave this terminal, these packages act as if they never existed and are not left in your global environment (though downloaded files remain cached in `/nix/store` until cleared by the next garbage collection).

This perfectly solves the problem of messy temporary dependencies scattered all over development machines!
