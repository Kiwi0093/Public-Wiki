## I. Introduction: The Philosophy of Portage and USE Flags

When installing software in Gentoo, the system defaults to fetching source code and compiling it "live" on your machine. This introduces Gentoo's most powerful core feature: **USE Flags**. By defining USE Flags, you can decide at compile time whether to exclude or include specific features (e.g., compiling the entire system without Bluetooth support, or without GUI interfaces), achieving ultimate lightweight optimization.

Global configuration files are typically located at `/etc/portage/make.conf`, while fine-grained settings for individual packages are placed in `/etc/portage/package.use/`.

## II. Basic Maintenance: Syncing and Updating the System

Gentoo's update command is playfully referred to by players as "chanting a spell" because the parameters are very long, but every single one of them is crucial.

**1. Sync the Portage Tree (Sync)** First, fetch the latest compilation script (ebuilds) directory from the remote repository:

```bash
# Traditional usage
sudo emerge --sync

# Modern recommended usage (faster, supports multiple repositories)
sudo emaint sync -a
```

**2. Comprehensive System Update (World Update)** This line is the ultimate command most familiar to Gentoo users:

```bash
sudo emerge --ask --verbose --update --deep --newuse @world
# Usually abbreviated as:
sudo emerge -avuDN @world
```

> **Parameter Breakdown:**
> 
> - `-a (ask)`: List packages and ask for confirmation before compiling (essential to prevent typos).
> - `-v (verbose)`: Display detailed information (including USE Flag changes).
> - `-u (update)`: Update packages.
> - `-D (deep)`: Check updates along the entire dependency chain of dependencies.
> - `-N (newuse)`: If you modify USE Flags, this automatically catches affected packages and "recompiles" them to apply the new settings.

**3. Updating Configuration Files (Dispatch-conf)** After updating software, if global configuration files conflict, Gentoo will not overwrite them directly. You need to run:

```bash
sudo dispatch-conf
# Or
sudo etc-update
```

Press `u` to apply new settings, or `z` to discard them.

## III. Package Installation and "Orphan" Cleanup

**1. Searching and Installing Packages**

```bash
# Search for packages (though native search is very slow; an alternative eix will be introduced later)
emerge --search <keyword>

# Install a package (and record it in the world file)
sudo emerge -av <package_name>

# ⚠️ Key Tip: Install without recording (Oneshot)
# Use this when you want to install a build tool or dependency without recording it as primary software:
sudo emerge -av --oneshot <package_name>
```

**2. Uninstallation and Depclean (Orphan Cleanup)** Gentoo's removal logic is extremely rigorous. If you forcibly remove a package using `emerge -C <package>` (unmerge), you can easily break other packages' dependencies and cause system failure.

**Standard and Safe Removal Workflow:**

```bash
# 1. Unselect the specified package, removing it from the @world list (it checks dependencies and will block you if anyone else needs it)
sudo emerge --deselect <package_name>

# 2. Run dependency cleanup (Depclean)! This will clean up all orphan packages that are neither in @world nor needed by anyone else
sudo emerge --ask --depclean
# Abbreviated as:
sudo emerge -a --depclean
```

> [!info] Updated 2026-11-27
> Additional note: `emerge --deselect <package_name>` only removes the package from the `@world` list and **does not** immediately check reverse dependencies or uninstall the package; actual dependency checks and safe removal are handled by step 2 (`emerge -a --depclean`). (If you only want to check and remove a specific package individually, you can use `emerge -a --depclean <package_name>`.)

**3. Rebuilding Broken Dynamic Libraries (Preserved-rebuild)** After cleaning up or upgrading core libraries (such as glibc, openssl), some older software might fail to find `.so` files. Running this line automatically identifies affected software and recompiles them:

```bash
sudo emerge @preserved-rebuild
```

## IV. Freeing Disk Space: Source Code Cache Cleanup

Gentoo downloads all source code archive files (tarballs) before compilation, storing them all in `/var/cache/distfiles/`. Over time, this consumes a terrifying amount of space.

**1. Install Gentoolkit** This is an official toolkit containing powerful management utilities, a must-install:

```bash
sudo emerge -av app-portage/gentoolkit
```

**2. Clean Cache Using eclean**

```bash
# Safe cleanup: Keep source archives for currently installed packages, delete outdated versions
sudo eclean-dist

# Deep cleanup: Aggressive! Delete everything that is not the latest version in the Portage tree (-d = deep)
sudo eclean-dist -d

# If you build binary packages (buildpkg), clean old binary packages
sudo eclean-pkg -d
```

## V. Lifesaving Tools: Package Downgrading, Version Locking, and Masking

In Gentoo, version control is implemented via `/etc/portage/package.mask` (blacklist/disable) and `/etc/portage/package.accept_keywords` (unlock testing versions).

**1. Installing a Specific Older Version (Downgrade)** If you find a bug in a newer version, you can use `=` to specify the version number and force-install an older version:

```bash
# Note that the leading = sign is mandatory, and the full category path must be provided
sudo emerge -av =sys-kernel/gentoo-sources-6.1.60
```

**2. Locking Versions to Prevent Upgrades (Masking)** To prevent the system from automatically upgrading it back when running `emerge -avuDN @world` next time, you must "Mask" the newer version.

Edit or create the `/etc/portage/package.mask` file (or create a directory with the same name and place text files inside):

```bash
# Tell Portage: I do not want any version greater than or equal to 6.2 of this software
>=sys-kernel/gentoo-sources-6.2.0
```

Once configured, Portage will act as if versions 6.2 and above do not exist in the world.

## VI. Advanced Power Tools (Acceleration and Search)

**1. Eix: Ultra-Fast Search Tool** Native `emerge --search` scans the entire text database every time, which is excruciatingly slow. Be sure to install `eix`.

```bash
sudo emerge -av app-portage/eix

# Initialize and build the index database
sudo eix-update

# Ultra-fast package search
eix <keyword>
```

**2. Compilation Acceleration: MAKEOPTS** Because everything is compiled from source, compilation speed depends on your CPU core count. Be sure to configure parallel compilation in `/etc/portage/make.conf`:

```toml
# Assuming your CPU has 16 threads, typically set to core count or core count + 1
MAKEOPTS="-j16 -l16"
```

**3. Ccache: Compilation Cache** If you frequently recompile the same packages (e.g., when tweaking your kernel config or testing different USE Flags), installing and enabling `ccache` can make secondary compilation times several times faster. This is also a staple setup for Gentoo users.
