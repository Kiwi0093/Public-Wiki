## I. Getting Started: How to Install Yay (According to Different Arch Branches)

In Arch systems, software outside the official repositories resides in the AUR (Arch User Repository). `yay` is a powerful tool written in Go that is compatible with `pacman` syntax and seamlessly helps you download and compile software from the AUR.

Depending on the Arch branch you are using, the difficulty of installing `yay` varies:

**1. Vanilla Arch Linux or <span style="color:#e06c75"><del>ArchWSL</del></span> *(Updated 2026-11-27: The third-party ArchWSL project has been archived; you can now install Arch directly via the official WSL image `wsl --install -d archlinux`)***

Since official vanilla Arch repositories do not include an AUR helper, you must manually clone the source code and compile it the first time:

```bash
# 1. Install essential compilation tools and Git
sudo pacman -S --needed git base-devel

# 2. Clone the yay source code and enter the directory
git clone https://aur.archlinux.org/yay.git
cd yay

# 3. Compile and install (-s automatically resolves dependencies, -i automatically installs after compilation)
makepkg -si
```

**2. Manjaro**

Manjaro officially puts `yay` into their <span style="color:#e06c75"><del>community repository</del></span> *(Updated 2026-11-27: Manjaro has merged `community` into the `extra` repository)*, so it can be installed directly using `pacman`:

```bash
# Although you can install yay directly, it is recommended to install base-devel together so compilation won't throw errors when building AUR software later
sudo pacman -S base-devel yay
```

**3. EndeavourOS / Garuda Linux**

These two out-of-the-box Arch branches **come with `yay` pre-installed by default** when you set up the system, so no manual work is needed. If it happens to be removed by accident, because they have their own repositories mounted, you can run the command directly as well:

```bash
sudo pacman -S yay
```

Once installed, you can basically replace `pacman` with `yay` for your daily package management.

## II. Basic Maintenance: Installing and Updating the System

**1. Comprehensive System Update and Downgrade Synchronization**

Under normal circumstances, this updates both official packages and AUR packages simultaneously:

```bash
yay -Syu
```

> **Advanced Knowledge: What is the difference between `yay -Syu` and `yay -Syyuu`?**
>
> - **`-Syu` (Standard Update):** `-y` synchronizes the latest package databases, `-u` upgrades all outdated packages. This is the most frequently used command for daily updates.
>
> - **`-Syyuu` (Force Synchronization and Allow Downgrades):**
>     - **`-yy`**: **Forces** re-downloading and syncing from the server regardless of whether your local database is up to date (usually used when you just changed mirrors or if your database is corrupted).
>     - **`-uu`**: Allows package **downgrades**. If the software version on the server is older than the one on your computer (e.g., officials discovered a critical bug in a new version and urgently rolled it back), appending two `u`'s forces the system to revert to the older version to match the official repository state.

**2. Searching and Installing Packages**

```bash
# Install a specific package
yay -S <package_name>

# If you don't know the exact name, just type yay followed by a keyword to list matching choices
yay <keyword>
```

## III. Package Uninstallation and "Orphan" Cleanup

In Arch, the biggest pitfall is using `pacman -R` to remove the main program while leaving behind a pile of dependencies that were installed for it.

**1. Clean Package Removal (Including Dependencies)**

Make it a habit to append `s` when removing software, and append `n` if you also want to purge global configuration files:

```bash
sudo pacman -Rns <package_name>
# or
yay -Rns <package_name>
```

**2. Cleaning Up Orphan Packages**

Through system rolling updates or repeated software installation and removal, some "orphan packages" with no remaining software dependencies will accumulate.

- **Pacman Native Approach:**

    ```bash
    # One-click removal of all orphan packages
    sudo pacman -Rns $(pacman -Qtdq)
    ```

- **Yay Built-in Master Trick (Recommended):** Instead of memorizing the command above, `yay` has a dedicated built-in cleanup command:

    ```bash
    yay -Yc
    ```

## IV. Freeing Up Disk Space: Cache Cleaning

Every installation package downloaded or updated accumulates in `/var/cache/pacman/pkg/`, which can consume a massive amount of disk space over time.

**1. Manual Cache Cleaning**

```bash
# Safe cleanup: Only delete cache files of packages that have already been uninstalled
yay -Sc

# Deep cleanup: Clear "all" caches (frees up maximum space, but local older files will not be available for future downgrades)
yay -Scc
```

**2. Advanced Technique: Using Systemd for Automatic Scheduled Cleaning**

Utilize the `paccache -r` command (by default, it keeps the latest 3 versions and deletes older files).

> **Note:** Requires installing the `pacman-contrib` package (`yay -S pacman-contrib`).

Create the service file `/etc/systemd/system/paccache.service`:

```toml
[Unit]
Description=Clean-up old pacman pkg cache

[Service]
ExecStart=/usr/bin/paccache -r
```

Create the timer file `/etc/systemd/system/paccache.timer`:

```toml
[Unit]
Description=Clean-up old pacman pkg cache

[Timer]
OnCalendar=monthly    # Set to run once a month
Persistent=true       # Ensure scheduled runs aren't missed due to shutdown

[Install]
WantedBy=multi-user.target
```

Enable and start the timer:

```bash
sudo systemctl enable paccache.timer
sudo systemctl start paccache.timer
```

> [!info] Updated 2026-11-27
> 1. After installing `pacman-contrib`, the system includes `/usr/lib/systemd/system/paccache.service` and `paccache.timer` by default (scheduled weekly). Usually, you can simply run `sudo systemctl enable --now paccache.timer` without manually creating new unit files.
> 2. If you need to customize a `.timer` file, **systemd unit files do not support inline `#` comments on the same line as `Key=Value`** (e.g., `OnCalendar=monthly # ...` and `Persistent=true # ...` in the example above will cause syntax parsing errors); comments must be written on their own separate lines.

## V. Lifesaving Tool: Package Downgrade

Arch is a rolling release distribution, so you will inevitably encounter situations where a software update or kernel breaks things. In such cases, you need the `downgrade` tool to revert to a stable previous version.

**1. Installing the Downgrade Tool**

This program is hosted in the AUR; install it via `yay`:

```bash
yay -S downgrade
```

**2. Downgrading a Specific Package**

When you find that a package (such as Firefox or the Linux Kernel) broke after an update, run:

```bash
sudo downgrade <package_name>
```

**Post-Execution Workflow and Tips:**

1. The program will list all historical versions of the package. It will first check your local cache (`/var/cache/pacman/pkg/`); if not found locally, it will connect to the Arch Linux Archive (A.L.A.) cloud history repository to fetch it.
2. Type the "number" corresponding to the desired version and press Enter.
3. **⚠️ Critical Step:** After the downgrade completes, the terminal will ask: `add <package_name> to IgnorePkg? [y/N]` **It is strongly recommended to select `y`**. This adds the package to `pacman`'s blacklist, so the next time you run a global update with `yay -Syu`, `pacman` will automatically skip it, preventing it from being stealthily upgraded back to the broken version.

**3. How to Lift the Downgrade Lock (Remove IgnorePkg)**

When the official team releases a fix update and you want to allow the software to upgrade again, edit `/etc/pacman.conf`:

```bash
sudo vim /etc/pacman.conf
```

Find the line `IgnorePkg = <package_name>`, delete it or comment it out by prepending `#`, save and exit, and normal updates will resume next time.
