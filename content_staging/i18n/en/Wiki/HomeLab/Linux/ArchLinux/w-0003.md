## 1. Introduction to systemd-boot: A Lighter Modern UEFI Bootloader than GRUB

Under modern UEFI architectures, an increasing number of native Arch users and `archinstall` scripts choose **systemd-boot** (formerly Gummiboot). Compared to GRUB, which has bulky configuration files and relies on `grub-mkconfig` for regeneration, systemd-boot offers the following advantages:

- **Native Integration**: Built directly into systemd, eliminating the need to install bulky standalone bootloader packages.
- **Modular Configuration**: Each kernel boot entry is an independent `.conf` file without mutual interference.
- **Blazing Fast Boot**: Directly calls UEFI firmware interfaces to load EFI executables, resulting in extremely low boot latency.

## 2. systemd-boot Core Structure and Daily Management

All configurations and kernel image files for systemd-boot are stored in the EFI system partition (typically mounted at `/boot` or `/efi`, referred to as `/boot` below).

### 1. Core File Directory Tree

```text
/boot/
├── EFI/
│   ├── systemd/systemd-bootx64.efi
│   └── BOOT/BOOTX64.EFI
└── loader/
    ├── loader.conf                 # Global boot configuration file
    └── entries/                    # Boot menu entries storage
        ├── arch.conf               # Default Linux kernel
        └── arch-linux-zen.conf     # Zen performance kernel
```

### 2. Kernel Boot Entry File Example (`loader/entries/arch-linux-zen.conf`)

```toml
title   Arch Linux (Linux-Zen)
linux   /vmlinuz-linux-zen
initrd  /intel-ucode.img            # Use amd-ucode.img if using AMD
initrd  /initramfs-linux-zen.img
options root=UUID=xxxx-xxxx-xxxx rw quiet
```

> [!info] Updated 2026-11-27
> Boot Loader Specification `.conf` configuration files treat only lines starting with `#` at the **beginning of the line** as comments and do not support inline trailing `#` comments. When writing to `/boot/loader/entries/*.conf`, please move explanatory notes like `# 若為 AMD...` to an independent line or remove them to prevent path parsing errors that lead to boot failures.

### 3. Essential Boot Maintenance Command: bootctl

Daily maintenance requires no manual searching through configuration files; common operations can be completed via `bootctl`:

```bash
# View current boot status, default kernel, and all detected boot entries
bootctl status

# List all available boot entries
bootctl list

# Change the default boot entry with one click (the name corresponds to the filename in entries without the extension)
sudo bootctl set-default arch-linux-zen

# Set boot menu timeout (e.g., 3 seconds)
sudo bootctl set-timeout 3
```

> [!info] Updated 2026-11-27
> The `ID` parameter for `bootctl set-default` must be the full item identification name displayed by `bootctl list` (**including** the `.conf` extension), such as `sudo bootctl set-default arch-linux-zen.conf` (or use wildcards like `arch-linux-zen*`).

## 3. Core Pain Points: Why Are Kernel Updates Prone to Breaking Things?

When using systemd-boot, there are two common breakdown scenarios:

1. **Bootloader binary not synchronized after systemd package updates**: The system upgraded `systemd`, but `/boot/EFI/systemd/systemd-bootx64.efi` remains at the old version.
2. **Missing initramfs during multi-kernel switching**: When installing or removing new kernels (e.g., switching between `linux` and `linux-zen`), failure to promptly run `mkinitcpio -P` to regenerate images will cause reboots to hang directly on UEFI boot errors.

## 4. Ultimate Automation: Deploying Pacman Hooks Once and for All

In the Arch Linux philosophy, the most elegant solution is utilizing **Pacman Hooks** to automatically trigger maintenance scripts in the background after package installations or updates, completely eliminating human omissions.

### 1. Hook One: Automatically Upgrade Bootloader When systemd Updates

Create `/etc/pacman.d/hooks/95-systemd-boot.hook`:

```toml
[Trigger]
Type = Package
Operation = Upgrade
Target = systemd

[Action]
Description = Updating systemd-boot in EFI system partition...
When = PostTransaction
Exec = /usr/bin/bootctl update
```

_Effect: Whenever the `systemd` package is upgraded, the system automatically executes `bootctl update` to ensure the bootloader binary within the EFI partition remains synchronized with the system, preventing version drift._

### 2. Hook Two: Automatic Protection and Status Check After Kernel Updates

Although Arch's default `90-mkinitcpio-install.hook` automatically compiles images, if you frequently switch custom kernels or DKMS modules, you can create a custom check hook `/etc/pacman.d/hooks/99-boot-integrity.hook`:

```toml
[Trigger]
Type = Package
Operation = Install
Operation = Upgrade
Operation = Remove
Target = linux
Target = linux-zen
Target = linux-lts

[Action]
Description = Verifying bootloader entries integrity...
When = PostTransaction
Exec = /usr/bin/bootctl --dry-run list
```

_Effect: After any kernel installation, upgrade, or removal, it dry-runs and verifies the integrity of the boot menu configuration files in the terminal background. If paths are corrupted, warnings will be output directly within the pacman update flow, allowing you to fix them before shutting down._

> [!info] Updated 2026-11-27
> The `--dry-run` (`-n`) parameter for `bootctl` is only applicable to `unlink` and `cleanup` subcommands and has no actual effect on `list`. It is recommended to use `Exec = /usr/bin/bootctl --no-pager list` instead (`list` itself is already a read-only command). Additionally, `bootctl list` only checks entry file syntax and whether corresponding kernel/initrd file paths exist; it does not verify the internal integrity of the initramfs image itself.
