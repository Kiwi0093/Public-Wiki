## 📝 Background and Architecture Goals

For the resident `archdesk`, after upgrading to KDE Plasma 6.8, the native Wayland display server has deeply integrated the RDP protocol. To achieve more stable connections and better Wayland display support, this guide will walk through phasing out traditional X11-based TigerVNC and migrating to a modern remote desktop solution using `krdp` + Remmina (FreeRDP).

## 🛠️ Phase 1: System Upgrade and Environment Cleanup

### 1. System Update and Upgrade

Run a full system update to ensure you get the latest Plasma 6.8 and related dependencies:

```bash
sudo pacman -Syu
```

### 2. Remove TigerVNC Server

Clean up the old TigerVNC server and its orphaned dependencies to avoid port or background process conflicts with subsequent RDP services:

```bash
sudo pacman -Rns tigervnc
```

Remove leftover VNC passwords and configuration files in the user's home directory:

```bash
rm -rf ~/.vnc
```

## ⚙️ Phase 2: Core Key — Configuring SDDM Auto-Login

**⚠️ Important Concept:** `krdp` is a "user-level" service deeply integrated into KWin Wayland. If the VM reboots and stays at the SDDM login screen, the Wayland session has not started yet, meaning the `krdp` server will not be in a listening state, resulting in external connections being completely blocked.

### 1. Configure Auto-Login

Create or edit `/etc/sddm.conf.d/autologin.conf` on `archdesk` to have the system automatically load the default Wayland session upon booting:

```ini
[Autologin]
User=kiwi
Session=plasma
```

### 2. Handling KWallet (KDE Keyring) Password Popups

After configuring auto-login, the system will not receive plaintext passwords at login, so the default KDE KWallet will fail to unlock automatically.

- **Solution:** Once you log into the desktop via RDP, open **KWalletManager**, change the default wallet's password to "blank", and it will eliminate popup interruptions when subsequently opening browsers or other applications.
- *(Note: This setting does not affect SSH agent authorization running in the background as a Systemd User Service)*

## 🚀 Phase 3: Installing and Enabling KRDP

### 1. Install Necessary Packages

Install the KDE native RDP server component (`krdp`), along with the local client tool `remmina` and its dependent `freerdp` protocol core:

```bash
sudo pacman -S krdp remmina freerdp
```

### 2. Enable RDP Service

In KDE Plasma 6 and later Wayland environments, the RDP server is fully integrated into the graphical interface, eliminating the need to manually maintain configuration files:

1. Open **System Settings**.
2. Navigate to **System** -> **Remote Desktop**.
3. Enable the **Enable RDP server** option.
4. Set the username and password dedicated to remote connections in the interface.
5. *(Firewall check)*: Ensure the local firewall allows standard RDP ports (TCP 3389).

## 💻 Phase 4: Client Connection Setup (Remmina)

Open Remmina on the client machine initiating the connection (such as the physical Dell laptop at home, IP `192.168.31.21` / `.54`, etc.) to create a new connection profile:

- **Protocol**: Select `RDP - FreeRDP plugin`.
- **Server**: Enter the IP of the target `archdesk`, `192.168.31.11`.
- **Credentials**: Enter the RDP username and password created in KDE system settings.
- **Color & Quality**: In an intranet environment, it is recommended to set color depth to `True color (32 bpp)` or enable RemoteFX for optimal graphical rendering performance.

### Verify Connection

Run `sudo reboot` to restart `archdesk`. After waiting about 30 seconds, without opening any ESXi terminal consoles at all, initiate an RDP connection directly from the client. If you can log in directly and see the full KDE desktop, it indicates that both auto-login and the KRDP background service are working successfully.
