## I. Host Setting (Windows Host Settings)

**1. Update WSL Kernel**

Ensure your WSL is up to date by running in Windows PowerShell:

```powershell
wsl --update
```

**2. Enable Nested Virtualization**

> **⚠️ Common Pitfall Reminder:** Nested virtualization settings apply to the entire WSL2 virtual machine engine and must therefore be written in the global Windows configuration file `.wslconfig`, **not** inside WSL's internal `/etc/wsl.conf`.

Open Windows File Explorer, edit or create `C:\Users\<YourUsername>\.wslconfig`, and add the following section:

```ini
[wsl2]
nestedVirtualization=true
```

Once done, force restart WSL in PowerShell to apply the settings:

```powershell
wsl --shutdown
```

## II. Installing QEMU/KVM and Virt-Manager in ArchWSL

> [!info] Updated 2026-11-27
> 1. In addition to the third-party `ArchWSL`, Arch Linux now provides an official WSL2 image (`archlinux-wsl`), which can be installed directly in Windows via `wsl --install archlinux`.
> 2. Before executing `systemctl enable --now libvirtd` below, you must ensure that WSL's internal `/etc/wsl.conf` has configured `systemd=true` under the `[boot]` section and restarted via `wsl --shutdown`, otherwise `systemctl` will not function.

After restarting and entering WSL (Arch Linux), begin installing virtualization-related tools.

**1. Install Core and Network Packages**

```bash
sudo pacman -S archlinux-keyring qemu-full virt-manager virt-viewer edk2-ovmf dnsmasq vde2 bridge-utils openbsd-netcat libguestfs iptables virglrenderer
```

> [!info] Updated 2026-11-27
> 1. `ebtables` has been removed from the official Arch Linux package repositories, and its functionality has been replaced by `iptables` supporting the `nftables` backend. Please remove `ebtables` when running `pacman -S` to avoid `target not found` errors.
> 2. If you need the VirtioFS shared folder feature detailed in Section 4, please also install the `virtiofsd` package (split from QEMU into an independent package).

**2. Install TPM 2.0 Emulation Package (If running Windows 11 Guest)**

```bash
sudo pacman -S swtpm
```

**3. Start and Configure Libvirt Service**

```bash
# Start and enable libvirtd on boot
sudo systemctl enable --now libvirtd

# Start default virtual network (NAT)
sudo virsh net-start default

# Set virtual network to auto-start on boot
sudo virsh net-autostart default
```

**4. Adjust Account Permissions**

To avoid entering the root password every time you open Virt-Manager, add the current user to the relevant groups:

```bash
sudo usermod -a -G libvirt $USER
sudo usermod -a -G libvirt root
sudo usermod -a -G kvm $USER
sudo usermod -a -G kvm root
```

> [!info] Updated 2026-11-27
> The `root` account inherently possesses full system permissions and does not require running `usermod -a -G libvirt root` and `usermod -a -G kvm root`. You only need to add the regular user `$USER` to the `libvirt` and `kvm` groups and re-login (or restart WSL).

**5. Configure Polkit Rules (Passwordless Management)**

Edit `/etc/polkit-1/rules.d/50-libvirt.rules`:

```javascript
/* Allow users in kvm group to manage the libvirt daemon without authentication */
polkit.addRule(function(action, subject) {
    if (action.id == "org.libvirt.unix.manage" &&
        subject.isInGroup("kvm")) {
            return polkit.Result.YES;
    }
});
```

After making modifications, restart the service to apply permissions (safest is to log out of WSL and log back in, or run `wsl --shutdown`):

```bash
sudo systemctl restart libvirtd
```

## III. Guest OS Settings (Taking Arch Linux as a Second-Layer Example)

Once you have installed a Guest OS (virtual machine) in Virt-Manager, you need to install enhancement packages similar to VMware Tools to enable auto-scaling windows and clipboard sharing.

**1. Install QEMU and SPICE Guest Agents**

Run inside the **Guest OS (inside the virtual machine)**:

```bash
sudo pacman -S spice-vdagent qemu-guest-agent xf86-video-qxl
```

If you are using an X11 desktop environment, you can install `x-resize` via AUR for window auto-scaling:

```bash
yay -S x-resize
```

> **💡 Confusion Regarding Service Enable:** Many older online tutorials state that you need to `systemctl enable` these services. However, modern `spice-vdagent` is usually automatically started by the desktop environment (such as GNOME / KDE / XFCE autostart), while `qemu-guest-agent` is triggered via socket. Therefore, not finding corresponding service files or not needing to manually enable them is normal; as long as the functionality works normally after rebooting.

## IV. Mounting Shared Folder (VirtioFS)

Through VirtioFS, the Guest OS can natively and efficiently access folders on the Host (referring to WSL here).

**1. Virt-Manager Hardware Configuration**

1. Shut down the Guest OS first.
2. Click the "light bulb" icon on the top row of the Virt-Manager window (Show virtual hardware details).
3. Click **Add Hardware** at the bottom left.
4. Select **Filesystem**:
   - **Driver:** Select `virtiofs`
   - **Source path:** Enter the directory in WSL, e.g., `/home/kiwi/host` (remember to create this folder in WSL first)
   - **Target path:** This is the Mount Tag, name it freely, e.g., `host`
5. Click Finish and start the virtual machine.

> [!info] Updated 2026-11-27
> Before using VirtioFS, you must also check **Enable shared memory** in the **Memory** page of the Virt-Manager virtual machine settings, otherwise starting the virtual machine will result in a `virtiofs requires shared memory` error.

**2. Mounting in Guest OS**

**Manual mount test:**

```bash
# -t virtiofs <Target Path Tag> <Mount point inside Guest OS>
sudo mount -t virtiofs host /home/kiwi/host
```

**Write to `/etc/fstab` for auto-mount on boot:**

After confirming manual mounting works, edit `/etc/fstab` inside the Guest OS and add this line:

```text
# Shared Folder with HOST (WSL)
# <Target Tag>    <Mount Point>     <Format>   <Options>                    <dump> <pass>
host              /home/kiwi/host   virtiofs   rw,noatime,_netdev           0      2
```

> **Note:** Adding the `_netdev` option ensures the system mounts after loading network and external device modules, preventing boot hangs.

> [!info] Updated 2026-11-27
> The sixth column `pass` (`fsck` check order) is recommended to be set to `0` (i.e., `0 0`) rather than `2`, because `virtiofs` is a virtual shared filesystem and there is no corresponding `fsck.virtiofs` checking tool in the system.
