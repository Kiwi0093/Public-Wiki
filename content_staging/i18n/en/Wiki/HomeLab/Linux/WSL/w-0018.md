## Basic Environment and Requirements

**Windows System Version Verification**

- **Minimum Requirements:** Windows 10 version 2004 and later (Build 19041 and above) or Windows 11.
- **How to Check Version:** Press `Win + R` and type `winver`.
- **Windows 10 Note:** <span style="color:#e06c75"><del>To fully support the latest WSL features, Windows 10 generally requires update **KB5020030**. If your system does not update automatically, you can search and download it from the [Microsoft Update Catalog](https://www.catalog.update.microsoft.com/Search.aspx?q=KB5020030) according to your platform.</del></span> *(Updated 2026-11-27: KB5020030 has been superseded by subsequent cumulative updates, and Windows 10 reached end of life (EOL) on October 14, 2025; it is recommended to use Windows 11 directly.)*

## WSL Installation Steps

There are two ways to install WSL now. Using the command line is recommended for speed, but you can also use the GUI if you prefer:

### Method 1: Quick Command Installation (Recommended)

Open PowerShell with administrator privileges and enter:

```powershell
wsl --install
```

This command will automatically enable all necessary Windows features and install Ubuntu by default. If you want to enable the features without installing Ubuntu, you can append the `--no-distribution` flag. Reboot your system after the process finishes.

### Method 2: Traditional GUI Installation

If you prefer manually confirming features or downloading from the Microsoft Store:

1. Search for **WSL** in the Microsoft Store and install it.
2. Open "Turn Windows features on or off".
3. Ensure the following core components are checked:

   - <span style="color:#e06c75"><del>**Hyper-V**: This must be enabled.</del></span> *(Updated 2026-11-27: Running WSL 2 does not require enabling the full Hyper-V role, and Windows Home editions do not have this option.)*
   - <span style="color:#e06c75"><del>**Windows Hypervisor Platform**</del></span> *(Updated 2026-11-27: This option is intended for third-party emulators/virtual machines and is not a required component for WSL 2.)*
   - **Windows Subsystem for Linux**: The core component for WSL.
   - **Virtual Machine Platform**: Required for WSL 2.

4. Reboot your computer after configuration.

## Recommended Tool: Windows Terminal

Using **Windows Terminal** (also available in the Store) is strongly recommended when working with WSL.

> **Customization Tip:** Remember to install the **Nerd Fonts** family and set it as the font in Windows Terminal settings. This ensures that when you use `zsh` with themes like `powerlevel10k` inside WSL, those fancy icons and status bars won't render as garbled characters (essentially required for any customized environment).

## Custom Distribution: ArchWSL

Since I am not fond of the built-in WSL distributions (mostly Debian/Ubuntu derivatives), I chose to use **ArchWSL**.

- **Installation Usage:** <span style="color:#e06c75"><del>Very simple; you can now open the **Microsoft Store**, search for **ArchWSL** (or Arch Linux), and click get and install. After installation, launch it directly from the start menu to perform initial environment initialization. Compared to downloading and extracting archives from GitHub manually in the past, installing and managing through the Microsoft Store is much more convenient.</del></span> *(Updated 2026-11-27: `yuk7/ArchWSL` is a third-party GitHub project rather than an official Microsoft Store listing; official native Arch Linux WSL images are now available and can be installed directly in PowerShell via `wsl --install archlinux`.)*

## Verifying Systemd Status

After installing ArchWSL via the Store, we need to verify and manually enable `systemd` support inside WSL by following these steps:

**1. Check WSL Version** Enter the following in Windows PowerShell or CMD:

```powershell
wsl --version
```

_Confirm that the version number is displayed and is Store version (1.0.0 or higher)._

**2. Check and Modify WSL Configuration File** Enter your ArchWSL terminal and ensure `/etc/wsl.conf` exists and contains the following lines:

```ini
[boot]
systemd=true
```

**3. Restart and Verify** Go back to Windows PowerShell, completely shut down WSL, and restart it:

```powershell
wsl --shutdown
wsl
```

After re-entering WSL, run the following command to check the PID 1 process:

```bash
ps --no-headers -o comm 1
```

If `systemd` is displayed on the screen, it was successful!

## Appendix: VirtualBox Conflict Resolution (Hyper-V support)

Since Hyper-V and the Virtual Machine Platform are enabled, if you also use VirtualBox, you might encounter issues where virtual machines fail to start. The solution is simple: go to the VM settings in VirtualBox, navigate to "System" -> "Acceleration", and change the **Paravirtualization Interface** to `Hyper-V`.
