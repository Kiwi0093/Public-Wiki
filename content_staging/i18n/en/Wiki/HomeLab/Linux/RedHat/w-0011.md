## Installation

After downloading the ISO image, create a new virtual machine on VMware Workstation or VMware ESXi (select VMware Photon OS 64-bit or the latest Linux Kernel 64-bit for guest OS type), boot from the ISO, and complete the installation using the setup wizard.

Photon OS itself requires minimal memory and disk space, but primary resource consumption will stem from subsequently running Docker containers. Plan RAM and disk capacity reasonably based on your anticipated services when creating the VM.

## Basic Setup

**Verify Basic Services**

Verify that core system services (such as `open-vm-tools`) are running properly:

```bash
systemctl status vmtoolsd.service
```

**Account Setup**

The `root` password is configured during installation. For daily operational security, you can create a standard user account using `useradd`:

```bash
# Add user (-m creates home directory, -g specifies root group)
useradd -m -g root $(your_id)

# Set password for your account
passwd $(your_id)
```

> [!info] Updated 2026-11-27
> `$(your_id)` in the example above will be evaluated as command substitution in Bash; replace it directly with the target username when executing (e.g., `useradd -m -G wheel <your_id>`). Additionally, it is practically recommended to grant privilege escalation via `-G wheel` or `sudo` rather than setting the regular user's primary group directly to `root`.

Since system administration frequently requires `root` privileges, you can choose according to personal preference whether to create a standard account combined with `su` / `sudo`, or modify `/etc/ssh/sshd_config` to permit `root` logins via SSH.

## Network Configuration (systemd-networkd)

The default post-installation system enables DHCP. If you require only a single IP and the local network already utilizes a DHCP Server with MAC address reservation controls, you can keep the defaults; if you have advanced requirements like static IPs, modify the following configuration files.

**Disable DHCP**

Edit `/etc/systemd/network/99-dhcp-en.network`:

```ini
[Match]
Name=e*

[Network]
DHCP=no    # Change to no to disable DHCP
IPv6AcceptRA=no
```

**Static IP Configuration Method**

Edit `/etc/systemd/network/10-static-en.network`:

```ini
[Match]
Name=ens160                                # Network interface name

[Network]
Address=10.1.10.9/24                       # IP address, can be repeated in multiple lines
Gateway=10.1.10.1                          # Gateway IP
DNS=10.1.10.1                              # DNS IP
# NTP settings, separated by spaces for multiple servers
NTP=tock.stdtime.gov.tw watch.stdtime.gov.tw time.stdtime.gov.tw
# Disable IPv6
LinkLocalAddressing=no
IPv6AcceptRA=no
```

**Customizing Network Interface Names**

Edit `/etc/systemd/network/10-ethusb0.link`:

```ini
[Match]
MACAddress=00:00:00:00:00:00               # Network card MAC address

[Link]
Description=USB to Ethernet Adapter        # Description
Name=ethusb0                               # Interface name
```

If you have multiple network cards, simply create corresponding `.link` and `.network` files specifying their respective MAC addresses and interface names.

## System Updates and Installing Packages

## System Updates and Installing Packages

> **Correction Note:** The underlying package management tool in Photon OS is actually `tdnf`. While the system provides an alias so that running `yum` works interchangeably, it is recommended to build the habit of using `tdnf` directly.

```bash
tdnf update -y          # Upgrade system packages
tdnf install -y vim     # Install vim
tdnf search python      # Search packages containing python in their name
```

## Mounting SMB Shared Folders

In practice, Docker volume directories are commonly mounted to backup/shared directories on a NAS, offering several benefits:

1. Simplifies centralized data backups.
2. Reduces disk space consumption on the Photon OS virtual machine itself.
3. Enables direct access for Docker services that need to read NAS files (e.g., personal music libraries stored on a NAS are very convenient to access via SMB/CIFS).

First, install `cifs-utils` on Photon OS using `tdnf`:

```bash
tdnf install -y cifs-utils
```

Next, create the credentials file `/root/secret`:

```ini
username=sushi    # SMB account
password=yummy    # SMB password
```

> It is recommended to restrict `/root/secret` permissions to `0400` for security (`chmod 0400 /root/secret`).

Add the mount configuration to `/etc/fstab`:

```text
\\winbox\getme /mnt/win cifs user,uid=500,rw,noauto,suid,credentials=/root/secret 0 0
```

> [!info] Updated 2026-11-27
> When writing CIFS shared paths in Linux `/etc/fstab`, use forward slashes `//winbox/getme` (backslashes `\\` are treated as escape characters in fstab, causing parsing errors), and modern NAS environments typically require SMB version parameters like `vers=3.0`. Furthermore, in addition to the independent systemd service approach below, modern systems can also append `_netdev,x-systemd.automount` directly to `/etc/fstab` mount options to ensure automatic mounting once the network is ready.

**Using systemd for Automatic Boot Mounting**

I previously experimented with `autofs` (which proved ineffective on Photon OS) and direct `auto` mounting in `/etc/fstab`, which frequently failed because mounting occurred before network connectivity was established. Therefore, the most stable approach is creating a systemd service that explicitly triggers mounting after the network is online.

Edit `/etc/systemd/system/mount-nas.service`:

```ini
[Unit]
Description=mount CIFS
# Ensure execution occurs after network connectivity is truly established
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/bin/mount -a
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
```

The key is setting `After=network-online.target` to ensure mounts run only after network connectivity is confirmed. Once configured, reload and enable the service:

```bash
systemctl daemon-reload
systemctl enable --now mount-nas.service
```

## Advanced Tip: Disk Expansion

After running for a while, even with space conservation, the initial disk capacity allocated to the virtual machine may become insufficient (I've encountered this two or three times). When using Windows VMs in the past, one would typically add a virtual disk and mount it as a new drive letter; under Photon OS, however, you usually want to expand the original `/dev/sda` directly.

**1. Adjusting Virtual Disk Capacity in ESXi**

Go to the ESXi backend, edit the virtual machine settings, and increase the hard disk capacity.

**2. Rescanning and Expanding Partitions in the System**

If `parted` is not installed, install it first:

```bash
tdnf -y install parted
```

Next, rescan disk changes and launch `parted`:

```bash
# Rescan block devices so the system detects space added by ESXi
echo 1 > /sys/class/block/sda/device/rescan

# Enter parted interactive shell
parted /dev/sda
```

Inside `parted`, run the following sequentially:

```text
# List partitions; if the system prompts that all disk space is not yet applied and asks whether to fix, enter f (or fix)
(parted) print

# Confirm the primary partition number in use (usually 1 or 3), then use resizepart to allocate all space (100%)
(parted) resizepart 1 100%

# Quit parted when finished
(parted) quit
```

**3. Expanding the File System**

> **Correction Note:** `resize2fs` should take the partition device name (e.g., `/dev/sda1`) rather than the entire disk (`/dev/sda`).

Use `resize2fs` to expand the file system on that partition (assuming the first partition was expanded):

```bash
resize2fs /dev/sda1
```

Once completed, verify whether capacity has expanded successfully using `df -H`!
