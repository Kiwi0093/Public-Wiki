## Prerequisites

* First, verify that the system booted from the LiveCD has network connectivity.

* Check whether the script can be reached with `host raw.githubusercontent.com`; if not, configure `/etc/hosts` or your DNS settings.

* The direct URL to the script is as follows:

  [https://Kiwi0093.github.io/script/Arch/arch.sh](https://Kiwi0093.github.io/script/Arch/arch.sh)

* You can configure the network manually (if DHCP is not available on your network):

```bash
#利用ip指令設定網路連線
ip address add $YOUR_IP/24 dev $your_dev
ip route add default $Gateway_IP dev $your_dev
```

> [!info] Updated 2026-11-27
> The original example `ip route add default $Gateway_IP dev $your_dev` is missing the `via` keyword; the correct syntax is `ip route add default via $Gateway_IP dev $your_dev`.

#### Mirrorlist Configuration

```bash
#Modify Mirrorlist to setting country
echo -n "${COLOR1}Please Select the country you want to set for mirror list\n${NC}${COLOR_H1}C)China\nT)Taiwan\n*)whatever..I don't care\n${NC}"
while :
do
	read COUNTRY
	case $COUNTRY in
		C)
			echo -e "${COLOR2}Set China${NC}"
			sed -i '/Score/{/China/!{n;s/^/#/}}' /etc/pacman.d/mirrorlist
			break
			;;
		T)
			echo -e "${COLOR2}SetTaiwan${NC}"
			sed -i '/Score/{/Taiwan/!{n;s/^/#/}}' /etc/pacman.d/mirrorlist
			break
			;;
		*)
			echo -e "${COLOR2}Keep original Setting${NC}"
			break
			;;
	esac
done
echo -e "${COLOR2}Completed${NC}"
```

Since Arch Linux does not have a built-in `pacman-mirrors` command, the official approach of using `sed` on `/etc/pacman.d/mirrorlist` is used to configure the *mirror list*.

The `pacman -Syyu` added later is mainly used to refresh the mirror list.

*Update 2021/06/15: Added color tags to all options for better visual readability*

> [!info] Updated 2026-11-27
> Modern Arch Linux Live ISOs use `reflector` by default to generate `/etc/pacman.d/mirrorlist` and no longer include `# Score` markers, so this `sed` filter rule no longer works.

#### Fdisk & Mount

```bash
#Fdisk
echo -e "${COLOR1}Partition your HDD please create sda1 for Data and sda2 for Swap.${NC}"
fdisk /dev/sda
echo -e "${COLOR2}Partition Setup Completed${NC}"

#Format
echo -e "${COLOR1}Format /dev/sda1 as EXT4 format${NC}"
mkfs.ext4 /dev/sda1
echo -e "${COLOR2}EXT4 formatting Completed${NC}"
echo -e "${COLOR1}Format /dev/sda2 as Linux Swap${NC}"
mkswap /dev/sda2
echo -e "${COLOR2}Swap Formatting Completed${NC}"
echo -e "${COLOR1}Mount /dev/sda1 to /mnt${NC}"
mount /dev/sda1 /mnt
echo -e "${COLOR2}Completed${NC}"
echo -e "${COLOR1}Mount Swap${NC}"
swapon /dev/sda2
echo -e "${COLOR2}Completed${NC}"
```

This is one of the main reasons this script cannot be universal: the **_format_** section hardcodes the HDD partition layout and mount points, removing flexibility.

In addition, because every use case for this script was installing an *Arch Linux guest* under **_VMware ESXi_**, simple `fdisk` was chosen over other partitioning tools, which also locked the subsequent `grub` installation to *MBR* rather than today's standard *UEFI*.

The script uses ext4—the most common format, though not the highest-performing—for this Arch Linux system; if you prefer another filesystem, you can change it to suit your needs.

#### Installation

```bash
#Install
echo -e "${COLOR1}Starting Install Archlinux into /mnt${NC}"
echo -e "${COLOR1}Please select your CPU vendor and Linux Kernel you want:\n${NC}${COLOR_H1}1)Intel+Linux\n2)Intel+Linux-LTS\n3)Amd+Linux\n4)Amd+Linux-LTS\n5)Linux-LTS Kernel\n*)Whatever, Normal Linux Kernel is good enough to me\n${NC}"
while :
do
	read CPU
	case $CPU in
	1)
		echo -e "${COLOR2}Linux Kernel＋Intel${NC}"
		pacman -Syyu
		pacstrap /mnt base linux linux-firmware vim zsh curl netctl intel-ucode grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	2)
		echo -e "${COLOR2}Linux-LTS Kernel＋Intel${NC}"
		pacman -Syyu
		pacstrap /mnt base linux-lts linux-firmware vim zsh curl netctl intel-ucode grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	3)
		echo -e "${COLOR2}Linux Kernel＋Amd${NC}"
		pacman -Syyu
		pacstrap /mnt base linux linux-firmware vim zsh curl netctl amd-ucode grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	4)
		echo -e "${COLOR2}Linux-LTS Kernel＋Amd${NC}"
		pacman -Syyu
		pacstrap /mnt base linux-lts linux-firmware vim zsh curl netctl amd-ucode grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	5)
		echo -e "${COLOR2}Linux-LTS Kernel${NC}"
		pacman -Syyu
		pacstrap /mnt base linux-lts linux-firmware vim zsh curl netctl grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	*)
		echo -e "${COLOR2}Linux Kernel${NC}"
		pacman -Syyu
		pacstrap /mnt base linux linux-firmware vim zsh curl netctl grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	esac
done
echo -e "${COLOR2}Completed${NC}"
```

Because this installation runs inside the Live CD environment to install packages onto the HDD, you cannot use **_pacman_** directly; instead, you must use **_pacstrap_** to install packages to the target location.

`pacstrap /<location> package1 package2 ....`

We can use this command to directly install the common packages that would otherwise be installed inside `arch-chroot`. I haven't tested running all packages here yet, though it should not affect systemd operation.

> [!info] Updated 2026-11-27
> 1. The official Arch Wiki advises against running `pacman -Syyu` in the Live ISO environment (it can easily exhaust the in-memory cowspace or cause package conflicts in the Live environment; if you only need to update signing keys, use `pacman -Sy archlinux-keyring` instead).
> 2. The `dnsutils` package has been renamed to `bind` in Arch Linux; `net-tools` and `netctl` are also legacy tools, and modern environments should use `iproute2` with `NetworkManager` or `systemd-networkd` instead.
> 3. In the original command, `vim` is listed twice.

#### Generating fstab for the New System

```bash
#fstab
echo -e "${COLOR1}Starting Gernerate fstab${NC}"
genfstab -U -p /mnt >> /mnt/etc/fstab
echo -e "${COLOR2}Completed${NC}"
```

Because Arch Linux does not have an installer that automatically writes fstab to the new system after partitioning the HDD, `genfstab` is used to generate it and redirect the output directly into */etc/* on the HDD.

> [!info] Updated 2026-11-27
> Newer versions of `genfstab` from `arch-install-scripts` already exclude virtual filesystems by default and have deprecated the `-p` flag. The modern standard usage is `genfstab -U /mnt >> /mnt/etc/fstab`.

#### Copying zsh Configuration to the New System

```bash
#Copy Zsh
echo -e "${COLOR1}Starting Copy ZSH setting file to new Archlinux${NC}"
cp -Rv /etc/zsh /mnt/etc/
echo -e "${COLOR2}Completed${NC}"
```

Since I personally quite like the default `zshrc` configuration style in the Arch Linux Live CD, I simply copy the config files automatically during installation so that every Arch Linux instance installed via this script has a consistent shell style.

#### Choosing Which Install Script to Fetch and Entering arch-chroot

```bash
echo -n "${COLOR1}Please select which type you want${NC}${COLOR_H1}\na)Simple Server\nb)Nextcloud Server\nc)V2Ray Server\nd)V2Ray Gateway\n*)I'm the best! let me do by my own!!\n${NC}"
while :
do
	read SCRIPT
	case $SCRIPT in
		a)
			echo -e "${COLOR2}Simple Arch Linux${NC}"
			arch-chroot /mnt /bin/zsh <(curl -L -s https://Kiwi0093.github.io/script/simple_arch.sh)
			break
			;;
		b)
			echo -e "${COLOR2}Nextcloud Server${NC}"
			arch-chroot /mnt /bin/zsh <(curl -L -s https://Kiwi0093.github.io/script/nextc_arch.sh)
			break
			;;
		c)
			echo -e "${COLOR2}V2Ray Server${NC}"
			arch-chroot /mnt /bin/zsh <(curl -L -s https://Kiwi0093.github.io/script/arch_v2ray.sh)
			break
			;;
		d)
			echo -e "${COLOR2}V2Ray Gateway${NC}"
			arch-chroot /mnt /bin/zsh <(curl -L -s https://Kiwi0093.github.io/script/arch_v2ray_gate.sh)
			break
			;;
		*)
			echo -e "${COLOR2}Yes! you're the chosen one!${NC}"
			arch-root /mnt /bin/zsh
			break
			;;
	esac
done
```

Because the Arch Linux installation flow is:

> Prepare the HDD inside the Live CD OS, install the new Arch Linux system onto the HDD over the network, then chroot into the new system to perform initial setup and bootloader configuration, and finally exit and reboot from the HDD to complete the new system installation.

So it was built as an option menu to automatically run the corresponding script after entering `arch-chroot`, or drop directly into `arch-chroot` for manual setup.

*Update 2021/06/15: Removed the Kiwi's Private Router option since it is no longer needed*

> [!info] Updated 2026-11-27
> The `*)` fallback branch has a typo (`arch-root` instead of the correct `arch-chroot /mnt /bin/zsh`), and all auxiliary sub-scripts under `Kiwi0093.github.io/script/` have been retired and are no longer available.

echo -e "${COLOR2}Finished Installation, will reboot, Good luck${NC}"
