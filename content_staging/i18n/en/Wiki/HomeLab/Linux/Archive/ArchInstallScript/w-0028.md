> [!info] Updated 2026-11-27
> In a static IP environment without DHCP, setting only the IP address and default gateway is not enough for `pacman` or `curl` to resolve domain names; you also need to configure `/etc/resolv.conf` in the Live ISO environment (e.g., `nameserver 1.1.1.1`). Additionally, for modern Arch Linux installations, using the built-in `archinstall` is recommended, and Nextcloud itself is better deployed using the official Docker Compose or Nextcloud AIO containers.

Once that's done, just ping to verify network connectivity.


#### Network Configuration

```bash
#Hostname
echo -e "${COLOR1}Please input your hostname\n${NC}"
read HOSTNAME
echo ${HOSTNAME} > /etc/hostname
echo "127.0.0.1 localhost ${HOSTNAME}" >> /etc/hosts
echo -e "${COLOR2}Completed${NC}"

echo -e "${COLOR1}Define your NIC by Mac address${NC}"
echo -e "${COLOR1}Please input your MAC Address(need to be lowcase):\n${NC}"
read OUTSIDE
echo 'SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="'${OUTSIDE}'", NAME="EXT0"' > /etc/udev/rules.d/10-network.rules
echo -e "${COLOR2}Completed${NC}"

echo -e "${COLOR1}Define your IP for EXT0:${NC}"
echo "Description='EXT0 IP SETTING'" > /etc/netctl/EXT0.service
echo "Interface=EXT0" >> /etc/netctl/EXT0.service
echo "Connection=ethernet" >> /etc/netctl/EXT0.service
echo "IP=static" >> /etc/netctl/EXT0.service
echo -n "${COLOR1}Please input your IP address:\n${NC}"
read EXT_IP
echo "Address=('${EXT_IP}/24')" >> /etc/netctl/EXT0.service
echo -n "${COLOR1}Please input your Gateway IP address:\n${NC}"
read GATE_IP
echo "Gateway='${GATE_IP}'" >> /etc/netctl/EXT0.service
echo -n "${COLOR1}Please input your DNS IP address:\n${NC}"
read DNS_IP
echo "DNS=('${DNS_IP}')" >> /etc/netctl/EXT0.service
echo -e "${COLOR2}Enable EXT0${NC}"
netctl enable EXT0.service
echo -e "${COLOR2}Finished.${NC}"
```

* This configuration uses a fixed **_MAC Address_** to name the **_NIC Interface_** as **_EXT0_**.
* This configuration is handled using `netctl`.

> [!info] Updated 2026-11-27
> `netctl` is considered legacy on modern Arch Linux, where `systemd-networkd` (with `.link` / `.network` files) or `NetworkManager` is typically used instead. Furthermore, `netctl` profile files should not have a `.service` extension (it should be `/etc/netctl/EXT0` followed by `netctl enable EXT0`); the original syntax creates a redundant `netctl@EXT0.service.service`.

#### Changing the root Password and Creating Additional Accounts

```bash
#Root Password
echo -e "${COLOR1}Set your root password${NC}"
passwd
chsh -s /bin/zsh
echo -e "${COLOR2}Completed${NC}"

#add User
echo -e "${COLOR1}Add user account:${NC}"
echo -n "${COLOR1}What ID you want:${NC}"
read YOURID
useradd -m -g root -s /bin/zsh ${YOURID}
passwd ${YOURID}
echo -e "${COLOR2}Completed${NC}"

echo -e "${COLOR1}Add $YOURID into sudo list${NC}"
pacman -Syu sudo
echo "${YOURID} ALL=(ALL) ALL" >> /etc/sudoers
echo -e "${COLOR2}Completed${NC}"
```

> [!info] Updated 2026-11-27
> There are three issues with this section of the script:
> 1. The `zsh` package is not installed before running `chsh -s /bin/zsh` and `useradd -s /bin/zsh`, which will prevent login.
> 2. `useradd -g root` sets the regular user's primary group to `root` (GID 0), which violates security best practices; the standard approach is `useradd -m -G wheel` and enabling `%wheel` in sudoers.
> 3. `pacman -Syu sudo` is missing `--noconfirm`, and appending directly with `>> /etc/sudoers` risks syntax errors; it is recommended to create a separate drop-in file under `/etc/sudoers.d/` and validate it with `visudo -c`.

**Update 2021/06/16**:

> [!info] Updated 2026-11-27
> This section of the script contains the following errors and package changes:
> 1. `chomd 777 yay` is a typo (it should be `chmod`).
> 2. Running `sudo -u kiwi makepkg -si` inside `/root` will fail due to insufficient permissions on `/root`, and the username `kiwi` is hardcoded instead of using `${YOURID}` from earlier (building in `/tmp/yay` is recommended).
> 3. Modern Arch Linux official repositories have removed `php-imap` (moved to PECL/AUR since PHP 8.4), and Arch's `nextcloud` package often depends on `php-legacy` / `php-legacy-fpm` depending on version compatibility.

##### MariaDB

```bash
#Setup service
#setup MariaDB
echo -e "${COLOR1}Start to Setup MariaDB${NC}"
mariadb-install-db --user=mysql --basedir=/usr --datadir=/var/lib/mysql
mkdir -pv /var/lib/mysqltmp

echo "[client]" >> /etc/my.cnf

echo "" >> /etc/my.cnf
echo "[mysql]" >> /etc/my.cnf
echo "default-character-set = utf8mb4" >> /etc/my.cnf
echo "" >> /etc/my.cnf
echo "[mysqld]" >> /etc/my.cnf
echo "collation_server = utf8mb4_unicode_ci" >> /etc/my.cnf
echo "character_set_server = utf8mb4" >> /etc/my.cnf
echo "tmpdir      = /var/lib/mysqltmp" >> /etc/my.cnf
mount /var/lib/mysqltmp
systemctl enable mariadb.service
sudo -u mysql /usr/bin/mariadbd &

mysql_secure_installation
echo -n "${COLOR1}Please input your Username for Nextcloud Database:\n${NC}"
read NCUSER
echo -n "${COLOR1}Please input your Password for Nextcloud Database User:\n${NC}"
read NCPASSWD
mysql -u root -p -e"CREATE DATABASE nextcloud DEFAULT CHARACTER SET 'utf8mb4' COLLATE 'utf8mb4_general_ci';GRANT ALL PRIVILEGES ON nextcloud.* TO '${NCUSER}'@'localhost' IDENTIFIED BY '${NCPASSWD}';FLUSH PRIVILEGES;"
echo -e "${COLOR2}MariaDB setup compleated${NC}"
```

> [!info] Updated 2026-11-27
> Newer versions of MariaDB have deprecated `mysql_secure_installation` and `mysql` as aliases; use `mariadb-secure-installation` and `mariadb` instead. Configuration should also be placed in files under `/etc/my.cnf.d/` rather than overwriting or appending directly to `/etc/my.cnf`. In addition, launching `mariadbd &` in the background inside `arch-chroot` was only a workaround at the time—it is better to initialize services after booting the system with systemd.

##### Nextcloud

```bash
#Setup nextcloud
echo -e "${COLOR1}Set up Nextcloud${NC}"
echo "nexcloud ALL=(ALL) ALL" >> /etc/sudoers
sudo -u nextcloud occ maintenance:install --database mysql --database-name nextcloud --database-host localhost --database-user ${NCUSER} --database-pass=<${NCPASSWD}> --data-dir /var/lib/nextcloud/data/
curl -o /usr/share/webapps/nextcloud/config/config.php https://kiwi0093.github.io/script/Arch/config.php
echo -e "${COLOR2}nexcloud set up compleated${NC}"
```

> [!info] Updated 2026-11-27
> This section of the script has four issues:
> 1. `nexcloud ALL=(ALL) ALL` is missing a `t`, and a web service account should never be granted full `sudo` root privileges (running `sudo -u nextcloud` as `root` does not require this anyway).
> 2. `--database-pass=<${NCPASSWD}>` has extra `< >` angle brackets, which without quotes in Bash will be interpreted as input/output redirection and immediately fail with a syntax error.
> 3. The Arch Linux packaged Nextcloud provides a wrapper command at `/usr/bin/occ` (or you can run `php /usr/share/webapps/nextcloud/occ`), and the writable configuration file path is `/etc/webapps/nextcloud/config/config.php`.
> 4. Downloading and overwriting `config.php` from the dead URL `https://kiwi0093.github.io/script/Arch/config.php` would wipe out the `instanceid`, `passwordsalt`, and `secret` generated automatically by `occ maintenance:install`.

> [!info] Updated 2026-11-27
> This Nginx configuration also has several outdated or erroneous parts:
> 1. `listen 443 ssl http2;` has been deprecated since Nginx 1.25.1; newer versions should use `listen 443 ssl;` paired with a standalone `http2 on;` directive.
> 2. The official Arch Linux `nextcloud` package installs to `/usr/share/webapps/nextcloud`, not `/var/www/nextcloud`.
> 3. The `location /` line mistakenly writes to `/etc/nginx/sitqes-enabled/nextcloud` (a typo in the path), which fails at execution and leaves the `nextcloud` config file missing its closing brace.
> 4. Specifying `/etc/ssl/nginx/${NCDOMAIN}.crt` before running Certbot to obtain a certificate causes the Nginx configuration test to fail because the file does not exist yet.
> 5. The `X-XSS-Protection` header has been deprecated by modern browsers and removed from newer official Nextcloud examples.
