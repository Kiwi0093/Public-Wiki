## Pre-Start

First, prepare the WSL / WSL2 environment:

- Open `PowerShell` with administrator privileges and run the following command to enable the Windows Subsystem for Linux:

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
```

- Open `PowerShell` with administrator privileges and run the following command to enable Virtual Machine Platform:

```powershell
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

- Download and install the [WSL-Kernel](https://www.catalog.update.microsoft.com/Search.aspx?q=wsl)
- Set the default version to WSL2:

```powershell
wsl --set-default-version 2
```

> [!info] Updated 2026-11-27
> Modern Windows 10 (2004+) and Windows 11 support one-click installation and enabling of required components directly via `wsl --install` (and `wsl --update`), eliminating the need to manually run `dism.exe` or download the WSL2 Kernel update package separately.

## Install & Initialize ManjaroWSL

### Download

[ManjaroWSL](https://github.com/sileshn/ManjaroWSL) was pre-packaged; at the time, you could directly download the latest zip file from the [Releases page](https://github.com/sileshn/ManjaroWSL/releases).

> [!info] Updated 2026-11-27
> The `sileshn/ManjaroWSL` project is currently unmaintained/archived. For modern WSL2 environments requiring an Arch-based distribution, it is recommended to use the officially supported `wsl --install -d archlinux` or the new `.wsl` image import mechanism.

### Placement & Installation

Place the downloaded zip file into the directory where you intend to store the entire ManjaroWSL system, extract it, and open PowerShell to run:

```powershell
./Manjaro.exe
```

After it automatically completes extraction and initialization, run it once more:

```powershell
./Manjaro.exe
```

### Initialize

Follow the on-screen prompts to decide whether to Resize and create a New User. At the time, it was recommended to select `No` for both reasons:

- You won't exceed 250GB of space (and WSL automatically mounts Windows drives to `/mnt/`).
- User accounts are uniformly created by subsequent scripts, which conveniently applies a complete Zsh terminal and Xfce environment setup.

## Configure System

Run the initialization script as `root`:

```bash
bash <(curl -L -s https://kiwi0093.github.io/script/WSL/manjaro.sh)
```

### Script Usage Notes

- Manually specifying the country code at the beginning is usually faster than auto-speed-testing to pick a mirror.
- When the `vi` editor interface pops up mid-way for `/etc/wsl.conf`, add the following settings:

```ini
[Users]
# Add the following information
default = <User Name you created and wish to be default>
```

After editing, type `:wq` to save and exit.

### Script Description

The following excerpts the main configuration sections executed in the script:

#### Mirrorlist & System Upgrade

```bash
# Basic system configuration
echo -e "${color1}Basic system configuration started${NC}"
echo -e "${color1}Setting your Repo${NC}"
echo -e "${color2}Do you want to set location for the mirror-list?(Y for Location, others for fastest 3 location)${NC}"
while :
do
        read LT
        case $LT in
                Y)
                        echo -e "${color2}Please input location you want(EX, tw for Taiwan, us for USA)\n${NC}"
                        read LT2
                        pacman-mirrors -c $LT2
                        break
                        ;;
                *)
                        pacman-mirrors --fasttrack 3
                        break
                        ;;
        esac
done
echo -e "${color1}Update system${NC}"
pacman -Syyu
```

This primarily provides interactive options to execute `pacman-mirrors` and `pacman -Syyu`.

#### Basic Tools Install

```bash
echo -e "${color1}Install Basic tools${NC}"
pacman -S git yay wget curl rsync sshpass zsh manjaro-zsh-config \
ttf-nerd-fonts-symbols ttf-meslo-nerd-font-powerlevel10k \
ttf-meslo-nerd-font-powerlevel10k powerline-fonts \
nerd-fonts-noto-sans-mono vim wireguard-tools systemd-resolvconf htop --noconfirm
```

This section installs `zsh`, aesthetic-related fonts/settings, and common tools such as `git`, `yay`, `rsync`, and `wireguard`.

#### Xfce4 & Manjaro Theme

```bash
echo -e "${color1}Install Xfce4 for GUI${NC}"
pacman -S xfce4-gtk3 xfce4-goodies xfce4-terminal network-manager-applet \
xfce4-notifyd-gtk3 xfce4-whiskermenu-plugin-gtk3 tumbler engrampa lightdm \
lightdm-gtk-greeter lightdm-gtk-greeter-settings manjaro-xfce-gtk3-settings \
manjaro-settings-manager --noconfirm
```

This part mainly follows Manjaro's official documentation to install Xfce4 and theme packages.

#### GUI Tools & Chinese Environment

```bash
echo -e "${color1}Install GUI$ tools${NC}"
pacman -S terminator brave-browser tigervnc gnome-pie --noconfirm
echo -e "${color1}Install Chinese Environment${NC}"
pacman -S adobe-source-han-serif-tw-fonts adobe-source-han-serif-hk-fonts \
adobe-source-han-serif-cn-fonts adobe-source-han-sans-tw-fonts \
adobe-source-han-sans-hk-fonts adobe-source-han-sans-cn-fonts \
adobe-source-han-serif-jp-fonts adobe-source-han-sans-jp-fonts \
fcitx fcitx-chewing fcitx-configtool fcitx-mozc fcitx-configtool --noconfirm
```

This section installs basic browsers, terminals, Chinese fonts, and input method packages, alongside some personal configuration imports and account creation.

> [!info] Updated 2026-11-27
> In the historical script above, `ttf-meslo-nerd-font-powerlevel10k` and `fcitx-configtool` were listed redundantly; additionally, traditional `fcitx` (v4) has been completely superseded by `fcitx5` (`fcitx5-im`, `fcitx5-chewing`, `fcitx5-mozc`) in the Arch / Manjaro ecosystem.

#### Systemd on WSL

```bash
echo -e "${color1}Change your root password & shell to zsh${NC}"
sudo -u $USERN yay -S genie-systemd-git
echo 'genie -i' > /etc/init.wsl
chmod +x /etc/init.wsl
genie -i
genie -c systemctl disable auditd.service
genie -c systemctl disable multipathd.service
genie -c systemctl disable systemd-modules-load.service
genie -c systemctl enable systemd-resolved.service
genie -c systemctl start systemd-resolved.service
```

At the time, practical testing showed that the only relatively simple and functional solution was `genie-systemd-git`: after installation, initialize the bottle environment with `genie -i`, and then execute commands or enter a new shell via `genie -c`.

> [!info] Updated 2026-11-27
> Since WSL 0.67.6, WSL2 has natively supported systemd. Modern environments simply require adding `[boot]` and `systemd=true` to `/etc/wsl.conf` and restarting WSL (`wsl --shutdown`), eliminating the need to install `genie-systemd-git` or apply the service-disabling workarounds above.

#### Creating Desktop Shortcuts

Configure using [GWSL](https://opticos.github.io/gwsl/):

- Open `GWSL Distro Tools` → `Display/Audio auto exporting`
- Open `GWSL Distro Tools` → `LibGL Indirect`
- Then open `Shortcut Creator`:

![](https://raw.githubusercontent.com/Kiwi0093/graph/master/2022/03/16-15-22-35-gwsl-shortcut.PNG)

- **Shortcut Label**: The shortcut name displayed in the Windows Start menu, customizable.
- **Shortcut Command**: When using Xfce4, always enter `startxfce4`.
- **Display Mode**: To display the full desktop environment, select `Single Window` or `Fullscreen`.
- **Keep Xserver Instance**: If Display Mode is set to `Fullscreen`, this option must be set to `true`, otherwise it is prone to crashing.

After configuration, you can click `Test Configuration` to test, and once confirmed working, click `Add to Start Menu`.

> [!info] Updated 2026-11-27
> Windows 11 built-in WSLg natively provides Linux GUI (X11 / Wayland) integration with audio and Chinese input methods, making third-party X servers like GWSL largely unnecessary for general graphical applications.

## Conclusion

To be honest, when I first saw `WSL` I was thrilled, and discovering a `Manjaro` community distribution made it even more anticipated, but actual installation and usage revealed some gaps for the following reasons:

- Execution speed was not as smooth as expected, especially when running a full desktop environment.
- Programs running in multi-monitor environments often failed to switch input methods correctly (perhaps only manageable by defaulting to Chewing and toggling with `Shift`).
- Desktop mode tended to freeze directly after being idle for a period of time, bringing down any running applications inside it as well.
- Although `systemd` managed to run via third-party tools, its overall stability still had a noticeable gap compared to a native environment.

Therefore, if you only need a Linux shell to run tools, or must work simultaneously across Windows and Linux due to special requirements, WSL is a great choice. However, comparing it to a true Linux Desktop falls short, and even remote VNC connection performance to another Linux desktop beats it. But after all, this was an expedient solution adopted for specific scenarios.
