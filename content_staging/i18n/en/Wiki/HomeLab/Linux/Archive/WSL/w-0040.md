> [!info] Updated 2026-11-27
> This is an archived note on early testing of `ManjaroWSL2`. Below are technical corrections and modern environment comparisons:
> 1. **`ManjaroWSL2` and `wsldl` are obsolete**: Both `sileshn/ManjaroWSL2` and `yuk7/wsldl` (including early `ArchWSL`) are obsolete/archived projects. Modern WSL users are advised to directly use Microsoft's official `wsl --install` or native `.wsl` distribution packages.
> 2. **WSL1 vs WSL2 / WSLg Misconception**: The conclusion stating "WSL1.0 supports systemd and GUI apps do not require wslg" is incorrect; automatically generating Windows Start Menu shortcuts and running Linux GUI apps without an extra DE is precisely the feature of **WSL2 + WSLg**, whereas native `systemd` support was also added in **WSL2 (0.67.6+)** via `/etc/wsl.conf`. WSL1 does not support systemd or WSLg.
> 3. **Package Updates and IME**: `pacman -Syyuu` forces redownloading databases and allows package downgrades; routine system updates should use `pacman -Syu`. For Chinese input methods on newer systems, switching to `fcitx5` is recommended.
> 4. **Cross-Filesystem I/O**: Running `git` or build commands under Windows directories (`/mnt/c/...`) is slow due to known characteristics of WSL2 accessing NTFS via the 9P protocol. Moving projects to a native Linux ext4 directory (such as `~/`) will noticeably improve performance.

# ManjaroWSL2 (based on wsldl) Installation and Usage Notes

[GitHub - sileshn/ManjaroWSL2: Manjaro for WSL2 using wsldl](https://github.com/sileshn/ManjaroWSL2)

This project basically uses the same approach as the previous version, leveraging [wsldl: Advanced WSL launcher](https://github.com/yuk7/wsldl). Anyone interested in building their own can also do it using `wsldl`.

## Install

Simply extract the downloaded files to your preferred location, then run the extracted `Manjaro.exe` and click through the prompts.

## Basic Configuration

```bash
# make sure you're root
# Set your mirrorlist to what you like
pacman-mirrors -c tw
# system full update
pacman -Syyuu
# Install basic tools
pacman -S yay neovim zsh noto-fonts-cjk .......etc 
# completed
```

Does reading the above make you feel dumbfounded? After all, it looks exactly the same as a normal `Manjaro` setup...

That's right, basically it is the same (which is why it's great).

However, compared to previous version instructions, there are some differences:

* You can run GUI apps normally without installing a DE.

For example, `pacman -S brave-browser` will install Brave directly, and magically, shortcuts will automatically be generated in Windows without needing to do anything else:

![](https://raw.githubusercontent.com/Kiwi0093/graph/master/img/start_manu_wsl.png)

You can see that whatever I install will automatically generate shortcuts like this.

This allows launching them directly inside Windows without opening `wslg`.

## Points to Note

Since WSL is still a VM after all (especially WSL2), although you can directly run Linux GUI apps, non-English input from Windows cannot be directly typed into Linux GUI apps. This is why you need to install `fcitx` and its related input methods, such as `chewing`, etc.

### Chinese Input Method

```bash
# Add the following to /etc/profile
# Add Chinese Input Support
export GTK_IM_MODULE=fcitx
export XMODIFIERS=@im=fcitx
export QT_IM_MODULE=fcitx
export DefaultIMModule=fcitx
fcitx-autostart &>/dev/null
```

Then shut down WSL in `PowerShell` using `wsl --shutdown`, and reopen it using `wsl`.

Remember to set a global hotkey to activate it (since we didn't install a DE, we can't use the mouse to click and switch input methods).

### Slow I/O

I originally thought the I/O part would be greatly improved, but in actual testing, running common commands like `git clone`, `git push`, and `hexo g -d` inside a `Windows` folder clearly shows that this I/O performance is not cutting it...

# Conclusion

Although it's very appealing that WSL1.0 supports systemd and allows normal use of GUI apps without `wslg`, as we can see, there are still areas that need polishing—for instance, Chinese input methods sometimes still have issues, and I/O is still slow... etc.

However, for light usage (or even moderate usage), it is still quite handy.
