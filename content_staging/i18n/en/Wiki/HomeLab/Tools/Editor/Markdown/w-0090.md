> [!tip]
> Ever since Typora transitioned to paid software, the open-source **MarkText** has become an excellent alternative. To break free from the pain of manual image uploads, combining it with the command-line **PicGo-Core** enables a smooth automated image hosting workflow. This logic can also be seamlessly extended to the **Obsidian** note-taking environment.

> [!note] Updated 2026-11-27
> The `MarkText` upstream project has been in a stagnant maintenance state since v0.17.1 (2022); for newly established note-taking environments, it is recommended to evaluate Obsidian or other actively maintained Markdown editors.

**MarkText Common Shortcuts and Formatting Mapping**

| **Function Name** | **Shortcut** | **Output Syntax and Effect** |
|---|---|---|
| **Insert Image** | `Ctrl + Shift + I` | `![Alt Text](Image Link)` (Pops up a dialog to enter info; if an Image Uploader is configured, it automatically uploads) |
| **Code Block** | `Ctrl + Shift + K` | <code>```</code> (Quickly generates a Code Fence code block) |
| **Math Formula** | `Ctrl + Shift + $` | Inserts a math expression block |

**PicGo-Core Installation Practice on Linux (Manjaro)**

In a Linux environment (such as Manjaro / Arch), remember **not to install** the GUI version `picgo-appimage` commonly found online, because MarkText's image upload plugin cannot directly bind and capture that GUI's background process. You must instead use Node.js's command-line core **PicGo-Core**:

- **Global Installation Command:**

  ```bash
  sudo npm install picgo -g
  ```

  *(Note: `sudo` is required to ensure full global environment permissions and prevent write path failures.)* *(Updated 2026-11-27: If using version managers like nvm/fnm, or to avoid root permissions polluting global directories, it is recommended to use user-directory installation or configure npm prefix without `sudo`)*

- **Initialization and Image Bed Configuration:**

  Run the interactive configuration wizard, taking the GitHub image bed as an example:

  ```bash
  picgo set uploader
  ```

  Sequentially fill in the relevant parameters (such as `repo` repository name, `token` permission credentials, `path` storage path, etc.).

- **Enable Specified Image Bed:**

  After configuration is complete, **be sure to run the following command** to officially apply it:

  ```bash
  picgo use uploader
  ```

- **Plugin Mapping in MarkText:**

  Open MarkText's preferences, and check `picgo` under the image upload options. As long as configured correctly, pasting or importing images will automatically upload them via the command-line background.

**Obsidian PicGo Integration Application**

Unlike MarkText which focuses on real-time editing with "paste-to-upload", Obsidian defaults to being centered around local Markdown files and folders Vaults. If you wish to enjoy the same automatic cloud image bed upload experience with PicGo in Obsidian, it is usually achieved through community plugins:

1. **Install Plugin:**

   Search for and install **Image Auto Upload Plugin** or **PicGo Integration** in Obsidian's "Community Plugins".

2. **Specify PicGo Executable Path:**

   In the plugin's settings page, point the PicGo Path to the global executable path installed via npm in the previous step (e.g., `/usr/bin/picgo` or queried via `which picgo`).

3. **Operation Mechanism:**

   When you paste a screenshot or image inside Obsidian, the plugin automatically calls the system's `picgo` command to push the image to GitHub cloud storage, and automatically replaces the local absolute path in Markdown with the remote image bed's CDN link, ensuring that when synchronizing notes across devices, images do not break due to being unfound.
