## I. Foreword: Why use Homebrew on Linux?

Traditionally Homebrew is a macOS staple, but its support for Linux (formerly Linuxbrew) is now very mature.

**The ultimate pain point solution: Servers without `sudo` privileges.** When working on shared company or university servers (especially legacy CentOS 7 or older RHEL), system-provided packages are usually ancient, and you lack root privileges to run `apt` or `yum` to install newer software. Homebrew solves this problem perfectly—it installs all the latest CLI tools (such as `git`, `python`, `node`, `fzf`, `ripgrep`) entirely within your own home directory, without polluting or interfering with the underlying system.

## II. Getting Started: Installation Without Root Privileges

The official automated installation script defaults to attempting to use `sudo` to install the system in `/home/linuxbrew/.linuxbrew`. If you lack root privileges, the script automatically falls back to installing it under your home directory (typically `~/.linuxbrew`).

**1. Run the official installation script**

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

_(If prompted for a sudo password during execution, you can press Enter to skip it; it will automatically fall back to local home directory installation)_

**2. Add Environment Variables (Extremely Important)** Once installation is complete, Homebrew will not take effect automatically; you must add it to your environment variables. Follow the prompt at the end of the installation screen to add the following to your `~/.bashrc` or `~/.zshrc`:

```bash
# Automatically load Homebrew environment variables upon system startup (using bash as an example)
echo 'eval "$(/home/your_username/.linuxbrew/bin/brew shellenv)"' >> ~/.bashrc
source ~/.bashrc
```

**3. Verify Installation**

```bash
brew doctor
```

If it displays `Your system is ready to brew.`, it means you now have your very own high-level package manager!

## III. Basic Maintenance: Daily Package Management

Homebrew's syntax is extremely intuitive, and because it is installed in the user directory, all commands **do not** require `sudo`.

**1. Software Installation and Removal**

```bash
# Search for packages
brew search <keyword>

# Install a package
brew install <package_name>

# Remove a package
brew uninstall <package_name>

# List all packages you "actively installed" (excludes dependencies, great for auditing your environment)
brew leaves
```

**2. System and Software Updates**

```bash
# Update Homebrew itself and remote package lists
brew update

# Upgrade all installed packages to the latest versions
brew upgrade

# Upgrade a specific package only
brew upgrade <package_name>
```

## IV. Freeing Up Disk Space: Cache Cleanup

When compiling or downloading precompiled binary packages (Bottles), Homebrew caches files in `~/.cache/Homebrew`, which can consume a significant amount of space over time.

```bash
# Safe cleanup: remove old version caches, keeping the latest versions
brew cleanup

# Deep cleanup: delete all caches including the latest ones (-s = scrub)
brew cleanup -s

# Check how much disk space Homebrew is currently occupying
brew info
```

## V. Advanced Tips and Pitfalls Guide

### 1. Resolving C Library Dependency Issues on Legacy Systems (gcc / glibc)

On extremely old servers, after installing newer software via brew, you might encounter errors like `lib64/libc.so.6: version 'GLIBC_2.28' not found` when executing it. This means the underlying system's C library is too old. Homebrew's solution is aggressive and effective—**it installs a modern version of gcc directly in your home directory!**

```bash
# Actively install a modern gcc via brew when encountering compilation or execution errors
brew install gcc
```

Once installed, software managed by Homebrew will automatically use this modern version of the library, no longer constrained by the underlying system.

### 2. Infrastructure as Code: Brewfile (IaC Practice)

If you frequently switch between different servers or development machines, running `brew install` for dozens of tools every time is extremely painful. Homebrew has a built-in mechanism similar to `requirements.txt` or `package.json`, called **Brewfile**.

- **Export current environment:**

  ```bash
  # Dump a list of all currently installed packages into a file named Brewfile
  brew bundle dump
  ```

- **Restore with one click on a new machine:** Drop this `Brewfile` onto the new machine and run in the same directory:

  ```bash
  # Homebrew automatically reads the Brewfile and installs everything inside it
  brew bundle
  ```

For developers without root privileges, this trick is the ultimate silver bullet for quickly replicating a familiar personal development environment (the Dotfiles philosophy).
