# When You Don't Have a Key

Generate a new key:

```bash
ssh-keygen -t rsa -C "your@mail.for.github"
```

> [!info] Updated 2026-11-27
> Since OpenSSH 8.8, legacy SHA-1 `ssh-rsa` signatures are disabled by default. GitHub also recommends prioritizing the more secure and concise **Ed25519** key algorithm:
> ```bash
> ssh-keygen -t ed25519 -C "your@mail.for.github"
> ```

Then paste the contents of <span style="color:#e06c75"><del>id_rsa.pub</del></span> *(Updated 2026-11-27: or `~/.ssh/id_ed25519.pub` if using Ed25519)* into GitHub under **Settings → SSH and GPG keys → New SSH key**, and you are all set.

# When You Already Have an Existing Private Key

```bash
eval `ssh-agent -s`
ssh-add /location/to/your/key
```

*(Note: Modern shells recommend using `eval "$(ssh-agent -s)"` instead of backticks.)*

# Changing the Repository Connection Method

```bash
vi /location/to/repo/.git/config
# Change:
url = https://github.com/<USER>/Repo.git
# To:
url = git@github.com:<USER>/Repo.git
```

> [!tip] Updated 2026-11-27
> In practice, you can also switch the remote URL directly inside the repository directory using Git commands without manually editing `.git/config`:
> ```bash
> git remote set-url origin git@github.com:<USER>/<Repo>.git
> ```

Then you can connect happily.

# Additional Notes

Although `ssh-add` can be used to add the key for use, you often run into the issue of having to re-add it repeatedly; <span style="color:#e06c75"><del>the fundamental solution is to keep the key filename as id_rsa so it can be used directly....</del></span> *(Updated 2026-11-27: It is recommended to keep the default filename (such as `id_ed25519`), or configure `IdentityFile` and `IdentitiesOnly yes` for `Host github.com` in `~/.ssh/config`, adding `AddKeysToAgent yes` as needed.)*
