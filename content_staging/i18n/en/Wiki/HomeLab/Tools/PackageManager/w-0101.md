Below is a summary of the core differences and practical operations of the three major cross-distribution Linux sandbox tools:

## I. Overview of Core Natures and Characteristics of the Three Formats

| **Format** | **Main Promoter** | **Core Philosophy** | **Runtime Mechanism** | **Advantages** | **Disadvantages / Pain Points** |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Flatpak** | Red Hat / Community | Focused on desktop GUI apps | Shared Runtime dependency, Bubblewrap sandbox isolation | Excellent permission control, decentralized repository (Flathub), fast startup speed | Poor CLI tool support, mainly targets desktop applications |
| **Snap** | Canonical (Ubuntu) | All-in-one (Desktop + Server) | squashfs mount dependency, AppArmor sandbox isolation | Supports server backend/Daemons, powerful automatic update mechanism | Slightly slower cold boot, centralized (Canonical official store only), `lsblk` gets filled with loop devices |
| **AppImage** | Open Source Community (probono) | Ultimate single file, portable "green" install-free | Read-only image with built-in dependencies, executed directly via FUSE | Run anywhere, no root required, completely non-polluting to the system | Lacks official unified update mechanism, desktop integration (shortcuts/icons) must be handled manually |

## II. Flatpak: The Preferred Choice for Modern Linux Desktop GUI Apps

Flatpak has become the de facto standard on the desktop for communities like Fedora, Arch, and Debian. Its packages are primarily centralized on [Flathub](https://flathub.org/), and its permission control is very strict (unable to read your home directory by default).

### 1. Getting Started: Installing and Enabling the Flathub Repository

Most modern desktop distributions have it built-in. If your system does not have it pre-installed, you can install it manually:

```bash
# Arch: sudo pacman -S flatpak
# Debian/Ubuntu: sudo apt install flatpak

# Add Flathub, the largest software repository currently (Required)
flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
```

### 2. Basic Operations

Flatpak software typically uses Java-like "reverse domain name" naming conventions (e.g., `org.mozilla.firefox`, `com.spotify.Client`).

```bash
# Search for software
flatpak search <software_name>

# Install software (can use full name or keyword to prompt selection)
flatpak install flathub com.spotify.Client

# Run software (application menu usually shows icons automatically; to run in terminal):
flatpak run com.spotify.Client

# Fully update all Flatpak software and runtimes
flatpak update -y

# Remove software
flatpak uninstall com.spotify.Client
```

### 3. God-tier Cleanup and Permission Tuning (Must Learn)

- **Clean up unused runtimes (free up disk space):**

    After Flatpak upgrades, old runtimes (such as GNOME/KDE execution environments) often remain and occupy hard drive space:

    ```bash
    flatpak uninstall --unused
    ```

- **Permission Modification Tool Flatseal:**

    Because Flatpak has sandbox isolation by default, sometimes when you install an editor (like VSCode or GIMP), you might find it "cannot read folders on other hard drive partitions" or "cannot access a USB flash drive". Install **Flatseal** directly:

    ```bash
    flatpak install flathub com.github.tchx84.Flatseal
    ```

    Open this graphical tool to easily toggle whether a program can access the network, file system, camera, or Wayland/X11 display, just like on a mobile phone.

## III. Snap: Ubuntu's Pride, Amphibious for Desktop and Server

Snap is a technology built by Canonical. Beyond desktop software, its biggest feature is that it **can package system daemons and server software directly** (such as Nextcloud, Docker, Certbot).

### 1. Basic Operations

```bash
# Install software
sudo snap install <software_name>

# ⚠️ Critical parameter: Classic mode (--classic)
# Some development tools that require deep system access (such as VSCode, Go, Node.js) need to be installed with sandbox mode disabled:
sudo snap install code --classic

# Search and info
snap find <keyword>
snap info <software_name>

# Update software (Snap automatically updates in the background by default, but you can also trigger it manually)
sudo snap refresh

# Remove software
sudo snap remove <software_name>
```

### 2. Space Slimming Skill (Clean up old snap versions)

Snap retains "old versions" of each software by default in case upgrade rollbacks fail, but this causes `/var/lib/snapd/snaps/` to consume a large amount of disk space.

You can adjust the number of retained versions (default is 3, change to keep only 2):

```bash
sudo snap set system refresh.retain=2
```

## IV. AppImage: The True Single Executable "Portable Software"

AppImage is like the install-free portable software (`.exe`) of the Windows era. It packages all code, libraries, and dependencies into a single `.AppImage` file.

### 1. Usage Workflow (Extremely Simple)

1. Download `xxx.AppImage` from GitHub Releases or the official website.
2. Grant execution permissions:

    ```bash
    chmod +x xxx.AppImage
    ```

3. Double-click to execute directly, or enter in the terminal:

    ```bash
    ./xxx.AppImage
    ```

4. **Want to get rid of it?** Simply throw the file into the trash, and it is completely uninstalled with zero system library residue.

### 2. Pitfall Guide: Essential FUSE Support

Many modern Linux distributions (such as Ubuntu 22.04+ or some minimalist systems) do not have older FUSE installed by default, causing AppImage execution to fail with the error: `dlopen(): error loading libfuse.so.2`.

When encountering this issue, install the corresponding compatibility package:

- **Ubuntu / Debian:** <span style="color:#e06c75"><del>sudo apt install libfuse2</del></span> *(Updated 2026-11-27: Due to the `t64` transition in Ubuntu 24.04+ and Debian 13+, the package name has changed to `sudo apt install libfuse2t64`)*
- **Arch:** `sudo pacman -S fuse2`
- **Fedora:** `sudo dnf install fuse-libs`

### 3. Advanced Tool: AppImageLauncher (Solving Desktop Shortcut Pain Points)

The biggest drawback of AppImage is that it is just a file; it does not automatically appear in your system application menu, nor does it have an icon.

A community tool commonly used in the past is **[AppImageLauncher](https://github.com/TheAssassin/AppImageLauncher)**:

- After installation, whenever you double-click any new `.AppImage` file, it pops up a prompt asking: "Would you like to integrate it into the system?".
- Selecting "Yes" automatically archives the file to a centralized directory and creates a standard desktop shortcut and icon in the application menu, providing an experience close to native software.

> [!info] Updated 2026-11-27
> `AppImageLauncher` upstream has not been actively maintained for years, and you may encounter installation or dependency issues on some newer distributions. If unavailable, modern desktop environments can instead use **Gear Lever** installed via Flatpak (`flatpak install flathub it.mijorus.gearlever`) to manage and integrate AppImages.
