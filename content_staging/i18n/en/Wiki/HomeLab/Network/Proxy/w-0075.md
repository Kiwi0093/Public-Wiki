## Quick Connection Information Reference (Based on Previous Architecture)

- **Reality Direct Node**:

    - Domain: `reality.yourdomain.com`, Port: `443`

    - Transport: `TCP`, Security: `Reality`, Flow Control: `xtls-rprx-vision`

    - SNI: `reality.yourdomain.com`, Fingerprint: `chrome`

    - Required Parameters: `UUID`, `Public Key`, `Short ID`

- **WS+TLS+CDN Rescue Node**:

    - Domain: `cdn.yourdomain.com` (or Cloudflare Anycast/Preferred IP), Port: `443`

    - Transport: `WebSocket (WS)`, Path: `/ray-ws-stream`

    - Security: `TLS`, SNI / Host: `cdn.yourdomain.com`

    - Required Parameters: `UUID`

## 1. Android Client Recommendation and Setup

### Recommended Clients

- **Primary Choice: v2rayNG** (Intuitive interface, most complete Xray core support, full support for Reality/Vision features)

- **Advanced Alternative: sing-box (Android Official Version)** (Powerful rule-based routing, extremely low battery consumption)

### v2rayNG Setup Steps

#### Fastest Import Method (Clipboard Import)

1. Copy the `vless://` link of the node in the 3X-UI panel.

2. Open v2rayNG, tap the **`+`** icon in the upper right corner -> Select **"Import config from clipboard"**.

3. Tap the V icon in the lower right corner to connect, and tap the status bar below to test latency.

#### Manual Setup for VLESS-Reality

1. Tap **`+`** in the upper right corner -> **"Manually input [VLESS]"**.

2. Fill in the fields sequentially:

    - **Remark**: `Reality-Direct`

    - **Address**: `reality.yourdomain.com`

    - **Port**: `443`

    - **UUID (id)**: Enter your `UUID`

    - **Flow (flow)**: Select `xtls-rprx-vision`

    - **Network (network)**: `tcp`

    - **Stream Security (streamSecurity)**: Select `reality`

    - **SNI**: `reality.yourdomain.com`

    - **Fingerprint (uTLS)**: `chrome`

    - **PublicKey**: Enter the `Public Key` generated by 3X-UI

    - **ShortId**: Enter the corresponding `Short ID`

3. Tap the checkmark in the upper right corner to save.

#### Manual Setup for VLESS-WS+TLS+CDN

1. Tap **`+`** in the upper right corner -> **"Manually input [VLESS]"**.

2. Fill in the fields sequentially:

    - **Remark**: `WS-CDN-Rescue`

    - **Address**: `cdn.yourdomain.com` (or Cloudflare Preferred IP)

    - **Port**: `443`

    - **UUID (id)**: Enter your `UUID`

    - **Flow (flow)**: Leave blank

    - **Network (network)**: Select `ws`

    - **WebSocket -> path**: `/ray-ws-stream`

    - **WebSocket -> host**: `cdn.yourdomain.com`

    - **Stream Security (streamSecurity)**: Select `tls`

    - **SNI**: `cdn.yourdomain.com`

3. Tap the checkmark in the upper right corner to save.

## 2. iPhone (iOS) Client Recommendation and Setup

### Recommended Clients

- **Primary Choice: Shadowrocket** (Best cost-performance ratio, one-time purchase, great compatibility, supports Reality and uTLS)

- **Alternative / Advanced: Loon**, **Sing-box**, or **Stash (Clash for iOS)**

### Shadowrocket Setup Steps

#### Fastest Import Method (QR Code / Link)

1. Tap the QR Code icon of the node in the 3X-UI panel.

2. Open Shadowrocket, tap the **scan button** in the upper left corner to aim at the screen, or copy the `vless://` link and open the App for automatic prompt addition.

#### Manual Setup for VLESS-Reality

1. Tap **`+`** in the upper right corner.

2. **Type**: Select `VLESS`.

3. Fill in the fields sequentially:

    - **Server**: `reality.yourdomain.com`

    - **Port**: `443`

    - **Password (UUID)**: Enter `UUID`

    - **Security (Security)**: Select `Reality`

    - **PublicKey**: Enter `Public Key`

    - **Short ID**: Enter `Short ID`

    - **Peer (SNI)**: `reality.yourdomain.com`

    - **Flow (Flow)**: Select `xtls-rprx-vision`

    - **Fingerprint**: Select `chrome`

4. Tap **Save** in the upper right corner.

#### Manual Setup for VLESS-WS+TLS+CDN

1. Tap **`+`** in the upper right corner.

2. **Type**: Select `VLESS`.

3. Fill in the fields sequentially:

    - **Server**: `cdn.yourdomain.com`

    - **Port**: `443`

    - **Password (UUID)**: Enter `UUID`

    - **Transport (Transport)**: Select `websocket`

    - **Path**: `/ray-ws-stream`

    - **Host**: `cdn.yourdomain.com`

    - **TLS**: Enable toggle

    - **SNI**: `cdn.yourdomain.com`

4. Tap **Save** in the upper right corner.

## 3. Windows Client Recommendation and Setup

### Recommended Clients

- **Primary Choice (Intuitive GUI): v2rayN** (Supports Xray core, out-of-the-box support for Reality)

- **Primary Choice (Rule-Based Routing): Clash Verge Rev** (Based on Mihomo / Clash Meta core, gorgeous UI, supports subscriptions and custom rules)

### Option A: v2rayN (Xray Core)

#### Quick Import

Copy the `vless://` node text and press `Ctrl + V` in the main v2rayN window to automatically add it.

#### Manual Addition of VLESS-Reality

1. Click **Servers** at the top -> **Add VLESS Server**.

2. Align parameters:

    - **Address**: `reality.yourdomain.com`

    - **Port**: `443`

    - **UUID (id)**: Your `UUID`

    - **Flow (flow)**: `xtls-rprx-vision`

    - **Network (network)**: `tcp`

    - **Stream Security (streamSecurity)**: Select `reality`

    - **SNI**: `reality.yourdomain.com`

    - **uTLS**: `chrome`

    - **PublicKey**: Paste Public Key

    - **ShortId**: Paste Short ID

3. Click OK. Right-click the system tray icon in the lower right corner, and switch "System Proxy" to **Set System Proxy (PAC/Global)**.

### Option B: Clash Verge Rev (Mihomo Core)

Manually add the following proxies snippet into your configuration file:

```yaml
proxies:
  # 1. Reality Direct Node
  - name: "Reality-Direct"
    type: vless
    server: reality.yourdomain.com
    port: 443
    uuid: YOUR_UUID_HERE
    network: tcp
    flow: xtls-rprx-vision
    tls: true
    udp: true
    servername: reality.yourdomain.com
    client-fingerprint: chrome
    reality-opts:
      public-key: YOUR_PUBLIC_KEY_HERE
      short-id: YOUR_SHORT_ID_HERE

  # 2. WS+TLS+CDN Rescue Node
  - name: "CDN-Rescue"
    type: vless
    server: cdn.yourdomain.com       # Can be replaced with a Cloudflare Preferred IP if blocked
    port: 443
    uuid: YOUR_UUID_HERE
    cipher: auto
    tls: true
    udp: true
    servername: cdn.yourdomain.com   # SNI retains domain name
    network: ws
    ws-opts:
      path: "/ray-ws-stream"
      headers:
        Host: cdn.yourdomain.com
```

> [!info] Updated 2026-11-27
> The `cipher: auto` parameter in the second `VLESS` node example is a VMess protocol parameter; VLESS itself does not require specifying `cipher` (the Mihomo core usually ignores it, but it is recommended to omit it in VLESS settings).

## 4. Linux (Desktop/Server/Photon OS) Client Recommendation and Setup

### Recommended Clients

- **Desktop Environment (GUI)**: **Clash Verge Rev (AppImage / .deb / .rpm)**

- **Server / Command Line (CLI Primary)**: **sing-box (Single binary executable or Systemd service)**

### sing-box CLI Setup Steps (Common for Debian/Ubuntu/Photon OS)

#### Step 1: Install sing-box

```bash
# Download official binary (using amd64 as an example)
bash -c "$(curl -fsSL https://sing-box.app/deb-install.sh)" 2>/dev/null || \
curl -Lo /usr/local/bin/sing-box https://github.com/SagerNet/sing-box/releases/latest/download/sing-box-linux-amd64.tar.gz
chmod +x /usr/local/bin/sing-box
```

> [!info] Updated 2026-11-27
> The original backup download command contained two errors: GitHub Releases tarballs for `SagerNet/sing-box` all include version numbers (e.g., `sing-box-<VERSION>-linux-amd64.tar.gz`), so requesting `sing-box-linux-amd64.tar.gz` directly results in a 404. Furthermore, `.tar.gz` files must first be extracted using `tar -xzf` to obtain the `sing-box` binary executable before moving it to `/usr/local/bin/`. For Debian/Ubuntu, it is recommended to use the official `deb-install.sh` or the official APT repository for installation.

#### Step 2: Configure `/etc/sing-box/config.json`

Create the configuration file, locally opening <span style="color:#e06c75"><del>SOCKS5 (Port 10808) and HTTP proxy (Port 10809)</del></span> *(Updated 2026-11-27: The configuration below actually uses a single `mixed` inbound, providing both HTTP and SOCKS5 proxies simultaneously on Port `10809`, and does not enable `10808`)*:

```json
{
  "log": {
    "level": "info",
    "timestamp": true
  },
  "inbounds": [
    {
      "type": "mixed",
      "tag": "mixed-in",
      "listen": "127.0.0.1",
      "listen_port": 10809
    }
  ],
  "outbounds": [
    {
      "type": "vless",
      "tag": "reality-out",
      "server": "reality.yourdomain.com",
      "server_port": 443,
      "uuid": "YOUR_UUID_HERE",
      "flow": "xtls-rprx-vision",
      "network": "tcp",
      "tls": {
        "enabled": true,
        "server_name": "reality.yourdomain.com",
        "utls": {
          "enabled": true,
          "fingerprint": "chrome"
        },
        "reality": {
          "enabled": true,
          "public_key": "YOUR_PUBLIC_KEY_HERE",
          "short_id": "YOUR_SHORT_ID_HERE"
        }
      }
    },
    {
      "type": "vless",
      "tag": "cdn-out",
      "server": "cdn.yourdomain.com",
      "server_port": 443,
      "uuid": "YOUR_UUID_HERE",
      "network": "ws",
      "tls": {
        "enabled": true,
        "server_name": "cdn.yourdomain.com"
      },
      "transport": {
        "type": "ws",
        "path": "/ray-ws-stream",
        "headers": {
          "Host": "cdn.yourdomain.com"
        }
      }
    }
  ],
  "route": {
    "rules": [
      {
        "outbound": "reality-out"
      }
    ]
  }
}
```

> [!info] Updated 2026-11-27
> In `sing-box` version 1.11+, routing rules officially adopt the explicit `"action": "route"` syntax. If you only need to set a default outbound, it is recommended to write `"route"` as `"rules": [], "final": "reality-out"`, replacing the unconditional empty rule object.

#### Step 3: Start and Run in Background

```bash
# Test configuration file validity
sing-box check -c /etc/sing-box/config.json

# Start running directly
sing-box run -c /etc/sing-box/config.json

# Test connection
curl -x http://127.0.0.1:10809 https://ip.sb
```
