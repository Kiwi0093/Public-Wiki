## 1. Automated Deployment Architecture Topology

GitHub Pages currently supports two publishing modes:

1. **GitHub Actions Native Artifact Publishing (Recommended)**: Build artifacts (`build/`) are directly sent as binary zip packages to the underlying GitHub Pages infrastructure. There is **no need** to maintain an extra `gh-pages` branch filled with build noise in the repository, making it clean and extremely fast to execute.
2. **Traditional Branch Override Publishing (`gh-pages` Branch)**: The Action automatically creates a `gh-pages` branch and commits static artifacts to it.

## 2. Prerequisites: Aligning Repository and `docusaurus.config.js` URLs

During compilation, Docusaurus strictly calculates the absolute paths of all resources (CSS, JS, images) based on `url` and `baseUrl`. Incorrect path configurations are the primary cause of broken styles (layout corruption) and 404 errors after deploying to GitHub Pages.

### 2.1 URL Configuration Calculation Formula

Assuming your GitHub account is `kiwihome` and your repository name is `kiwi-wiki`:

- **`url`**: `https://kiwihome.github.io` (or your custom domain if bound, e.g., `https://wiki.example.com`)
- **`baseUrl`**: `/<Repo Name>/` (must have leading and trailing slashes, e.g., `/kiwi-wiki/`; **if using a custom apex domain, this must be changed to `'/'**)
- **`organizationName`**: GitHub organization or personal account name
- **`projectName`**: Repository name
- **`trailingSlash`**: Explicitly specify whether to include a trailing slash (recommended to set to `false` to prevent specific anchor link redirection failures on GitHub Pages)

Edit `docusaurus.config.js` in the project root:

```javascript
// @ts-check

/** @type {import('@docusaurus/types').Config} */
const config = {
  title: 'My HomeLab Wiki',
  tagline: 'Automated Operations & Technical Documentation Library',
  favicon: 'img/favicon.ico',

  // Core path declarations (strictly replace according to your project)
  url: 'https://<USERNAME>.github.io',
  baseUrl: '/<REPO_NAME>/',

  organizationName: '<USERNAME>',
  projectName: '<REPO_NAME>',
  trailingSlash: false,

  onBrokenLinks: 'throw',         // Abruptly abort build on broken links to prevent dirty data deployment
  onBrokenMarkdownLinks: 'warn',

  // ... Remaining theme and plugin configurations remain unchanged
};

module.exports = config;
```

> [!info] Updated 2026-11-27
> In Docusaurus 3.9+, the top-level `onBrokenMarkdownLinks` option has been marked as deprecated. It is recommended to move it to `markdown: { hooks: { onBrokenMarkdownLinks: 'warn' } }`.

## 3. One-Time GitHub Repository Console Permission Settings

Before pushing the Workflow, you must navigate to the GitHub repository web interface to grant permissions:

1. Open the target GitHub repository.
2. Click **Settings** in the top navigation bar.
3. Find **Pages** in the left menu (under the Code and automation section):
   - **Build and deployment -> Source**: Change the default `Deploy from a branch` to **`GitHub Actions`**.
4. Click **Actions** -> **General** in the left menu:
   - Scroll to the **Workflow permissions** section.
   - Ensure **Read and write permissions** is selected.
   - Check **Allow GitHub Actions to create and approve pull requests** (if prompted), and click **Save**.

## 4. GitHub Actions Workflow Configuration File

Create the directory and file in the local project root: `.github/workflows/deploy.yml`.

### Option A: Modern Native Pages Deployment (Strongly Recommended, Zero Branch Pollution)

This configuration uses GitHub's official `upload-pages-artifact` and `deploy-pages` modules, requiring no Personal Access Token (PAT) and relying entirely on the runner's built-in short-lived OIDC Token for secure deployment.

```yaml
name: Deploy Docusaurus to GitHub Pages

on:
  push:
    branches:
      - main # Trigger branch; adjust if your default is master

# Strictly define Workflow permissions
permissions:
  contents: read      # Read repository code
  pages: write         # Write GitHub Pages artifact
  id-token: write      # Used for OIDC authentication to achieve keyless deployment

# Avoid concurrency conflicts when multiple commits are pushed simultaneously; automatically cancel the previous unfinished task
concurrency:
  group: 'pages'
  cancel-in-progress: false

jobs:
  build:
    name: Build Docusaurus
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          # fetch-depth: 0 means fetching the full Git history
          # Crucial: If set to 1, Docusaurus will not be able to retrieve document "last edited time" and "author information"
          fetch-depth: 0

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm # Automatically cache ~/.npm directory to significantly speed up npm ci time

      - name: Install dependencies
        # Use npm ci instead of npm install to strictly restore versions based on package-lock.json
        run: npm ci

      - name: Build website
        # Compile and generate the static build/ directory
        run: npm run build

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: build/ # Specify Docusaurus compilation output directory

  deploy:
    name: Deploy to GitHub Pages
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

> [!info] Updated 2026-11-27
> 1. The comment "automatically cancel the previous unfinished task" in the YAML above is opposite to the actual setting `cancel-in-progress: false`: setting it to `false` allows ongoing deployment tasks to finish and queue up (which is GitHub's official recommendation for Pages deployments to prevent interruptions mid-deployment).
> 2. `node-version: 20`: Node.js 20 reached End-of-Life (EOL) on 2026-04-30; it is recommended to upgrade to a current LTS version (such as `22` or `24`).

### Option B: Traditional Push to `gh-pages` Branch (Compatible with Legacy Architecture)

If your organization's project guidelines require physical files and commit history to be visible in the branch list, you can use Docusaurus's official built-in CLI publishing script:

```yaml
name: Deploy to gh-pages Branch

on:
  push:
    branches:
      - main

permissions:
  contents: write # Must have write permission to the repository to create branches

jobs:
  deploy:
    name: Deploy via Docusaurus CLI
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Deploy to gh-pages
        run: |
          git config --global user.name "github-actions[bot]"
          git config --global user.email "github-actions[bot]@users.noreply.github.com"
          npx docusaurus deploy
        env:
          # Use built-in GITHUB_TOKEN, no manual Secret configuration needed
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

> [!info] Updated 2026-11-27
> `node-version: 20`: Node.js 20 reached End-of-Life (EOL) on 2026-04-30; it is recommended to upgrade to a current LTS version (such as `22` or `24`).

## 5. Custom Domain and HTTPS Configuration

If you plan to bind your own domain to the Wiki (e.g., `wiki.example.com`):

### Step 1: Create a `CNAME` Static File

Create a plain text file named **`CNAME`** (without file extension) under the **`static/`** directory of your project, and fill it with your domain name:

```
wiki.example.com
```

_Files placed under `static/` are automatically copied verbatim to the `build/` root during build._

### Step 2: Modify `docusaurus.config.js`

```javascript
  url: 'https://wiki.example.com',
  baseUrl: '/',                     // After binding a custom domain, baseUrl must be changed back to the root path '/'
```

### Step 3: DNS Settings (Using Cloudflare / DNS Provider as an Example)

Add a **CNAME record** at your DNS provider:

- **Name**: `wiki`
- **Target**: `<USERNAME>.github.io`
- **Proxy status**: If using Cloudflare, it is recommended to set it to **DNS Only (Grey Cloud)** when first applying for the certificate, and evaluate enabling the Orange Cloud after GitHub successfully issues the Let's Encrypt certificate and enables "Enforce HTTPS".

## 6. Troubleshooting

### 6.1 Action Build Fails with `Docusaurus found broken links!` in Logs

- **Cause**: Docusaurus has built-in fool-proofing mechanisms during compilation. If Markdown text references non-existent document file names, has incorrect relative paths, or references non-existent Markdown anchors (`#section-title`), the build will be forcibly aborted.
- **Resolution**:
  1. Inspect the Action execution logs; the output will clearly indicate which file and line number contains the broken link.
  2. Fix the path; if a specific page is still in draft stage, add `draft: true` to that Markdown's Frontmatter to skip compilation.

### 6.2 Visiting the Website After Deployment Shows a Blank Page with Numerous 404 Errors in Console

- **Cause**: `baseUrl` does not match the GitHub repository name. For example, if the repository is named `my-wiki`, but `baseUrl` was set to `'/'`, causing the browser to fetch resources from `https://<User>.github.io/assets/css/...` instead of `https://<User>.github.io/my-wiki/assets/css/...`.
- **Resolution**: Review `docusaurus.config.js` and ensure `baseUrl: '/<REPO_NAME>/'` has slashes at both ends.

### 6.3 Action Reports `Permission to ... denied to github-actions[bot]`

- **Cause**: Actions write permissions are not enabled for the repository.
- **Resolution**: Go to repository **Settings** -> **Actions** -> **General** -> **Workflow permissions**, switch to **Read and write permissions**, and click Save.

### 6.4 `npm start` Runs Locally, but `npm run build` Throws Out-Of-Memory (OOM) in Actions

- **Cause**: When the document count reaches hundreds or more, Node.js default heap memory (around 1.5GB) is exhausted while compiling Webpack artifacts.
- **Resolution**: Inject Node environment variables before the build step in the Workflow to increase the memory limit:

    ```yaml
        - name: Build website
          run: npm run build
          env:
            NODE_OPTIONS: "--max-old-space-size=4096"
    ```
