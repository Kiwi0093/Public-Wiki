# Docusaurus Modern Static Documentation Site Setup Guide

> <img src='https://img.shields.io/badge/Status-Active-A8FF24?style=for-the-badge&labelWidth=100' height='38' />

## 1. Architecture Overview & Directory Structure

A standard Docusaurus site consists of documentation (`docs`), a blog (`blog`), and custom React pages (`src/pages`):

```
my-website/
├── docs/                   <-- Markdown / MDX technical docs (sidebar tree structure)
│   ├── intro.md
│   └── tutorial/
├── blog/                   <-- Timeline articles (Blog mode, optional to disable)
├── static/                 <-- Static assets (images, favicon, robots.txt)
├── src/
│   ├── css/custom.css      <-- Custom styles (supports overriding dark/light variables)
│   └── pages/index.js      <-- Landing page
├── docusaurus.config.js    <-- Core global config (site name, routes, plugins)
├── sidebars.js             <-- Sidebar structure definition
└── package.json            <-- Dependency management and startup scripts
```

## 2. Quick Initialization & Core Commands

### 2.1 Creating a Project

It is recommended to use the officially recommended `classic` template:

```bash
# Create project using Node.js 18+
npx create-docusaurus@latest my-website classic

cd my-website
```

### 2.2 Local Development & Building

```bash
# Start local live preview server (default Port: 3000, supports HMR hot reload)
npm start

# Build static artifacts (output to build/ directory for production release)
npm run build

# Locally preview the built static files
npm run serve
```

## 3. Core Configuration Details (`docusaurus.config.js`)

The configuration file is responsible for defining the site's base URL, Navbar, Footer, and default plugins:

```javascript
// @ts-check
const {themes} = require('prism-react-renderer');

/** @type {import('@docusaurus/types').Config} */
const config = {
  title: 'My HomeLab Wiki',
  tagline: 'Automation Ops & Self-Hosted Services Technical Manual',
  favicon: 'img/favicon.ico',

  // Production URL settings
  url: 'https://wiki.example.com',
  baseUrl: '/',

  // Used for GitHub Pages deployment (can be anything if not using GH Pages)
  organizationName: 'my-org',
  projectName: 'my-wiki',

  onBrokenLinks: 'throw',         // Abort build on broken links (CI/CD safeguard)
  onBrokenMarkdownLinks: 'warn',

  i18n: {
    defaultLocale: 'zh-Hant',     // Default locale: Traditional Chinese
    locales: ['zh-Hant', 'en'],
  },

  presets: [
    [
      'classic',
      /** @type {import('@docusaurus/preset-classic').Options} */
      ({
        docs: {
          sidebarPath: './sidebars.js',
          routeBasePath: 'docs',  // Docs root path; if set to '/', the entire site acts solely as a doc site
          editUrl: undefined,     // Disable "Edit this page" button (applicable to private repos)
        },
        blog: false,              // If acting purely as a Wiki knowledge base, can be set to false to close blog
        theme: {
          customCss: './src/css/custom.css',
        },
      }),
    ],
  ],

  themeConfig:
    /** @type {import('@docusaurus/preset-classic').ThemeConfig} */
    ({
      navbar: {
        title: 'HomeLab Wiki',
        logo: {
          alt: 'Site Logo',
          src: 'img/logo.svg',
        },
        items: [
          {
            type: 'docSidebar',
            sidebarId: 'tutorialSidebar',
            position: 'left',
            label: 'Documentation',
          },
          {
            href: 'https://github.com/my-org/my-wiki',
            label: 'GitHub',
            position: 'right',
          },
        ],
      },
      colorMode: {
        defaultMode: 'dark',      // Default to dark mode
        respectPrefersColorScheme: true,
      },
      prism: {
        theme: themes.github,
        darkTheme: themes.dracula,
        additionalLanguages: ['bash', 'yaml', 'docker', 'nginx', 'json'], // Extended syntax highlighting
      },
    }),
};

module.exports = config;
```

> [!info] Updated 2026-11-27
> Starting from **Docusaurus v3.9**, the top-level configuration `onBrokenMarkdownLinks` has been deprecated (scheduled for removal in v4). It is recommended to migrate it under `markdown.hooks.onBrokenMarkdownLinks`:
> ```javascript
> markdown: {
>   hooks: {
>     onBrokenMarkdownLinks: 'warn',
>   },
> },
> ```

## 4. Document Structure & Sidebar Management (`sidebars.js`)

Sidebars are divided into "**Auto-generated**" and "**Manual**" modes. For a Wiki with a large volume of documents, the auto-generated mode is strongly recommended, utilizing the directory structure and Markdown Frontmatter to control sorting.

### 4.1 Auto-Generated Sidebar (`sidebars.js`)

```javascript
// @ts-check
/** @type {import('@docusaurus/plugin-content-docs').SidebarsConfig} */
const sidebars = {
  tutorialSidebar: [
    {
      type: 'autogenerated',
      dirName: '.', // Automatically recursively scan all folders and files under docs/
    },
  ],
};

module.exports = sidebars;
```

### 4.2 Document Frontmatter Core Header Control

Adding YAML metadata at the top of each Markdown file allows precise control over its name and weight in the sidebar:

```markdown
---
id: uptime-kuma-guide
title: Uptime Kuma Monitoring Manual
sidebar_label: Uptime Kuma Monitoring      # Short name displayed in sidebar
sidebar_position: 1                 # Sorting weight (smaller numbers appear higher)
description: Cross-host container guarding and status page setup
tags:
  - Docker
  - Monitoring
---

# Uptime Kuma Monitoring Manual Body...
```

### 4.3 Directory Grouping & Naming Control (`_category_.json`)

To set a sidebar display name for a subfolder inside `docs/`, place a `_category_.json` inside that folder:

```json
{
  "label": "Media Streaming Packages",
  "position": 2,
  "link": {
    "type": "generated-index",
    "description": "Covers integration guides for Navidrome, Emby, and Lidarr."
  }
}
```

## 5. MDX Extended Syntax Practice

Docusaurus supports direct use of special warning boxes (Admonitions) and React UI components within Markdown:

### 5.1 Admonitions

```markdown
:::tip Practical Tip
When mounting a music library via NFS, adding the `_netdev` option prevents boot hangs.
:::

:::warning Precautions
Do not store SQLite databases on CIFS/SMB network shares.
:::

:::danger Severe Warning
Be sure to perform snapshot backups before executing data cleanups!
:::
```

### 5.2 Code Tabs

Suitable for demonstrating comparative commands across different operating systems or tools:

````markdown
import Tabs from '@theme/Tabs';
import TabItem from '@theme/TabItem';

<Tabs>
  <TabItem value="photon" label="Photon OS" default>

```bash
tdnf -y install cifs-utils
```

  </TabItem>
  <TabItem value="debian" label="Debian / Ubuntu">

```bash
apt-get update && apt-get install -y cifs-utils
```

  </TabItem>
</Tabs>
````

## 6. Local Full-Text Search Engine Integration (Zero External Dependencies)

Docusaurus officially recommends Algolia by default, but when building an internal private knowledge base, external crawlers cannot access it. The community's most mature offline solution is **`@easyops-cn/docusaurus-search-local`**.

### Step 1: Install Offline Search Plugin

```bash
npm install @easyops-cn/docusaurus-search-local
```

### Step 2: Register Plugin in `docusaurus.config.js`

```javascript
// Add the themes block within the config object:
themes: [
  [
    require.resolve('@easyops-cn/docusaurus-search-local'),
    /** @type {import("@easyops-cn/docusaurus-search-local").PluginOptions} */
    ({
      hashed: true,
      language: ['zh', 'en'],       // Supports Chinese and English word segmentation search
      indexDocs: true,
      indexBlog: false,
      docsRouteBasePath: '/docs',
    }),
  ],
],
```

_Once configured, running `npm run build` will automatically build index files locally, and an offline search bar will appear directly at the top of the site._

## 7. Production Environment Deployment Solutions

Docusaurus compiled outputs consist purely of static files (located in the `build/` directory). Common self-hosted containerization modes involve **Docker Nginx containers** or pairing with **Traefik v3**.

### 7.1 Dockerfile Multi-stage Build

Create a `Dockerfile` utilizing a Node container for compilation and an Alpine Nginx image for serving, resulting in a size of around 20MB:

```dockerfile
# Stage 1: Build
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Serve
FROM nginx:alpine
COPY --from=builder /app/build /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

> [!info] Updated 2026-11-27
> Node.js 20 (associated with `node:20-alpine`) reached its official End-of-Life (EOL) on 2026-04-30. It is recommended to update the build stage base image to a currently maintained LTS version (such as `node:22-alpine` or `node:24-alpine`).

Corresponding `nginx.conf`:

```nginx
server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # Enable Gzip compression for static assets
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml image/svg+xml;
}
```

### 7.2 Docker Compose + Traefik v3 Integration Template

```yaml
services:
  wiki:
    build: .
    container_name: docusaurus-wiki
    restart: unless-stopped
    networks:
      - proxy-network
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.wiki.rule=Host(`wiki.example.com`)"
      - "traefik.http.routers.wiki.entrypoints=websecure"
      - "traefik.http.routers.wiki.tls=true"
      - "traefik.http.routers.wiki.tls.certresolver=myresolver"
      - "traefik.http.services.wiki.loadbalancer.server.port=80"

networks:
  proxy-network:
    external: true
```

## 8. Troubleshooting

| **Anomaly** | **Root Cause** | **Resolution** |
| --- | --- | --- |
| **`npm run build` throws `Docusaurus found broken links!`** | Cross-page hyperlink paths in the text are incorrect, or referenced anchors do not exist. | Fix paths according to the file line numbers printed in logs, or temporarily change `onBrokenLinks` to `'warn'` in `docusaurus.config.js`. |
| **Markdown contains special characters causing build failure** | The MDX parser misinterprets `<` or `{` as JSX tags or code variables. | Wrap inline code in backticks (e.g., `` `<Your_IP>` ``) or replace with HTML entity encoding. |
| **Chinese strings cannot be searched** | The search plugin lacks Chinese word segmentation support. | Verify that `@easyops-cn/docusaurus-search-local` configuration includes `language: ["zh", "en"]`. |
| **Custom styles breaking in dark mode** | CSS hardcodes color codes without overriding global CSS variables. | Edit `src/css/custom.css` and override theme variables like `--ifm-color-primary` inside the `[data-theme='dark']` selector. |
