## 1. Container Lifecycle Management

### 1.1 Creation and Startup

```bash
# Run container in background with name, port mapping, auto-restart, and environment variables
docker run -d \
  --name web-app \
  -p 8080:80 \
  -e ENV=production \
  --restart unless-stopped \
  nginx:alpine

# Enter temporary container in interactive mode (automatically destroyed upon exit)
docker run --rm -it alpine:latest sh

# Limit CPU and memory quotas
docker run -d \
  --name limited-app \
  --memory="512m" \
  --cpus="1.5" \
  nginx:alpine
```

### 1.2 Status Control and Inspection

```bash
# List running containers
docker ps

# List all containers (including stopped or Exited), showing only ID and name
docker ps -a --format "table {{.ID}}\t{{.Names}}\t{{.Status}}\t{{.Ports}}"

# Start / Stop / Restart container
docker start <container_id_or_name>
docker stop <container_id_or_name>
docker restart <container_id_or_name>

# Force stop container (send SIGKILL)
docker kill <container_id_or_name>

# Pause and unpause container processes (freeze cgroup)
docker pause <container_id_or_name>
docker unpause <container_id_or_name>

# Remove stopped container
docker rm <container_id_or_name>

# Force remove running container (equivalent to kill + rm)
docker rm -f <container_id_or_name>
```

## 2. Debug & Operations

### 2.1 Entering Containers and Viewing Logs

```bash
# Enter running container's Shell (most common)
docker exec -it <container_name> /bin/sh
# If bash is installed
docker exec -it <container_name> /bin/bash

# Execute a specific single-line command inside the container as root
docker exec -u 0 -it <container_name> whoami

# Tail logs in real-time, limiting line count and timestamps
docker logs -f --tail 100 -t <container_name>

# View logs since a specific timestamp
docker logs --since "2026-09-01T00:00:00" <container_name>
```

### 2.2 Dynamic Resource Monitoring and Process Inspection

```bash
# Real-time container resource utilization (CPU, Memory, Network I/O, Block I/O)
docker stats

# Formatted non-streaming resource usage snapshot
docker stats --no-stream --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}\t{{.NetIO}}"

# View process list inside the container (from Host perspective)
docker top <container_name>
```

### 2.3 File Copying and Low-Level Inspection

```bash
# Copy local file into container
docker cp /path/to/local/file.conf <container_name>:/etc/app/file.conf

# Copy container file to local host
docker cp <container_name>:/var/log/app.log ./app.log

# View container filesystem modifications compared to the Image (A: Added, C: Changed, D: Deleted)
docker diff <container_name>

# Inspect full container low-level JSON properties (IP, Mounts, Env, Config, etc.)
docker inspect <container_name>

# Quickly extract container IP using jq or Go templates
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' <container_name>
```

## 3. Image Management

```bash
# Search Docker Hub for images
docker search nginx

# Pull specific version of an image
docker pull ubuntu:24.04

# List existing local images
docker images

# Display sorted by image size
docker images --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}" | sort -k 3 -h

# Build image (specifying Dockerfile and tag)
docker build -t my-app:v1.0 .

# Force rebuild without cache
docker build --no-cache -t my-app:v1.0 .

# Tag image for pushing to a Private Registry
docker tag my-app:v1.0 registry.example.com/proj/my-app:v1.0

# Push to Registry
docker push registry.example.com/proj/my-app:v1.0

# View image layer structure and build history (for troubleshooting bloated images)
docker history --no-trunc my-app:v1.0

# Export and import images (offline deployment)
docker save -o my-app.tar my-app:v1.0
docker load -i my-app.tar

# Remove specific image
docker rmi <image_id_or_name>

# Force remove image (even if referenced by stopped containers)
docker rmi -f <image_id_or_name>
```

## 4. Volumes and Persistent Storage

```bash
# Create named volume
docker volume create my-data-vol

# List all volumes
docker volume ls

# List dangling volumes (not used by any container)
docker volume ls -f dangling=true

# Inspect actual host mountpoint of a volume
docker volume inspect my-data-vol

# Remove specific volume (must not be in use by any container)
docker volume rm my-data-vol

# Prune all unused volumes
docker volume prune -f
```

## 5. Network Management

```bash
# List all network drivers and network lists
docker network ls

# Create custom bridge network (supports direct DNS resolution between containers by service/container name)
docker network create --driver bridge my-isolated-net

# Create custom network with specific subnet
docker network create --subnet 172.28.0.0/16 my-custom-net

# Inspect network configuration, connected containers, and IPs
docker network inspect my-isolated-net

# Dynamically connect running container to network
docker network connect my-isolated-net <container_name>

# Disconnect container from network
docker network disconnect my-isolated-net <container_name>

# Remove unused network
docker network rm my-isolated-net
docker network prune -f
```

## 6. Modern Docker Compose (V2) Core Commands

Compose V2 is integrated directly into the Docker CLI using Go, with commands structured around `docker compose`:

```bash
# Start and run in background (auto-create networks and volumes)
docker compose up -d

# Force recreate containers (apply configuration or daemon.json changes)
docker compose up -d --force-recreate

# Build and start services
docker compose up -d --build

# Stop and remove Compose project containers and custom networks
docker compose down

# Stop and remove along with volume data (destructive operation, use with caution)
docker compose down -v

# Stop and remove all images (--rmi all or local)
docker compose down --rmi local

# Tail logs for all containers in project in real-time
docker compose logs -f

# Tail logs for specific service only
docker compose logs -f <service_name>

# View project container running status and port mapping
docker compose ps

# Restart specific single service
docker compose restart <service_name>

# Run a one-off command for a service temporarily (without exposing ports)
docker compose run --rm <service_name> sh
```

## 7. System Maintenance & Troubleshooting

```bash
# View Docker engine version and detailed architecture (Kernel, Storage Driver, OS, etc.)
docker version
docker info

# Listen in real-time to Docker daemon events (container start, stop, OOM, etc.)
docker events

# Check resource usage breakdown by type
docker system df

# View detailed disk usage breakdown
docker system df -v

# One-click cleanup: stopped containers + unused networks + dangling images (<none>)
docker system prune -f

# Deep cleanup: includes all unreferenced images and build cache
docker system prune -a -f
```
