## 1. Installing Docker Engine on Common Linux Distributions

### 1.1 VMware Photon OS

Photon OS comes with Docker Engine pre-loaded in its official package repository:

```bash
# Enable and start on boot
systemctl enable --now docker

# Check status
systemctl status docker
```

### 1.2 Debian / Ubuntu

Install the latest version using Docker's official APT repository:

```bash
# 1. Update package lists and install basic prerequisites
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg

# 2. Add Docker's official GPG key
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/$(. /etc/os-release && echo "$ID")/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# 3. Set up the APT repository
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/$(. /etc/os-release && echo "$ID") \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 4. Install Docker Engine and CLI plugins
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 5. Enable and start on boot
sudo systemctl enable --now docker
```

### 1.3 RHEL / Rocky Linux / AlmaLinux / CentOS

Configure the official repository using DNF / YUM:

```bash
# 1. Install necessary utilities
sudo dnf install -y dnf-utils

# 2. Add Docker's official repo
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# 3. Install Docker packages
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 4. Enable and start on boot
sudo systemctl enable --now docker
```

*(Note: In environments using DNF 5 such as Fedora 41+ or RHEL 10, the step 2 command syntax changes to `sudo dnf config-manager addrepo --from-repofile=https://download.docker.com/linux/centos/docker-ce.repo`.)*

### 1.4 Alpine Linux

Alpine uses OpenRC as its service manager and provides packages in the Community repository by default:

```bash
# 1. Enable Community repository (if not enabled, edit /etc/apk/repositories and uncomment the community line)
# 2. Install Docker
apk update
apk add docker

# 3. Add to default boot runlevel and start
rc-update add docker boot
service docker start
```

## 2. Docker Compose Installation and Deployment Methods

Modern standards have completely deprecated the old Python pip installation method (`pip install docker-compose`) in favor of **Docker Compose V2** (the Go-written CLI plugin `docker compose`), which offers great compatibility without interfering with the system Python environment.

| **Distribution** | **Recommended Installation Method** | **Command** |
| :--- | :--- | :--- |
| **Photon OS** | Official package repo native install (V1/V2 binary) | `tdnf -y install docker-compose` |
| **Ubuntu / Debian** | APT official plugin (Recommended) | `sudo apt-get install -y docker-compose-plugin` |
| **RHEL / Rocky Linux** | DNF official plugin (Recommended) | `sudo dnf install -y docker-compose-plugin` |
| **Alpine Linux** | APK package repo (`docker-cli-compose`) | `apk add docker-cli-compose` |
| **Universal Manual Install** | Official GitHub Binary Standalone / Plugin | See "Universal Manual Deployment" below |

### Universal Manual Deployment (Applicable to Any x86_64 / aarch64 Linux)

When distribution package repositories are outdated or on minimalist systems, download the binary directly and install it to the CLI plugin path:

```bash
# 1. Create Docker CLI plugins directory
sudo mkdir -p /usr/libexec/docker/cli-plugins

# 2. Automatically fetch and download the latest version (using x86_64 as an example; change to aarch64 for ARM)
COMPOSE_VERSION=$(curl -s https://api.github.com/repos/docker/compose/releases/latest | grep '"tag_name":' | sed -E 's/.*"([^"]+)".*/\1/')
sudo curl -SL "https://github.com/docker/compose/releases/download/${COMPOSE_VERSION}/docker-compose-linux-$(uname -m)" -o /usr/libexec/docker/cli-plugins/docker-compose

# 3. Grant execution permissions
sudo chmod +x /usr/libexec/docker/cli-plugins/docker-compose

# 4. (Optional) Create a global symlink for legacy command compatibility
sudo ln -sf /usr/libexec/docker/cli-plugins/docker-compose /usr/local/bin/docker-compose

# 5. Verify
docker compose version
```

## 3. Global Optimization and Permission Settings

### 3.1 Non-Root User Execution Permissions

To avoid using root for daily operations:

```bash
# Add target user to the docker group
sudo usermod -aG docker $USER

# Apply group permissions (or re-login to SSH)
newgrp docker
```

### 3.2 Daemon Optimization (`/etc/docker/daemon.json`)

Create or overwrite `/etc/docker/daemon.json` to prevent container logs from filling up disk space and to enable live-restore:

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "50m",
    "max-file": "3"
  },
  "storage-driver": "overlay2",
  "live-restore": true,
  "default-ulimits": {
    "nofile": {
      "Name": "nofile",
      "Hard": 65535,
      "Soft": 65535
    }
  }
}
```

Apply settings:

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
```

### 3.3 Kernel IP Forwarding

If container networks cannot communicate externally or port exposure fails, ensure IPv4 forwarding is enabled:

```bash
# Check status (returns 1 if normal)
sysctl net.ipv4.ip_forward

# If 0, write to configuration file for persistence
echo "net.ipv4.ip_forward = 1" | sudo tee /etc/sysctl.d/99-docker-forward.conf
sudo sysctl -p /etc/sysctl.d/99-docker-forward.conf
```

## 4. Managing Docker Compose Services on Boot with Systemd

In addition to declaring `restart: always` or `restart: unless-stopped` in `compose.yaml`, production environments benefit from encapsulating entire Compose projects into **Systemd Units** for standard OS monitoring, dependency ordering, and auto-restart mechanisms.

### Step 1: Create Project Directory and Compose File

Taking `/opt/apps/my-stack` as an example:

```bash
sudo mkdir -p /opt/apps/my-stack
cd /opt/apps/my-stack
```

Create `docker-compose.yml`:

```yaml
services:
  app:
    image: nginx:alpine
    ports:
      - "8080:80"
```

### Step 2: Create Systemd Service Unit

Create the file `/etc/systemd/system/docker-compose@.service` (using the instantiation template `@` to support multiple Compose projects simultaneously):

```ini
[Unit]
Description=Docker Compose Application Service (%i)
Requires=docker.service
After=docker.service network-online.target
Wants=network-online.target

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/apps/%i

# Pull images and start container stack before starting
ExecStartPre=-/usr/bin/docker compose pull
ExecStart=/usr/bin/docker compose up -d --remove-orphans

# Gracefully stop all containers on shutdown
ExecStop=/usr/bin/docker compose down

# Reload configuration
ExecReload=/usr/bin/docker compose pull
ExecReload=/usr/bin/docker compose up -d --remove-orphans

# Timeout settings
TimeoutStartSec=300
TimeoutStopSec=60

[Install]
WantedBy=multi-user.target
```

> **Note**: Verify the path using `which docker`. If it is `/usr/local/bin/docker`, adjust the `Exec*` paths accordingly.

### Step 3: Load and Enable Service

The template unit automatically matches directory names. For instance, if the directory is `/opt/apps/my-stack`, the service name is `docker-compose@my-stack`:

```bash
# 1. Reload systemd configuration
sudo systemctl daemon-reload

# 2. Start service and enable on boot
sudo systemctl enable --now docker-compose@my-stack

# 3. Check service running status
sudo systemctl status docker-compose@my-stack

# 4. View container operational logs
journalctl -u docker-compose@my-stack -f
```

## 5. System Maintenance and Disk Space Management Quick Reference

Regularly run maintenance commands to reclaim unreleased space:

```bash
# 1. View current Docker space usage
docker system df

# 2. Clean up all stopped containers, unused networks, and dangling images
docker system prune -f

# 3. Deep cleanup: Delete images not used by any existing container as well
docker system prune -a -f

# 4. Clean up orphaned volumes (Warning: Destructive, may delete data no longer mounted)
docker volume prune -f
```
