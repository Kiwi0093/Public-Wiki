### 1.2 Community Latest Evolution and Selection Corrections (Change Log: Rev 2.0+)

1. **Only wrap the downloader in VPN, release the management layer completely**:

    - The past practice of "stuffing all services into the Gluetun network" would cause API requests from Sonarr/Radarr/Lidarr (such as MusicBrainz, TheTVDB, and other external metadata) to be constrained by VPN node quality; once a VPN node experiences unstable routing or public IP check failure, all metadata fetching comes to a complete standstill.

    - **Latest Standard Solution**: Only let **qBittorrent** share Gluetun's network namespace (`network_mode: "service:gluetun"`), ensuring that only actual BT/PT download traffic goes through the VPN. The rest of the management containers go through the standard Docker custom bridge network, communicating directly via "container names" and avoiding the tedious maintenance of hardcoding static IPs.

2. **Use Prowlarr to Replace Jackett**:

    - Jackett is a traditional indexer proxy tool; the next-generation **Prowlarr**, along with Sonarr / Radarr, belongs to the LinuxServer/*arr family with higher native integration. It can automatically synchronize configured indexers to all Sonarr, Radarr, and Lidarr instances with "one click" through a single interface, eliminating the need to manually copy Torznab URLs and API Keys in each tool.

3. **Use Bazarr to Replace ChineseSubFinder**:

    - ChineseSubFinder is no longer maintained. The current best alternative is **Bazarr**, which directly monitors Sonarr / Radarr databases via API and supports multiple subtitle sources (such as Zimuku, Shooter, Assrt), automatically retrying in the background on a schedule when subtitles are missing.

## 2. Prerequisites: Storage Architecture, Hardlinks, and System Underlying Layer

### 2.1 Storage Directory Structure and Hardlinks (Extremely Important)

Many beginners mount the download directory as `/downloads` and the media directory as `/media`, which causes Docker to treat them as two different file systems. When downloads complete, Sonarr/Radarr can only use **cross-volume copying (Copy + Delete)**, which is not only slow and heavily consumes disk lifespan, but also causes hard drive space to be occupied twice.

**Best Practice: Uniformly Mount a Single Root Directory to Implement Hardlinks**

```
/data
├── torrents         <-- qBittorrent download staging and seeding directory
│   ├── movies
│   ├── tv
│   ├── anime
│   └── music
└── media            <-- Organized media library read by Emby / Navidrome
    ├── movies       <-- Hardlinked from Radarr (zero disk space duplication)
    ├── tv           <-- Hardlinked from Sonarr
    ├── anime
    └── music        <-- Hardlinked from Lidarr
```

All containers uniformly mount `/data:/data` internally. When a download completes, the system only needs to create inode pointers (Hardlinks), completing the import in one second while maintaining the original BT files in the `torrents` directory to continue seeding.

### 2.2 Photon OS Loading TUN Kernel Module

Gluetun requires the host to support the TUN virtual network interface. Photon OS does not load `tun.ko` by default:

```bash
# 1. Manually load TUN kernel module
modprobe tun

# 2. Verify successful loading
lsmod | grep tun

# 3. Configure automatic loading at boot
echo tun > /etc/modules-load.d/tun.conf
```
