## 1. Variable Definition and Assignment Conventions

- **Basic Definition**:

    ```bash
    VAR_NAME="value"      # Absolutely no spaces are allowed on either side of the equals sign
    echo "${VAR_NAME}"    # It is recommended to always wrap with curly braces ${} to prevent boundary ambiguity
    ```

- **Command Output Assignment (Command Substitution)**:

    ```bash
    CURRENT_USER=$(whoami)
    BACKUP_DATE=$(date +%F)
    ```

- **Variable Scope**:
    - Declared as a local variable by default (restricted to the current process).
    - Declared as an environment variable via `export VAR_NAME` so it can be inherited by forked child processes.

## 2. Special Automatic Variables and Positional Parameters Quick Reference

| **Variable Name** | **Meaning Description** | **Behavior Analysis and Engineer-Essential Details** | **Practical Examples** |
| :--- | :--- | :--- | :--- |
| **`$?`** | Exit Status Code of the last command | `0` indicates successful execution; non-zero (such as `1`, `2`, `127`, etc.) indicates execution failure or abnormality. | `systemctl restart nginx`<br />`[ $? -eq 0 ] && echo "OK"` |
| **`$$`** | Process ID (PID) of the current shell process | Commonly used in scripts to create unique temporary file names and avoid concurrency conflicts. | `TMP_FILE="/tmp/run_$$.tmp"` |
| **`$!`** | PID of the last background-executed job | Captures the process ID just sent to the background with `&`, convenient for subsequent monitoring with `wait`. | `python3 job.py &`<br />`JOB_PID=$!` |
| **`$-`** | Flags currently enabled in the shell | Displays the current shell's execution options (such as interactive mode flags like `h`, `B`, `i`, etc.). | `echo "$-"` |
| **`$0`** | Filename or path of the current shell script | The command path entered at execution (e.g., `./deploy.sh` or `/opt/deploy.sh`). | `SCRIPT_DIR=$(dirname "$0")` |
| **`$1` ~ `$9`** | Command-line Positional Arguments | Sequentially receives the first through ninth arguments passed from outside (the tenth and beyond require `${10}`). | `./backup.sh /data /mnt/nas`<br />`# $1=/data, $2=/mnt/nas` |
| **`$#`** | Total number of arguments passed to the script | Commonly used at the beginning of a script to validate whether the number of arguments is sufficient. | `[ $# -lt 2 ] && exit 1` |
| **`$*`** | Collection of all passed arguments (merged string) | When wrapped in double quotes `"$*"` joins all arguments into a single string separated by `$IFS` (default is space): `"$1 $2 $3"`. | `echo "All args: $*"` |
| **`$@`** | Collection of all passed arguments (independent array) | **Most commonly used in loops and forwarding**. Double quotes `"$@"` keep each argument as an independent string: `"$1" "$2" "$3"`. | `for arg in "$@"; do ... done` |

## 4. Handling Empty and Unset Variables (Parameter Expansion)

In shell scripts, using unassigned variables directly can easily lead to unexpected behaviors (or even disasters like root directory deletion via `rm -rf /${DIR}`). Using Bash parameter expansion syntax allows you to safely and gracefully set default values or exit defensively:

| **Syntax Format** | **Condition Check** | **Handling Behavior** | **Practical Examples** |
| :--- | :--- | :--- | :--- |
| **`${var:-word}`** | `var` is empty or unset | **Temporarily uses** `word` as the return value, **does not change** the actual content of `var`. | `PORT=${CUSTOM_PORT:-8080}`<br />_(Defaults to 8080 when unspecified)_ |
| **`${var:=word}`** | `var` is empty or unset | **Assigns `word` to `var`**, and subsequently uses the new value. | `${DATABASE_NAME:=homelab}`<br />_(Automatically defines and stores in the variable when unset)_ |
| **`${var:?word}`** | `var` is empty or unset | Prints the `word` error message to stderr and **immediately forces termination of the program**. | `DIR=${1:?"Please provide the target directory path!"}`<br />_(Aborts execution immediately if argument is missing)_ |
| **`${var:+word}`** | `var` **is set and non-empty** | Temporarily replaces it with `word`; returns empty value if it is empty (used for existence checks). | `[ -n "${DEBUG:+x}" ] && echo "Debug on"` |

> **Tip**: Omitting the colon (e.g., `${var-word}`) triggers only when `var` is **completely unset (Unset)**; including the colon (`${var:-word}`) covers both **unset** and **set to an empty string `""`** cases. Using the colon syntax is recommended for all routine scripts.

## 5. Input Variables: Advanced Usage of the `read` Command

The `read` command is used to pause in the terminal and read user keyboard input:

```bash
# Basic syntax
echo -n "Please enter project name: "
read PROJECT_NAME
echo "You entered: ${PROJECT_NAME}"

# Recommended modern single-line syntax (combining -p prompt, -t timeout, -s password hiding)
# 1. With prompt string (-p)
read -p "Please enter database name: " DB_NAME

# 2. Hidden password input (-s, prevents printing password to screen)
read -sp "Please enter connection password: " DB_PASSWORD
echo "" # Manually print newline after password input

# 3. Timeout auto-skip (-t, e.g., wait 10 seconds)
read -t 10 -p "Confirm to continue execution? (y/N): " CONFIRM
CONFIRM=${CONFIRM:-N} # Defaults to N if no input before timeout
```

## 6. Command Substitution and Safe Conditional Judgment Practice

After storing external command output into a variable, make sure to wrap it defensively when performing comparisons:

```bash
#!/usr/bin/env bash

# 1. Capture current executor identity
CURRENT_USER=$(whoami)

# 2. Safe conditional judgment (recommended [[ ]] structure, most complete compatibility and features)
if [[ "${CURRENT_USER}" == "root" ]]; then
    echo "Success: Currently executing with root privileges"
else
    echo "Warning: Must execute this script with root privileges (current user: ${CURRENT_USER})" >&2
    exit 1
fi

# 3. Check critical path variables (defensive programming, avoiding undefined accidental deletion)
TARGET_DIR="${1:-}"

# Strict validation to avoid rm -rf /
if [[ -z "${TARGET_DIR}" ]]; then
    echo "Error: Cleanup directory not specified!" >&2
    exit 1
fi

echo "Cleaning up temporary folder: ${TARGET_DIR}..."
```
