## 1. Architecture Prerequisites: Photon OS Mounting NAS Music Library (SMB vs. NFS)

If your music library resides on an external NAS, you need to securely mount the directory to the host. In Linux / Photon OS environments, **NFS generally offers lower CPU overhead and better audio small-file read performance than SMB/CIFS**.

### Option A: CIFS / SMB Mounting (Traditional & Universal)

Suitable for scenarios where NAS native permissions lean toward Windows ACLs or require dedicated credential protection.

```bash
# 1. Install tool utilities
tdnf -y install cifs-utils

# 2. Create credential protection file (preventing plaintext passwords in fstab)
sudo mkdir -p /root/.smbcredentials
sudo bash -c 'cat << EOF > /root/.smbcredentials/nas
username=nas_username
password=nas_secret_password
domain=WORKGROUP
EOF'
sudo chmod 600 /root/.smbcredentials/nas

# 3. Create local mount point
sudo mkdir -p /mnt/nas/music
```

Edit `/etc/fstab` and append:

```bash
//192.168.1.50/Music /mnt/nas/music cifs credentials=/root/.smbcredentials/nas,uid=1000,gid=1000,ro,iocharset=utf8,_netdev,nofail 0 0
```

### Option B: NFS Mounting (Recommended, Better Performance, Native Linux Support)

NFS runs on the native Linux protocol with lower overhead. First, enable the NFS service for the target folder on your NAS and **add the Photon OS IP to the allow list** (setting it to read-only `ro` is recommended, along with configuring `all_squash` mapped to a specific UID/GID).

#### Step 1: Install NFS Client on Photon OS

```bash
# Install NFS support package
tdnf -y install nfs-utils

# Enable and start rpcbind service on boot
systemctl enable --now rpcbind
```

#### Step 2: Test NAS NFS Export Path

Verify that shared folders provided by the NAS are visible:

```bash
showmount -e 192.168.1.50
# Output example:
# /volume1/Music  192.168.1.0/24
```

#### Step 3: Create Local Mount Point

```bash
sudo mkdir -p /mnt/nas/music
```

#### Step 4: Configure `/etc/fstab` for Automatic Boot Mounting

Edit `/etc/fstab` and add the following setting:

```bash
192.168.1.50:/volume1/Music /mnt/nas/music nfs nfsvers=4.1,ro,_netdev,nofail,hard,intr,rsize=1048576,wsize=1048576 0 0
```

- **Key Parameter Analysis**:
    
    - **`nfsvers=4.1`**: Prefer NFSv4.1 (offers better state management and firewall friendliness; use `nfsvers=3` if the NAS is older).
        
    - **`ro`**: Mounts as **read-only mode**. Navidrome only requires reading audio; setting read-only completely eliminates accidental deletion or ransomware risks.
        
    - **`_netdev`**: Core parameter forcing the system to **wait for network connectivity** before mounting, preventing boot freezes if the NAS is unreachable during startup.
        
    - **`nofail`**: If the NAS reboots or goes offline, the operating system will skip this entry and continue normal startup without entering Emergency Mode.
        
    - **`hard,intr`**: If connection is temporarily interrupted, operations will wait for the server to recover rather than immediately throwing an error and interrupting playback<span style="color:#e06c75"><del>, and allows users to interrupt requests</del></span> *(Updated 2026-11-27: Since Linux Kernel 2.6.25, the `intr` option has been deprecated and treated as invalid; modern kernels default to allowing interruption of `hard` mounts solely via `SIGKILL`)*.
        
    - **`rsize/wsize=1048576`**: Sets transfer buffer to 1MB, significantly boosting throughput when streaming high-resolution audio (FLAC / DSD).
        

#### Step 5: Test Mounting

```bash
# Test mounting all entries in /etc/fstab
sudo mount -a

# Check if mounted successfully and inspect contents
df -h | grep /mnt/nas/music
ls -la /mnt/nas/music
```

### CIFS vs. NFS Selection Comparison

|Comparison Dimension|CIFS / SMB|NFS (v4.1) (Recommended)|
|---|---|---|
|**Authentication**|Uses user account / password authentication|Uses client host IP whitelist verification|
|**Transfer Efficiency**|Protocol is more cumbersome; CPU overhead slightly higher during frequent small file reads|Protocol is streamlined, lower transfer latency, better throughput|
|**Permission Mapping**|Must explicitly declare `uid=1000,gid=1000` in mount parameters|Supports NAS-side `all_squash` configuration to unify user mapping|
|**Cross-Platform Compatibility**|Universal across Windows / macOS / Linux|Tailored specifically for the Unix / Linux ecosystem|

> **Storage Separation Rule (Regardless of SMB or NFS)**: Feel free to mount the music library `/music` on the NAS, but Navidrome's data directory `/data` (including the SQLite `navidrome.db`) **must be kept on the local SSD**. Do not place it on any network shared disk to ensure smooth search and play count writes, and to prevent SQLite database corruption.

## 2. Docker Compose Deployment Configuration (Integrating Traefik v3)

In reverse proxy planning, there are two common modes:

1. **Dedicated Subdomain Mode (Recommended)**: e.g., `music.example.com`, simple paths, no URL forwarding issues to handle.
    
2. **Subpath Mode**: e.g., `example.com/music`, requiring special configuration of `ND_BASEURL` and Traefik's `PathPrefix`.
    

### Step 1: Create Local Dedicated Directory

```bash
sudo mkdir -p /opt/navidrome/data
sudo chown -R 1000:1000 /opt/navidrome/data
```

### Step 2: `docker-compose.yml` Configuration (Using Dedicated Subdomain as Example)

```yaml
services:
  navidrome:
    image: deluan/navidrome:latest
    container_name: navidrome
    restart: unless-stopped
    user: "1000:1000"
    environment:
      # Timezone setting
      - TZ=Asia/Taipei
      # Background scan schedule (scan directory changes every 1 hour)
      - ND_SCANSCHEDULE=1h
      # Log level (debug, info, warn, error)
      - ND_LOGLEVEL=info
      # Session timeout
      - ND_SESSIONTIMEOUT=24h
      # Trusted reverse proxy IP subnets (supports Docker subnets)
      - ND_REVERSEPROXYWHITELIST=172.16.0.0/12,10.0.0.0/8,192.168.0.0/16
      # Transcoding configuration (enable as needed, allowing clients to optionally transcode to MP3/Opus)
      - ND_ENABLETRANSCODINGCONFIG=true
      # Set only if using subpath (e.g., "/music"), leave blank or delete this line for subdomains
      - ND_BASEURL=
    volumes:
      - /opt/navidrome/data:/data
      - /mnt/nas/music:/music:ro
    networks:
      - proxy-network
    labels:
      - "traefik.enable=true"
      # 1. Routing rules
      - "traefik.http.routers.navidrome.rule=Host(`music.example.com`)"
      - "traefik.http.routers.navidrome.entrypoints=websecure"
      - "traefik.http.routers.navidrome.tls=true"
      - "traefik.http.routers.navidrome.tls.certresolver=myresolver"
      # 2. Explicitly declare forwarding to port 4533 inside the container
      - "traefik.http.services.navidrome.loadbalancer.server.port=4533"

networks:
  proxy-network:
    external: true
```

## 3. Nginx / Nginx Proxy Manager Dedicated Configuration

If Nginx or NPM is used in front of the environment:

```nginx
location /music {
    proxy_pass http://navidrome:4533;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $http_host;
    
    # Streaming optimization: disable buffering to prevent audio stuttering during high-bitrate FLAC/DSD playback
    proxy_buffering off;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    
    # Extend timeout to prevent interruption during long playback sessions
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```
