## Basic Workflow

### Prerequisites

This approach places both the DB and the AP inside the same `docker-compose.yml`. Looking back, it is indeed true that avoiding tightly coupling the DB makes containerization more convenient and makes splitting services like this much easier.

### Steps

1. First use `docker run` to run the script inside the image to generate the initial DB.
2. Use a compose file to create the DB standalone first (and define volumes to persist data).
3. Import the initial DB into the DB container's database inside the DB container (persisting the result via volumes).
4. Remove the standalone DB container (technically you don't have to remove it, though subsequent adjustments are more tedious).
5. Use `docker-compose.yml` to create all related containers directly (including the DB container).

## Actual Commands and Files

### Pull Image

```bash
docker pull guacamole/guacamole
docker pull guacamole/guacd
docker pull mariadb/server
```

> [!info] Updated 2026-11-27
> `mariadb/server` is an unmaintained legacy image; modern deployments should use the official `mariadb:lts` image instead (the `MARIADB_*` prefix is also recommended for environment variables).

### Create Initial DB

```bash
docker run --rm guacamole/guacamole /opt/guacamole/bin/initdb.sh --mysql > guac_db.sql
```

### Create Initial DB Container/Volume

#### `initial.yml`

```yaml
version: '3'
services:
  guacdb:
    container_name: guacdb
    image: mariadb/server:latest
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: '<PASSWD_YOU_WANT>'
      MYSQL_DATABASE: 'guacamole_db'
      MYSQL_USER: 'guacamole_user'
      MYSQL_PASSWORD: '<PASSWD_YOU_WANT>'
    volumes:
      - /var/lib/docker/volumes/<Dir_you_want>:/var/lib/mysql
```

#### Commands

```bash
# Establish initial DB Container
docker-compose up -d

# Copy initial sql into db container
docker cp guac_db.sql guacdb:/guac_db.sql

# Opening a shell and initializing the db:
docker exec -it guacdb bash
cat /guac_db.sql | mysql -u root -p guacamole_db
exit

# Remove initial DB OS
docker-compose -f /where/is/your/docker-compose down
```

> [!info] Updated 2026-11-27
> 1. `docker-compose` v1 has reached end of life; in modern environments, use `docker compose` v2 instead (for example, `docker compose -f initial.yml up -d` and `docker compose -f initial.yml down`; the last line of the original commands was also missing the `.yml` extension).
> 2. The top-level `version: '3'` field in Compose YAML is obsolete in Compose v2 and can simply be omitted.

### Service Up

#### `docker-compose.yml`

```yaml
version: '3'
services:
  guacdb:
    container_name: guacdb
    image: mariadb/server:latest
    restart: unless-stopped
    networks:
      - traefik
    environment:
      MYSQL_ROOT_PASSWORD: '<PASSWD_YOU_WANT>'
      MYSQL_DATABASE: 'guacamole_db'
      MYSQL_USER: 'guacamole_user'
      MYSQL_PASSWORD: '<PASSWD_YOU_WANT>'
    volumes:
      - /var/lib/docker/volumes/guacamole/db:/var/lib/mysql
  guacd:
    container_name: guacd
    image: guacamole/guacd
    restart: unless-stopped
    networks:
      - traefik
  guacamole:
    container_name: guacamole
    image: 'guacamole/guacamole:latest'
    restart: unless-stopped
    networks:
      - traefik
 #   ports:
 #     - '8080:8080'
    environment:
      GUACD_HOSTNAME: "guacd"
      MYSQL_HOSTNAME: "guacdb"
      MYSQL_DATABASE: "guacamole_db"
      MYSQL_USER: "guacamole_user"
      MYSQL_PASSWORD: "<PASSWD_YOU_WANT>"
    depends_on:
      - guacdb
      - guacd
    labels:
      traefik.enable: true
      traefik.http.routers.guacamole.rule: Host(`<hostname.you.want>`)
      traefik.http.routers.guacamole.tls: true
      traefik.http.routers.guacamole.tls.certresolver: myresolver
      traefik.http.services.guacamole.loadbalancer.server.port: 8080

networks:
  traefik:
    external: true
    name: web-service
```

> [!info] Updated 2026-11-27
> As above, Compose v2 does not need `version: '3'`, and `mariadb/server:latest` should be changed to `mariadb:lts` (in the new official image, the client tool is the `mariadb` CLI).

## Reasons for Deprecation

- Poor security: this setup essentially punches a hole through the firewall.
- Replaced with `WireGuard` + `VNC`, which is relatively safer and simpler.
