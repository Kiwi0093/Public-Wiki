# BookStack Knowledge Base System Deployment

> <img src='https://img.shields.io/badge/Status-Obsolete-red?style=for-the-badge&labelWidth=100' height='38' />

![Docker](https://img.shields.io/badge/Docker-Supported-green?style=plastic&logo=docker)

## 1. Core Architecture and Major Breaking Changes

- **Storage Model**: BookStack's article contents, user permissions, and page metadata are stored in **MariaDB / MySQL**; images, attachments, and uploaded files are stored in the file system directory (`/config/www/storage`).

- **LinuxServer Variable Renaming Trap**:
  - LinuxServer.io image has gradually unified its database environment variable naming convention to align with Laravel's default variables:
    - Legacy parameters: `DB_USER` / `DB_PASS`
    - **New mandatory parameters**: `DB_USERNAME` / `DB_PASSWORD`
  - If legacy examples are followed, the container will pick up null values during initialization, causing the container to repeatedly output `Database connection error: SQLSTATE[HY000] [1045] Access denied`.

- **`APP_URL` Strict Limitation**:
  - The underlying Laravel framework strongly relies on `APP_URL` to generate static assets (CSS / JS) and page redirection hyperlinks.
  - When running behind an HTTPS reverse proxy, **`APP_URL` must strictly include `https://` and the full domain name** (cannot be left blank or set to `http://localhost`), otherwise it will cause front-end Mixed Content breaking issues, login CSRF Token verification failures, or infinite redirect loops.

## 2. Docker Compose Deployment Configuration (Integrating Traefik v3)

Deployment uses Traefik v3 for edge SSL termination. The backend container does not expose any host ports externally, communicating uniformly through a shared external Docker network.

### Step 1: Create Dedicated Directory and Permissions

```bash
# Create database and application configuration directories
sudo mkdir -p /opt/bookstack/db /opt/bookstack/app

# Set PUID/PGID aligned owner (using UID 1000 as an example)
sudo chown -R 1000:1000 /opt/bookstack
```

### Step 2: Complete `docker-compose.yml` Configuration

Orchestrate services in `/opt/bookstack/docker-compose.yml`:

```yaml
services:
  bookstack_db:
    image: lscr.io/linuxserver/mariadb:latest
    container_name: bookstack_db
    restart: unless-stopped
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Asia/Taipei
      - MYSQL_ROOT_PASSWORD=your_super_root_pass
      - MYSQL_DATABASE=bookstackapp
      - MYSQL_USER=bookstack
      - MYSQL_PASSWORD=your_db_secret_pass
    volumes:
      - /opt/bookstack/db:/config
    networks:
      - bookstack_internal

  bookstack:
    image: lscr.io/linuxserver/bookstack:latest
    container_name: bookstack
    restart: unless-stopped
    depends_on:
      - bookstack_db
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Asia/Taipei
      # Crucial: Must fully include https:// and match the Traefik routing domain
      - APP_URL=https://wiki.example.com
      # Database connection (note the new parameter names)
      - DB_HOST=bookstack_db
      - DB_DATABASE=bookstackapp
      - DB_USERNAME=bookstack
      - DB_PASSWORD=your_db_secret_pass
      # SMTP mail notification settings (optional)
      - MAIL_DRIVER=smtp
      - MAIL_HOST=smtp.example.com
      - MAIL_PORT=587
      - MAIL_ENCRYPTION=tls
      - MAIL_USERNAME=notify@example.com
      - MAIL_PASSWORD=your_smtp_password
      - MAIL_FROM=notify@example.com
      - MAIL_FROM_NAME=BookStack Wiki
    volumes:
      - /opt/bookstack/app:/config
    networks:
      - bookstack_internal
      - proxy-network
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.bookstack.rule=Host(`wiki.example.com`)"
      - "traefik.http.routers.bookstack.entrypoints=websecure"
      - "traefik.http.routers.bookstack.tls=true"
      - "traefik.http.routers.bookstack.tls.certresolver=myresolver"
      # Crucial: LinuxServer internal Nginx listens on Port 80, must explicitly specify the load balancing target port
      - "traefik.http.services.bookstack.loadbalancer.server.port=80"

networks:
  bookstack_internal:
    driver: bridge
  proxy-network:
    external: true
```

Start services:

```bash
docker compose up -d
```

## 3. Initial Administrator Login and Security Changes

The container automatically executes database migration and default seed data population upon first startup:

1. Open in browser: [https://wiki.example.com](https://wiki.example.com)

2. **Default High-Privilege Account**:
   - **Email**: `admin@admin.com`
   - **Password**: `password`

3. After logging in, immediately go to "Settings" -> "Users" -> click `Admin` to change the Email and replace it with a high-strength password.

## 4. Key Pitfalls and Advanced Troubleshooting

### 4.1 Redirecting to `http://localhost:6875` or CSS/JS Breaking (Mixed Content)

- **Cause**: `APP_URL` missing or misformatted, or reverse proxy not correctly forwarding proxy headers.

- **Solution**:
  1. Ensure `APP_URL` is correctly configured and starts with `https://`.
  2. If using a custom Nginx / NPM reverse proxy, ensure the following headers are passed upstream:

     ```nginx
     proxy_set_header X-Forwarded-Proto https;
     proxy_set_header X-Forwarded-Host $host;
     ```

### 4.2 Why Must Traefik Explicitly Specify `server.port=80`?

- LinuxServer.io image internally uses S6-overlay to start Nginx + PHP-FPM. The container image may declare multiple listening ports internally. If `traefik.http.services.bookstack.loadbalancer.server.port=80` is omitted, Traefik cannot determine the forwarding target in multi-port scenarios, resulting in forwarding to the wrong port and returning a `502 Bad Gateway`.

### 4.3 Image or Large File Upload Failure (HTTP 413 Payload Too Large)

Default upload limits are constrained by both PHP and Nginx. If uploading tens of MBs of PDF or video attachments:

1. Edit `/opt/bookstack/app/php/php-local.ini` (create if non-existent):

   ```ini
   upload_max_filesize = 100M
   post_max_size = 100M
   memory_limit = 512M
   ```

2. Edit `/opt/bookstack/app/nginx/site-confs/default.conf`, add inside the `server { ... }` block:

   ```nginx
   client_max_body_size 100M;
   ```

3. Restart container: `docker compose restart bookstack`.

## 5. Backup and Disaster Recovery

BookStack data integrity is maintained jointly by "database SQL" and "uploaded file directory", both of which must be backed up synchronously.

### 5.1 Full Backup Script

```bash
#!/bin/bash
BACKUP_DIR="/opt/backups/bookstack"
DATE=$(date +%F_%H%M%S)
mkdir -p $BACKUP_DIR

# 1. Export MariaDB database dump
docker compose exec -T bookstack_db mysqldump -u bookstack -pyour_db_secret_pass bookstackapp > $BACKUP_DIR/db_$DATE.sql

# 2. Archive uploaded attachments, images, and config files
tar -czvf $BACKUP_DIR/app_data_$DATE.tar.gz -C /opt/bookstack/app .

echo "Backup completed: $DATE"
```

### 5.2 Disaster Recovery Steps

1. Start fresh MariaDB and BookStack containers.

2. Restore file system: extract `app_data_*.tar.gz` overwriting `/opt/bookstack/app/` and fix permissions (`chown -R 1000:1000`).

3. Restore database:

   ```bash
   docker compose exec -i bookstack_db mysql -u bookstack -pyour_db_secret_pass bookstackapp < /opt/backups/bookstack/db_*.sql
   ```

4. Clear Laravel cache and restart:

   ```bash
   docker compose exec -it bookstack php /app/www/artisan cache:clear
   docker compose restart bookstack
   ```

> [!info] Updated 2026-11-27
> This document has been moved to `Archive/` for historical reference. Please note the following updates when applying in practice:
> 1. Docker Compose v2 recommends naming configuration files `compose.yaml` (`docker-compose.yml` remains compatible).
> 2. `lscr.io/linuxserver/mariadb:latest` (MariaDB 11+) marks `mysqldump` and `mysql` commands as deprecated aliases; it is recommended to use `mariadb-dump` and `mariadb` instead.
> 3. It is recommended to wrap `$BACKUP_DIR` and `$DATE` variables in double quotes in the backup script (`"$BACKUP_DIR"`, `"$DATE"`); when performing restore redirection (`<`), specify a single explicit `.sql` file path. Using wildcards like `db_*.sql` when multiple backups exist in the directory will cause a shell error (ambiguous redirect).
