## Approach

### `docker-compose.yml` Content

```yaml
version: '2'
services:
  mariadb:
    image: docker.io/bitnami/mariadb:10.3
    environment:
      - ALLOW_EMPTY_PASSWORD=yes
      - MARIADB_USER=bn_phpbb
      - MARIADB_DATABASE=bitnami_phpbb
    volumes:
      - /var/lib/docker/volumes/phpbb/mariadb:/bitnami/mariadb
  phpbb:
    image: docker.io/bitnami/phpbb:3
    ports:
      - 192.168.131.2:8082:8080
    environment:
      - PHPBB_DATABASE_HOST=mariadb
      - PHPBB_DATABASE_PORT_NUMBER=3306
      - PHPBB_DATABASE_USER=bn_phpbb
      - PHPBB_DATABASE_NAME=bitnami_phpbb
      - ALLOW_EMPTY_PASSWORD=yes
    volumes:
      - /var/lib/docker/volumes/phpbb/phpbb:/bitnami/phpbb
    depends_on:
      - mariadb
```

> [!info] Updated 2026-11-27
> The historical configuration above contains several outdated or discouraged practices, kept solely for archival reference:
> 1. The top-level `version: '2'` attribute is deprecated in modern Docker Compose v2 (`docker compose`); omit `version` and start directly with `services:`.
> 2. `bitnami/mariadb:10.3` has reached EOL and is unmaintained, and older free Bitnami images have since migrated to `bitnamilegacy` with revised maintenance policies; in practice, use official `mariadb:11` or another long-term supported image, and never set `ALLOW_EMPTY_PASSWORD=yes`.
> 3. Mounting bind mounts directly to `/var/lib/docker/volumes/...` (which is the internal managed named volumes directory of Docker Engine) is discouraged; mount to independent host paths such as `/opt/phpbb/...` instead.

To be honest, I was already running another MariaDB at the time, and theoretically they could have been integrated, but for simplicity I just ran an additional separate MariaDB container. If using this approach, make sure container names and ports do not conflict.

However, this Compose file does not expose database ports externally by default, so network isolation security for the database is maintained even when run independently.

## Notes

Personally, I am not very fond of Bitnami image permission conventions: after the container starts, you usually have to adjust the permissions of the `/var/lib/docker/volumes/phpbb` directory.

Since the image runs as `UID=1001` by default, rather than using `chown 1001`, <span style="color:#e06c75"><del>or directly using `chmod 777`</del></span> *(Updated 2026-11-27: In practice, never use `chmod 777` as it poses severe security risks; use `chown -R 1001:1001` to precisely assign container UID permissions instead)*, otherwise the service will fail to start properly due to lack of write permissions.

## Reason for Deprecation

- Not actually in use; nowadays instant messaging (IM) apps are so advanced that family and friends rarely bother setting up traditional forums for daily communication.
