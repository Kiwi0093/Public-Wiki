> [!info] Updated 2026-11-27
> This is an archived record from the early Hexo + Isso era. Below are modern environment comparison notes:
> 1. Modern Docker Compose v2 recommends using the `compose.yaml` filename and running with the `docker compose` command.
> 2. `isso.conf` is in INI format and will not expand `$(...)` shell variables. During actual deployment, you must directly replace them with the real database filename and Blog URL; it is also recommended to explicitly specify `traefik.http.services.isso.loadbalancer.server.port=8080`.
> 3. The official Isso website and documentation have migrated to `https://isso-comments.org/`, and this site has migrated from Hexo to Docusaurus and deprecated Isso.

# Method

## docker-compose.yml Contents

*Updated on 2022/7/26*

```bash
services:
  isso:
    image: ghcr.io/isso-comments/isso:latest
    container_name: isso
    environment:
      - PUID=1000
    volumes:
      - /var/lib/docker/volumes/isso/config:/config
      - /var/lib/docker/volumes/isso/data:/db
    restart: unless-stopped
    networks:
      - traefik
    labels:
      traefik.enable: true
      traefik.http.routers.isso.rule: Host(`$domain_you_like`)
      traefik.http.routers.isso.tls: true
      traefik.http.routers.isso.tls.certresolver: myresolver

networks:
  traefik:
    external: true
    name: web-service
```

Basically, this setup requires `touch`ing an `isso.conf` file beforehand, and making sure the permissions allow the defined `PUID` to read it.

## isso.conf Contents

```bash
[general]
dbpath = /db/$(databasename).db        # This filename can be defined by yourself
host = https://$(your_Blog_domain)        # Remember to set your Blog URL here
[server]
listen = http://0.0.0.0:8080            # The port set here is the internal container port defined in docker-compose.yml
[guard]
enabled = true
ratelimit = 2
direct-reply = 3
reply-to-self = false
require-author = true
require-email = true
[moderation]                            # Whether comments need moderation before posting; change to true if needed
enabled = false
purge-after = 30d
[admin]                                     # Admin configuration
enabled = false
password = strong-password
```

## NexT Configuration

Add the following to `_config.next.yml`:

```bash
# ---------------------------------------------------------------
# Comments Settings
# See: https://theme-next.js.org/docs/third-party-services/comments
# ---------------------------------------------------------------

# Multiple Comment System Support
comments:
  # Available values: tabs | buttons
  style: tabs
  # Choose a comment system to be displayed by default.
  # Available values: disqus | disqusjs | changyan | livere | gitalk | utterances
  active: isso 
  # Setting `true` means remembering the comment system selected by the visitor.
  storage: true
  # Lazyload all comment systems.
  lazyload: false
  # Modify texts or order for any naves, here are some examples.
  nav:
    #disqus:
    #  text: Load Disqus
    #  order: -1
    #gitalk:
    #  order: -2
    # .....
    # .....
# Isso
# For more information: https://posativ.org/isso/
isso: https://$domain_you_like/
```

Then just run `hexo d -g`.

# Notes

* When running `https` with Traefik, use `https://$domain_you_like/` for `data-isso` to replace `//$domain_you_like/` in the tutorial.
* Comments cannot be seen locally when running `hexo s`... You must push to GitHub with `hexo d -g` to see them...
