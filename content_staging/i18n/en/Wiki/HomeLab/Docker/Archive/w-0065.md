# MS SQL-Server docker-compose.yml

```yml
# Docker-compose.yml
version: '3'
services:
  mssql:
    image:  mcr.microsoft.com/mssql/server:2019-latest
    container_name: sql-server
    environment:
      - PUID=1000
      - ACCEPT_EULA=Y
#     - MSSQL_PID=<your_product_id | edition_name> (default: Developer)"
      - SA_PASSWORD=<your@Passw0rd>
    ports:
      - 1433:1433
    volumes:
      - /var/lib/docker/volumes/mssql:/var/lib/mssqlql
    restart: always
```

> [!info] Updated 2026-11-27
> This archived configuration file contains several syntax errors and outdated parameters, preserved for historical comparison:
> - **YAML Syntax Error**: The `mssql` service name is missing a trailing colon (should be `mssql:`).
> - **Mount Path Error**: The data directory for Microsoft's official SQL Server container is `/var/opt/mssql` (incorrectly typed as `/var/lib/mssqlql` in the original), and using Docker named volumes is recommended over hardcoding `/var/lib/docker/volumes/...`.
> - **Compose V2 Standard**: Declaring top-level `version: '3'` is no longer required when using modern `docker compose`.
> - **Environment Variables and Version**: `2019-latest` is outdated; starting from SQL Server 2022, `MSSQL_SA_PASSWORD` replaces `SA_PASSWORD`.

### Basic Notes

* <span style="color:#e06c75"><del>PUID=1000 is specified because SQL Server cannot run as root and requires a separate user, otherwise issues easily arise. However, I noticed many tutorials omit this, so if it runs fine without it, this line can be skipped.</del></span> *(Updated 2026-11-27: Microsoft's official `mcr.microsoft.com/mssql/server` image does not support the `PUID` environment variable (which is a LinuxServer.io convention); if non-root execution is required, use `user:` in Compose along with directory permission settings.)*
* `ACCEPT_EULA=Y`: This is actually stating the obvious since it cannot run without agreement, but since this image is made by Microsoft, there's no way around it.
* `MSSQL_PID`: This is actually the most important parameter because it determines the edition of SQL Server you are running. For enterprise use, put your purchased license key (or edition name) here.
* `SA_PASSWORD`: As the name implies, equivalent to the MySQL root password definition.

# Conclusion
