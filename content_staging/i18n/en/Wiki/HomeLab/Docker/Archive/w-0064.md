## Certbot

### Installation and Certificate Signing

Refer to <span style="color:#e06c75"><del>https://certbot.eff.org/docs/install.html#running-with-docker</del></span> *(Updated 2026-11-27: Official documentation has migrated to [eff-certbot.readthedocs.io](https://eff-certbot.readthedocs.io/en/latest/install.html#running-with-docker))*

```bash
sudo docker run -it --rm --name certbot -v "/etc/letsencrypt:/etc/letsencrypt" -v "/var/lib/letsencrypt:/var/lib/letsencrypt" \
            certbot/certbot certonly
```

If you want different domains for a specific IP, you can append the parameter `-p your_ip:80:80 -p your_ip:443:443` to map them accordingly.

### Automatic Renewal Setup

Add the following to crontab:

```bash
0 0 * * * docker run --rm -v /etc/letsencrypt:/etc/letsencrypt -ti certbot/certbot renew
```

That's it.

> [!info] Updated 2026-11-27
> 1. `crontab` runs in a non-interactive environment; the `-ti` flags (especially `-t` allocating a pseudo-TTY) in the original scheduled command will cause Docker to throw an error `the input device is not a TTY` and fail. The scheduled command should remove `-ti`.
> 2. If using standalone mode for HTTP-01 validation, you must append `-p 80:80` (or `--network host`) during initial signing so the container can receive Let's Encrypt validation requests.
> 3. Modern container architectures generally use reverse proxies with built-in ACME automatic signing and renewal mechanisms (such as Traefik, Caddy, or Nginx Proxy Manager).

## Reason for Deprecation

No longer needed... Nowadays, reverse proxies with automatic SSL issuance like Traefik or Nginx Proxy Manager are used, so such a pure tool is no longer required.
