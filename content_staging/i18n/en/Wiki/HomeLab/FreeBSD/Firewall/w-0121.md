# FreeBSD PF and dnctl (Dummynet) Traffic Shaping Guide

> <img src='https://img.shields.io/badge/Status-WIP-yellow?style=for-the-badge&labelWidth=100' height='38' />

![FreeBSD](https://img.shields.io/badge/FreeBSD-Supported-green?style=plastic&logo=freebsd)

:::tip
Even if your NIC does not support ALTQ, FreeBSD can still perform traffic shaping by pairing `pf` with `dnctl` (Dummynet).
:::

> [!info] Updated 2026-11-27
> Native `dnctl` / `dnpipe` integration in `pf` requires **FreeBSD 14.0 or later** (on FreeBSD 13 and earlier, use [IPFW + Dummynet](./w-0046) instead). If the host also acts as a NAT gateway, place `nat on $EXT_IF ...` translation rules before filter rules (`block all` / `pass ...`) in `/etc/pf.conf`.

## 1. Loading Kernel Modules

Although `pf` acts as the firewall, rate limiting is still driven by `dummynet`, so both kernel modules must be loaded.

### Manual Loading

```bash
kldload pf
kldload dummynet
```

### Auto-Load on Boot

Edit `/boot/loader.conf` to ensure both modules load automatically after a reboot:

```bash
# /boot/loader.conf
pf_load="YES"
dummynet_load="YES"
```

## 2. System Configuration (`/etc/rc.conf`)

Before starting the services, enable `pf` and `dnctl` in `/etc/rc.conf`:

```bash
# /etc/rc.conf
pf_enable="YES"
pf_rules="/etc/pf.conf"
dnctl_enable="YES"    # Enable the dummynet controller
```

## 3. Defining Traffic Pipes (`/etc/dnctl.conf`)

This uses the same syntax as `ipfw pipe` to define bandwidth limits for each pipe:

```bash
# /etc/dnctl.conf
# Flush old rules
flush

# Define pipe bandwidths
pipe 1 config bw 500KBytes/s    # VPN
pipe 2 config bw 100KBytes/s    # P2P
pipe 3 config bw 500KBytes/s    # RDP
pipe 4 config bw 350KBytes/s    # Server
pipe 5 config bw 30KBytes/s     # Guest
```

## 4. Firewall Filtering and Redirection (`/etc/pf.conf`)

In PF, use `dnpipe` to send matching packets into the `dnctl` pipes defined above:

```bash
# --- Interfaces & Macros ---
EXT_IF = "ext0"
INT_IF = "int0"

DMZ_NET = "192.168.0.0/24"
GUEST_NET = "192.168.2.0/24"
VPN_NET = "10.8.0.0/24"
P2P1_IP = "192.168.0.100"

# --- Rules ---

# 1. Skip loopback
set skip on lo0

# 2. Default deny
block all

# 3. Traffic shaping (route to dnpipe)

# VPN traffic
pass out quick on $EXT_IF to $VPN_NET dnpipe 1

# RDP traffic (P2P1 host)
pass in quick on $INT_IF proto tcp from $P2P1_IP to any port 3389 dnpipe 3

# P2P traffic
pass in quick on $INT_IF from $P2P1_IP to any dnpipe 2

# Guest network shaping
pass in quick on $INT_IF from $GUEST_NET to any dnpipe 5
pass out quick on $INT_IF from any to $GUEST_NET dnpipe 5

# DMZ egress traffic
pass out quick on $EXT_IF from $DMZ_NET to any dnpipe 4

# 4. Baseline outbound allow
pass out quick on $EXT_IF proto { tcp, udp, icmp } all keep state
```

## 5. Notes & Useful Commands (2026/04)

- **Why this setup?**: PF rule management is clean and expressive (such as `set skip on lo0`), while Dummynet (`dnctl`) offers the broadest compatibility for bandwidth shaping on FreeBSD.
- **Status inspection commands**:
  - Check firewall rules: `pfctl -sr`
  - Check shaping pipe status: `dnctl pipe show`
- **Latency optimization tip**: If latency spikes under throttling, append `codel` or `fq_codel` to your `pipe` rules in `/etc/dnctl.conf`, for example:

  ```bash
  pipe 2 config bw 100KBytes/s fq_codel
  ```
