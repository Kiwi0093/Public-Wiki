## Dummynet

### Dynamic Loading

Since most environments now use a Generic Kernel (saving the effort of recompiling the kernel yourself), you can directly use `kldload` to dynamically load `dummynet.ko`.

#### Manual Loading

```bash
kldload dummynet
```

To confirm whether the module has been loaded, run:

```bash
kldstat
```

This command will list all dynamically loaded `.ko` modules; please verify that the output includes `dummynet.ko`.

#### Automatic Loading at Boot

To make the settings persist after rebooting, modify `/boot/loader.conf`:

```bash
# /boot/loader.conf
dummynet_load="YES"
```

It will then be automatically loaded upon every subsequent reboot.

## ipfw System Configuration

Define in `/etc/rc.conf` how the system enables the firewall and loads rule scripts upon startup (ensure that `/etc/ipfw.conf` has executable permissions or is a valid Shell script):

```bash
# /etc/rc.conf
firewall_enable="YES"
firewall_script="/etc/ipfw.conf"  # Path to configuration file
firewall_type="unknown"           # Tells the system we are running our own script
natd_enable="NO"                  # Do not start natd
```

## Traffic Limitation Practical Example

`/etc/ipfw.conf`

This is the core part. The recommended approach is to maintain interface, subnet, and bandwidth variables separately from actual rules:

```bash
#!/bin/sh
# Define ipfw command path
IPFW="/sbin/ipfw"

# --- Define Interfaces ---
EXT_IF="ext0"
INT_IF="int0"

# --- Define Networks and IPs ---
DMZ_NET="192.168.0.0/24"
GUEST_NET="192.168.2.0/24"
VPN_NET="10.8.0.0/24"       # Correction: Added previously missing definition
P2P1_IP="192.168.0.100"     # Correction: Added previously missing definition
P2P2_IP="192.168.0.101"

# --- Define Bandwidth Types and Speeds ---
P2P_UP="100KBytes/s"
VPN_UP="500KBytes/s"
RDP_P2P="500KBytes/s"
SERV_UP="350KBytes/s"
GUEST_BAND="30KBytes/s"

# --- Rules Begin ---

# 1. Flush all existing rules and pipes
$IPFW -f flush
$IPFW -f pipe flush

# 2. Allow local loopback traffic (Important: Without this rule, system services will cut themselves off)
$IPFW add 10 allow ip from any to any via lo0

# 3. Use ipfw pipe to define each traffic limit and number
$IPFW pipe 1 config bw $VPN_UP
$IPFW pipe 2 config bw $P2P_UP
$IPFW pipe 3 config bw $RDP_P2P
$IPFW pipe 4 config bw $SERV_UP
$IPFW pipe 5 config bw $GUEST_BAND

# 4. Use pipes to define traffic rules (smaller numbers have higher priority)

# VPN traffic limitation
$IPFW add 20 pipe 1 ip from any to $VPN_NET

# RDP specific traffic (Correction: Added port 3389 to ensure precision)
$IPFW add 25 pipe 3 tcp from $P2P1_IP to any 3389 in recv $INT_IF

# P2P traffic limitation
$IPFW add 30 pipe 2 ip from $P2P1_IP to any in recv $INT_IF
$IPFW add 40 pipe 2 ip from $P2P2_IP to any in recv $INT_IF

# Guest network throttling (limit both incoming and outgoing)
$IPFW add 110 pipe 5 ip from $GUEST_NET to any
$IPFW add 120 pipe 5 ip from any to $GUEST_NET

# DMZ egress traffic limitation (Correction: Used variable $EXT_IF to replace hardcoded value in source)
$IPFW add 210 pipe 4 ip from $DMZ_NET to any via $EXT_IF

# 5. Allow all remaining traffic at the end
$IPFW add 65534 allow ip from any to any
```

## Conclusion

Nowadays, most firewalls on FreeBSD have switched to `PF` (Packet Filter), and `IPFW` is less commonly used purely for security filtering; however, `PF`'s bandwidth throttling configuration is not as intuitive or simple as `IPFW` + `dummynet`. Therefore, in practice, a dual-layer firewall division of labor is very suitable: **`PF` handles security filtering and NAT, while `IPFW` specializes in Traffic Shaping**.
