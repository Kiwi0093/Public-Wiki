## `login.conf` and `pw` Command Set

FreeBSD's mechanism differs from Linux; it controls lifecycle through Login Classes and account management commands.

1. **Setting Expiration via Login Classes (`/etc/login.conf`)**
   Edit the `/etc/login.conf` file, adding expiration parameters within the target group section (usually `default:\`):

   ```bash
   default:\
       :passwdtime=90d:\
       :passwordlength=12:\
       :tc=std-default:
   ```

   > [!info] Updated 2026-11-27
   > The aforementioned `login.conf(5)` field names were incorrect: the correct FreeBSD parameters for password expiration and minimum length are `passwordtime` (not `passwdtime`) and `minpasswordlen` (not `passwordlength`), and the standard `/etc/login.conf` `default:` section does not have a built-in `tc=std-default:`. Corrected example:
   > ```text
   > default:\
   >     :passwordtime=90d:\
   >     :minpasswordlen=12:
   > ```

   - <span style="color:#e06c75"><del>`:passwdtime=90d:`</del></span> *(Updated 2026-11-27: The correct parameter name is `:passwordtime=90d:`)* indicates that user passwords under this class expire after 90 days.

   - After modification, you must recompile the database via command for it to take effect:

     ```bash
     sudo cap_mkdb /etc/login.conf
     ```

2. **Modifying Single Account Restrictions via the `pw` Command**
   If you do not want to apply it globally by class, you can operate directly on specific users:

   - **Set Password Expiration Date:**

     ```bash
     sudo pw usermod john -p 2026-12-31
     ```

     > [!info] Updated 2026-11-27
     > FreeBSD `pw(8)`'s `-p` parameter does not accept the `YYYY-MM-DD` format, supporting only `dd-mmm-yyyy` (such as `31-Dec-2026`), relative time offsets (such as `+90d`), or UNIX Epoch seconds. Corrected examples: `sudo pw usermod john -p 31-Dec-2026` or `sudo pw usermod john -p +90d`.

   - **Lock or Unlock Account:**

     ```bash
     sudo pw lock john
     sudo pw unlock john
     ```

## Password Complexity Settings (`pam_passwdqc`)

FreeBSD adopts the Pluggable Authentication Modules (PAM) mechanism, limiting password strength through the `pam_passwdqc` module.

- Edit `/etc/pam.d/passwd` file, adjusting or adding checking rules:

  ```bash
  password required pam_passwdqc.so min=disabled,disabled,12,8,6
  ```

- The five numerical values of the parameter respectively represent: <span style="color:#e06c75"><del>minimum length restrictions when the password is a passphrase, long word, short word, general mixed string, and extremely short string</del></span> *(Updated 2026-11-27: According to the `pam_passwdqc(8)` specification, `min=N0,N1,N2,N3,N4` sequentially correspond to minimum length restrictions for "single character class", "two character classes", "passphrase", "three character classes", and "four character classes"; taking `disabled,disabled,12,8,6` as an example, it means disabling 1-2 character class passwords, requiring passphrases to be at least 12 characters, 3-character-class passwords at least 8 characters, and 4-character-class passwords at least 6 characters)*, thereby filtering out overly simple weak passwords.

## Maintenance Tips and Emergency Countermeasures

- **Workaround When Stuck at SSH Login Due to Expired Password:**
  If you have `root` privilege on the machine or another account with `sudo` capability (or via cloud host serial console / Recovery mode), directly execute the following command to lift the restriction, allowing you to log in again and reset your password:

  ```bash
  sudo chage -M -1 <Username>
  ```

  > [!info] Updated 2026-11-27
  > `chage` is a Linux (`shadow-utils`) specific command; FreeBSD systems do not have this tool. To clear or remove account password expiration restrictions on FreeBSD, use `sudo pw usermod <Username> -p 0` (or `chpass -p 0 <Username>`) instead.
