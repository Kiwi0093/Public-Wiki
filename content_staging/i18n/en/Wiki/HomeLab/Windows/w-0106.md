# Duo Stream (Moonlight + Sunshine) Multiplayer Gaming Streaming Solution

This is a multi-user independent concurrent game streaming architecture based on Windows 11 and hardware virtualization technology. Traditional streaming solutions (such as standard Sunshine) can only capture the current single foreground desktop and cannot support simultaneous multi-user operation. This solution leverages **Duo** paired with virtual graphics cards and virtual gamepad drivers to achieve simultaneous output of 2 completely independent 1080p 60fps game streams on a single physical host—without requiring a virtual machine (VM)—with zero input focus conflicts.

## 2. Software Requirements

- **Main Programs**:

    - **[Duo (Multi-user Sunshine Fork)](https://github.com/DuoStream/Duo)** (<span style="color:#e06c75"><del>https://www.google.com/search?q=https://github.com/giggio/duo</del></span> *(Updated 2026-11-27: The original link was a search redirect pointing to the wrong repository; corrected to the official DuoStream/Duo repository)*): Core scheduling manager specifically designed to assign multiple Windows accounts, virtual screens, and virtual input devices.

    - **Sunshine**: Open-source low-latency game streaming host.

    - **Moonlight**: Streaming client receiver (supports Windows / macOS / Linux / Android / iOS / tvOS).

- **Underlying Dependent Drivers**:

    - **IddSampleDriver (Virtual Display Driver)**: Windows virtual graphics card driver that generates extended virtual screens without requiring a physical HDMI dummy plug.

    - **ViGEmBus (Virtual Gamepad Emulation Bus)**: Virtual gamepad driver responsible for isolating gamepad signals from each client and injecting them into the designated Session.

- **Peripheral Management (Optional)**:

    - **EmuDeck for Windows**: Retro emulator integration suite.

    - **RomM**: Centralized game ROM / BIOS management platform (mounted via NFS/SMB provided by a NAS or backend server).

## 3. Setup Guide

### Step A: Basic Environment and Driver Configuration

1. **Install Clean Drivers**: Install the latest NVIDIA GeForce Game Ready or Studio drivers.

2. **Install ViGEmBus**: Download and install the latest ViGEmBus driver to provide virtual gamepad support.

3. **Configure IddSampleDriver (Virtual Screen)**:

    - After installing the virtual display driver, go to system Display settings to confirm a new virtual screen (Display) has been added.

    - Set the virtual screen resolution to **1920x1080** and refresh rate to **60Hz** (can be set to 120Hz if streaming to high-refresh devices).

    - Set display mode to "Extend these displays".

### Step B: Create Isolated User Accounts

To prevent multi-user connections from fighting over keyboard, mouse, and active window focus, independent user environments must be established in Windows:

1. Create two local standard user accounts (e.g., `Player1` and `Player2`).

2. Configure auto-login or ensure both accounts possess background Session execution permissions.

### Step C: Duo and Sunshine Configuration

1. **Install Duo**:

    - Run the Duo setup wizard; it will automatically detect and bind the Sunshine executable and IddSampleDriver.

    - Create two "Seats" in the Duo configuration panel:

        - **Seat 1**: Bind user `Player1`, associate virtual screen `Display 1`, assign virtual gamepad 1.

        - **Seat 2**: Bind user `Player2`, associate virtual screen `Display 2`, assign virtual gamepad 2.

2. **Sunshine Encoder Tuning**:

    - Open Sunshine WebUI (`https://localhost:47990`).

    - **Configuration ➔ Audio/Video**:

        - **Encoder**: Force-specify `NVENC`.

        - **NVENC Preset**: Set to `P1` or `P2` (Performance, minimizing encoding latency).

        - **Capture Method**: Select `Desktop Duplication API (DXGI)`.

3. **Moonlight Pairing**:

    - Client A (e.g., Living room TV Shield TV) opens Moonlight, pairs with Duo's Seat 1 port.

    - Client B (e.g., Laptop/room device) opens Moonlight, pairs with Duo's Seat 2 port.

## 4. Tips & Optimization

- **Shutdown Prevention**:

    - When the living room Moonlight client clicks "Quit / Turn Off PC" in the menu, it may trigger a physical Windows shutdown by default.

    - **Solution**: Press `Win + R`, type `gpedit.msc` (Local Group Editor) ➔ Navigate to `Computer Configuration ➔ Windows Settings ➔ Security Settings ➔ Local Policies ➔ User Rights Assignment` ➔ Edit "Shut down the system", remove the standard Users group, and **leave only Administrators** to prevent remote players from accidentally shutting down the system.

- **Wake-on-LAN Troubleshooting Optimization**:

    - Windows 11 enables "Fast Startup" by default, which cuts off network card standby power, preventing it from receiving Magic Packages.

    - Go to Power Options and **turn off "Turn on fast startup"**; in Device Manager network card properties, set "Shutdown Wake-On-Lan" to **Enabled** and "Energy Efficient Ethernet" to **Disabled**.

- **Local Save Data Isolation, Centralized ROM / BIOS Sharing**:

    - If paired with EmuDeck or emulators, game ROMs and BIOS should be centrally mounted from a NAS via SMB network shares; however, **game saves (Saves / States) must remain local under each user's `%APPDATA%` or respective Windows user directory**. This prevents file lock issues or save data overwriting when Duo runs the same game concurrently.

- **Laptop Battery Care**:

    - If using a gaming laptop as the Duo host, keeping it plugged in long-term at high temperatures will easily cause lithium batteries to swell. Be sure to use manufacturer control software (such as MSI Center / Dragon Center) to lock the charge limit to **50%–60%**, or physically disconnect the internal battery and run solely on AC power.

- **Same-Subnet L2 Direct Routing to Relieve Gateway Burden**:

    - Dual 1080p 60fps streams can reach instantaneous bandwidths of 80–100 Mbps. Ensure the streaming host and main clients (such as Shield TV) are plugged into the same network switch (same VLAN/subnet), allowing packets to route entirely via hardware line-speed switching and avoiding unnecessary routing through software routers which causes latency and jitter.
