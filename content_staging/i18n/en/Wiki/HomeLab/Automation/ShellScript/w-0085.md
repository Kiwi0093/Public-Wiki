## 1. Variable Definition and Assignment Conventions

- **Basic Definition**:

    ```bash
    VAR_NAME="value"      # Absolutely no spaces are allowed on either side of the equals sign
    echo "${VAR_NAME}"    # It is recommended to always wrap variables in curly braces ${} to prevent boundary confusion
    ```

- **Command Substitution**:

    ```bash
    CURRENT_USER=$(whoami)
    BACKUP_DATE=$(date +%F)
    ```

- **Variable Scope**:
    - Declared normally as local variables (restricted to the current process).
    - Declared as environment variables using `export VAR_NAME` so they can be inherited by forked child processes.

## 2. Special Automatic Variables and Positional Parameters Quick Reference

| **Variable Name** | **Meaning Description** | **Behavior Analysis & Engineer Must-Know Details** | **Practical Example** |
| --------------- | ------------------------------ | ------------------------------------------------------ | --------------------------------------------------------- |
| **`$?`** | Exit code of the last command | `0` means execution succeeded; non-zero (e.g., `1`, `2`, `127`, etc.) means execution failed or encountered an anomaly | `systemctl restart nginx`<br />`[ $? -eq 0 ] && echo "OK"` |
| **`$$`** | Process ID (PID) of the current shell process | Commonly used in scripts to create unique temporary file names and prevent concurrency conflicts | `TMP_FILE="/tmp/run_$$.tmp"` |
| **`$!`** | PID of the last background program execution | Captures the process ID just sent to the background with `&`, convenient for subsequent monitoring with `wait` | `python3 job.py &`<br />`JOB_PID=$!` |
| **`$-`** | Flags enabled in the current shell | Displays current shell execution options (such as interactive mode flags like `h`, `B`, `i`, etc.) | `echo "$-"` |
| **`$0`** | File name or path of the current shell script | The command path entered upon execution (such as `./deploy.sh` or `/opt/deploy.sh`) | `SCRIPT_DIR=$(dirname "$0")` |
| **`$1` ~ `$9`** | Positional Arguments | Sequentially receives the first to ninth external parameters passed in (the tenth onward requires `${10}`) | `./backup.sh /data /mnt/nas`<br />`# $1=/data, $2=/mnt/nas` |
| **`$#`** | Total number of parameters passed to the script | Commonly used at the beginning of scripts to validate whether the parameter count is sufficient | `[ $# -lt 2 ] && exit 1` |
| **`$*`** | Collection of all passed parameters (merged string) | When wrapped in double quotes `"$*"`, all parameters are concatenated into a single string using `$IFS` (defaulting to space): `"$1 $2 $3"` | `echo "All args: $*"` |
| **`$@`** | Collection of all passed parameters (independent array) | **Most commonly used in loops and forwarding**. Double quotes `"$@"` keep each parameter as an independent string: `"$1" "$2" "$3"` | `for arg in "$@"; do ... done` |

## 3. Common Bash Built-in Environment Variables

|**Variable Name**|**Description**|**Typical Use Case**|
|---|---|---|
|**`$BASH_ENV`**|Path of the configuration file automatically loaded when a non-interactive shell starts|Automated CI/CD scheduling environment injection|
|**`$CDPATH`**|Colon-separated search directory list when using the `cd` command|Quickly switching deep directories|
|**`$LINENO`**|Code line number currently being executed|Log tracking and debugging: `echo "Error at line $LINENO"`|
|**`$LINES` / `$COLUMNS`**|Height (number of rows) and width (number of columns) of the current terminal screen|Terminal UI / progress bar width adaptive calculation|
|**`$PPID`**|Parent Process ID of the current process|Checking who called this script|
|**`$RANDOM`**|Randomly generates an integer between 0 and 32767|Generating random passwords or random ports: `PORT=$((10000 + RANDOM % 10000))`|
|**`$SECONDS`**|Cumulative seconds elapsed since script startup|Calculating script elapsed time: `echo "Elapsed time: ${SECONDS}s"`|
|**`$SHELL`**|Absolute path of the user's default preferred shell|Viewing the default shell (usually `/bin/bash`)|
|**`$TMOUT`**|Inactivity auto-logout time (unit: seconds)|Security hardening: automatically disconnect terminal connection after specified idle seconds|

## 4. Handling Empty and Unset Variables (Parameter Expansion)

In shell scripts, directly using unassigned variables can easily lead to unexpected behavior (or even disasters like accidental root directory deletion such as `rm -rf /${DIR}`). Using Bash's parameter expansion syntax allows you to safely and gracefully set default values or defensive exits:

| **Syntax Format** | **Condition Judgment** | **Handling Behavior** | **Practical Example** |
| ------------------ | ---------------- | ---------------------------------------- | ------------------------------------------------ |
| **`${var:-word}`** | `var` is empty or unset | **Temporarily uses** `word` as the return value, **without changing** the content of `var` itself | `PORT=${CUSTOM_PORT:-8080}`<br />_(Defaults to 8080 when unspecified)_ |
| **`${var:=word}`** | `var` is empty or unset | **Assigns `word` to `var`**, then uses the new value | `${DATABASE_NAME:=homelab}`<br />_(Automatically defines and stores in variable when unset)_ |
| **`${var:?word}`** | `var` is empty or unset | Prints the `word` error message to stderr and **immediately forcefully halts and terminates the program** | `DIR=${1:?"Please provide the target directory path!"}`<br />_(Aborts execution immediately if parameter is missing)_ |
| **`${var:+word}`** | `var` **is set and non-empty** | Temporarily replaces it with `word`; returns an empty value if empty (used for existence detection) | `[ -n "${DEBUG:+x}" ] && echo "Debug on"` |

> **Tip**: If the colon is omitted (e.g., `${var-word}`), it triggers only when `var` is **completely unset**; adding the colon (``${var:-word}``) covers both cases where it is **unset** or **set but has an empty string value `""`**. Using the colon syntax is recommended for all daily scripts.

## 5. Input Variables: Advanced `read` Command Usage

The `read` command is used to pause in the terminal and read keyboard input from the user:

```bash
# Basic usage
echo -n "Please enter project name: "
read PROJECT_NAME
echo "You entered: ${PROJECT_NAME}"

# Recommended modern single-line usage (combining -p prompt, -t timeout, -s password hiding)
# 1. With prompt string (-p)
read -p "Please enter database name: " DB_NAME

# 2. Hidden password input (-s, prevents printing password to screen)
read -sp "Please enter connection password: " DB_PASSWORD
echo "" # Manually add a newline after password input

# 3. Automatic timeout skip (-t, e.g., waiting 10 seconds)
read -t 10 -p "Confirm to continue execution? (y/N): " CONFIRM
CONFIRM=${CONFIRM:-N} # Defaults to N if no input before timeout
```

## 6. Command Substitution and Safe Conditional Judgment Practices

After storing external command output into a variable, make sure to wrap comparisons defensively:

```bash
#!/usr/bin/env bash

# 1. Capture current executor identity
CURRENT_USER=$(whoami)

# 2. Safe conditional judgment (recommended [[ ]] structure, best compatibility and features)
if [[ "${CURRENT_USER}" == "root" ]]; then
    echo "Success: Currently executing with root privileges"
else
    echo "Warning: Must execute this script with root privileges (current user is: ${CURRENT_USER})" >&2
    exit 1
fi

# 3. Check critical path variables (defensive programming to avoid undefined accidental deletion)
TARGET_DIR="${1:-}"

# Strict validation to avoid rm -rf /
if [[ -z "${TARGET_DIR}" ]]; then
    echo "Error: Cleanup directory not specified!" >&2
    exit 1
fi

echo "Cleaning up temporary folder: ${TARGET_DIR}..."
```
