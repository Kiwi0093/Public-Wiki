## 1. Core Concepts: Flow Control Jump Keywords

Inside any loop structure (`while`, `until`, `for`), the primary instructions for controlling execution flow are:

| **Keyword** | **Core Behavior** | **Typical Use Case** |
| --- | --- | --- |
| **`break`** | **Exits the entire loop**, immediately executing the line following the loop's `done` statement | User completes menu operations or target file has been found |
| **`continue`** | **Skips the current iteration**, skipping remaining code and returning directly to the loop condition check | Prompting user upon invalid input and retrying, or skipping temporary files |
| **`exit`** | **Terminates the entire script process immediately**, returning a specified exit status code to the parent process (default 0) | User actively chooses to exit or an unrecoverable fatal error occurs |

## 2. Standard While + Case Interactive Menu Architecture

For interactive menu scenarios, here is a standardized template featuring prompt strings (`read -r -p`) and `case` validation mechanisms:

```bash
#!/usr/bin/env bash

while true; do
    echo "=================================="
    echo "  HomeLab Operations Management Menu"
    echo "=================================="
    echo "  a) View Docker container status"
    echo "  b) Restart Nextcloud service"
    echo "  c) Run database backup"
    echo "  q) Exit menu"
    echo "=================================="
    
    # -r prevents backslash escaping, -p displays prompt text
    read -r -p "Please enter an option [a-c, q]: " CHOICE

    case "${CHOICE}" in
        a|A)
            echo "--> Listing running containers..."
            docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
            break  # Exit menu after execution
            ;;
        b|B)
            echo "--> Restarting Nextcloud..."
            docker compose -f /opt/nextcloud/docker-compose.yml restart
            echo "Restart complete."
            continue  # Return to the beginning of the menu
            ;;
        c|C)
            echo "--> Executing backup task..."
            /opt/scripts/backup.sh
            continue
            ;;
        q|Q)
            echo "Exiting program."
            exit 0  # Terminate script normally
            ;;
        *)
            echo "Error: Invalid option [${CHOICE}], please try again!" >&2
            sleep 1
            continue
            ;;
    esac
done

echo "Menu exited, proceeding with subsequent automation tasks..."
```

> **Syntax Details Reminder**:
> 
> - `case` supports multi-value matching: Using the pipe `|` allows capturing both uppercase and lowercase (e.g., `a|A)`).
> - Each conditional branch block must end with double semicolons `;;`, indicating the end of that branch.
> - `*)` acts as a wildcard, matching any other characters not previously matched, serving as a default fallback branch.

## 3. Three Classic Bash Loop Syntax Structures

Beyond building menus with `case`, the following three loops are most commonly used when processing data in daily scripts:

### 3.1 For Loop (Fixed List / Array / Range Iteration)

Suitable for scenarios with a clearly defined quantity of targets (such as batch inspecting multiple Docker Compose projects):

```bash
# 1. Iterate over a list
STACKS=("nextcloud" "bookstack" "gitea" "wireguard")

for stack in "${STACKS[@]}"; do
    echo "Checking stack: ${stack}..."
    docker compose -f "/opt/${stack}/docker-compose.yml" ps
done

# 2. Numeric sequence (C-language style)
for ((i=1; i<=5; i++)); do
    echo "Retry attempt ${i}..."
done
```

### 3.2 While Loop (Execute While Condition is True)

Frequently used for **polling service health** until a specific state is reached:

```bash
# Wait for MariaDB container to fully start (Health Check polling)
CONTAINER="gitea_db"

while ! docker inspect --format='{{.State.Health.Status}}' "${CONTAINER}" 2>/dev/null | grep -q "healthy"; do
    echo "Waiting for ${CONTAINER} database initialization (checking every 2 seconds)..."
    sleep 2
done

echo "${CONTAINER} is ready, starting main application!"
```

### 3.3 Reading Files Line by Line (While Read Mode)

When processing configuration files, host lists, or logs, **never use `for line in $(cat file)`** (which causes bugs due to space word-splitting). The standard writing practice is to use `while IFS= read -r line`:

```bash
# Safely read host IP list line by line and perform ping tests
HOSTS_FILE="/opt/network/hosts.txt"

if [[ -f "${HOSTS_FILE}" ]]; then
    while IFS= read -r host || [[ -n "${host}" ]]; do
        # Skip empty lines and comment lines starting with #
        [[ -z "${host}" || "${host}" =~ ^# ]] && continue
        
        if ping -c 1 -W 1 "${host}" >/dev/null 2>&1; then
            echo "[OK] ${host} is reachable"
        else
            echo "[FAIL] ${host} is unreachable" >&2
        fi
    done < "${HOSTS_FILE}"
fi
```

## 4. Advanced Tip: Built-in Select Menu Syntax

If you only need to quickly present a numbered menu for users to pick from, Bash natively provides an extremely concise `select` structure, which automatically renders numbers and eliminates tedious manual formatting code:

```bash
#!/usr/bin/env bash

PS3="Please select the service number to maintain: "  # Define prompt string

SERVICES=("Nextcloud" "BookStack" "Gitea" "Exit")

select srv in "${SERVICES[@]}"; do
    case "${srv}" in
        "Nextcloud")
            echo "Maintaining Nextcloud..."
            break
            ;;
        "BookStack")
            echo "Maintaining BookStack..."
            break
            ;;
        "Gitea")
            echo "Maintaining Gitea..."
            break
            ;;
        "Exit")
            echo "Program ended."
            exit 0
            ;;
        *)
            echo "Invalid input, please enter a number between 1 and 4."
            ;;
    esac
done
```
