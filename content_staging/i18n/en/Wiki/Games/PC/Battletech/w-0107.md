## Core Concepts

BattleTech's equipment and weapon system is entirely driven by JSON files. Every weapon, ammo bin, piece of equipment, and even projectiles themselves have independent JSON definition files. The core principles of modification lie in **ensuring ID uniqueness** and **correct logical relationships**.

## Modification and Application Workflow (SOP)

### 1. File Preparation and Editing

- **Essential Tools**: Use Notepad++ or other plain text editors to process JSON files, ensuring correct formatting without garbled characters.
- **Copy and Naming**: Directly copy factory files (e.g., `Weapon_Autocannon_UAC20.json`) to modify. **Filenames must never duplicate**, and it is recommended to add a custom suffix (e.g., `_VerK`).
- **ID Consistency**: The `"Id"` parameter inside the JSON file **must** exactly match the modified new filename, otherwise reading errors will occur when the game launches.

> [!info] Updated 2026-11-27
> If you copy and **create** a new custom filename (rather than directly overwriting original files), the vanilla BattleTech engine will not automatically scan unregistered new JSON files. In practice, you must pair it with **ModTek** (writing a `mod.json` manifest in a custom Mod folder) or register new entries in `VersionManifest.csv` for the game to correctly load the equipment.

### 2. Methods for Implementing into the Game

- **Store Generation Method (Conventional)**: Modify `"Cost"`, `"Rarity"` (recommended to set lower for easier testing), and `"Purchasable"` (set to `true`) in `Description`, and remove the `"BLACKLISTED"` tag from `"ComponentTags"` so the equipment can randomly spawn in in-game galactic stores.
- **Save Editor Method (Quick Testing)**: Utilize community-provided `BattleTech Save Editor` to directly write the newly created equipment ID into existing save inventories, launching the game to immediately install and test.
