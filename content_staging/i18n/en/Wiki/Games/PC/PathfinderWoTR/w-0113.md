## 4. Why Does Ultrasonic Easily Run into Issues? Subsonic Authentication Mechanism Explained

Many users encounter `401 Unauthorized` or repeated password prompts when connecting legacy clients like Ultrasonic:

- **Core Cause (Plaintext Token vs. MD5 Salt Hash)**:
    
    - Early Subsonic API versions used <span style="color:#e06c75"><del>direct password transmission or outdated SHA1 authentication</del></span> *(Updated 2026-11-27: Early Subsonic API transmitted passwords in plaintext `p=` or simple Hex encoding `p=enc:...`, rather than SHA1)*; whereas modern Subsonic / OpenSubsonic API specifications require the `Token + Salt` (`token=md5(password+salt)`) pattern.
        
    - **Ultrasonic** has a lower maintenance frequency and has compatibility issues handling OpenSubsonic extended specifications and specific URL escaping, causing the authorization header sent to Navidrome to not match expectations.
        
- **Troubleshooting**:
    
    - In client connection settings, look for and check **"Use Token Authentication"** or force select **Subsonic API 1.16+**.
        
    - It is recommended to directly use modern clients that have been actively maintained by the community in recent years.

## 6. Music Library Tagging, Lidarr Automated Management, and Lyrics Download Organization

Navidrome is a server that **heavily relies on ID3 audio tags**, not depending on folder structures for categorization at the bottom layer, but reading audio metadata directly. Although Lidarr does not come with a built-in lyrics fetching module, you can build a complete automated closed-loop of "Download -> Auto Tag -> Auto Fetch Synchronized Dynamic Lyrics (.lrc) -> Instantly Trigger Navidrome Scan" through **Lidarr Custom Scripts** or **Independent Sidecar Containers**.

### 6.1 Lidarr Backend Automatic Standardization Settings (Replacing Manual Tag Editing)

Lidarr integrates the MusicBrainz database, automatically completing standardized tagging and file renaming when importing music:

1. **Enable Audio File Tag Writing (Media Management)**:
    
    - Go to Lidarr **Settings** -> **Media Management**.
        
    - Check **Write Audio Tags**: Set to `Sync` or `Scrub and Sync`.
        
    - **Key Checkboxes**: Check **Write Embedded Cover Art** (embeds high-res cover art into files) and **Save Artwork to Album Folder** (generates `folder.jpg` / `cover.jpg`, which Navidrome will preferentially read as cache thumbnails).
        
2. **Standardized Renaming Structure (Naming)**:
    
    - Enable **Rename Tracks**.
        
    - **Artist Folder Format**: `{Artist CleanName}`
        
    - **Album Folder Format**: `{Artist CleanName} - {Release Year} - {Album CleanTitle}`
        
    - **Track File Format**: `{Track:00} - {Track CleanTitle}`

### 6.2 Dynamic Lyrics Auto-Fetching and Organization Solutions (Two Mainstream Approaches)

#### Approach A: Lidarr Integration with Custom Script (Most Elegant: Fully Automated Trigger Upon Import)

Community open-source tools (such as `synclyr2metadata`) can be packaged into a single static binary and seamlessly embedded into the Lidarr container:

1. **Get the Tool**: Place the compiled static executable into Lidarr's mounted directory, for example `/opt/appdata/lidarr/scripts/synclyr2metadata`.
       
   ```bash
   chmod +x /opt/appdata/lidarr/scripts/synclyr2metadata
   ```
    
2. **Configure Custom Script in Lidarr**:
    
    - Go to Lidarr **Settings** -> **Connect** -> Click **+** to add **Custom Script**.
        
    - **Name**: `Auto Sync Lyrics`
        
    - **Triggers**: Check `On Release Import` and `On Upgrade`.
        
    - **Path**: Enter the container-internal path `/config/scripts/synclyr2metadata`.
        
3. **Workflow Mechanism**: Whenever Lidarr downloads and organizes a new album, the script automatically requests synchronized lyrics from the largest open lyrics repository **LRCLIB** using the audio's Artist/Title/Duration, and directly writes them into the audio file's embedded `LYRICS` / `SYLT` tags (or outputs a same-named `.lrc` file).

#### Approach B: Deploying an Independent Lyrics Fetching Container (LRCGET-CLI / LyricFlow)

If you prefer not to put scripts inside Lidarr, you can mount a dedicated lyrics fetching sidecar service in Docker Compose (e.g., using the official `lrcget-cli` developed based on LRCLIB):

Add to `docker-compose.yml`:

```yaml
  lrcget:
    image: diegoninja/lrcget-cli:latest
    container_name: lrcget-cli
    restart: unless-stopped
    environment:
      - TZ=Asia/Taipei
    volumes:
      - /mnt/nas/music:/music:rw  # Requires write permissions to store .lrc lyric files
    # Can also set scheduled scan jobs
```

It will automatically monitor new audio under the `/music` directory, automatically generating same-named `Song.lrc` dynamic scrolling lyric files in the same directory.

### 6.3 Closed-Loop Automation: Lidarr Download Complete Automatically Notifying Navidrome to Refresh

Navidrome scans periodically according to `ND_SCANSCHEDULE` by default (e.g., every 1 hour). Through Lidarr's Webhook integration, you can **immediately trigger a partial Navidrome scan** the moment a new album is downloaded and organized:

1. Go to Lidarr **Settings** -> **Connect** -> Click **+** to add **Webhook**.
    
2. **URL**:
    
    `http://navidrome:4533/rest/startScan?u=<admin_user>&t=<token>&s=<salt>&v=1.16.1&c=Lidarr`
    
3. **Triggers**: Check `On Download` and `On Upgrade`. _(Token and Salt generation methods follow the Subsonic API standard: token=md5(password+salt))_.

### 6.4 Legacy File Patching Tool (MusicBrainz Picard)

For older local collections or rare self-recorded audio not included in the Lidarr monitoring workflow, it is recommended to use **MusicBrainz Picard** for manual organization before throwing them into the NAS, cleaning up standard `Title`, `Artist`, `Album Artist`, `Track Number`, and `Date` fields before archiving.

## 7. Maintenance and Data Backup

After separating `/music` (NAS remote library) and `/data` (local SSD), data backup only requires backing up the lightweight local directory:

```bash
# Backup Navidrome database and playback history
sudo tar -czvf /opt/backups/navidrome-$(date +%F).tar.gz -C /opt/navidrome data

# Restoration method
sudo tar -xzvf /opt/backups/navidrome-*.tar.gz -C /opt/navidrome/
sudo chown -R 1000:1000 /opt/navidrome/data
docker compose restart navidrome
```
