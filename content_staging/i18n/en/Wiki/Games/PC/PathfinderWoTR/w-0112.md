## Basic Workflow

Since generating all followers directly with newly created characters hasn't been tested yet, for the first version it's recommended to keep things simpler by modifying mercenaries for the other three after the first `MythicSkeletonCompanion` (which generates automatically).

The recommended operation workflow is as follows:

1. Use ToyBox to add the `MythicSkeletonCompanion` Feat (any class branch works).
2. In-game, recreate a companion appearance and portrait that you like.
3. Edit the save JSON, pasting the companion appearance section and portrait of your favorite character into the corresponding companion data.
4. Recruit three additional mercenaries in-game.
5. Add the other three `MythicSkeletonCompanion` Feats.
6. ~~Modify the save file to map the corresponding mercenary's UniqueId to the Feat~~, `m_pet`, and add these three `UniqueId`s into the Master's definition.

   `*` Latest confirmation: only defining the Master and Pet relationship is required.

### Method for Transforming Mercenaries into the Other Three MythicSkeletonCompanions

#### Feat Data Format (No Longer Needs Modification)

```json
 {
                        "$id": "109",
                        "$type": "Kingmaker.UnitLogic.Feature, Assembly-CSharp",
                        "m_Context": {
                            "AssociatedBlueprint": "048456cce79943f4c9c9eec1aa5ce9a0",
                            "m_OwnerRef": "e51cd2f4-f8e6-4956-93a7-86281cd5e92a",
                            "m_Params": null
                        },
                        "Blueprint": "048456cce79943f4c9c9eec1aa5ce9a0",
                        "UniqueId": "e731dd8b-31cc-4114-9dd5-650a8672ddf0",
                        "AttachTime": "12:00:47.3910000",
                        "IsActive": true,
                        "Components": {
                            "$AddPet$858ef2c0-f8cf-41f4-af45-0bb06f90fa00": {
                                "$type": "Kingmaker.EntitySystem.EntityFactComponentDelegate`2+ComponentRuntime[[Kingmaker.EntitySystem.Entities.UnitEntityData, Assembly-CSharp, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null],[Kingmaker.UnitLogic.FactLogic.AddPetData, Assembly-CSharp, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null]], Assembly-CSharp, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null",
                                "m_Data": {
                                    "$id": "110",
                                    "SpawnedPetRef": "b27cd89c-a8b0-4a1c-a5f0-379c5e5fd9c3",
                                    "Disabled": false
                                }
                            }
                        }
                    },
```

Basically, as long as the Feat is added, you can search for the corresponding UUID in the save file to find the corresponding Section (only one structure like the above paragraph will exist).

The previous approach was to paste the UUID of the mercenary (or corresponding character) into the `"SpawnedPetRef"` field (the value for this item in the second added Feat will be `null`).

#### Part Relationship Configuration

##### Part Section for the Character Becoming a Companion

```json
#Add inside m_part
{
      "$id": "2459",
      "$type": "Kingmaker.UnitLogic.Parts.UnitPartPet, Assembly-CSharp",
      "m_MasterRef": {
              "m_Ref": "e51cd2f4-f8e6-4956-93a7-86281cd5e92a"						
                     },
      "Type": "MythicSkeletalChampion"										
},
```

The `m_Ref` under `m_MasterRef` needs to be confirmed as the Master's (Feat owner's) UUID.

##### Part Section for the Master

```json
#Add inside m_part
{
        "$id": "10",
        "$type": "Kingmaker.UnitLogic.Parts.UnitPartPetMaster, Assembly-CSharp",
        "m_Pets": [
                      {
                "m_Ref": "b27cd89c-a8b0-4a1c-a5f0-379c5e5fd9c3"					
                      },
                      {
                "m_Ref": "46694232-fba8-4a18-8daa-1a1c933290e2"
                      },
                      {
                "m_Ref": "14547546-c716-4e63-9a5c-d8126e9c01f6"
                      },
                      {
                "m_Ref": "2577f7e3-a782-439d-90df-eaa70a440af4"
                      }
                   ],
           "m_ExPets": []
}
```

Following the example above, add each companion's `m_Ref` definition into the `m_Pets` array to correctly bind multiple companions under the master character.
