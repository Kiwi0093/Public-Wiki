## I. Architecture Planning: Centralized Read-Only Library and Multi-User Local Save Isolation

When configuring Duo / Sunshine for multi-user concurrent streaming or family multi-account sharing, the most stable storage logic is "Centralized read-only sharing for ROMs and BIOS, local isolation for game saves per account":

- **Read-Only Centralized Sharing (NAS / RomM)**: ROMs and BIOS are stored on the NAS and mapped to each device via SMB (e.g., `Z:\roms` and `Z:\bios`).

- **Local Multi-Account Save Isolation (Saves / States)**: User game saves (`.srm`, `.sav`) and Save States must strictly avoid writing back to network shared directories. If saves are shared, simultaneous or multi-player gameplay of the same title will cause file lock contention and progression overwrite disasters.

### 1. NAS Directory Structure Specifications

The remote NAS shared directory must follow a standard hierarchical structure:

```
\\<NAS_IP>\Emulation\          <-- Network drive root directory (mapped as Z:\)
├── bios\                     <-- BIOS for various systems (e.g., scph1001.bin, etc.)
│   └── ...
└── roms\                     <-- Platform folder names must exactly match EmuDeck specifications
    ├── gba\
    ├── ps2\
    └── snes\
```

### 2. Windows Local Startup Persistent Network Drive (Z:)

1. Open "File Explorer" ➔ "Map network drive".

2. Select `Z:` for the drive letter, and enter `\\<NAS_IP>\Emulation` for the folder path (check "Reconnect at sign-in").

3. If `Z:` frequently disconnects with a cross mark upon booting due to network latency, a startup batch script can be created:

```bat
@echo off
timeout /t 5 /nobreak >nul
net use Z: \\<NAS_IP>\Emulation /persistent:yes
```

## II. Windows Environment Installation and Troubleshooting "adb.zip Freeze"

### 1. Causes of Installation Freezing on "adb.zip" When Pointing to a Network Drive

During the "Prerequisites" stage of the EmuDeck for Windows installation wizard, even if no Android emulators are selected, it still forcefully downloads platform-tools (i.e., `adb.zip`) for extraction. When the installation target points directly to a **network drive (Z:)**, SMB file handle locking latency or asynchronous write characteristics cause the script to misjudge file status during deletion or retry loops, leading to infinite waiting or application deadlock.

### 2. Solutions (Choose One of Two Paths)

#### Option A: Local Installation Followed by <span style="color:#e06c75"><del>Directory Junction</del></span> *(Updated 2026-11-27: `mklink /D` creates a Directory Symbolic Link, which is compatible with network drives `Z:\`; `mklink /J` Junctions only support local drives)* Bridging to NetDrive (Recommended, Most Robust)

To completely avoid SMB permission privilege invocation issues running setup wizards over remote paths, complete the installation locally first and then establish symbolic links:

1. **Force Terminate Residual Processes**: Open PowerShell as Administrator and terminate background locking processes:

   ```powershell
    Stop-Process -Name "adb" -Force -ErrorAction SilentlyContinue
    Stop-Process -Name "EmuDeck*" -Force -ErrorAction SilentlyContinue
   ```

2. **Manually Create Dummy Files to Prevent Check Interruption**:

   ```powershell
    $paths = @(
        "$env:USERPROFILE\EmuDeck",
        "$env:APPDATA\EmuDeck",
        "$env:TEMP"
    )
    foreach ($p in $paths) {
        if (Test-Path $p) {
            New-Item -ItemType File -Path "$p\adb.zip" -Force -ErrorAction SilentlyContinue
        }
    }
   ```

3. **Execute Local Installation**:

    - Run the EmuDeck installer and select **Custom Mode**.

    - Select a local drive for the target directory (such as the default `C:\Users\%USERNAME%\Emulation`).

    - Uncheck all Android-related emulators in the emulator list.

4. **Create Directory Symbolic Links**: Completely close EmuDeck after installation finishes, and delete the locally generated empty folders:

    - Delete `C:\Users\%USERNAME%\Emulation\roms`

    - Delete `C:\Users\%USERNAME%\Emulation\bios`

    Open CMD as Administrator to create directory symbolic links:

   ```cmd
    mklink /D "C:\Users\%USERNAME%\Emulation\roms" "Z:\roms"
    mklink /D "C:\Users\%USERNAME%\Emulation\bios" "Z:\bios"
   ```

    _Verification method_: Open `C:\Users\%USERNAME%\Emulation\roms` and verify that files from `Z:\roms` can be read and operated normally.

#### Option B: Manually Modify settings.json to Bypass ADB Check (Direct Installation to Z:)

If you insist on pointing EmuDeck's installation root directory directly to `Z:\`, you can manually modify the configuration file to forcefully declare that ADB and Android modules have already been installed, causing the installation wizard to skip downloading, extracting, and deleting `adb.zip`:

1. **Force Terminate Installation Process**: Press `Ctrl + Shift + Esc` to open Task Manager, and forcefully terminate all `EmuDeck`, `PowerShell`, `cmd.exe`, and `adb.exe` processes.

2. **Modify settings.json to Declare Status**: Open `%USERPROFILE%\EmuDeck\settings.json` (or `%APPDATA%\EmuDeck\settings.json` if in AppData) and manually set the status of `adb` and `android` to `true` and `skip`:

   ```json
    {
      "tools": {
        "adb": {
          "installed": true,
          "configured": true
        },
        "platformTools": {
          "installed": true
        }
      },
      "android": {
        "installed": true,
        "configured": true,
        "skip": true
      }
    }
   ```

3. **Populate Local Dummy Tool Files and Clear Caches**: Run the following commands in PowerShell to create dummy files passing existence checks and remove any stuck archive remnants:

   ```powershell
    # Create platform-tools placeholder directory and dummy executable
    $toolsPath = "$env:USERPROFILE\EmuDeck\tools\platform-tools"
    New-Item -ItemType Directory -Path $toolsPath -Force -ErrorAction SilentlyContinue
    New-Item -ItemType File -Path "$toolsPath\adb.exe" -Force -ErrorAction SilentlyContinue

    # Clear lingering adb.zip in temporary directories
    Remove-Item "$env:USERPROFILE\EmuDeck\adb.zip" -Force -ErrorAction SilentlyContinue
    Remove-Item "$env:TEMP\adb.zip" -Force -ErrorAction SilentlyContinue
   ```

4. **Restart Installation**: Right-click the EmuDeck installer and select "Run as administrator". The wizard will skip the ADB stage and proceed directly to the emulator selection and configuration page.

## III. Multi-User Independent Save Configuration (Preventing Multi-User Progress Conflicts)

By default, EmuDeck points saves to the home directory saves folder (e.g., `Z:\Emulation\saves`). You must forcefully redirect save paths back to each user's local space:

### 1. RetroArch Save and Savestate Path Redirection

Open RetroArch ➔ Go to "Settings" ➔ "Directory":

- **Savefile Directory**: Set to local path, e.g., `C:\Users\%USERNAME%\EmuDeck\saves\`

- **Savestate Directory**: Set to local path, e.g., `C:\Users\%USERNAME%\EmuDeck\states\`

- Enable "Save Saves to Current Directory" or "Sort Saves into Folders by Core Name" to ensure individual game saves are isolated.

### 2. Standalone Emulators (PCSX2, RPCS3, Dolphin, etc.)

- **PCSX2**: Go to Settings ➔ Memory Cards, and ensure memory card files are located locally under `%APPDATA%\PCSX2\memcards\` or `C:\Users\%USERNAME%\Documents\PCSX2\memcards/`. Strictly avoid pointing them to `Z:\`.

- **Dolphin**: GC/Wii virtual memory cards are created locally under `%USERPROFILE%\Documents\Dolphin Emulator\` by default; maintaining the default local path is recommended.

### 3. Multi-User Automated Personal Save Backup (Scheduled Batch Task)

If backing up personal local saves to a remote NAS is required, each account can create an independent scheduled script:

```cmd
robocopy "C:\Users\%USERNAME%\EmuDeck\saves" "\\<NAS_IP>\Backup\%USERNAME%_Saves" /MIR
```

## IV. Linux Environment Installation (Arch Linux and Other Distributions)

### 1. Arch Linux

For Arch Linux, it is recommended to use the official installation script combined with the Flatpak container architecture.

#### 1. Install Prerequisite Dependencies

```bash
sudo pacman -Syu --needed base-devel git curl flatpak zenity
flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
```

#### 2. Download and Run EmuDeck

```bash
mkdir -p ~/Downloads/EmuDeck && cd ~/Downloads/EmuDeck
curl -L -O https://www.emudeck.com/EmuDeck.desktop
chmod +x EmuDeck.desktop
./EmuDeck.desktop
```

In the installation wizard, choose Expert Mode. Storage directories can be set to local `/home/<user>/Emulation`, or pointed to a remote NFS/SMB directory pre-mounted via `/etc/fstab`:

```
<NAS_IP>:/mnt/share/Emulation /mnt/Emulation nfs _netdev,nofail,x-systemd.automount 0 0
```

### 2. Other Linux Distributions

- **SteamOS (Steam Deck)**: Switch to Desktop Mode, download `EmuDeck.desktop` from the official website to the desktop and execute it, selecting installation to the SD card or internal storage. The system will automatically configure TDP and refresh rate optimization scripts.

- **Ubuntu / Debian Derivatives**:

   ```bash
    sudo apt update && sudo apt install -y flatpak git curl zenity dialog libfuse2
    flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
    bash -c "$(curl -fsSL https://raw.githubusercontent.com/dragoonDorise/EmuDeck/main/install.sh)"
   ```

- **Fedora**:

   ```bash
    sudo dnf install -y flatpak git curl zenity
    flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
    bash -c "$(curl -fsSL https://raw.githubusercontent.com/dragoonDorise/EmuDeck/main/install.sh)"
   ```

## V. Steam ROM Manager (SRM) Injection and Notes

1. **Close Steam Before Execution**: Completely exit the Steam client before generating shortcuts or saving box art to prevent write conflicts resulting in cache corruption.

2. **Verify Parsers Paths**: Ensure that each platform's ROMs Directory correctly points to `Z:\roms\<Platform_Name>` or local symbolic link directories (e.g., `C:\Users\%USERNAME%\Emulation\roms\<Platform_Name>`).

3. **Parse & Save**: Click Preview ➔ Parse to download covers and box art, review them, and click Save to Steam to write shortcuts.
