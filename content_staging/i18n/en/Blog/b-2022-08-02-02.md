# Story Outline

## Previously

A few days ago while messing around with the machines (Wait, that phrasing sounds a bit sketchy?!), I noticed the freeloaded VPS currently serving most of my services was severely short on RAM.. so I decided to set my sights on that ARM-based VPS that had been sitting idle.

## The Main Event

### Rebuilding

Honestly, I don't even know how that old system got so messed up before.. even Traefik's corresponding features were acting weird. So I put the system out of its misery and spun up a brand new one with the exact same specs (actually I originally wanted to split it into two x86 instances.. but looking at that gorgeous 4Gbps network and 24GB RAM, I shamelessly clicked it again).

### Side Episode

Along the way I discovered it could create four network interfaces, so I excitedly created four, then despairingly discovered you can only have two `public IP`s, so I deleted two. Then I discovered having two IPs caused Traefik to go haywire.... so I deleted one more...

## Service Migration

Actually, the biggest takeaway was discovering that `Traefik` really is a Swiss Army knife—the URLs it reverse-proxies can be completely unrelated to its own domain.... Pretty awesome, so I moved the services over without users noticing a thing and without changing the domains....

# Conclusion

Although it's super convenient to migrate services painlessly, the price was that the `docker-compose.yml` files I had originally organized by machine DN turned into a complete mess. Though in the end I still sorted them out by host machine (all of this lives in a private repo where nobody else can see it anyway, so what am I even talking about).
