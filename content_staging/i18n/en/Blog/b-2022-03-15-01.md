# Preface

Reorganizing the internal services at home.. splitting internal and external servers into Private & DMZ. However, always using `http://ip:port` for internal connections is really ugly (okay, I know I'm obsessive), so I wanted to set up a reverse proxy to route them directly.. Unfortunately, it turned out to be another story of half-baked skills..

<!--truncate-->

# Goal

It's actually pretty simple. I wasn't planning to do anything crazy complicated like that `dual chroot bind` setup from years ago. Instead, I used a simple `dnsmasq+adguard home` combo to handle internal DNS (including internal domain mapping and ad blocking).. Why didn't I use `Pi Hole`?
Because I'm lazy and I saw AdGuard Home first, though to keep things minimal I might also just move ad-blocking directly into dnsmasq.

PS: Thanks for [this great link provided by Master](https://pgl.yoyo.org/adservers/)

# Basic Architecture

You can't really call it an architecture... It's just that compared to using Traefik externally, internal services don't need automatic SSL (and it's hard to do SSL for internal domains anyway), so internally I added an `Nginx Proxy Manager` and used NPM for forwarding.

## The Disaster

For some reason, what should have been a super simple config just refused to work.. for example:

```bash
http://emby.private -> http://emby.private:8888
```

Yet it failed to map over.

## Solution

In the end, pointing directly between Docker containers worked:

```bash
http://emby.private -> http://emby:8888
```

That settled it (provided they are all on the same Docker network).
