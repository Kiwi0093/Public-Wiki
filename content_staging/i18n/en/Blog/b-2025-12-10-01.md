# Preface

Recently I got a bit diligent about updating my system... and then my UniFi Controller blew up right under a single `yay -Syu --noconfirm`.

<!--truncate-->

# Incident Log

After firing off `yay -Syu --noconfirm` and letting it run all the way through... the UniFi Controller Web UI became unreachable.
Started investigating and found:

* `systemctl status unifi.service` reported active and ok, yet `netstat -an` showed no listening port for UniFi Controller.

* Checked `/var/log/unifi/server.log` and saw `exit code=62`.

* Checked `systemctl status mongodb.service` and saw `exit code=62` there too; looking into it revealed MongoDB couldn't start normally because the database version was too old.

* Checked `/var/log/mongodb/mongodb.log` and confirmed the MongoDB data version was 7.0, while the updated `mongodb-bin` package in the AUR was version 8.2—too big of a version gap, so it refused to start.

* Switched to installing the `mongodb80-bin` package, which allowed upgrading MongoDB's major version to 8.0 via commands.

The frustrating detour part:

* MongoDB's database upgrade concept:
  
  * MongoDB cannot skip multiple versions in one jump when upgrading a database (yes, MongoDB's binary version and database version aren't automatically coupled—they're separate and must be upgraded manually).
  
  * Going from 7.0 to 8.2 requires stepping 7.0 --> 8.0 --> 8.2. Generally a newer version is compatible with the previous version's database, whereas a newer database cannot work with an older binary.

* The chaotic detour experience:
  
  * First I removed both the `unifi` and `mongodb-bin` packages, installed `mongodb80-bin` instead, and upgraded the admin database from 7.0 --> 8.0 --> 8.2.
  
  * Then I removed `mongodb80-bin` again and reinstalled `mongodb-bin` and `unifi`. `systemctl status mongodb.service` looked fine, and `systemctl status unifi.service` looked fine too, yet UniFi Controller still wouldn't come up—checking `/var/log/unifi/server.log` still showed `exit code=62`.
  
  * No matter how much I looked around, I still couldn't figure out how to upgrade UniFi's own MongoDB database (this is probably because this old guy hadn't put skill points into the right tree... so I looked completely clueless here).
  
  * And so I got stuck with the main MongoDB admin database upgraded fine, while UniFi's MongoDB database couldn't be upgraded....
  
  * Finally I checked UniFi's `PKGBUILD` file and discovered... its dependency just requires *any* `mongodb`....
  
  * In the end, pairing `mongodb80-bin` + `unifi` worked because 8.0 is compatible with a 7.0 database, and it magically came right back to life.....
  
  
# Key Technical Takeaways

The two main things learned from this incident:
* MongoDB concepts and upgrades — I still need to look into how to upgrade MongoDB databases other than `admin` (honestly I couldn't even list the databases).
* I need to look into how to upgrade UniFi in the future without hitting landmines. I tried running it in Docker before, though I didn't stick with it due to networking issues—maybe it's time to dig that back up.
