# Detailed Notes

## UniFi Series

Honestly, the main motivation here was just showing off...

I figured I'd upgrade my new home's IT infrastructure to prosumer/semi-enterprise grade, and being able to push settings to APs from a single central controller seemed much more convenient. Plus I got burned by the **TP-Link Deco X75** I bought for my parents' place earlier—a pricey Mesh AP that didn't even have a whitelist mode for MAC Address filtering...

Originally I thought the apartment wasn't big so a single **U6 In-Wall** would cover everything, but unfortunately the placement wasn't great and the signal behind the TV wall ended up weak.

So I bought a **U6 Pro** to fill in the dead zone.

## HPE MicroServer Gen8

This is an older box—I used to have two of them, but my parents' ASUS Server died (after ~10 years, it definitely earned its keep), so I had to move one back there to serve as their NAS. The remaining one got a **10GbE NIC + 16TB HDD x4** upgrade, turning it into a **48TB** usable **raidz1** NAS.

## ASUS TS110-E14

No surprises here—this is the **ESXi Server**, though setting up the foundational network environment was still quite a headache.

### FreeBSD 14 Gateway

Sticking with old habits, I still went with the tried-and-true FreeBSD + pf + ipfw for the gateway.

#### Network Architecture

Initially I wanted to put everything on a single Class C subnet to keep things simple (which meant no DMZ isolation, though DMZ was basically half-baked in my hands anyway). Turns out I hit a **NAT Loopback** issue where internal hosts couldn't access ~~my external-facing services, so I had to revert back to the original WAN+LAN+DMZ layout~~—after tweaking the pf rules, I fixed it by referring to [this guide](https://www.twbsd.org/cht/book/new/ch12.htm):

```shell
# Nat Loopback
no nat on $int_if proto tcp from $int_if to $int_net
rdr on $int_if proto tcp from $int_net to $ext_ip port { 25, 165, 993 } -> 192.168.0.2
nat on $int_if proto tcp from $int_net to 192.168.0.2 port { 25, 165, 993 } -> $int_if
```

So in the end, I still managed to consolidate everything back onto a single Class C subnet.

### Archlinux Dnsmasq + UniFi

This turned out to be part of the big landmine of this build. My original plan was to just spin up both **dnsmasq** and **UniFi Network Application** in Docker containers and call it a day, and well...

#### Dnsmasq

It *ran* in Docker, sure, but because of IP subnetting and me not digging carefully into network mapping, the service appeared to be up while none of the clients could actually get DHCP or DNS working properly. After fighting with it forever, moving dnsmasq onto a standalone VM made everything work immediately without changing a single thing...

#### UniFi Network Application

This one was even more infuriating. Either the **MongoDB** version specified in the docs threw issues, or once MongoDB was sorted out, the controller refused to serve the web UI properly due to Java version mismatches... After wading through walls of documentation, I discovered that on **Archlinux** with `yay` installed, all you need is:

```bash
yay -S unifi
```

And then just make sure the JRE version is 17... One single command took care of everything...

### XigmaNAS

Given the storage needs of the Docker backend and system backups, I mounted a ZFS Mirror NAS via NFS to the various servers for basic backups. Later on, I'll pair it with a self-hosted Git server for overall internal project management.

Also, on my parents' old server I used to attach an HDD directly in ESXi as a TEMP drive for BT downloads and overflow storage, and during this migration I suffered horribly because certain VMs refused to boot without that HDD attached.

So this time I mounted the Temp HDD inside XigmaNAS and exported it over NFS instead.

# Pain Points Along the Way

## XigmaNAS Refusing to Mount the Temp Drive

For whatever reason, my existing XigmaNAS VM just wouldn't add the Temp drive, so in the end I had to spin up an extra VM with dedicated PCI Passthrough hardware running a separate XigmaNAS instance solely for exporting Temp storage.

## UniFi Series

As mentioned earlier, the cursed UniFi-Network-Application wouldn't behave properly in Docker... plus Dnsmasq didn't play nice either, so I ended up spinning up an extra VM.

## Poor WiFi AP Placement

My brain must have been eaten by something during the interior design phase, because the U6 In-Wall ended up in a terrible spot—facing away from two bedrooms and two bathrooms, leaving weak signal in all of them... So I had to add a U6 Pro, kicking off the UniFi asexual reproduction cycle ahead of schedule...
