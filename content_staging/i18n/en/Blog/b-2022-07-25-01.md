# Introduction

As written in <span style="color:#e06c75"><del>[My Wiki](https://kiwi0093.github.io/wiki/wiki/Network/Ansible/Install%20&%20Configuration/1-Intro/)</del></span> *(Updated 2026-11-27: [Kiwi Wiki](https://blog.kiwireich.com/docs), Ansible entries are currently being organized)*, this is a handy server management tool from Red Hat. Using Python + SSH, it can run playbooks or commands from the management node on the client side to control and manage clients. Its biggest advantage is having many modules to verify client state (for example, whether a certain package is installed, etc.) in order to achieve configuration management across clients.

## Limitations

* Basically, to connect smoothly you need to pair it with an SSH private key that doesn't require entering a passphrase each time.

* Execution speed isn't as fast as running a script directly.

* Unless there is a large amount of repetitive configuration, it won't be faster or easier to use than a general-purpose shell script.

## General Structure

Basically, you use `inventory` to manage the target hosts and `action-definition.yml` to define automated actions.

This `action-definition.yml` can be a top-level playbook, the main tasks inside a role, or another `action-definition.yml` pulled into tasks via `inculde_tasks`. That way, when writing, you can build standalone objects piece by piece and then tie them all together in a top-level playbook with variables and conditionals—eventually achieving a generic server management framework (at which point you can go back to `inventory` to define different groups doing different things).
