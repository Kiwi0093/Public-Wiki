# What is Ansible?

## Previous Roadblocks

Previously, I mainly got stuck on two things when using Ansible:

### Using Variables / Loops

Loops in Ansible almost always go hand-in-hand with variables. If you don't know how to define the `"{{  }}"` Jinja2 variable syntax, you basically can't use loops.
An Ansible playbook without loops becomes bloated—the more machines and repetitive tasks you have, the more verbose and sluggish it runs.

### Conditionals

This is also a huge point. Just like with `shell script`, if you don't know how to use `if ..else ..fi` to check states, you won't get very far writing a `shell script` either....

## Other Addictive Parts

## include_task, include_roles

Previously, I already liked Ansible's `roles` feature—after all, it lets you break down a huge `playbook.yml` into smaller, easier-to-write `roles`, reducing the writing burden and enabling reuse.
However, `roles` are static: whatever you write there will definitely be called and executed. When combined with `include_task` and variable checks, though, you can inspect a `node`'s properties (such as `os_family` to automatically detect the OS type) and `dynamically` load the corresponding `task.yml`. That expands the coverage of a single `playbook.yml` to almost every machine (especially for someone like me who likes using different `distribution`s for different types of servers/workstations).

## Beautifying Output

This one is purely asking for extra trouble... Although you can set `display.skipped.host=false` in `ansible.cfg` to hide skipped items and make the output look nicer—or even go further and set `display.ok.host=false` so nothing shows up except changed items....
Or I saw a trick using `callback` parameter tweaks so nothing displays unless explicitly defined (kind of like only showing text from `echo` inside a `shell script`).
Truth be told, I don't really need to spend effort on this anyway, since I have no intention of publishing my Ansible project externally.... Either way, I'm the only one using it, so it doesn't matter if it's ugly—good enough is good enough.
