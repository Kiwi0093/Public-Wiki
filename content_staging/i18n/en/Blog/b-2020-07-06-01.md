# Preface

A few days ago, I watched [CTT](https://www.youtube.com/user/homergfunk/featured)'s YouTube channel and discovered that Hugo + GitHub or Hugo + Netlify are also great options for building a blog. Considering that Blogger's editing mode really isn't that modern, and my hard work trying to switch over to Markdown syntax, starting with this post I plan to move this unread blog of mine from Blogger to GitHub—and take the opportunity to learn the trendy Git way of managing my blog.

<!--truncate-->

## Prerequisites

The new blog requires the following tools:

* **[Hugo](https://gohugo.io/)** - A tool for generating static websites, available on Linux, Windows, macOS, FreeBSD, etc.—a pure CLI tool.

* **[Github](https://www.github.com)** - Arguably Microsoft's most generous service. We mainly use it because we can create our own projects for free and easily upload and manage them using `git` commands.

* **[Remarkable](https://remarkable.com/)** or **[Typora](https://typora.io/)** or other Markdown editors - Mainly for comfortably editing `.md` files as the body of blog posts, which is also my primary reason for switching.

* **[git](https://git-scm.com/)** - An ultra-powerful tool that basically comes pre-installed on Linux by default; if you're on Windows, you'll need to install it separately.

Surprisingly, not many tools are needed, though since I'm not familiar with it, I had to look up quite a lot of references. Actually, there are plenty of resources out there—just search Google for *hugo tutorial* and tons of results pop up.

## Installation Steps

### Installing Hugo

Since I mostly sneak in blog writing during work hours, my main machine runs Manjaro. Anyway, let's install Hugo first:

```bash
sudo pacman -S hugo
```

### Creating the GitHub Repos

Here I recommend following [chanmitsu55](https://chanmitsu55.github.io/posts/2017/12/create-blog-by-hugo/)'s approach.
First, you'll need a GitHub account—it's free, just sign up with an email. Once registered, please create two repositories:

1. A repo with the same name as your site; in my case, `Blog`.
2. A repo named `<username>github.io`.

First, clone the repo with the same name as your local base directory:

`git clone https://github.com/<username>/Blog.git`

### Creating the Site Body, Copying to the Local Working Directory & Mounting the Public Submodule

Next, create a new site. This step basically only needs to be done the first time:

```bash
hugo new site _blog
cp -p -f -R _blog/* Blog/
cd Blog
git submodule add -b master https://github.com/<username>/<username>.github.io.git public
```

The reason for copying it over first is that the Fuji theme I use is attached as a submodule, and you can't add a submodule outside a git directory.
Also, the reason for attaching `public` before Hugo generates the site is that otherwise you'd have to run *rm -rf public* later to attach it anyway, so you might as well attach it before anything is generated.

### Installing a Theme

Now we have a basic web framework. Next, let's install a theme so it actually looks like something.
I'm pretty minimalist, so I picked a simple theme, [Fuji](https://themes.gohugo.io/hugo-theme-fuji/), though you can install whichever one you like.

```bash
cd ~/Blog
git submodule add https://github.com/amzrk2/hugo-theme-fuji.git themes/fuji
```

That installs the theme. Next, let's do some simple configuration for it:

```bash
cp themes/fuji/exampleSite/config.toml ./
cp -R themes/fuji/exampleSite/content/archives ./content/
cp -R themes/fuji/exampleSite/content/search ./content/
```

The important part of this step is taking `config.toml` from `exampleSite` to modify; the other two are because I only plan to keep the Archives and Search menus, so I copied them over.

Next, edit `config.toml`:

`vim config.toml`

There are a few main items to change:

```bash
#這個是定義你的主頁網址,請跟你的設定一致
baseURL = "https://Kiwi0093.github.io"	
#這個是你的網頁主要Title
title = "中年大叔的自言自語"
#這個是定義你網頁的主題
theme = "fuji"

[params]
  #這個是作者的名字
  author = "Kiwi.L"
  #這個是網頁的副標
  subTitle = "對應老年癡呆與記憶衰退的筆記"	

[taxonomies]
  #這是定義Tag會使用tags來進行分類
  tag = "tags"

[menu]
  #這個定義的是導向哪邊而非簡單的link
  [[menu.nav]]
   #這個定義了右邊連結的Home
   name = "Home"
   #連線是相對位置*/*對應的是*./content*
   url = "/"
   #這個定義了排序
   weight = 1
[[menu.nav]]
   name = "Archives"
   url = "/archives/"
   weight = 2
[[menu.nav]]
   name = "Search"
   url = "/search/"
   weight = 3
 #這個定義的是簡單的link
[[menu.link]]
 #這個是你想要表現的字串
   name = "R2d Blog"
   #這個是他的連結
   url = "https://roidintw.kaienroid.com/"
   #這個一樣是排序
   weight = 1
```

### Creating and Writing a New Post

With that set up, the basic website framework is ready. Next, let's write a simple post:

```bash
cd ~/Blog
hugo new post/what-ever-you-like-to-name.md
```

Then open this file with your favorite editor and you will see:

```bash
#這個---不要動
---
#這個是這個文件的主題會出現在Post的標題上
title: "what-ever-you-like-to-name"
#這個是時間戳記
date: 2020-07-06
#這是標記是否為草稿,寫好要正式發出去的文章把這行去掉
draft: true
#增加tag的寫法
tags: [ "A-tag", "B-tag", "C-tag" ]
#這個---不要動
---
```

Edit the section above as the header of your file, and then write your blog content directly below using Markdown syntax. At this point, the core essentials are done; next comes generating the site and putting it on GitHub.

### Generating the Site & Local Testing

Before pushing it live, please generate the site and preview it locally to make sure it looks the way you want:

```bash
cd ~/Blog
hugo && hugo server
```

Remember to follow the prompt to view it locally and see if anything else needs adjusting; if not, it's time to push it to GitHub!

### Auto-Deploy Script

For this part, it's easy to forget the manual commit message part in the official recommended script, so here I'm using [chanmitsu55]'s version, which basically just appends the update timestamp at the end:

```bash
#!/bin/bash

echo -e "\033[0;32mDeploying updates to GitHub...\033[0m"

# Build the project.我們已經在config.toml裡定義了theme所以簡單的hugo就夠了
hugo

# Go To Public folder
cd public
# Add changes to git.
git add .

# Commit changes.
msg="rebuilding site `date`"
   if [ $# -eq 1 ]
   then msg="$1"
   fi
git commit -m "$msg"

# Push source and build repos.
git push origin master

# Come Back up to the Project Root
cd ..

# Commit source repository changes
git add .
git commit -m "$msg"
git push
```

I don't like making it an executable directly, so I put the above contents in `deploy.sh` and run it with:

`sh ./deploy.sh`

During the process, it will ask for your GitHub username and password twice—once for pushing `Blog` and once for `Public`—don't mistype them.

### Working Remotely Across Machines

What if you also want to edit on other machines? Basically, you just need the following command to pull everything down from scratch:

`git clone --recursive https://github.com/<username>/Blog.git`

On machines that already have an existing git folder, you can just write new updates, because `git push`/`pull` compare diffs.
Files that aren't updated won't be uploaded (of course, if you're paranoid and have unlimited bandwidth, you can re-clone every time).
That way, we can ensure our data is basically all stored on GitHub.
