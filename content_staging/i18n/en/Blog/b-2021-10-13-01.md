# Basic Concept

It's actually very simple: turn a Windows PC capable of gaming into something you can remotely stream and play on, so you can freely use any other console/device to play games without being tied down to your Gaming PC/laptop.

There are plenty of guides and tutorials on how to do this—even [Learn Linux TV](https://www.youtube.com/c/LearnLinuxtv) has a tutorial...

# Related Tools

* Wake on Lan

  This is basically a feature every motherboard has nowadays—just Google how to use it in detail. On the client side, Android has APKs and Linux can use `gwake`; both are super simple.

* Nvidia Experiance

  This is mainly because I use an Nvidia card, so it's installed anyway. If you don't use an Nvidia card, I'd recommend Steam Link or Kino Console, though neither is as fast as pairing with Moonlight.

* Moonlight

  This is a really great client—fast, free, awesome, and available on every platform.

# A Few Thoughts

## Rambling

I thought before that with growing needs of all kinds, you'd end up needing lots of powerful devices: a fast tablet, a laptop beefy enough to game on, another lightweight portable laptop, a laptop that integrates well with work, and a whole bunch of others.

Since the services at home had already been gradually virtualized and consolidated via VMs, and after introducing Docker and WireGuard the boundary between home and outside grew increasingly blurry—from the Windows P2P box on a VM starting 10 years ago to Guacamole + Manjaro not long ago—I've really been heading down the path of cloudifying my systems so the client device goes back to truly being a thin console that doesn't need high speed or high performance (though a decent NIC is still needed). Yet the most original and important function of a PC/laptop for me—Gaming—had still never been integrated...

This test confirmed that as long as network conditions allow, even Gaming can be remoted along with everything else. Still, due to power consumption and other factors, I wouldn't recommend cramming it into a VM right from the start (even with PCI passthrough); leaving it powered on burning electricity when you're not gaming is just too wasteful.

## Key Takeaways

* The importance of Wake on Lan

  To put it bluntly, it's about saving power... Honestly, if you don't care about electricity bills or the fate of polar bears, you could leave your Gaming Server running 24/7...

* Auto Login

  This is actually really important because of Windows' quirks: if you don't actually log in after booting, Nvidia Shield won't start, so you won't be able to connect. And if you connect via RDP, it'll conflict and RDP doesn't actually log into the local desktop session... So without auto-login you'd need a console you can connect to—something like VNC or DWService (and you'll also need it when typing a PIN to pair a device, unless you just walk over to the machine locally, set it up, and leave).

* MSTSC.EXE

  You need to add this into Shield to launch directly as a substitute for Steam's Big Picture mode, otherwise you'll have to get a Fake HDMI dongle or actually plug in a monitor (mentioned in LLT).

  This is another Windows quirk... but adding `MSTSC.EXE` solves that problem (though it also turns it into a remote desktop where controllers aren't convenient for direct control).

## Post-Use Impressions

Moonlight really is quite smooth—when the network is solid, it doesn't feel much different from playing locally, though when the network is bad it stutters badly...

Also, as long as your network allows it, it's best not to set the streaming resolution lower than what the game itself is running at... because then it has to compress it down even further before sending it out... which actually introduces more latency.
