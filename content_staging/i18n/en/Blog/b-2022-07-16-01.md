# Preface

Since it's a company computer, I had been holding back from messing around too much, thinking I'd just make do with WSL2+WSLg and not push my luck (though honestly that was already pushing it pretty far). But last weekend, when my itchy fingers decided to tidy up the ManjaroWSL instance I was using, I realized I couldn't reproduce that fully functional WSL setup I had just wiped out... and so I said bye-bye to WSL.

<!--truncate-->

# Current Solution

Calling it a "solution" sounds a bit heavy—it's really just a Manjaro KDE guest in VirtualBox @ Windows 10 host.

# The Painful Journey

### Hypervisor Choice

Actually, before settling on the final setup, I hesitated a lot between VirtualBox and VMware Workstation Player...

To be honest, if it weren't a company machine where I had to be careful about licensing, I would have gone straight for VMware Workstation Pro..

Why didn't I pick QEMU? Well.... the answer is dead simple: I assumed performance on a Windows host would be terrible, so I skipped it without even testing....

In the end, VMware Player's features were just too bare-bones—it doesn't even have auto-resize.... so I reluctantly gave up on it.

### Convert from WSL to Virtualbox

Honestly I only have myself to blame for being stupid here...

When removing WSL I was still half-hearted about it, so Hyper-V related components weren't cleanly uninstalled, and I ran into almost every weird symptom you'd normally see over a whole month:

Like the guest OS randomly freezing, Linux failing to boot with multiple cores, or being super slow even when it worked....

In the end, turning off Windows's Virtual Machine Platform fixed everything... zero bullshit issues after that.

### System Tuning

We're really lucky to live in this era—none of that manual post-install base tuning is needed anymore, everything comes preconfigured out of the box...

Just remove what you don't want, install what you need, and you're ready to roll...

### The Obligatory Rant

Even though everything looks great, I still have to complain about that Guest/Host shared folder feature. I guess it's not that they didn't want to make it good, there must be real limitations, because in short, if I put my Git repo inside that shared folder, all kinds of bizarre issues happen: `git clone` fails mysteriously, weird files under `.git` get locked by the host and can't be removed... or `npm install` fails because symlinks fail...

Completely shattered my fancy dream of doing Git & Hexo on Linux while editing in Windows; now I just have to be good and do all of that inside Linux...

### Next Steps

Need to test whether a multi-monitor setup can run one full-screen OS per monitor (if that works, it'd actually be pretty awesome).

# Conclusion

Windows is best left for gaming (and work).... WSL, Microsoft's attempt at integrating Linux, really feels like a crippled piece of cannon fodder—can't run anything depending on systemd (I tried genie systemd and it was pretty awful too), plus `resolv.conf` has its own set of issues.

In an era where Linux increasingly depends on systemd, I can only describe WSL as tasteless yet hard to throw away.

And as for that flashy-looking WSLg—it's not terrible, but it's basically just VcXsrv wrapped in a Microsoft skin without any special Microsoft black magic...
