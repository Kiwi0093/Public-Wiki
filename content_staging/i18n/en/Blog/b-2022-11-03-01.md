# Basic Concept

## DistroBox

Project URL - [GitHub - 89luca89/distrobox](https://github.com/89luca89/distrobox)

Intro page - [Distrobox: Try Multiple Linux Distributions via the Terminal](https://itsfoss.com/distrobox/)

Put simply, it uses Docker or Podman to spin up another Linux distribution and export apps from inside it to run on the host outside.

# Hands-on Experience

I personally tested it on `Fedora 36 KDE Plasma Edition` (unfortunately I deleted the entire VM without taking screenshots).

It does work, though there are a few quirks:

## DE & WM

Basically, whatever you're running on the host outside is what gets used inside. So... when I was on `Wayland` outside, `ulauncher` inside acted super weird...

## Related Commands

All that said, it's very likely I just haven't figured out the best way to use it yet. Even just having exported programs pick up external config files is already great—in fact, I'm not even sure why that machine had my Brave profile without Brave installed, yet when Brave launched from inside the container it actually loaded the host's config... awesome! (Though `ulauncher` died beyond repair.)

Here are the basic commands:

| Out/In distrobox | command | usage | Example | Manual Link |
| ---------------- |:-----------------------------------------------------:| ------------------------------------------------------ | ------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| outside | distrobox create -n name -i Docker image | Create a distrobox container | distrobox create -n Archlinux -i Archlinux | [Distrobox-create](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-create.md) |
| outside | distrobox enter `<name>` | into named container | distrobox enter Archlinux | [Distrobox-enter](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-enter.md) |
| outside | distrobox list | list all containers | distrobox list | [Distrobox-llist](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-list.md) |
| outside | distrobox rm `<name>` | delete container | distrobox rm Archlinux | [Distrobox-rm](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-rm.md) |
| Outside | distrobox upgrade `<name>` | upgrade container | distrobox upgrade Archlinux | [Distrobox-upgrade](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-upgrade.md) |
| Inside | distrobox-export -a `<app Name>`  -ep `<path to outside>` | export apps installed inside container to outside to use | distrobox-export -a Brave -ep ~/.local/bin | [Distrobox-export](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-export.md) |

## Extra Notes

In all my examples, I used `distrobox` to spin up an `Archlinux` container and abuse the `AUR`. The main reason is that there's basically no need to run `Fedora` or `Debian/Ubuntu` on top of an Arch-based distro (apart from updates occasionally breaking things, Arch's software availability pretty much sweeps everything else...).

There is one awkward catch though—rather than saying I'm already shaped like `Archlinux`, it's more accurate to say I'm shaped like `Manjaro`... Unfortunately `manjaro` fails to deliver—its official Docker image is terrible... nowhere near as good as Archlinux's...
