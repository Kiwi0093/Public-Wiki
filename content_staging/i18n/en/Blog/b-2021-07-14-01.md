# Experiments

## Portainer-agent

### Ramblings

I installed Docker on the VPS without knowing what to do with it, so the very first container I ran was `portainer-agent`. Pairing it with my existing host dashboard, I found it actually works! Even without running `k8s` or `docker-swarm`, you can add nodes to manage (though the price is having to install `portainer-agent`).

### Thoughts

Since I put the setup steps on the Wiki, I'll just ramble a bit here. My impression is that using `portaner-ce` + `portainer-agent` together with its Stacks feature is really nice—you don't need to drop into the console to run `docker-compose` commands. For anyone who doesn't insist on doing everything via CLI, I think it's genuinely convenient (especially since Stacks can be migrated or duplicated to other machines).

## Nginx Proxy Manager

### Ramblings & Thoughts

The main reason I installed this thing was that I originally wanted to expose various web services through multiple layers, and writing Nginx configs by hand felt annoying, so I installed it. After using it for a while, though, I noticed that Nginx `location` rules are tedious to configure and break easily, so I gradually started thinking I might as well just attach a Virtual Host for every single service. After all, this thing can request SSL certificates too, and not doing it that way would feel like <ruby><del>letting down the me who paid for a domain name...</del><rt style="color:orange">being needlessly fussy</rt></ruby>.
I originally thought about setting one up on the VPS as well, then looked at my V2ray config file and suddenly felt too lazy... forget it....

# Conclusion

Still, messing around with this made me realize a problem.

Right now, this habit of mapping a bunch of random services directly to the host IP works fine behind a private network, but on a directly exposed VPS it feels pretty sketchy. Even though nothing serious is running on it, I still don't like leaving the front door wide open like that. Later on, I should really get into the habit of configuring Docker networks properly and keeping things tucked inside the internal Docker network as much as possible.
