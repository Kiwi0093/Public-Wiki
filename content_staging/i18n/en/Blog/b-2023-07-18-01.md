# ArchWSL

## Github Project

* Link - [GitHub - yuk7/ArchWSL](https://github.com/yuk7/ArchWSL)

* Online Manual - [How to Setup | ArchWSL official documentation](https://wsldl-pg.github.io/ArchW-docs/How-to-Setup/)

## Notes

* You need to initialize `archlinux-keyring` first to avoid issues:
  
  ```bash
  [root@wsl]$ pacman-key --init
  [root@wsl]$ pacman-key --populate
  [root@wsl]$ pacman -Sy archlinux-keyring
  [root@wsl]$ pacman -Syyu
  ```

* You need to create a regular user account (otherwise some GUI apps will have issues):
  
  ```bash
  # 定義wheel群組的User都可以sudo
  [root@wsl]$ echo "%wheel ALL=(ALL) ALL" > /etc/sudoers.d/wheel
  # 建立一個{username}帳號,並且屬於wheel群組
  [root@wsl]$ useradd -m -G wheel -s /bin/bash `{username}`
  ```

* You need to set `{username}` as the default user—this operation must be done outside WSL:
  
  ```bash
  [User@Windows]$ Arch.exe config --default-user `{username}`
  ```

# Archlinux Guest in Virtualbox

## Install

Basically you just boot from the ISO, pick your options in `archinstall`, and install directly. From testing it myself, if you need a desktop you can just choose its `desktop profile`. Looking at my own choice of `KDE`:

* It installs both `Xorg` & `Wayland` by default, and you can choose between them at the `SDDM` login screen.
  
  * Currently `Wayland` support still isn't great—even `ArchWiki` recommends sticking with `Xorg` for now.

## Essential Packages

Recommended essential packages are as follows:

| Pkg Name               | Description                                                     |
| ---------------------- | --------------------------------------------------------------- |
| git                    | Aside from regular Git usage, installing `AUR` packages before `yay` is set up (including installing `yay` itself) relies on it. |
| base-devel             | This is actually a package group containing compilers and related tools, needed if you compile packages yourself. |
| virtualbox-guest-utils | VirtualBox guest tools including special drivers, equivalent to VMware Tools. |
| yay                    | Anyone using an Arch-based distro knows what this is. Manjaro lets you install it directly with pacman, while on Arch you have to install it using the method below. |

### How to Install yay (under Archlinux)

```bash
# 不能用root
[user@archlinux]$ git clone https://aur.archlinux.org/yay-git.git
[user@archlinux]$ cd yay-git
[user@archlinux]$ makepkg -si
```

## Notes

* systemd services need to be enabled manually:
  
  * systemd-resolved.service
    
    * This is the systemd version of resolvconf, mainly needed by `wireguard`.
    
    * `systemctl enable --now systemd-resolved.service`
  
  * vboxservice.service
    
    * This automatically loads components from virtualbox-guest-utils.
    
    * `systemctl enable --now vboxservice.service`

# Conclusion

From what I've seen so far, as long as you copy over some customization configs from `Manjaro` (or another distro you like, such as zsh-theme-powerlevel10k settings), `Archlinux` won't look plain at all.

Installation has also become super easy. In daily use it's Arch-based, pretty much no different (compared to Manjaro).

I'll probably need to observe it for a while longer before making a clearer comparison of pros and cons.
