# Preface

Ever since this uncle switched to using GitHub + Markdown syntax to write blog posts, my efficiency has definitely improved a lot. However, because I wasn't familiar enough with Git commands, I did a lot of really dumb things (like nuking my own repo and starting over from scratch multiple times).

Things like not knowing how to handle diverged branches when pushing—stuff that looks hilariously stupid to experienced Git veterans. So I decided to spend a short post writing down the Git commands I actually use, along with turning the commands I frequently run for this blog into scripts for future use.

# Basic Writing Environment

Basically, my workflow is very simple—I just write on different machines and can't finish a post in one sitting, so I need a way to seamlessly pick up where I left off across machines (when I say "multiple locations," it's really just the office and my dorm).

1. A machine that can run Git — for me, that's basically Manjaro running on my work PC and a Manjaro VM inside Windows in my room.
2. Typora + PicGo — since Typora is cross-platform, there's zero issue there.
3. A GitHub account — based on what I learned in the previous post, you need one repo for the whole site, one repo to serve the public web pages, and another repo to act as an image host. Later on, I'll probably create one more repo to store reusable general-purpose scripts.

In short, as long as I'm somewhere with Git, Typora, and an internet connection, I can write.

# Tool Setup

## Typora

First, you need to install Typora (I used to write with Remarkable, but after getting hooked on Typora, I switched completely).

### Windows

We can use Chocolatey to install it, which is super convenient:

```
choco upgrade typora -y
```

I know the standard syntax is `choco install`, but `choco upgrade` not only upgrades existing packages, it also installs ones that aren't installed yet... so just using this one command is super convenient.

### Linux (Manjaro)

```
yay -Syu typora
```

Typora is currently still in the AUR, so you need to install it using *yay*.



On a side note, although Typora supports a lot of Markdown diagramming syntax, the Hugo theme I picked doesn't support it—so once Hugo generates the static site, those diagrams won't show up. To some extent, rather than trying to render diagrams directly with Markdown syntax, it's simpler to just draw an image and upload it to your image host.

### PicGO

On Typora regardless of platform, you can go to:

> File-->Preferences...-->Image and select PicGo-Core under Image Uploader

It will automatically install PicGo. As for the config file, although the official docs tell you to run:

```
picgo set uploader
```

to configure it interactively, PicGo installed this way is buried in a hard-to-find path, and when using GitHub as an image host, even the interactive setup configures it wrong... It's much easier to just click *Open Config File* and paste in a modified version of the config below.

#### PicGo Config File for GitHub

```json
{
  "picBed": {
    "current": "github",
    "github": {
      "repo": "<github_User_name/Repo_Name>",
      "branch": "master",
      "token": "<your Github Token>",
      "path": "<your path under your Repo>",
      "customUrl": ""
    }
  },
  "picgoPlugins": {}
}
```

> `<github_User_name/Repo_Name>` - Fill in your username/repository name
> `<your Github Token>` - Your GitHub Token for accessing the GitHub API
> `<your path under your Repo>` - Optional subfolder path inside your repo

Basically, this plugin is super powerful: it can upload your local images directly to your image host and automatically rewrite the link to point to the hosted URL, making it effortless to include and manage images in blog posts. One catch is that files with the same name cannot be overwritten, so if an upload fails, check whether there's a filename collision and rename it.

### Common Commands

* git clone - Download an entire Git repo from scratch where nothing exists yet

```bash
git clone --recursive https://github.com/<user_name>/<repo_name>.git
```

Because using GitHub for a blog in this setup involves more than one submodule inside a single Git repo, you need to add the *--recursive* flag to make sure submodules are downloaded as well.

* git config - Used to configure the Git environment; adding the *--global* flag applies settings globally

```bash
git config --global pull.ff only
```

Since I write everything myself, branches shouldn't diverge in general; this specifies that merges should only proceed in fast-forward mode.

```bash
git config --global user.name "<github_account>"
```

This line defines your Git account name.

```bash
git config --global user.email "<your_Email_address>"
```

This defines your email address.

* git branch - Used to create or list branches; for my use case, it's mainly to check whether any messy branches exist that might cause update issues

```bash
git branch
```

This lets you see which branches you have. For details, check out the [Taiwan Git Book](https://gitbook.tw/).

* git checkout - Used to switch branches

```bash
git checkout <repo_you_want>
```

Switches the current branch to `<repo_you_want>`.

* git pull - Fetch and sync from remote

```bash
git pull
```

  Syncs from `origin/master`, equivalent to *git fetch* + *git merge origin/master*.

* git push - The opposite of `git pull`

```bash
git push origin/master
```

Pushing from local up to `origin/master` is the primary command for publishing and uploading.

# Turning It Into Scripts

## Auto-Download to Sync Local with Remote Repo First (Reduces Branch Conflicts)

```bash
#!/bin/bash

echo -e "\033[0;32mSync your Local git folder with github\033[0m"

#pull data from github

git pull

#update theme

git submodule update --remote --merge

```



## Auto-Upload Website Updates and Back Up Source Files

```bash
#!/bin/bash

echo -e "\033[0;32mDeploying updates to GitHub...\033[0m"

# Build the project.

hugo 

# Go To Public folder

cd public

# Add changes to git.

git add .

# Commit changes.

msg="rebuilding site `date`"
if [ $# -eq 1 ]
  then msg="$1"
fi
git commit -m "$msg"

# Push source and build repos.

git push origin master

# Come Back up to the Project Root

cd ..

# Commit source repository changes

git add .
git commit -m "$msg"
git push
```
