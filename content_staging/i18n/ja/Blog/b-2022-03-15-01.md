# はじめに

自宅の内部サービスを整理しているところ……内部向けと外部向けの Server を Private と DMZ に分けたのだが、内部接続で毎回 `http://ip:port` を使うのがどうにも格好悪い（まあ私が気にしすぎなだけだが）。そこで直接名前で指定できるようにリバースプロキシを立てようとした……が、またしても未熟さを露呈する物語となってしまった……。


<!--truncate-->

# 目標

やることは至ってシンプルで、何年も前のような `dual chroot bind` みたいな超複雑な構成にするつもりはなく、手軽な `dnsmasq+adguard home` で内部 DNS（内部ドメインの指定と広告ブロックを含む）を片付けることにした。なぜ `Pi Hole` を使わないのかって？
面倒くさかったのと、先に AdGuard Home を見かけたから。もっとも、シンプルにするために dnsmasq 上で直接広告ブロックをする構成にしてもいいかもしれない。

PS：[師匠が教えてくれた素晴らしいリンク](https://pgl.yoyo.org/adservers/)に感謝。

# 基本構成

構成というほど大したものでもない……外部向けに Traefik を使っているのに対し、内部では自動 SSL が不要（内部ドメインで SSL を組むのも面倒）なので、内部用に `Nginx Proxy Manager` を追加して NPM 経由で転送するようにした。

## 惨劇

理由は分からないが、ごく単純なはずの設定がどうしても通らない……。例えば、

```bash
http://emby.private -> http://emby.private:8888
```

としても、うまくマッピングされてくれなかった。

## 解決策

最終的には docker container 間での指定方法にすることで解決できた。

```bash
http://emby.private -> http://emby:8888
```

これで動くようになった（前提として、同じ docker network 内に配置する必要がある）。
