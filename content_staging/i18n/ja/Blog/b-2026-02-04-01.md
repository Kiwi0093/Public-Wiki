# 調整内容

## Lidarr

### インシデント

原因は `Musicbrainz` が API 関連の設定を変更したことで、`lidarr` が `Musicbrainz` から正常にメタデータを取得できなくなり、`lidarr` の機能が事実上死んでしまったことでした。

### 対策

簡単に言うと、最終的な解決策は「<ruby><font color="lightgreen" size="+3">待つこと</font></ruby>」でした。実際、十分に待った後、`lidarr` の開発チームが `Musicbrainz` の新設定に対応した改修版 `lidarr` を提供してくれました（ただし text search の部分は相変わらずダメなままです）。
<ruby><font color="red" size="+3">しかし</font></ruby>、みんなそれまで待ちきれず、開発チームが修正する前に他の改造版を使ったり mod を当てたりしていました。その結果、改造版を使っていた環境ではそのまま新版にアップデートしても動かず、その後の苦難に満ちた経緯へと繋がってしまいました。

### 紆余曲折の過程

このおじさんが<ruby><font color="lightblue"><del>当時のベストソリューションを積極的に導入した</del></font><rp>(</rp><rt><font color="red">6〜7ヶ月待てずにうっかり手を出した</font></rt><rp>)</rp></ruby>せいで、アップデート後は `lidarr` の config を丸ごと<ruby><font color="red" size="+3">すべて削除</font></ruby>してから、最初から再設定とファイルのインポートをやり直す羽目になりました....いやはや..本当に長くて骨の折れる作業でした....



### 新旧の違い

最大の違いは、修正後の `lidarr` でも依然として `text search` を使って以前のようにアーティスト名やアルバム名を直接検索して `add new` することはできず、先に `Musicbrainz` でそのアーティストの `Artist ID` やアルバムの `Release group ID` を調べる必要がある点です。

そして `lidarr` の `add new` で次のように入力します。

```bash
lidarr:<artist ID/Release group ID>
```

あとは以前と同様に、表示された候補から選んで `lidarr` に追加します。

## ネットワーク関連

### Automedia 構成の調整

以前は参考資料の通りに automedia 構成全体（`radarr`、`sonarr`、`lidarr`、`jackett`... など）を `Gluten` の中にまとめて入れていたのですが、最近 `Gluten` の VPN の調子が少し悪く（実はいつから悪かったのかよく分かっていませんが）、
最初は `jackett` + `flaresolverr` の挙動がおかしいことに気づいたので、このペアを `Gluten` から外に出しました。
続いて `lidarr` の修正中（そう、上で書いたやつです...）に `add new` の search が繋がらないことが分かり...思い切って `lidarr` も `Gluten` から外に出したら直りました...
というわけで、automedia 構成全体から `qbittorrent` だけを `Gluten` 内に残し、それ以外はすべて外に出しました。結局のところ、`qbittorrent` だけ VPN を通して安全を確保し、他のものは VPN の帯域を消費しない方が理想的ですからね....
そして気づいたのですが、参考資料に書かれていた「一緒に置かないと通信できなくなる問題」がなぜか起きませんでした...（おそらく私が automedia 内の各 container に意図的に IP を割り振っているからだと思います...）

### VPN - ERROR [vpn] getting public IP address information:

`docker-compose.yml` の `enviroment` に `PUBLICIP_ENABLED=false` を追加するだけで直りました。
