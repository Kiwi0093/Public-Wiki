# はじめに

おじさんが GitHub + Markdown 記法でブログを書くようになってから、効率は確かに大きく向上しました。しかし、Git コマンドに不慣れだったせいで、かなり愚かな失敗もたくさんやらかしました（自分のリポジトリを何度も消して作り直すなど）。

Push 時に分岐が発生しても対処できないなど、Git を使いこなしている先輩方から見れば呆れるようなことばかりだったので、自分がよく使う Git コマンドやこのブログで頻繁に使うコマンドを簡単な記事にまとめつつ、今後のためにスクリプト化しておこうと思いました。

# 基本的な執筆環境

おじさんの使い方はとてもシンプルで、ただ異なるマシンでブログを書くことがあり、1 記事を一度に書き切れないこともあるため、複数の場所のマシンでシームレスに続きから執筆できる環境が必要です（複数の場所と言っても、実際は職場と寮の 2 拠点だけですが）。

1. Git が動かせるマシン - おじさんは基本的に会社のマシンで動かしている Manjaro と、部屋の Windows 内の VM 上の Manjaro です。
2. Typora + PicGo があること - Typora はクロスプラットフォームなのでまったく問題ありません。
3. GitHub アカウントがあること - 前回の学習結果のとおり、サイト全体を置くリポジトリが 1 つ、公開用の Web ページを置くリポジトリが 1 つ、さらに画像ホスティング用のリポジトリが 1 つ必要になります。今後はおそらく汎用スクリプトを置くリポジトリももう 1 つ作る予定です。

要するに、どこにいても Git と Typora を入れられてインターネットに繋げる環境さえあれば、おじさんはブログを書けるというわけです。

# ツールのセットアップ

## Typora

基本的にはまず Typora をインストールします（以前は Remarkable で書いていましたが、Typora にハマってからはすべてこちらに乗り換えました）。

### Windows

Chocolatey を使うと簡単にインストールできます。

```
choco upgrade typora -y
```

標準的な構文は `choco install` を使うべきだと分かっていますが、`choco upgrade` はパッケージのアップグレードだけでなく未インストールのものも導入してくれるので、このコマンドだけ覚えておけばとても便利です。

### Linux (Manjaro)

```
yay -Syu typora
```

Typora は現時点でも AUR 内にあるため、*yay* を使ってインストールします。



余談ですが、Typora は多くの Markdown 描画記法に対応しているものの、おじさんが選んだテーマが非対応だったため、Hugo で静的 Web ページを生成した後に図が表示されませんでした。なので、ある意味では Markdown 記法で直接図を描こうとするより、普通に画像を描いて画像ホスティングにアップロードした方が手っ取り早いです。

### PicGO

どのプラットフォームの Typora でも、以下のメニューから設定できます。

> File-->Preferences...-->Image 内の Image Uploader で PicGo-Core を選択

すると自動で PicGo がインストールされます。設定ファイルについては、公式サイトでは次のコマンドを使う方法が案内されていますが、

```
picgo set uploader
```

これで自動設定させても……この方法でインストールした PicGo の場所は見つけにくく、しかも GitHub を画像ホスティングにする場合は自動設定を使っても設定内容が間違ってしまいます……。それなら最初から *Open Config File* を使って、設定ファイルを以下の内容に書き換えて貼り付けた方が早いです。

#### GitHub 用 PicGo 設定ファイル

```json
{
  "picBed": {
    "current": "github",
    "github": {
      "repo": "<github_User_name/Repo_Name>",
      "branch": "master",
      "token": "<your Github Token>",
      "path": "<your path under your Repo>",
      "customUrl": ""
    }
  },
  "picgoPlugins": {}
}
```

> `<github_User_name/Repo_Name>` - あなたのアカウント名／リポジトリ名を記入
> `<your Github Token>` - GitHub API にアクセスするための GitHub Token
> `<your path under your Repo>` - リポジトリ内に作成したいディレクトリパスを指定

基本的にこのプラグインは非常に強力で、ローカルの画像ファイルをそのまま画像ホスティングへアップロードしつつ、リンクも画像ホスティングの URL に書き換えてくれます。これによりブログ内で使う画像を簡単にアップロードして適切に設定できます。ただし同じファイル名の画像は上書きできないため、もし失敗したときはファイル名が重複していないか確認してリネームすれば大丈夫です。

### よく使う構文

* git clone - 何もない場所に Git リポジトリ全体をダウンロードする

```bash
git clone --recursive https://github.com/<user_name>/<repo_name>.git
```

この手順で GitHub をブログとして使う場合、1 つの Git リポジトリ内に複数の submodule が含まれるため、*--recursive* オプションを付けて submodule も一緒にダウンロードされるようにします。

* git config - Git の環境設定を行うコマンドで、*--global* オプションを付けるとグローバル設定になります

```bash
git config --global pull.ff only
```

おじさんは基本的に 1 人で書いているため、どのバージョンでも分岐は発生しないはずです。これはマージ時に常に Fast-Forward（FF）モードで行うよう指定する設定です。

```bash
git config --global user.name "<github_account>"
```

この行は自分の Git アカウント名を定義するためのものです。

```bash
git config --global user.email "<your_Email_address>"
```

こちらはメールアドレスを定義するためのものです。

* git branch - ブランチの作成や確認を行うコマンドです。おじさんの用途としては、基本的に変なブランチができていてアップデートがうまくいかないことがないか確認するために使います

```bash
git branch
```

これでどのブランチがあるか確認できます。詳細は[台湾の git book](https://gitbook.tw/) を参照してください。

* git checkout - ブランチを切り替えるコマンド

```bash
git checkout <repo_you_want>
```

現在のブランチを `<repo_you_want>` に切り替えます。

* git pull - リモートから取得して同期する

```bash
git pull
```

  origin/master から取得して同期します。*git fetch* + *git merge origin/master* と同義です。

* git push - git pull の逆

```bash
git push origin/master
```

ローカルから origin/master へプッシュする、公開およびアップロード時の主要コマンドです。

# スクリプト化する

## 自動ダウンロードでローカルを先にリモートリポジトリと同期する（ブランチ発生を防止）

```bash
#!/bin/bash

echo -e "\033[0;32mSync your Local git folder with github\033[0m"

#pull data from github

git pull

#update theme

git submodule update --remote --merge

```



## 自動アップロードで Web ページを更新し、ファイルをバックアップする

```bash
#!/bin/bash

echo -e "\033[0;32mDeploying updates to GitHub...\033[0m"

# Build the project.

hugo 

# Go To Public folder

cd public

# Add changes to git.

git add .

# Commit changes.

msg="rebuilding site `date`"
if [ $# -eq 1 ]
  then msg="$1"
fi
git commit -m "$msg"

# Push source and build repos.

git push origin master

# Come Back up to the Project Root

cd ..

# Commit source repository changes

git add .
git commit -m "$msg"
git push
```
