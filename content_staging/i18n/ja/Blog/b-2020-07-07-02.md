# 事前準備
## VPS
これは多くの人がさまざまな用途でレンタルするものですが、壁越え専用に特化して使うのはおそらく天朝（中国）のネット民くらいでしょう。そのためネット上には数多くのレビューや比較記事があります。おじさんは「ネット上の自由は本来当たり前のものでは？」という思いが長年あるため、VPS 選びはかなりケチな方針です。とにかく最安値で「使えればOK」という基準で選びます。マシンスペックは重要ではありません（ただし KVM であることはとても重要です）……。
* [Anynode](https://anynode.net/) - こちらがおじさんのメイン機です。年額 20 USD のプランを利用しており、月間 500GB の転送量があるため、自室のメイン VPS としては十分です。
* [Hostenos](https://hosteons.com/) - 安くて大容量のお得な選択肢です。2年間で 21 USD、転送量無制限で、唯一の制約は帯域上限 100Mbps という点だけです。気前よくシェアしたい場合や、転送量を気にせず使い倒したい場合に最適です（もっとも 500GB でも 1人で使う分には実質無制限のようなものですが……）。
* [Bandwagonhost](https://bandwagonhost.com/) - 搬瓦工（Bandwagonhost）はとても便利な選択肢です。初期の VPS からすでに *S~hadow~S~ocks~ ワンクリックインストール* サービスを提供しており、最近では *[Just my socks](https://bwgjms.com/post/how-to-buy-justmysocks/)* というサービスも展開しています。少し話が逸れますが、自分で構築する予定がない方には、手間が省けるこうしたプランも検討の価値があります。
## VPS 用の Linux ディストリビューション
安価な VPS を選んでいる以上、GUI 環境や Windows を動かすことはまず不可能で、シンプルな CLI ベースの OS を動かすしかありません。その中で最も扱いやすいのはおそらく ~~FreeBSD~~ Linux でしょう。ただ、人の好みはそれぞれなので、VPS プロバイダが提供している選択肢の中から自分がコマンドに慣れているものを選んでください。
おじさんの好みとしては、基本的に Ubuntu や Debian のような apt パッケージマネージャを使うシステムを選ぶことが多いです。
もっとも、おじさんは Arch Linux に洗脳されて以来、ローリングリリース型のシステムが特に気に入っています（もっとも、システムの安定性を考えると本当は逆を選ぶべきなのですが）。
そのため、ここでは Debian をベースに解説します。別のディストリビューションを使う方は……頭の中でコマンドを読み替えてくださいね。

## ドメイン（任意）

これは WebSocket + TLS + Web 方式でトラフィックを偽装したい場合に必要になります。厳密には SSL 証明書も取得する必要がありますが、SSL の部分は Caddy が自動処理してくれるのでとても簡単です。無料でも有料でも構わないので、自分のドメインを 1つ用意するだけで大丈夫です。

## Cloudflare アカウント（任意）

これは WebSocket + TLS + Web 構成の上にもう一層偽装を重ねて、VPS の Web ポートへの通信経路をすべて遮断されるのを防ぐための「賭け」をする場合に必要です。仕組みとしては、CDN の転送機能を利用して通信を迂回させ、接続を維持します。要するに「Cloudflare ほどの大企業なら、全 IP がブロックされることはないだろう」という考えです。もちろん Cloudflare が好みでなければ他の CDN を使っても構いませんが、やはり Cloudflare の無料アカウントは魅力的です。

なお、偽装を多く重ねるほど通信速度は落ちてしまいます。こればかりは仕方ないので、各自のニーズに合わせて速度と信頼性のバランスを見極めてください。

# インストール

## システムの基本インストール
1. ブラウザから VPS の管理画面を開き、好みの Linux ディストリビューションを選択して OS をインストールします。おじさんは Debian を選びました。

2. インストール完了後、SSH の設定を行います（Web ターミナルなど、どの方法で設定しても構いません）。

3. お好みの SSH クライアントで VPS にログインします。

4. 今後の管理ログインのためにパスワードを変更します。

```bash
passwd
```

5. システムを更新します。

  ```bash
  #Debain or Ubuntu
  sudo apt update && apt upgrade
  
  #Archlinux
  sudo pacman -Syu
  ```

  

6. 必要なプログラム（Vim、V2Ray、Caddy）をインストールします。

   ```bash
   #Debain or Ubuntu
   sudo apt install vim
   bash <(curl -L -s https://install.direct/go.sh)
   echo "deb [trusted=yes] https://apt.fury.io/caddy/ /" | sudo tee -a /etc/apt/sources.list.d/caddy-fury.list
   sudo apt update
   sudo apt install caddy
   
   #Archlinux
   sudo pacman -Sy yay
   yay -Sy vim v2ray caddy2 
   ```

   

元のブログを書いた当時は Caddy がまだ正式に Caddy2 へ移行していませんでしたが、Caddy 公式サイトが「Caddy v1 は現在 limited support のみ」と宣言しているため、v2 へのアップデートは遅かれ早かれ必須になります。

  こうして見ると、やはり Arch の方が簡潔できれいですね（単なるひいき目です）。

### 自動インストールスクリプト - Apt 系（Debian/Ubuntu）

```bash
#!bash

#變數定義
COLOR='\033[1;35m'
NC='\033[0m'

echo -e "${COLOR}Update Ubuntu System${NC}"
apt-get -y update
apt-get -y upgrade

echo -e "${COLOR}Install V2ray${NC}"
bash <(curl -L -s https://install.direct/go.sh)

echo -e "${COLOR}Set Auto Monthy Update V2ray${NC}"
echo '59 3    1 * *   root    bash <(curl -L -s https://install.direct/go.sh)'  >> /etc/crontab

echo -e "${COLOR}Install BBR${NC}"
bash <(curl -L -s https://github.com/teddysun/across/raw/master/bbr.sh)

echo -e "${COLOR}Install Caddy${NC}"
wget "https://github.com/caddyserver/caddy/releases/download/v2.1.1/caddy_2.1.1_linux_amd64.deb"
dpkg -i ./caddy_2.1.1_linux_amd64.deb"

echo -e "${COLOR}Setup  Caddy${NC}"
mkdir /etc/caddy
chown -R root:www-data /etc/caddy
mkdir /etc/ssl/caddy
chown -R www-data:root /etc/ssl/caddy
chmod 0770 /etc/ssl/caddy
mkdir /var/www
chown www-data:www-data /var/www
ufw allow http
ufw allow https
apt install libcap2-bin
setcap cap_net_bind_service=+ep /usr/local/bin/caddy
echo '<h1>Hello World!</h1>' | sudo tee /var/www/index.html

#Making Caddyfile for Caddy2
echo -e "${COLOR}Configure your Caddy setting${NC}"
echo -n "Please Enter your Domain name:"
read domain
echo "$domain" { > /etc/caddy/Caddyfile
echo tls { >> /etc/caddy/Caddyfile
echo "protocols tls1.2 tls1.3" >> /etc/caddy/Caddyfile
echo ciphers TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384 TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256 >> /etc/caddy/Caddyfile
echo curves x25519 >> /etc/caddy/Caddyfile
echo } >> /etc/caddy/Caddyfile
echo @v2ray_websocket { >> /etc/caddy/Caddyfile
echo path /ray >> /etc/caddy/Caddyfile
echo header Connection *Upgrade* >> /etc/caddy/Caddyfile
echo header Upgrade websocket >> /etc/caddy/Caddyfile
echo } >> /etc/caddy/Caddyfile
echo -n "Please Enter your V2Ray port"
read PORT
echo reverse_proxy @v2ray_websocket localhost:$PORT >> /etc/caddy/Caddyfile
echo } >> /etc/caddy/Caddyfile

echo -e "${COLOR}Setup V2ray${NC}"
echo -n "${COLOR}Please Enter where you put the file:${NC}"
read link
echo -n "${COLOR}Please Enter the file name:${NC}"
read conffile
wget $Link/$conffile
mv -f  ./$conffile /etc/v2ray/config.json

echo -e "${COLOR}Please enter information as required, and press Ctl+c when Caddy running well${NC}"
caddy run -conf=/etc/caddy/Caddyfile

echo -e "${COLOR}Rebooting your VPS for normal operation${NC}"
reboot
```

## V2Ray

正直なところ、V2Ray は非常に優秀なツールです。基本的には単一のプロトコルではなく「フレームワーク」であるため、設定は（比較的）複雑ですが、一度理解してしまえば、仮に将来 VMess が使えなくなったとしても、

おそらく VMess2 や別の有用なプロトコルが V2Ray フレームワークに組み込まれて使い続けられるでしょう。

現在の V2Ray は、ネットワークのトラフィック制御ソフトウェアとしての特性上、すでに次のような機能を備えています。

* ローカルの UDP 53 番ポート宛てのパケットをすべて捕捉し、指定した特定 IP の特定ポートへ転送することで DNS 機能を実現する

* 指定したポートに流入するトラフィックをすべて特定のプロトコルで指定先の IP マシンへ転送し、プロキシ（踏み台）のような機能を実現する

一歩引いて考えれば、たとえ壁越え用の踏み台として使わなくても、V2Ray を使って家庭内ネットワークにファイアウォールのような制限をかけ、子どもが家のネットから接続してはいけないサイトにアクセスするのを防ぐこともできるはずです（もっとも、そうした機能は普通の FW で実装すれば済む話なので、わざわざこんな手間をかける必要はありませんが）。

V2Ray の具体的な設定については [新V2Ray白話文指南](https://guide.v2fly.org/advanced/wss_and_web.html#%E6%9C%8D%E5%8A%A1%E5%99%A8%E9%85%8D%E7%BD%AE) を参照してください。非常に詳しく実用的で、基本的には自分で少し書き換えるだけでそのまま使えます。

現在の環境では、WebSocket + TLS + Web に Cloudflare などの CDN を組み合わせる構成がおすすめです。ネット上にも多くのチュートリアルがあるので参考にできます。


## Caddy

Caddy v2 のインストールを比べると、やはり Arch 系で `yay` を使ってインストールする方が簡単です。Debian/Ubuntu 系では公式サイト通りの手順だと `apt` でうまくインストールできなかったため、おじさんは最終的に GitHub 上の `.deb` ファイルをダウンロードしてインストールする方法を選びました。欠点としては、自動インストールスクリプト内のファイルバージョンを毎回最新版に合わせて書き換える必要がある点です。

もう 1つの違いとして、Arch 系では設定ファイルが */etc/caddy/caddy.conf* になるのに対し、`.deb` でインストールした場合は従来通り */etc/caddy/Caddyfile* になります。

今後の運用でトラブルを起こさないよう、この点には注意してください。

### Caddy2 設定
この設定ファイルは [新V2Ray白話文指南](https://guide.v2fly.org/advanced/wss_and_web.html#%E6%9C%8D%E5%8A%A1%E5%99%A8%E9%85%8D%E7%BD%AE) を完全に参考にしています。
```json
# Caddy v2 (recommended)

<mydomain.me> {
    log {
        output file /etc/caddy/caddy.log
    }
    tls {
        protocols tls1.2 tls1.3
        ciphers TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384 TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256
        curves x25519
    }
    @v2ray_websocket {
        path /<your_path>
        header Connection *Upgrade*
        header Upgrade websocket
    }
    reverse_proxy @v2ray_websocket localhost:<your_port_Number>
}
```

> `<mydomain.me>` はご自身のドメインに置き換えてください（`<>` は不要です）
>
> `<your_path>` は V2Ray で設定した WebSocket パスに置き換えてください（`<>` は不要です）
>
> `<your_port_Number>` は V2Ray のポート番号に置き換えてください（`<>` は不要です）

それ以外はそのままコピーして構いません。

厳密に言えば、Caddy の設定ファイルはこの記事を書くタイミングで v2 へ移行したばかりなので、おじさん自身もまだあまり慣れていません。詳しくは [Caddy の公式ドキュメント](https://caddyserver.com/docs/getting-started) を直接確認することをおすすめします。
