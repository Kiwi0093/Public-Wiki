## Ansible の制約

Ansible は高機能で何でもスマートにこなせそうに見えますが、（私にとっては）次のような制約もあります。

* 実行中に手動で入力を求めるような運用に向いておらず、すべての設定をあらかじめ記述しておく必要があります。`GitHub` のようなパブリックな Git サーバーを使う場合、セキュリティ面が少し気になります。

* 挙動の差分は Host Vars で定義し、非定型の処理は独立した playbook セクションで制御する形になるため、上記の点と合わせるとサーバーの初期構築時のセットアップにはあまり使い勝手が良くありません。

* SSH アカウント経由で制御するため、同様に、インストール直後でユーザーアカウントも対応する SSH キーもまだないマシンにはすぐには使えません。

## Kiwi 流の使い方

* 一般的な初期インストールは `shell script` で行い、対話的な手動入力などのオプションを残しておくことでスクリプトの汎用性を高めます。

* スクリプトと併用しつつ、Ansible は主に反復性・均質性の高い作業の制御に使います。たとえば全サーバーの一斉アップデートや、Ansible を介した全サーバーの設定ファイルのバージョン管理などです（Ansible は基本的に Git サーバーと組み合わせて運用するため）。

* 複雑な設定を要する利用環境を Ansible で自動構築します。たとえば複数台のデスクトップ環境を揃えたり、デスクトップを再インストールする際の手間を省いたりする用途です（この点自体はスクリプトでも実現できますが、スクリプトだと設定ファイル単体でのバージョン管理がやややりにくくなります）。

# やり方
