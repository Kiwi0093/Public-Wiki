# 爆散

以前、誰かが「Arch Linux を使うならアップデート後にいきなり原因不明で落ちる覚悟をしておけ」と言っているのを見たことがありますが、私はもう10年近く使っていて（ハッ！！ 私ってそんなに年を取ったのか？ 2015年から使い始めたんだっけ……）、正直なところアップデートで動かなくなった経験が一度もありませんでした。だから「壊れるのを恐れて意地でもアップデートしない」人がいるのが理解できずにいました……。

先週、何気なく自分のリモートデスクトップに `yay -Syu --noconfirm` を一発食らわせるまでは……。そして気づいたら……「その後」はありませんでした。マシン自体は起動しているようなのにリモート接続ができず、ESXi に繋いでコンソールを覗くと画面が真っ暗……完全に……逝っていました……。

# Root Cause

root cause が何かなんて私が知るわけないでしょう……プログラムなんて書けないんですから……。

ただ、以下の検証は行ってみました。

* Manjaro with sddm + KDE plasma をインストール - 正常に使用可能
* EndeavourOS with KDE をインストール - LiveDVD は起動するが、再インストール後は画面が真っ暗
* Re-install
	* `linux-6.14`、`linux-lts-6.12` などの選択肢を組み合わせても、インストール後の再起動で画面が真っ暗
	* `gdm` + KDE Plasma に変更 - 正常だが、ESXi 内では Wayland のみ正常動作

しかもこれらの異常はすべて VMware Workstation 17 Pro でテストしても同様に発生しました……。

## 推測される原因

1. `sddm` と VMware の相性が悪い。Manjaro 以外では、`sddm` を使うと起動時に画面が真っ暗になる。
2. X11 と `gdm` の相性が悪い。`gdm` にすれば画面は表示されるものの、`plasma-x11` セッションにログインしようとすると問題が起きる。

以上2点から察するに、~~Broadcom がお祓いに行かなかったせいで~~ VMware は親会社が変わってからみんなに嫌われるようになったのでは……。

# まとめ

現在私は `gdm` + KDE Plasma という構成にしていますが、Wayland 版 Plasma は VNC に対応しておらず、このマシンは主に私の VDI 用として使っているため、`systemd` で `vncserver@:1.service` を動かし、起動時に VNC で `plasma-x11` セッションを立ち上げるようにしています。
今のところ問題は起きていませんが、やはり最終的には ESXi から PVE（Proxmox VE）へ移行するしかなさそうです。

ちなみに、今回の騒動は別で動かしているコンソール専用の Arch Linux には一切影響がなかったため、厳密には Arch Linux の突然死とは言えません。よかった！！ むしろ Arch Linux への信頼度は下がるどころか上がりました（えっ？？）。
