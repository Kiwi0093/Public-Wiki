# 不思議なとあるプロジェクト

## 発端

事の始まりは、上司から IT 部門の某プロジェクト（企業秘密に関わるため詳細は伏せます……）のサポートをアサインされたことでした。

ポイントは、私に割り当てられた任務がそのプロジェクトの PM 役だったはずなのに、お節介な性格が災いして……プロジェクトのサーバー構成にまで手を出してしまったことです……。

## 主な罪状

この案件では社内環境に `SQL-Server + JDK 環境 + Samba` を用意する必要がありました。

当初、弊社の IT 部門が伝家の宝刀である Windows Server を持ち出してすべてを片付けようとしていたところ、私がつい余計な一言を挟んでしまいました。

`これってペンギン＋コンテナで直接構築した方がバックアップも楽じゃないですか？`

しかも、目立ちたがり屋な私は以前から自宅環境の成果を IT メンバーに見せびらかしていたため……こんな返事が返ってきました。

`私たちもそう思うんですが、やり方が分からないので、環境を立ち上げてもらえませんか？`

## 結果

### Amazon Linux 2

将来的にこのマシンはそのまま AWS 上で動かす予定のため、Linux のディストリビューションは Amazon Linux に限定されました。

正直なところ、ローカルの VMware Workstation 上でこの代物をテストするのはなかなか萎える作業でした……。

インストールが面倒で煩わしいのです（というか本当に面倒というより、自分の実力不足でネットワーク設定ひとつに苦戦して自滅しかけただけです）。

セットアップが終わってみると、使い心地は `Oracle Linux` にかなり似ています（まあ、ほぼ同じソースをベースに改変しているのだから当然ですが……）。

### MS SQL-Server on Docker

こちらは Microsoft が太っ腹にも SQL-Server 2019 の公式 Docker Image を提供してくれているおかげで、そのまま導入するだけで済みました……。

（ええ、私の言う「開発」とは、動く `docker-compose.yml` を 1 本仕上げたらそれで完了というやつです）
