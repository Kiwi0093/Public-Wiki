# 基本概念

## DistroBox

プロジェクト URL - [GitHub - 89luca89/distrobox](https://github.com/89luca89/distrobox)

紹介記事 - [Distrobox: Try Multiple Linux Distributions via the Terminal](https://itsfoss.com/distrobox/)

要するに、これは `docker` や `podman` を使って別の Linux ディストリビューションをコンテナとして動かし、その中にあるアプリをホスト側にエクスポートして実行できる仕組みです。

# 実際に使ってみた

個人的には `Fedora 36 KDE Plasma Edition` 上で試してみました（残念ながらスクリーンショットを撮る前に VM ごと削除してしまいましたが）。

動作自体は問題なくできましたが、いくつか気になる点もありました。

## DE & WM

基本的にはホスト側の環境がそのまま使われるため、ホスト側が `Wayland` だとコンテナ内の `ulauncher` の挙動がおかしくなりました……。

## Kernel

そもそも `docker` / `podman` をベースに動いている仕組みなので……カーネルがホストと違うわけがないですよね？？

## 関連コマンド

いろいろ書きましたが、実際にはまだ一番ベストな使い方を使いこなせていないだけかもしれません。ただ、エクスポートしたアプリがホスト側の設定ファイルをそのまま読み込めるだけでも非常に便利です。実際、なぜかホスト側に Brave をインストールしていないのに設定ファイルだけ置いてあった環境で、コンテナ内の Brave を起動したらホスト側の設定がそのまま適用されました……最高です！（ただし `ulauncher` は完全に動かなくなってしまいましたが。）

基本的なコマンドは以下の通りです。

| Distrobox 内外 | コマンド | 用途 | 使用例 | マニュアルリンク |
| ---------------- |:-----------------------------------------------------:| ------------------------------------------------------ | ------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| コンテナ外 | distrobox create -n name -i Docker image | distrobox コンテナを作成する | distrobox create -n Archlinux -i Archlinux | [Distrobox-create](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-create.md) |
| コンテナ外 | distrobox enter `<name>` | 指定した名前のコンテナに入る | distrobox enter Archlinux | [Distrobox-enter](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-enter.md) |
| コンテナ外 | distrobox list | すべてのコンテナを一覧表示する | distrobox list | [Distrobox-llist](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-list.md) |
| コンテナ外 | distrobox rm `<name>` | コンテナを削除する | distrobox rm Archlinux | [Distrobox-rm](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-rm.md) |
| コンテナ外 | distrobox upgrade `<name>` | コンテナをアップグレードする | distrobox upgrade Archlinux | [Distrobox-upgrade](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-upgrade.md) |
| コンテナ内 | distrobox-export -a `<app Name>`  -ep `<path to outside>` | コンテナ内にインストールしたアプリをホスト側へエクスポートして使えるようにする | distrobox-export -a Brave -ep ~/.local/bin | [Distrobox-export](https://github.com/89luca89/distrobox/blob/main/docs/usage/distrobox-export.md) |

## 追加のポイント

私の例ではすべて `distrobox` で `Archlinux` コンテナを作成して `AUR` を使い倒す形にしています。その一番の理由は、逆に Arch 系ディストリビューションの上でわざわざ `Fedora` や `Debian/Ubuntu` を動かす必要がないからです（アップデートで壊れるリスクがある点を除けば、Arch 系のアプリ導入のしやすさは圧倒的なので……）。

ただ、ここで少し困った点があって――自分でも `Archlinux` 派というより `Manjaro` 派と言った方が近いのですが……残念ながら `manjaro` はいまいちで、公式 Docker イメージの出来がかなり悪く、Archlinux には到底及びません……。

# 今後の最適解候補

最近 `Fedora` を試してみて、ベース OS として非常に優秀だと感じました。これに AUR が使える組み合わせとなればまさに無敵です（私のようなお気楽な人間が想像するほど単純な話であれば、ですが）。とはいえ、デスクトップの雰囲気やカスタマイズ可能な範囲を考えると……まだしばらくは `Manjaro` のまま使い続けることになりそうです……。
