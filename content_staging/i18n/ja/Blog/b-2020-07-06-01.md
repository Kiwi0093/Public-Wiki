# はじめに

先日 [CTT](https://www.youtube.com/user/homergfunk/featured) の YouTube チャンネルを見て、Hugo + GitHub や Hugo + Netlify という選択肢もブログ作りにちょうど良さそうだと知りました。Blogger の編集モードがあまり先進的ではないことや、私自身 Markdown 記法へ移行しようと頑張っていることもあり、この記事を機に、誰も見ていないこのブログを Blogger から GitHub へ引っ越ししつつ、今風の Git を使ったブログ管理も学んでみることにしました。

## 事前準備

新しいブログには以下のツールが必要になります。

* **[Hugo](https://gohugo.io/)** - 静的サイトを生成するためのツールで、Linux、Windows、macOS、FreeBSD などのプラットフォームに対応した純粋な CLI ツールです。

* **[Github](https://www.github.com)** - Microsoft の中で最も太っ腹なサービスと言えるでしょう。主に無料で自分のプロジェクトを作成でき、git コマンドで手軽にアップロードや管理ができる点を利用します。

* **[Remarkable](https://remarkable.com/)** や **[Typora](https://typora.io/)** などの Markdown エディタ - 主にブログ記事の本体となる md ファイルを手軽に編集するためのもので、今回乗り換える一番の理由でもあります。

* **[git](https://git-scm.com/)** - 非常に強力なツールです。Linux であれば基本的に最初からインストールされていますが、Windows を使う場合は別途インストールが必要です。

意外と必要なツールは少ないのですが、私自身まだ慣れていないため参考資料はそれなりに多く必要でした。ただ、Google で *hugo チュートリアル* などと検索すれば情報自体はたくさん見つかります。

## インストール手順

### Hugo のインストール

私は主に勤務時間中にこっそりブログを書くので、メイン環境として Manjaro を使っています。まずは何はともあれ Hugo をインストールします。

```bash
sudo pacman -S hugo
```

### GitHub リポジトリの作成
ここでは [chanmitsu55 氏](https://chanmitsu55.github.io/posts/2017/12/create-blog-by-hugo/) のやり方を参考にすることをおすすめします。
まず GitHub のアカウントが必要になりますが、これは無料なのでメールアドレスで登録してください。登録できたら、リポジトリを2つ作成します。

1. 自分のサイトと同じ名前のリポジトリ（私の場合なら `Blog`）
2. `<username>.github.io` というリポジトリ

先にサイトと同名のリポジトリをローカルの基本ディレクトリとして clone しておきます。

	`git clone https://github.com/<username>/Blog.git`

### サイト本体の作成・ローカル作業ディレクトリへのコピー・public サブモジュールの追加
次に新しいサイトを作成します。この手順はおそらく初回に1回やれば十分です。

```bash
hugo new site _blog
cp -p -f -R _blog/* Blog/
cd Blog
git submodule add -b master https://github.com/<username>/<username>.github.io.git public
```

先にコピーしてから行う理由は、私が使っている Fuji テーマが submodule 形式で組み込む仕組みになっており、git 管理下のディレクトリでないと submodule を追加できないためです。
また、Hugo でサイトを生成する前に `public` を追加しておくのは、どうせ後から追加しようとすると一度 *rm -rf public* してからでないと追加できないため、最初から無い状態で追加しておいた方が手間がないからです。

### テーマのインストール
これで基本的なサイトの骨組みができたので、次に見た目を整えるためにテーマをインストールします。
私はシンプルなものが好みなので、[Fuji](https://themes.gohugo.io/hugo-theme-fuji/) というシンプルなテーマを選びましたが、皆さんはお好みのものを入れてみてください。

```bash
cd ~/Blog
git submodule add https://github.com/amzrk2/hugo-theme-fuji.git themes/fuji
```

これでテーマのインストールは完了です。続いてこのテーマの簡単な設定を行います。

```bash
cp themes/fuji/exampleSite/config.toml ./
cp -R themes/fuji/exampleSite/content/archives ./content/
cp -R themes/fuji/exampleSite/content/search ./content/
```

ここで重要なのは `exampleSite` の中にある `config.toml` を持ってきて編集することです。残りの2つは、メニューに Archive と Search だけを残したかったのでコピーしました。

次に `config.toml` を編集します。

`vim config.toml`

いくつかの主な項目を変更します。

```bash
#這個是定義你的主頁網址,請跟你的設定一致
baseURL = "https://Kiwi0093.github.io"	
#這個是你的網頁主要Title
title = "中年大叔的自言自語"
#這個是定義你網頁的主題
theme = "fuji"

[params]
  #這個是作者的名字
  author = "Kiwi.L"
  #這個是網頁的副標
  subTitle = "對應老年癡呆與記憶衰退的筆記"	

[taxonomies]
  #這是定義Tag會使用tags來進行分類
  tag = "tags"

[menu]
  #這個定義的是導向哪邊而非簡單的link
  [[menu.nav]]
   #這個定義了右邊連結的Home
   name = "Home"
   #連線是相對位置*/*對應的是*./content*
   url = "/"
   #這個定義了排序
   weight = 1
[[menu.nav]]
   name = "Archives"
   url = "/archives/"
   weight = 2
[[menu.nav]]
   name = "Search"
   url = "/search/"
   weight = 3
 #這個定義的是簡單的link
[[menu.link]]
 #這個是你想要表現的字串
   name = "R2d Blog"
   #這個是他的連結
   url = "https://roidintw.kaienroid.com/"
   #這個一樣是排序
   weight = 1
```

### 新規記事の作成と書き方
ここまでの設定が終わればサイトの骨組みはほぼ完成です。あとは簡単な記事を書いてみましょう。

```bash
cd ~/Blog
hugo new post/what-ever-you-like-to-name.md
```

お好みのエディタでこのファイルを開くと、次のような内容になっています。

```bash
#這個---不要動
---
#這個是這個文件的主題會出現在Post的標題上
title: "what-ever-you-like-to-name"
#這個是時間戳記
date: 2020-07-06
#這是標記是否為草稿,寫好要正式發出去的文章把這行去掉
draft: true
#增加tag的寫法
tags: [ "A-tag", "B-tag", "C-tag" ]
#這個---不要動
---
```

上の内容をその記事のヘッダー（Frontmatter）として編集し、その下に Markdown 記法で直接ブログの本文を書いていけばOKです。ここまでで基本的なポイントは完了で、次はサイトの生成と GitHub への公開です。

### サイトの生成とローカルテスト
公開する前に、まずはサイトを生成してローカル環境で意図通りに表示されるか確認しましょう。

```bash
cd ~/Blog
hugo && hugo server
```

表示された案内に従ってアクセスし、他に調整する箇所がないか確認して、問題なければいよいよ GitHub へ公開します。

### 自動デプロイスクリプト
この部分については、公式が推奨しているスクリプトや手動での commit 入力はよく忘れがちなので、ここでは [chanmitsu55 氏] のバージョンを採用しました。後ろに更新日時を付けるだけのシンプルなものです。

```bash
#!/bin/bash

echo -e "\033[0;32mDeploying updates to GitHub...\033[0m"

# Build the project.我們已經在config.toml裡定義了theme所以簡單的hugo就夠了
hugo

# Go To Public folder
cd public
# Add changes to git.
git add .

# Commit changes.
msg="rebuilding site `date`"
   if [ $# -eq 1 ]
   then msg="$1"
   fi
git commit -m "$msg"

# Push source and build repos.
git push origin master

# Come Back up to the Project Root
cd ..

# Commit source repository changes
git add .
git commit -m "$msg"
git push
```

私は直接実行ファイルにするのがあまり好きではないので、上記の内容を `deploy.sh` に保存して以下のコマンドで実行しています。

`sh ./deploy.sh`

実行途中で GitHub のアカウントとパスワードを2回求められます。それぞれ `Blog` と `public` を push するためのものなので、入力ミスに気をつけてください。

### 別環境での作業

では、他のマシンでも編集したくなった場合はどうすればよいでしょうか？基本的には以下のコマンドを実行するだけで、最初からすべてを手元に取得できます。

`git clone --recursive https://github.com/<username>/Blog.git`

すでに古い git フォルダがあるマシンであれば、単純に新しい更新分だけ pull/push すれば問題ありません。`git push`/`pull` は差分比較で処理されるため、更新されていないファイルはアップロードされません（極度の心配性で通信費も気にならないなら、毎回新しく clone しても構いませんが）。
こうして、自分のデータは基本的にすべて GitHub 上に保存して管理できるようになります。
