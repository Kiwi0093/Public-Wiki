# 実験内容

## Portainer-agent

### 雑談

VPS に Docker を入れたものの何をするか決まっていなかったので、最初のコンテナとして `portainer-agent` を動かしてみました。すでに運用しているホスト側の管理画面に繋いでみたところ、ちゃんと動作しました！`k8s` や `docker-swarm` を動かしていなくてもノードを追加して管理できるのは便利ですね（ただし `portainer-agent` を入れる必要はありますが）。

### 感想

具体的な手順は Wiki の方にまとめてあるのでここでは雑談だけ書きますが、`portainer-ce` + `portainer-agent` に加えて stack 機能を使う運用はやはりかなり快適です。コンソールに入って `docker-compose` コマンドを叩く必要がなく、最初から CLI 派でなければ本当に使いやすいと思います（特に stack を他のマシンへマイグレーションしたり複製したりできる点が便利です）。

## Nginx Proxy manager

### 雑談＆感想

これを導入した一番の理由は、もともと複数の階層（パス）を使って各種 Web サービスを公開しようとしていたものの、自分で Nginx の設定ファイルを書くのが面倒になったからです。ただ実際に使ってみると、Nginx の location 設定は何かと面倒でトラブルも起きやすいため、だんだん「いっそすべてのサービスにそれぞれ Virtual Host を割り当ててしまえばいいや」と思うようになりました。どのみちこのツールなら SSL 証明書も自動取得できますし、そうしないとなんだか<ruby><del>お金を払ってドメイン名を買った自分に申し訳ない気がして……</del><rt style="color:orange">ただの見栄っ張りなだけです</rt></ruby>
当初は VPS 側にも同じものを立てようかと思っていたのですが、手元の V2Ray の設定ファイルを眺めていたら急に面倒になって……まあいいか、と諦めました……。

# まとめ

ただ、いろいろ触っているうちに一つ問題に気づきました。

これまでプライベートネットワークの内側でやっていたように、雑多なサービスを片っ端からホスト IP に直接マッピングするやり方を、外部に直接公開されている VPS 上でそのままやるのはやはり気持ちが悪いなと。大したものを動かしているわけではないとはいえ、こういう無防備に門戸を開け放つような構成はあまり好みではないので、今後はきちんと `docker network` の設定に慣れて、極力コンテナを Docker ネットワーク内部に隠蔽するようにしていきたいと思います。
