# Red Hat がダウンストリームの再構築向けソースコード公開を停止

## 個人的な見解

商用版（しかも有料で販売している製品）として、ライセンスや `source code` を提供しない形で商業的価値を維持するのはごく自然なことです。`SUSE` の商用版（SLES）だって、そのまま再構築できる形で `Source code` を直接配布したりはしていません

それに両者とも、それぞれアップストリームの `open source` 版を持っています

|                | Red Hat                  | SUSE                  |
| -------------- | ------------------------ | --------------------- |
| Open Source アップストリーム | Fedora / CentOS stream   | OpenSuSE              |
| 商用バージョン           | Red Hat Enterprise Linux | SUSE Linux Enterprise |

今回切り捨てられたのは `RHEL` のダウンストリームですが、よく考えれば無理もない話です。開発企業だって利益を出さなければなりませんし、開発者だって生活していかなければなりません。

会社が軌道に乗る前にどれほど良い約束をしていたとしても今さら反故にするなんて、とか言われますが、結婚したって離婚する人はいるし、神様の前で誓ったことだって平気でしらばっくれる世の中ですからね……

今のところ SUSE や Oracle などが便乗して話題に乗っかっていますが、結局のところこの機会に Red Hat を叩いて世論の風向きをうかがい、もともと Red Hat を支持していた潜在顧客が乗り換えて自社の有料ディストリビューションに流れてこないか狙っているだけだと思います。この先どうなるか見守っていくとしましょう

# NixOS

最近なぜだか Linux 系 YouTuber の間で急に NixOS が流行り始めたので、私も流行に乗って少し試してみました

## 試用してみた感想

正直なところ、最初に触れた瞬間の衝撃は昔初めて `Gentoo` をインストールしたときと近く、感想もだいたい似ていて、要するにこんな感じでした

> おお〜これの特殊機能めっちゃクールじゃん〜こんなこともあんなこともできるんだ〜～

そして冷静になってから考えてみると、使おうと思えば使えるけれど結構面倒だし、別になくても困らないかな、と。

どうしてもこれを使わなければならない理由が見つかりません……

### 特徴

`NixOS` は基本的に、1 つのパッケージマネージャが所有している専用 OS みたいなものです……（ある時代のプロイセンにそっくりですよね……よそは国家が軍隊を持っているけれど、プロイセンは軍隊が国家を持っている、というアレです）

`NixOS` の本体は `Nix` というパッケージマネージャそのものであり、1 つ（あるいはインポート可能な複数）の `.nix` 設定ファイルを使ってシステム全体を構成できます（とは言うものの、やはり `~/.config` 内に設定が残る仕様は普通にあります）。しかもパッケージの更新・追加・削除のたびにシステムリンクを再構築するため、各`バージョン`が独立しており、さらにシステム本体に影響を与えずに異なるプロファイルの開発環境を構築することもできます

聞いている分にはとてもクールで素晴らしいですよね

### 欠点

これだけクールな特徴がある以上、まだ克服されていない相応の欠点も当然あります（等価交換ですね）。ちょっとかじって試しただけでも以下の点が気になりました

* 恒久的にシステム設定を変更するには、必ず `/etc/nixos/configure.nix` の設定を書き換えて `nixos-rebuild switch` を走らせ、システム全体のバージョン更新を行う必要がある

* システム自体にメジャーバージョン番号があり、いわゆる `channel` という仕組みも存在するうえ、「`1 つの設定ファイルですべてを統べる（configure file rules them all）`」という要件を徹底するために `flake` なるものまで導入された結果……どんどん話が複雑になってしまいました……これなら最初からローリングリリース方式にしておけばよかったのでは……

* ディスク容量をかなり食います。`nix-garbage-collection` の機能で指定範囲外のバージョン履歴を削除することはできますが、それをやってしまうとある意味、支持者たちが誇りにしている各種バージョンロールバック機能も失われてしまいます。スナップショットを全部消してしまったら、一体何に戻すというのでしょうか？？

### 小さなまとめ

おもちゃとして遊ぶ用途や、同質性の高いマシンを大量に構築・管理する必要がある人にはかなり向いています。ただし、システムを頻繁にいじらないこと、あるいは設定調整専用の実験機で仕上げてから全体に適用する運用が前提になります。

一般的なデスクトップ環境として普段使い（daily drive）するにはあまり向いていないでしょう……

よほど複数の開発環境を 1 つのシステム上で干渉させずに統合したくて、なおかつ Docker 系のコンテナ技術が死ぬほど嫌いだというのでもない限りは……。

# NeoVim+Nvchad

これは実は手持ち無沙汰で `NixOS` をテストしていたついでにもう一度触ってみたものです（普段はしばらく手をつけていませんでした）

ポイントはいくつかだけです

* Arch ベースの Linux では `AUR` から `NvChad` をインストールしないでください。エラーが出ます。素直に `git clone` しましょう

* アップデート版ではデフォルトのキーバインドがかなり使いやすくなっていて、手動でキーマッピングを書き換える必要はほとんどありません。しかも `<leader>+ch` でホットキーの `cheat sheet` も確認できます

* LSP 周りと Format はまだうまく設定できていないので、また時間を見つけて調べてみます……
