# はじめに

最近ちょっとマメにシステムアップデートをかけてみたところ……私の Unifi Controller が一発の `yay -Syu --noconfirm` で見事に吹き飛びました。

<!--truncate-->

# 障害記録

`yay -Syu --noconfirm` を叩いてそのまま最後まで走り切ったあと、Unifi Controller の Web UI に接続できなくなりました。
調査を開始したところ、以下の状況が判明しました。

* `systemctl status unifi.service` の結果は `active` で一見正常だったが、`netstat -an` で確認すると Unifi Controller の待ち受けポートが開いていない

* `/var/log/unifi/server.log` を確認すると `exit code=62` で終了していた

* `systemctl status mongodb.service` を確認するとこちらも `exit code=62` になっており、調べたところ MongoDB のデータベースバージョンが古くて正常に起動できていなかった

* `/var/log/mongodb/mongodb.log` を確認すると、データベースのバージョンは 7.0 である一方、AUR で更新された `mongodb-bin` のバージョンは 8.2 になっており、バージョン差が大きすぎて起動できない状態だった

* `mongodb80-bin` パッケージに入れ替えたところ、コマンドで MongoDB のメジャーバージョンを 8.0 まで引き上げることができた

遠回りしてモヤモヤしたポイント

* MongoDB のデータベースアップグレードの仕組み
  
  * MongoDB は一気に複数バージョンを飛び越えてデータベースをアップグレードできない（MongoDB のバイナリとデータベースのバージョンは自動連動しておらず、別々に管理されているため手動で更新が必要）
  
  * 7.0 から 8.2 へ上げるには 7.0 --> 8.0 --> 8.2 の順で踏む必要があり、新しいバイナリはひとつ前のバージョンのデータベースと互換性があるが、新しすぎるデータベースや複数世代前のデータとはそのまま噛み合わない

* 迷走と遠回りの経緯
  
  * まず `unifi` と `mongodb-bin` の 2 つのパッケージを削除し、代わりに `mongodb80-bin` を入れて admin データベースを 7.0 --> 8.0 --> 8.2 へと段階的にアップグレードした
  
  * その後再び `mongodb80-bin` を削除して `mongodb-bin` と `unifi` を入れ直したところ、`systemctl status mongodb.service` は正常、`systemctl status unifi.service` も一見正常になったものの、Unifi Controller は相変わらず起動せず、`/var/log/unifi/server.log` には依然として `exit code=62` が出ていた
  
  * いろいろ調べても Unifi 側の MongoDB データベースをアップグレードする方法が見つからず（ここは自分のスキルツリーで必要なスキルを振り忘れていたせいで、完全にアホな状態になっていた）
  
  * 結局、メインの MongoDB admin database のアップグレードは完了したものの、Unifi が抱えている MongoDB データベースがアップグレードできずに詰まってしまった……
  
  * 最後に `unifi` の `PKGBUILD` ファイルを確認してみたところ……依存関係（depends）は単に `mongodb` であれば何でもよいことが判明……
  
  * 最終的に `mongodb80-bin` + `unifi` の組み合わせにしたところ、7.0 のデータベースと互換性があったおかげで嘘みたいにすんなり復活した……
