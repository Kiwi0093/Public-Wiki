# ArchWSL

## GitHub プロジェクト

* Link - [GitHub - yuk7/ArchWSL](https://github.com/yuk7/ArchWSL)

* Online Manual - [How to Setup | ArchWSL official documentation](https://wsldl-pg.github.io/ArchW-docs/How-to-Setup/)

## 注意事項

* 問題が起きないよう、先に `archlinux-keyring` を初期化しておく必要があります
  
  ```bash
  [root@wsl]$ pacman-key --init
  [root@wsl]$ pacman-key --populate
  [root@wsl]$ pacman -Sy archlinux-keyring
  [root@wsl]$ pacman -Syyu
  ```

* 一般ユーザーアカウントを作成する必要があります（そうしないと一部の GUI アプリで問題が発生します）
  
  ```bash
  # 定義wheel群組的User都可以sudo
  [root@wsl]$ echo "%wheel ALL=(ALL) ALL" > /etc/sudoers.d/wheel
  # 建立一個{username}帳號,並且屬於wheel群組
  [root@wsl]$ useradd -m -G wheel -s /bin/bash `{username}`
  ```

* デフォルトユーザーを `{username}` に設定する必要があります。この操作は WSL の外（Windows 側）から行います
  
  ```bash
  [User@Windows]$ Arch.exe config --default-user `{username}`
  ```

# Archlinux Guest in VirtualBox

## インストール

基本的には ISO から起動し、`archinstall` で項目を選んでそのままインストールするだけです。実際にインストールして確認したところ、デスクトップ環境が必要な場合は `desktop profile` を選べばそのまま入ります。私が直接 `KDE` を選択した結果は以下の通りです。

* デフォルトで `Xorg` と `Wayland` の両方がインストールされ、`SDDM` のログイン画面で選択できます
  
  * 今のところ `Wayland` のサポートはまだ十分とは言えず、`ArchWiki` でもまずは `Xorg` を使うことが推奨されています

## 必須パッケージ

インストールを推奨する必須パッケージは以下の通りです。

| Pkg Name               | Description                                                     |
| ---------------------- | --------------------------------------------------------------- |
| git                    | 通常の Git 利用だけでなく、`yay` を導入する前に `AUR` パッケージをインストールする際（`yay` 自体のビルド含む）にも必要です |
| base-devel             | コンパイラや関連ツールのパッケージグループで、自分でパッケージをビルドする人は導入が必要です |
| virtualbox-guest-utils | VirtualBox のゲスト用ツールで、専用ドライバなどを含み VMware Tools に相当するものです |
| yay                    | Arch ベースを使っている人ならおなじみのツール。Manjaro なら pacman で直接入りますが、Arch では下記の方法で導入する必要があります |

### yay のインストール方法 (under Archlinux)

```bash
# 不能用root
[user@archlinux]$ git clone https://aur.archlinux.org/yay-git.git
[user@archlinux]$ cd yay-git
[user@archlinux]$ makepkg -si
```

## 注意事項

* systemd サービスを手動で有効化する必要があります
  
  * systemd-resolved.service
    
    * systemd 版の resolvconf で、主に `wireguard` を使用する際に必要となります
    
    * `systemctl enable --now systemd-resolved.service`
  
  * vboxservice.service
    
    * `virtualbox-guest-utils` 内のコンポーネントを自動ロードするためのサービスです
    
    * `systemctl enable --now vboxservice.service`

# まとめ

今のところ、`Manjaro`（あるいは好みの他のディストロ）のカスタマイズ設定（たとえば `zsh-theme-powerlevel10k` の設定など）をコピーしてしまえば、`Archlinux` でも見栄えが物足りなくなることはありません。

インストールも非常に手軽になりましたし、使い勝手も（Manjaro と比べて）Arch ベースとして何ら変わりはありません。

明確なメリット・デメリットの比較については、もう少し使い続けて様子を見てみる必要がありそうです。
