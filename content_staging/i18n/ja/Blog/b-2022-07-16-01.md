# はじめに

会社の PC ということもあって無茶はいじらないよう我慢し、WSL2 + WSLg で適当にやり過ごそうと思っていました（もっとも、これでも十分やりすぎな気はしますが）。ところが先週末、うっかり手癖で常用していた ManjaroWSL をリセットしてしまい、あの完璧に動いていた WSL 環境を二度と再現できなくなってしまいました……というわけで、WSL にはお別れを告げることにしました。

<!--truncate-->

# 現在の構成

構成と言うと大げさですが、要は Windows 10 ホスト上の VirtualBox で Manjaro KDE ゲストを動かす形です。

# 苦難の道のり

### Hypervisor の選択

最終的な構成を決める前、VirtualBox にするか VMware Workstation Player にするかはかなり迷いました……。

本音を言えば、会社の PC で細かい制約を気にしなくていいなら迷わず VMware Workstation Pro を選んでいたところです。

なぜ QEMU を選ばなかったのかって？ うーん……理由はとても単純で、Windows ホスト上ではパフォーマンスが悪いだろうと勝手に思い込み、テストすらせずに候補から外したからです……。

最終的に VMware Player は機能があまりに貧弱で、画面の自動リサイズ（auto resize）すらないため、泣く泣く見送りました。

### WSL から VirtualBox への移行

これに関しては完全に自分が間抜けだったとしか言えません……。

WSL を削除する際になんとなく未練が残っていて、Hyper-V 関連のコンポーネントをきれいに消し切っていなかったせいで、本来なら何ヶ月かかけて遭遇しそうな不具合をほぼ全部踏む羽目になりました。

たとえば、ゲスト OS が理由もなくフリーズしたり、Linux でマルチコア起動ができなかったり、動いても異常に重かったり……。

結局、最後に Windows の「仮想マシン プラットフォーム」機能を無効化したらあっさり解決しました。何の問題も起きなくなりました。

### System Tuning

本当に良い時代に生まれたものです。OS を入れた後の基本的なチューニングは一切不要で、最初から全部いい感じに整っています……。

不要なものを外して、使いたいものを入れるだけで、そのまま快適に使い始められます。

### お決まりの愚痴

全体的にはかなり快適なのですが、Guest/Host の共有フォルダ（shared folder）機能には一言文句を言わせてください。わざと手を抜いているわけではなく技術的な制約があるのだとは思いますが、結論として、その共有フォルダ内に Git リポジトリを置くとさまざまな謎の不具合が起きます。`git clone` が意味不明な理由で失敗したり、`.git` 配下のよくわからないファイルがホスト側にロックされて削除できなくなったり、あるいは `npm install` の際にリンク作成に失敗してコケたり……。

「Git と Hexo は Linux 側で動かし、エディタは Windows 側で使う」というおしゃれ運用を夢見ていましたが、見事に打ち砕かれました。今は大人しくすべて Linux 側で完結させています。

### 今後の予定

マルチモニター環境で、1 枚の画面ごとに 1 つのシステムをフルスクリーンで割り当てる運用ができるか試してみたいです（もしできたら結構かっこいいはず）。

# まとめ

Windows はやっぱりゲーム（と仕事）専用にしておくのが一番ですね……。Linux を統合した WSL はどうにも中途半端な存在に見えてしまいます。`systemd` に依存するものがまともに動かず（`genie systemd` も試しましたがイマイチでした）、`resolv.conf` 周りでもトラブルが起きがちです。

今や Linux における `systemd` への依存度がどんどん高まっている時代ですから、正直「帯に短し襷に長し」としか言いようがありません。

あと、一見すごそうな WSLg も、悪いとまでは言いませんが、要するに Microsoft の皮をかぶせた VcXsrv に過ぎず、Microsoft ならではの特別な工夫が詰まっているわけではないな、という印象です。
