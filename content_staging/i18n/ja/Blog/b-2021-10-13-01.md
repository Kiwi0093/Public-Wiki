# 基本コンセプト

実はとてもシンプルで、ゲームが遊べる Windows マシンを 1 台用意して、リモートから続きを遊べるようにするだけです。そうすれば手元の Gaming PC やノート PC に縛られず、他の好きな Console から自由にゲームを遊べるようになります。

# 関連ツール

* Wake on Lan

  これは今のマザーボードなら大抵ついている機能ですね。詳しい使い方は各自 Google で調べてください。Client 側は Android なら Apk があり、Linux なら gwake が使えて、どちらも簡単です。

* Nvidia Experiance

  これは基本的に私が N 社のグラボを使っているから最初から入っているものですが、もし N 社のグラボを使わない場合は steam link か kino console を使うのがおすすめです。ただ、組み合わせたときの Moonlight ほどの速さはありません。

* Moonlight

  これは本当に使いやすい client です。高速で無料、めちゃくちゃ最高なうえに各プラットフォームに対応しています。

# いくつかの所感

## 雑談

以前から思っていたのですが、いろいろなニーズが増えるにつれて、高速なタブレットや、ゲームが動くノート PC、軽くて持ち運びやすいノート PC、仕事と連携できるノート PC など、強力な console がたくさん必要になります。

家の中の Service を徐々に VM 化して仮想化統合し始め、docker と Wireguard を導入して家の中と外の境界がますます曖昧になり、さらに 10 年前から動かしていた VM 上の Windows P2P 専用機から、この前の Guacamole+Manjaro に至るまで、私はシステムをクラウド化する路線を歩んできました。つまり console を本当の意味での「端末（console）」に回帰させ、高速さも性能も不要（ネットワークカードは必要ですが）にしようとしていたわけです。しかし、私にとって PC/ノート PC の最も原初的かつ重要な機能である Gaming だけは、ずっと統合されないまま残っていました...

今回の検証で、ネットワーク環境さえ許せば Gaming もまとめてリモート化できることが確認できました。ただ、消費電力などの関係から、最初から VM の中に統合すること（PCI passthrough 技術を使えば可能だとしても）はあまりおすすめしません。ゲームを遊ばない時間までずっと電源を入れっぱなしにして電気を食うのはもったいなさすぎますからね。

## 要点まとめ

* Wake on Lan の重要性

  突き詰めれば省エネです...正直なところ、電気代もホッキョクグマの生死も気にしないというなら、Gaming Server を 24時間365日つけっぱなしにしても構いませんが...

* Auto Login

  これは実はかなり重要です。Windows の仕様上、起動後に本当に login しないと Nvidia shield が起動せず、接続できません。かといって rdp で繋ぐと競合するうえ、rdp では本当の意味での desktop login にならないので...auto login を設定しない場合は、接続できる別の console が必要になります..おそらく VNC か DWservice のようなものです（それにデバイスを接続して PIN を入力するときにも必要になります。あるいは実機のところまで行って入力して戻るかですね）。

* MSTSC.EXE

  shield の中にこいつを登録して直接起動させ、Steam の Big Picture mode の代わりにする必要があります。そうしないと Fake HDMI を用意するか、実際にモニターを繋ぐ羽目になります（LLT でも触れられています）。

  これも Windows の厄介な仕様ですが...MSTSC.EXE を設定しておけばこの問題は起きません（ただその代わり、リモートデスクトップ扱いになってコントローラーで直接操作しにくくなります）。

## 使ってみた感想

実際 Moonlight は本当にスムーズで、ネットワークに問題がなければローカルと大差ない感覚で使えます。ただネットワークが悪いときはかなりカクつきます...

また、ネットワーク帯域が許す限り、解像度をゲーム本体が動いている解像度より小さく設定しない方がいいです..余計に小さく圧縮して送信することになり...かえって遅延が発生するためです。
