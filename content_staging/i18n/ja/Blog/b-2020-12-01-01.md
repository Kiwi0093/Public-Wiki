## アップグレード

正直なところ自分の性格からすると、たかが VPS で大した重要データも載っていないので……**V2Ray** の **config.json** の中身だけ控えておいて、そのまま **reinstall**（再インストール）を選んでゼロからやり直す方がずっと手っ取り早い気がします……。とはいえ、勝手に **reinstall** するわけにはいかない VPS もあるので、ちょっと面倒な正規手順でのアップグレードをやってみることにしました……。

なぜこういう技術的な手順を Wiki にまとめないのかって？ 一度やったら忘れてしまっていい使い捨ての作業を、わざわざ Wiki に残す必要はないでしょう？？

### アップグレードの詳細

簡単に言うと、流れは次の通りです。

* systemd 内のサービスを停止し、disable にする
* `rm` で以前インストールしたバイナリなどをすべて削除する
* `mv` で設定ファイルを従来のデフォルトである */etc/v2ray/* から */usr/local/etc/v2ray/* へ移動する。なぜ場所が変わったのかというと、おそらく ~~FreeBSD に魅了されたから~~ V2Ray の設定をシステムのメイン設定ディレクトリから分離したかったからでしょう
* 新しいスクリプトでインストールする（デフォルトのパスを変更したくない場合はスクリプトを手動で書き換える必要がありますが、そうすると crontab に入れて自動更新するのが面倒になりますよね~~）
* `v2ray.service` を enable にする
* `v2ray.service` が起動すれば作業完了

さらに **VLESS** を使うように変更する場合は、v2ray ユーザーアカウントの追加と certbot の鍵（ほかの方法で鍵を用意してもいいのですが、私はまだやり方を知りません）を処理し、最後に `config.json` の内容を書き換えれば完了です。

詳しいやり方は、[公式ドキュメント](https://github.com/v2fly/fhs-install-v2ray/wiki/Migrate-from-the-old-script-to-this) にかなり分かりやすく書かれています。

#### もしサーバーの OS に Archlinux を使っているなら……

この 1 行を実行するだけで済みます。

```bash
pacman -Syu
```

これで V2Ray が最新版にアップグレードされます……トラブルも一切なし。めちゃくちゃ楽です……。

ほんと、なぜ VPS の標準 OS 選択肢に Arch が用意されていないのか不満で仕方ない……面倒くさいなあ。

## クライアントの選定

クライアントに関しては、正直なところ私が一番よく使っているのは Archlinux 上の V2Ray です。サーバー側とまったく同じプログラムなので互換性が最も高く、安定性も抜群です。ただ、以前も書いた通り、他の環境向けのクライアントも一応検討しておきます。

#### Android

最近は本当に **V2RayNG** にハマっています。ただ、4.33 のコアから 4.23 のサーバーに接続できなくなった唯一のクライアントがこれでした……。最新アップデート前のバージョン（1.33）と最新バージョンでは VLESS のサポート状況や速度にかなり差があるので、今後はサーバー側の V2Ray-Core をアップグレードしたらこちらもすぐ追従してアップデートしないと快適に使えなくなるかもしれません……（そうならないことを願いますが……）。

#### Windows

Linux デスクトップではいつも QV2Ray + V2Ray-Core を使っているので非常に快適で問題ないのですが、Windows でも ~~別のものを探す必要はなく~~ 同じように QV2ray を使えば大丈夫です……（このソフトはクロスプラットフォームで、Windows / Linux / macOS すべてに対応しています）。

ダウンロード先：[QV2Ray](https://github.com/Qv2ray/Qv2ray/releases)、あわせて使用する [V2Ray-Core](https://github.com/v2fly/v2ray-core/releases)。

#### iOS

中国アカウントをお使いの方は、親切な誰かから米国アカウントを借りて導入するのが一番手っ取り早いです……。
