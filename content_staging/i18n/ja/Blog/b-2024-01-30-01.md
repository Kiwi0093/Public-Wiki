# 詳細紹介

## Unifi シリーズ

狙いはズバリ、見栄えと自己満足です……。

新居の IT インフラを準エンタープライズ級のものに入れ替え、1 つの管理コンソールから AP へ一括設定反映（apply）できるようにすれば楽だろうと思いました。ちょうど以前実家で導入した **TP-Link Deco X75** に痛い目（高価格帯の Mesh AP なのにホワイトリスト方式の MAC アドレスフィルタ機能がないとは……）に遭ったばかりだったこともあります。

最初は家もそこまで広くないので **U6 In-Wall** 1 台で足りると思っていたのですが、設置場所が悪くテレビボード裏側の部屋の電波がかなり弱くなってしまいました。

そのため **U6 Pro** をもう 1 台買い足して補完することにしました。

## HPE Microserver Gen8

こちらは旧環境から使っているマシンで元々 2 台ありました。ただ実家の ASUS サーバーのハードウェアが故障してしまったため（10 年ほど使ったので十分元は取りました）、1 台は実家へ移して NAS として使うことになりました。残った 1 台に **10GbE NIC + 16TB HDD × 4** を載せ、実効容量 **48TB** の **raidz1** NAS に仕立てています。

## ASUS TS110-E14

こちらは迷うことなく **ESXi サーバー** として運用しますが、ベースとなるネットワーク環境の構築はやはりなかなか骨が折れました。

### FreeBSD 14 Gateway

これまでの習慣通り、ゲートウェイには老舗で信頼性の高い FreeBSD + pf + ipfw を選択しました。

#### ネットワーク構成

当初はすべてを 1 つの C クラスサブネットにまとめてシンプルにするつもりでした（自分の手元ではあまり意味をなしていなかった DMZ 分離をなくす形）。ところが **NAT Loopback** の問題により内部ネットワークから~~外部公開サービスにアクセスできなくなったため、再び元の WAN+LAN+DMZ 構成に戻すしかないかと思いましたが、~~pf の設定を修正してこの問題を解決できました（[こちら](https://www.twbsd.org/cht/book/new/ch12.htm)を参考）。

```shell
# Nat Loopback
no nat on $int_if proto tcp from $int_if to $int_net
rdr on $int_if proto tcp from $int_net to $ext_ip port { 25, 165, 993 } -> 192.168.0.2
nat on $int_if proto tcp from $int_net to 192.168.0.2 port { 25, 165, 993 } -> $int_if
```

というわけで、最終的には予定通り 1 つの C クラスサブネット構成に落ち着きました。

### Archlinux Dnsmasq + Unifi

今回の大きなハマりポイントの一つがここでした。当初の構想では **dnsmasq** も **Unifi Network Application** も Docker コンテナでサクッと立てるつもりだったのですが……。

#### Dnsmasq

Docker で起動自体はできるものの、IP セグメントの絡みと自分がマッピングを真面目に調査しなかったせいで、サービスは動いているのに他のクライアントがまったく正常に DHCP と DNS を使えない状態に。散々格闘した末、dnsmasq を独立した VM に移したら何も変えずにあっさり動きました……。

#### Unifi Network Application

こちらはさらに厄介で、手順通りに合わせたはずの **mongodb** が動かないかと思えば、mongodb が解決したら今度は Java の問題でコントローラーの Web 画面が正しく表示されない始末……。延々と長いドキュメントを読んだ末、**Archlinux** に yay が入っていればこれだけで済むことが判明しました。

```bash
yay -S unifi
```

あとは JRE のバージョンが 17 であることを確認するだけ……。コマンド 1 行ですべて解決しました……。

### XigmaNAS

Docker のバックエンドや各種システムのバックアップ需要を見越して、ZFS Mirror 構成の NAS を構築し、NFS 経由で各サーバーへマウントして基本バックアップを取るようにしました。今後さらに自前の Git サーバーと連携させて内部プロジェクト全体を一元管理する予定です。

また、実家のマシンでは以前 ESXi 上に直接 HDD を増設して BT ダウンロードなどの Temp 領域や容量拡張用に使っていましたが、今回のサーバー移行ではその HDD を同時にマウントし忘れたせいで一部の VM が起動しないトラブルに散々悩まされました。

そこで今回は Temp 用 HDD を XigmaNAS 内にマウントし、そこから NFS でエクスポートする形に改めました。

# 苦戦したポイントまとめ

## XigmaNAS に Temp ドライブを追加できない問題

原因はよく分かりませんが、どうしても既存の XigmaNAS に Temp 用ドライブを追加できなかったため、最終的には独立した VM をもう 1 台立てて対応ハードウェアを PCI パススルーし、Temp エクスポート専用の XigmaNAS を別途走らせる羽目になりました。

## Unifi シリーズ

前述の通り、問題の Unifi-Network-Application がどうしても Docker 上でまともに動かず、さらに Dnsmasq も不調だったため、最終的に VM を 1 台余計に立てることになりました。

## WiFi AP の設置場所ミス

内装設計のとき、自分の頭はいったい何かに齧られていたのか、U6 In-Wall の設置場所が悪く、2 つの寝室と 2 つのトイレに背中を向ける形になって電波が弱くなってしまいました……。おかげで U6 Pro を 1 台買い足し、早くも Unifi の無性生殖が始まってしまいました……。
