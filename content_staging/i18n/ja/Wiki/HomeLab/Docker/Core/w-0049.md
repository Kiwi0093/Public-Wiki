## 1. コンテナライフサイクル管理 (Container Lifecycle)

### 1.1 作成と起動

```bash
# バックグラウンドでコンテナを実行し、名前・ポートマッピング・自動再起動・環境変数を指定
docker run -d \
  --name web-app \
  -p 8080:80 \
  -e ENV=production \
  --restart unless-stopped \
  nginx:alpine

# 対話モードで一時コンテナを起動（終了後に自動削除）
docker run --rm -it alpine:latest sh

# CPU とメモリの上限を制限
docker run -d \
  --name limited-app \
  --memory="512m" \
  --cpus="1.5" \
  nginx:alpine
```

### 1.2 状態制御と確認

```bash
# 実行中のコンテナを一覧表示
docker ps

# 全コンテナ（停止中や Exited を含む）を表示し、ID と名前などを整形出力
docker ps -a --format "table {{.ID}}\t{{.Names}}\t{{.Status}}\t{{.Ports}}"

# コンテナの起動 / 停止 / 再起動
docker start <container_id_or_name>
docker stop <container_id_or_name>
docker restart <container_id_or_name>

# コンテナの強制終了（SIGKILL を送信）
docker kill <container_id_or_name>

# コンテナプロセスの一時停止と再開（cgroup を凍結）
docker pause <container_id_or_name>
docker unpause <container_id_or_name>

# 停止済みコンテナの削除
docker rm <container_id_or_name>

# 実行中コンテナの強制削除（kill + rm と同等）
docker rm -f <container_id_or_name>
```

## 2. コンテナのデバッグ・プロセス・ファイル操作 (Debug & Operations)

### 2.1 コンテナへの接続とログ確認

```bash
# 実行中コンテナのシェルへ接続（最もよく使うコマンド）
docker exec -it <container_name> /bin/sh
# bash がインストールされている場合
docker exec -it <container_name> /bin/bash

# root 権限でコンテナ内の特定コマンドを単発実行
docker exec -u 0 -it <container_name> whoami

# ログをリアルタイム追跡（Tail -f）し、出力行数とタイムスタンプを指定
docker logs -f --tail 100 -t <container_name>

# 指定時刻以降のログを確認
docker logs --since "2026-09-01T00:00:00" <container_name>
```

### 2.2 動的リソース監視とプロセス確認

```bash
# コンテナのリソース使用率をリアルタイム表示（CPU, Memory, Network I/O, Block I/O）
docker stats

# ストリーミングせずスナップショットとして整形出力
docker stats --no-stream --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}\t{{.NetIO}}"

# コンテナ内部のプロセス一覧を表示（ホスト視点でのコンテナ内 PID を確認）
docker top <container_name>
```

### 2.3 ファイルコピーと詳細検査

```bash
# ホスト側のファイルをコンテナ内へコピー
docker cp /path/to/local/file.conf <container_name>:/etc/app/file.conf

# コンテナ内のファイルをホスト側へコピー
docker cp <container_name>:/var/log/app.log ./app.log

# イメージからのコンテナ内ファイルシステム変更履歴を確認 (A: Added, C: Changed, D: Deleted)
docker diff <container_name>

# コンテナの詳細な JSON 属性を確認（IP、Mounts、Env、Config など）
docker inspect <container_name>

# Go template を使ってコンテナ IP を素早く取得
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' <container_name>
```

## 3. イメージ管理 (Images)

```bash
# Docker Hub 上のイメージを検索
docker search nginx

# 指定バージョンのイメージを取得
docker pull ubuntu:24.04

# ローカルに存在するイメージ一覧を表示
docker images

# イメージサイズ順にソートして表示
docker images --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}" | sort -k 3 -h

# イメージをビルド（Dockerfile とタグを指定）
docker build -t my-app:v1.0 .

# キャッシュを使わずに強制リビルド
docker build --no-cache -t my-app:v1.0 .

# イメージに新しいタグを付与（Private Registry への Push 用）
docker tag my-app:v1.0 registry.example.com/proj/my-app:v1.0

# Registry へプッシュ
docker push registry.example.com/proj/my-app:v1.0

# イメージのレイヤー構造とビルド履歴を確認（イメージ肥大化の原因調査）
docker history --no-trunc my-app:v1.0

# イメージのエクスポートとインポート（オフライン環境でのデプロイ用）
docker save -o my-app.tar my-app:v1.0
docker load -i my-app.tar

# 指定イメージを削除
docker rmi <image_id_or_name>

# イメージを強制削除（停止中コンテナから参照されていても削除）
docker rmi -f <image_id_or_name>
```

## 4. ボリュームと永続化ストレージ (Volumes)

```bash
# 名前付きボリュームを作成
docker volume create my-data-vol

# 全ボリュームを一覧表示
docker volume ls

# どのコンテナからも使用されていない孤立ボリューム（Dangling Volumes）を表示
docker volume ls -f dangling=true

# ボリュームのホスト側実マウントパス（Mountpoint）を確認
docker volume inspect my-data-vol

# 特定のボリュームを削除（どのコンテナも使用していない状態である必要あり）
docker volume rm my-data-vol

# 未使用のボリュームをすべて一括削除
docker volume prune -f
```

## 5. 仮想ネットワーク管理 (Networks)

```bash
# ローカルの全ネットワークドライバとネットワーク一覧を表示
docker network ls

# カスタム Bridge ネットワークを作成（コンテナ間で「サービス名 / コンテナ名」による DNS 名前解決が可能）
docker network create --driver bridge my-isolated-net

# サブネットを指定してカスタムネットワークを作成
docker network create --subnet 172.28.0.0/16 my-custom-net

# ネットワーク構成および現在接続中のコンテナ一覧と IP を確認
docker network inspect my-isolated-net

# 稼働中のコンテナをネットワークへ動的に接続
docker network connect my-isolated-net <container_name>

# コンテナをネットワークから切断
docker network disconnect my-isolated-net <container_name>

# 未使用ネットワークの削除
docker network rm my-isolated-net
docker network prune -f
```

## 6. モダン Docker Compose (V2) 主要コマンド

Compose V2 は Go 言語で実装され Docker CLI に直接統合されており、スペース区切りの `docker compose` 形式で実行します：

```bash
# バックグラウンドで起動（ネットワークと Volume を自動作成）
docker compose up -d

# コンテナを強制的に再作成（設定や daemon.json の変更を反映）
docker compose up -d --force-recreate

# イメージをビルドしてサービスを起動
docker compose up -d --build

# Compose プロジェクトのコンテナと自動作成ネットワークを停止・削除
docker compose down

# 停止し、「Volume ボリュームも含めて」一括削除（破壊的操作のため要注意）
docker compose down -v

# 停止し、すべてのイメージも削除（--rmi all または local）
docker compose down --rmi local

# プロジェクト内の全コンテナのログをリアルタイム追跡
docker compose logs -f

# 特定サービスのログのみ追跡
docker compose logs -f <service_name>

# プロジェクト内コンテナの稼働状態とポートマッピングを確認
docker compose ps

# 指定した単一サービスを再起動
docker compose restart <service_name>

# 特定サービスに対して一時的な単発コマンドを実行（外部ポートは公開されない）
docker compose run --rm <service_name> sh
```

## 7. システムメンテナンスと全体トラブルシューティング (System)

```bash
# Docker エンジンのバージョンと詳細構成を確認（Kernel、Storage Driver、OS など）
docker version
docker info

# Docker デーモンで発生するイベントをリアルタイム監視（コンテナ起動、終了、OOM など）
docker events

# 各リソース種別のディスク使用割合を確認
docker system df

# ディスク使用量の詳細一覧を確認
docker system df -v

# 一括クリーンアップ：停止済みコンテナ + 未使用ネットワーク + タグなしイメージ (<none>)
docker system prune -f

# ディープクリーンアップ：「どのコンテナからも使用されていない」全イメージと Build Cache を削除
docker system prune -a -f
```
