## 1. 主要 Linux ディストリビューションでの Docker Engine インストール

### 1.1 VMware Photon OS

Photon OS には公式リポジトリに Docker Engine が標準で用意されています。

```bash
# 起動および自動起動の有効化
systemctl enable --now docker

# ステータスの確認
systemctl status docker
```

### 1.2 Debian / Ubuntu

Docker 公式 APT リポジトリを使用して最新バージョンをインストールします。

```bash
# 1. パッケージリストの更新と基本パッケージのインストール
sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg

# 2. Docker 公式 GPG 鍵の追加
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/$(. /etc/os-release && echo "$ID")/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

# 3. APT ソースリストの作成
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/$(. /etc/os-release && echo "$ID") \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 4. Engine と CLI プラグインのインストール
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 5. 起動および自動起動の有効化
sudo systemctl enable --now docker
```

### 1.3 RHEL / Rocky Linux / AlmaLinux / CentOS

DNF / YUM を使用して公式パッケージリポジトリを設定します。

```bash
# 1. 必要なツールのインストール
sudo dnf install -y dnf-utils

# 2. Docker 公式リポジトリの追加
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo

# 3. Docker パッケージのインストール
sudo dnf install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 4. 起動および自動起動の有効化
sudo systemctl enable --now docker
```

_(注：Fedora 41+ や RHEL 10 など DNF 5 を採用している環境では、手順 2 のコマンド構文が `sudo dnf config-manager addrepo --from-repofile=https://download.docker.com/linux/centos/docker-ce.repo` に変更されます。)_

### 1.4 Alpine Linux

Alpine はサービスマネージャーとして OpenRC を採用しており、デフォルトで Community リポジトリにパッケージが提供されています。

```bash
# 1. Community リポジトリの有効化（未有効の場合は /etc/apk/repositories を編集して community 行のコメントを解除）
# 2. Docker のインストール
apk update
apk add docker

# 3. デフォルトのランレベルへの追加と起動
rc-update add docker boot
service docker start
```

## 2. Docker Compose のインストールとデプロイ方法

現在の標準では旧来の Python pip によるインストール（`pip install docker-compose`）は完全に非推奨となり、Go で書かれた CLI プラグインである **Docker Compose V2**（`docker compose`）が採用されています。互換性が高く、システムの Python 環境にも干渉しません。

|**ディストリビューション**|**推奨インストール方法**|**コマンド**|
|---|---|---|
|**Photon OS**|公式リポジトリからのネイティブインストール（V1/V2 バイナリ）|`tdnf -y install docker-compose`|
|**Ubuntu / Debian**|APT 公式プラグイン（推奨）|`sudo apt-get install -y docker-compose-plugin`|
|**RHEL / Rocky Linux**|DNF 公式プラグイン（推奨）|`sudo dnf install -y docker-compose-plugin`|
|**Alpine Linux**|APK リポジトリ（`docker-cli-compose`）|`apk add docker-cli-compose`|
|**汎用手動インストール**|公式 GitHub バイナリ（Standalone / Plugin）|下記の「汎用手動デプロイ」を参照|

### 汎用手動デプロイ（あらゆる x86_64 / aarch64 Linux に適用可能）

ディストリビューションのリポジトリ版が古い場合や最小構成のシステムでは、バイナリを直接ダウンロードして CLI プラグインパスへ配置します。

```bash
# 1. Docker CLI プラグインディレクトリの作成
sudo mkdir -p /usr/libexec/docker/cli-plugins

# 2. 最新版を自動取得してダウンロード（x86_64 の例、aarch64 の場合は適宜変更）
COMPOSE_VERSION=$(curl -s https://api.github.com/repos/docker/compose/releases/latest | grep '"tag_name":' | sed -E 's/.*"([^"]+)".*/\1/')
sudo curl -SL "https://github.com/docker/compose/releases/download/${COMPOSE_VERSION}/docker-compose-linux-$(uname -m)" -o /usr/libexec/docker/cli-plugins/docker-compose

# 3. 実行権限の付与
sudo chmod +x /usr/libexec/docker/cli-plugins/docker-compose

# 4. （任意）旧コマンド互換用のグローバルシンボリックリンクを作成
sudo ln -sf /usr/libexec/docker/cli-plugins/docker-compose /usr/local/bin/docker-compose

# 5. 動作確認
docker compose version
```

## 3. グローバル最適化と権限設定

### 3.1 非 root ユーザーでの実行権限

日常的な操作を毎回 root 権限で行うのを避けます。

```bash
# 対象ユーザーを docker グループに追加
sudo usermod -aG docker $USER

# グループ権限の反映（または SSH へ再ログイン）
newgrp docker
```

### 3.2 デーモンの最適化 (`/etc/docker/daemon.json`)

コンテナのログによるディスク容量圧迫を防ぎ、デーモン再起動時の無停止維持を有効にするため、`/etc/docker/daemon.json` を作成または上書きします。

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "50m",
    "max-file": "3"
  },
  "storage-driver": "overlay2",
  "live-restore": true,
  "default-ulimits": {
    "nofile": {
      "Name": "nofile",
      "Hard": 65535,
      "Soft": 65535
    }
  }
}
```

設定を反映します。

```bash
sudo systemctl daemon-reload
sudo systemctl restart docker
```

### 3.3 カーネルの IP フォワーディング (IP Forwarding)

コンテナネットワークが外部と通信できない、またはポート公開に失敗する場合は、IPv4 フォワーディングが有効になっているか確認します。

```bash
# 状態の確認（1 が返れば正常）
sysctl net.ipv4.ip_forward

# 0 の場合は設定ファイルに書き込んで永続化
echo "net.ipv4.ip_forward = 1" | sudo tee /etc/sysctl.d/99-docker-forward.conf
sudo sysctl -p /etc/sysctl.d/99-docker-forward.conf
```

## 4. Systemd を用いた Docker Compose サービスの自動起動管理

`compose.yaml` で `restart: always` や `restart: unless-stopped` を宣言するだけでなく、本番環境では Compose プロジェクト全体を **Systemd Unit** としてカプセル化することが推奨されます。これにより OS 標準の監視、依存関係の順序制御、自動再起動の仕組みに組み込むことができます。

### 手順 1：プロジェクトディレクトリと Compose ファイルの作成

`/opt/apps/my-stack` を例とします。

```bash
sudo mkdir -p /opt/apps/my-stack
cd /opt/apps/my-stack
```

`docker-compose.yml` を作成します。

```yaml
services:
  app:
    image: nginx:alpine
    ports:
      - "8080:80"
```

### 手順 2：Systemd Service Unit の作成

ファイル `/etc/systemd/system/docker-compose@.service` を作成します（インスタンス化テンプレート `@` を使うことで、複数の Compose プロジェクトを同時にサポートできます）。

```ini
[Unit]
Description=Docker Compose Application Service (%i)
Requires=docker.service
After=docker.service network-online.target
Wants=network-online.target

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/apps/%i

# 起動前にイメージを事前プルしてコンテナスタックを起動
ExecStartPre=-/usr/bin/docker compose pull
ExecStart=/usr/bin/docker compose up -d --remove-orphans

# 停止時にすべてのコンテナを正常終了
ExecStop=/usr/bin/docker compose down

# 設定のリロード
ExecReload=/usr/bin/docker compose pull
ExecReload=/usr/bin/docker compose up -d --remove-orphans

# タイムアウト設定
TimeoutStartSec=300
TimeoutStopSec=60

[Install]
WantedBy=multi-user.target
```

> **注意**：`which docker` でパスを確認し、`/usr/local/bin/docker` である場合は `Exec*` のパスを調整してください。

### 手順 3：サービスの読み込みと有効化

テンプレートユニットはディレクトリ名に自動で対応します。例えばディレクトリが `/opt/apps/my-stack` の場合、サービス名は `docker-compose@my-stack` になります。

```bash
# 1. systemd 設定のリロード
sudo systemctl daemon-reload

# 2. サービスの起動および自動起動の有効化
sudo systemctl enable --now docker-compose@my-stack

# 3. サービス稼働状況の確認
sudo systemctl status docker-compose@my-stack

# 4. コンテナの動作ログの確認
journalctl -u docker-compose@my-stack -f
```

## 5. システムメンテナンスとディスク容量管理クイックリファレンス

未解放の領域を回収するため、定期的にメンテナンスコマンドを実行します。

```bash
# 1. 現在の Docker ディスク使用状況を確認
docker system df

# 2. 停止中のすべてのコンテナ、未使用ネットワーク、ダングリングイメージ（Dangling Images）を削除
docker system prune -f

# 3. ディープクリーンアップ：既存コンテナに使用されていないイメージも一括削除
docker system prune -a -f

# 4. 孤立ボリュームの削除（警告：破壊的操作であり、マウントされていないデータが削除される可能性があります）
docker volume prune -f
```
