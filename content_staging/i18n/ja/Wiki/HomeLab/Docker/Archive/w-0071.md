## 基本フロー

### 前提

これは DB と AP を同一の `docker-compose.yml` 内に配置する構成です。実際、後から気づいたのですが、無理に DB を統合しない方がコンテナ化後の管理が楽になりますし、今回のように分割するのも簡単になります。

### 手順

1. まず `docker run` でイメージ内のスクリプトを実行し、初期 DB（initial DB）の SQL を生成します。
2. compose ファイルを使ってまず DB のみを単体で立ち上げます（データの永続化のために volumes を定義します）。
3. DB コンテナ内で初期 DB の SQL をデータベースへインポートします（volumes を通じて結果を保持します）。
4. 単体の DB コンテナを削除します（削除しなくても動きますが、後続の調整が煩雑になります）。
5. `docker-compose.yml` を用いて関連するコンテナ一式（DB コンテナを含む）をまとめて立ち上げます。

## 実際のコマンドと設定ファイル

### Pull Image

```bash
docker pull guacamole/guacamole
docker pull guacamole/guacd
docker pull mariadb/server
```

> [!info] Updated 2026-11-27
> `mariadb/server` はメンテナンスが終了した旧版イメージです。現在の環境で構築する場合は公式イメージ `mariadb:lts` を使用してください（環境変数のプレフィックスも `MARIADB_*` の使用が推奨されます）。

### Create Initial DB

```bash
docker run --rm guacamole/guacamole /opt/guacamole/bin/initdb.sh --mysql > guac_db.sql
```

### Create Initial DB Container/Volume

#### `initial.yml`

```yaml
version: '3'
services:
  guacdb:
    container_name: guacdb
    image: mariadb/server:latest
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: '<PASSWD_YOU_WANT>'
      MYSQL_DATABASE: 'guacamole_db'
      MYSQL_USER: 'guacamole_user'
      MYSQL_PASSWORD: '<PASSWD_YOU_WANT>'
    volumes:
      - /var/lib/docker/volumes/<Dir_you_want>:/var/lib/mysql
```

#### コマンド

```bash
# Establish initial DB Container
docker-compose up -d

# Copy initial sql into db container
docker cp guac_db.sql guacdb:/guac_db.sql

# Opening a shell and initializing the db:
docker exec -it guacdb bash
cat /guac_db.sql | mysql -u root -p guacamole_db
exit

# Remove initial DB OS
docker-compose -f /where/is/your/docker-compose down
```

> [!info] Updated 2026-11-27
> 1. `docker-compose` v1 はすでにサポートが終了しているため、現在の環境では `docker compose` v2 を使用してください（例：`docker compose -f initial.yml up -d` および `docker compose -f initial.yml down`。元のコマンド最終行は `.yml` 拡張子も抜けていました）。
> 2. Compose YAML トップレベルの `version: '3'` フィールドは Compose v2 では非推奨（obsolete）属性となっているため、省略することを推奨します。

### Service Up

#### `docker-compose.yml`

```yaml
version: '3'
services:
  guacdb:
    container_name: guacdb
    image: mariadb/server:latest
    restart: unless-stopped
    networks:
      - traefik
    environment:
      MYSQL_ROOT_PASSWORD: '<PASSWD_YOU_WANT>'
      MYSQL_DATABASE: 'guacamole_db'
      MYSQL_USER: 'guacamole_user'
      MYSQL_PASSWORD: '<PASSWD_YOU_WANT>'
    volumes:
      - /var/lib/docker/volumes/guacamole/db:/var/lib/mysql
  guacd:
    container_name: guacd
    image: guacamole/guacd
    restart: unless-stopped
    networks:
      - traefik
  guacamole:
    container_name: guacamole
    image: 'guacamole/guacamole:latest'
    restart: unless-stopped
    networks:
      - traefik
 #   ports:
 #     - '8080:8080'
    environment:
      GUACD_HOSTNAME: "guacd"
      MYSQL_HOSTNAME: "guacdb"
      MYSQL_DATABASE: "guacamole_db"
      MYSQL_USER: "guacamole_user"
      MYSQL_PASSWORD: "<PASSWD_YOU_WANT>"
    depends_on:
      - guacdb
      - guacd
    labels:
      traefik.enable: true
      traefik.http.routers.guacamole.rule: Host(`<hostname.you.want>`)
      traefik.http.routers.guacamole.tls: true
      traefik.http.routers.guacamole.tls.certresolver: myresolver
      traefik.http.services.guacamole.loadbalancer.server.port: 8080

networks:
  traefik:
    external: true
    name: web-service
```

> [!info] Updated 2026-11-27
> 上記と同様、Compose v2 では `version: '3'` は不要であり、`mariadb/server:latest` は `mariadb:lts` に変更すべきです（公式の新イメージでは接続用クライアントツールが `mariadb` CLI になっています）。

## 廃止理由

- セキュリティ面で望ましくなく、実質的にファイアウォールに穴を開けるような構成になってしまうため。
- 代わりに `WireGuard` + `VNC` の構成へ移行したところ、より安全かつシンプルに運用できるようになりました。
