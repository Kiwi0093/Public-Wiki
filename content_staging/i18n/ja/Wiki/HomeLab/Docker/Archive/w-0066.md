# BookStack ナレッジベースシステム構築

## 1. コアアーキテクチャと環境変数の破壊的変更 (Breaking Changes)

- **ストレージモデル**：BookStack の記事内容、ユーザー権限、ページメタデータは **MariaDB / MySQL** に保存され、画像、添付ファイル、アップロードファイルはファイルシステムのディレクトリ（`/config/www/storage`）に保存されます。

- **LinuxServer 変数名変更の落とし穴**：
  - LinuxServer.io イメージは、データベース環境変数の命名規則を Laravel のデフォルト変数に合わせるよう段階的に統一しています。
    - 旧パラメータ：`DB_USER` / `DB_PASS`
    - **新必須パラメータ**：`DB_USERNAME` / `DB_PASSWORD`
  - 旧例をそのまま流用すると、コンテナ初期化時に空の値が読み込まれ、コンテナが繰り返し `Database connection error: SQLSTATE[HY000] [1045] Access denied` を出力する原因になります。

- **`APP_URL` の厳格な制限**：
  - Laravel フレームワークは、静的アセット（CSS / JS）の生成やページリダイレクトのハイパーリンクに `APP_URL` を強く依存しています。
  - HTTPS リバースプロキシ経由で公開する場合、**`APP_URL` には必ず `https://` と完全なドメイン名を含める必要があります**（空欄や `http://localhost` にしてはいけません）。そうしないと、フロントエンドでの Mixed Content によるレイアウト崩れ、ログイン時の CSRF Token 検証エラー、または無限リダイレクトが発生します。

## 2. Docker Compose デプロイ構成 (Traefik v3 連携)

デプロイでは Traefik v3 を使用してエッジで SSL 終端を行い、バックエンドコンテナはホストポートを一切公開せず、共有の外部 Docker ネットワーク経由で統一して通信します。

### ステップ 1：専用ディレクトリと権限の作成

```bash
# 建立資料庫與應用設定目錄
sudo mkdir -p /opt/bookstack/db /opt/bookstack/app

# 設定 PUID/PGID 對齊的擁有者（以 UID 1000 為例）
sudo chown -R 1000:1000 /opt/bookstack
```

### ステップ 2：`docker-compose.yml` 完全構成

`/opt/bookstack/docker-compose.yml` にサービスを定義します：

```yaml
services:
  bookstack_db:
    image: lscr.io/linuxserver/mariadb:latest
    container_name: bookstack_db
    restart: unless-stopped
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Asia/Taipei
      - MYSQL_ROOT_PASSWORD=your_super_root_pass
      - MYSQL_DATABASE=bookstackapp
      - MYSQL_USER=bookstack
      - MYSQL_PASSWORD=your_db_secret_pass
    volumes:
      - /opt/bookstack/db:/config
    networks:
      - bookstack_internal

  bookstack:
    image: lscr.io/linuxserver/bookstack:latest
    container_name: bookstack
    restart: unless-stopped
    depends_on:
      - bookstack_db
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Asia/Taipei
      # 關鍵：必須完整帶入 https:// 且與 Traefik 路由域名一致
      - APP_URL=https://wiki.example.com
      # 資料庫連線（注意新版參數名稱）
      - DB_HOST=bookstack_db
      - DB_DATABASE=bookstackapp
      - DB_USERNAME=bookstack
      - DB_PASSWORD=your_db_secret_pass
      # SMTP 郵件通知設定（選用）
      - MAIL_DRIVER=smtp
      - MAIL_HOST=smtp.example.com
      - MAIL_PORT=587
      - MAIL_ENCRYPTION=tls
      - MAIL_USERNAME=notify@example.com
      - MAIL_PASSWORD=your_smtp_password
      - MAIL_FROM=notify@example.com
      - MAIL_FROM_NAME=BookStack Wiki
    volumes:
      - /opt/bookstack/app:/config
    networks:
      - bookstack_internal
      - proxy-network
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.bookstack.rule=Host(`wiki.example.com`)"
      - "traefik.http.routers.bookstack.entrypoints=websecure"
      - "traefik.http.routers.bookstack.tls=true"
      - "traefik.http.routers.bookstack.tls.certresolver=myresolver"
      # 關鍵：LinuxServer 內部 Nginx 監聽 Port 80，必須明確指定負載平衡目標埠
      - "traefik.http.services.bookstack.loadbalancer.server.port=80"

networks:
  bookstack_internal:
    driver: bridge
  proxy-network:
    external: true
```

サービスを起動します：

```bash
docker compose up -d
```

## 4. 主なハマりポイントと詳細トラブルシューティングガイド (Troubleshooting)

### 4.1 `http://localhost:6875` へのリダイレクトや CSS/JS のレイアウト崩れ (Mixed Content)

- **原因**：`APP_URL` の設定漏れ・書式誤り、またはリバースプロキシが転送ヘッダーを正しく渡していないこと。

- **解決策**：
  1. `APP_URL` が正しく設定されており、`https://` で始まっていることを確認する。
  2. カスタム Nginx / NPM リバースプロキシを使用する場合は、アップストリームに以下のヘッダーを必ず渡すようにする：

     ```nginx
     proxy_set_header X-Forwarded-Proto https;
     proxy_set_header X-Forwarded-Host $host;
     ```

### 4.2 なぜ Traefik で `server.port=80` を明示的に指定する必要があるのか？

- LinuxServer.io のイメージは内部で S6-overlay を使用して Nginx + PHP-FPM を起動しています。コンテナイメージ内部では複数のリスンポートが宣言されている場合があり、`traefik.http.services.bookstack.loadbalancer.server.port=80` を指定しないと、Traefik がマルチポート環境で転送先を判定できず、誤ったポートに転送して `502 Bad Gateway` を返してしまいます。

### 4.3 画像や大容量ファイルのアップロード失敗 (HTTP 413 Payload Too Large)

デフォルトのアップロード制限は PHP と Nginx の双方によって制約されています。数十 MB の PDF や動画ファイルを添付したい場合は以下を設定します：

1. `/opt/bookstack/app/php/php-local.ini` を編集します（存在しない場合は新規作成）：

   ```ini
   upload_max_filesize = 100M
   post_max_size = 100M
   memory_limit = 512M
   ```

2. `/opt/bookstack/app/nginx/site-confs/default.conf` を編集し、`server { ... }` ブロック内に以下を追加します：

   ```nginx
   client_max_body_size 100M;
   ```

3. コンテナを再起動します：`docker compose restart bookstack`。

## 5. バックアップとディザスタリカバリ (Disaster Recovery)

BookStack のデータ整合性は「データベース SQL」と「アップロードファイルディレクトリ」の両方によって維持されているため、両方を同期してバックアップする必要があります。

### 5.1 完全バックアップスクリプト

```bash
#!/bin/bash
BACKUP_DIR="/opt/backups/bookstack"
DATE=$(date +%F_%H%M%S)
mkdir -p $BACKUP_DIR

# 1. 導出 MariaDB 資料庫 Dump
docker compose exec -T bookstack_db mysqldump -u bookstack -pyour_db_secret_pass bookstackapp > $BACKUP_DIR/db_$DATE.sql

# 2. 打包上傳的附件、圖片與設定檔
tar -czvf $BACKUP_DIR/app_data_$DATE.tar.gz -C /opt/bookstack/app .

echo "Backup completed: $DATE"
```

### 5.2 ディザスタリカバリ手順

1. 新規の MariaDB コンテナと BookStack コンテナを起動する。

2. ファイルシステムの復元：`app_data_*.tar.gz` を `/opt/bookstack/app/` に展開して上書きし、権限を修正する（`chown -R 1000:1000`）。

3. データベースの復元：

   ```bash
   docker compose exec -i bookstack_db mysql -u bookstack -pyour_db_secret_pass bookstackapp < /opt/backups/bookstack/db_*.sql
   ```

4. Laravel キャッシュをクリアして再起動する：

   ```bash
   docker compose exec -it bookstack php /app/www/artisan cache:clear
   docker compose restart bookstack
   ```
