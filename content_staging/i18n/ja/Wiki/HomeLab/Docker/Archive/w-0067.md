## 基本手順

### MariaDB

1. <font size="+1" color="Green"><code>vi mariadb.yml</code></font>

```yaml
# mariadb.yml
--------------------------------------------------------------------------------------------------------------------------------
services:
  mariadb:
    image: mariadb:latest
    container_name: mariadb
    environment:
      - MYSQL_ROOT_PASSWORD=${your_DB_root_Passwd}
      - TZ=Asia/Taipei
    ports:
      - ${your_DB_host}:${your_DB_port}:3306
    volumes:
      - /var/lib/docker/volumes/mariadb/data:/var/lib/mysql
      - /var/lib/docker/volumes/mariadb/mariadbcustom.cnf:/etc/mysql/conf.d/custom.cnf
    restart: unless-stopped
```

> [!info] Updated 2026-11-27
> - コードブロック内の `----` 区切り線に `#` コメントが付いていないため、そのまま YAML に貼り付けるとパースエラーになります。
> - `MYSQL_ROOT_PASSWORD` は MariaDB 11+ では `MARIADB_ROOT_PASSWORD` に置き換えられています。

2. <font size="+1" color="Green"><code>vi  /var/lib/docker/volumes/mariadb/mariadbcustom.cnf </code></font>

```bash
# /var/lib/docker/volumes/mariadb/mariadbcustom.cnf 
--------------------------------------------------------------------------------------------------------------------------------
[client]
default-character-set = utf8mb4

[mysql]" >> /etc/my.cnf
default-character-set = utf8mb4

[mysqld]
skip-character-set-client-handshake
collation_server = utf8mb4_unicode_ci
character_set_server = utf8mb4
tmpdir      = /var/lib/mysqltmp
```

これは MariaDB のデフォルト設定を定義するためのもので、すべて utf-8 unicode を使用するようにしています。

> [!info] Updated 2026-11-27
> - ブロック内の `----` 区切り線に `#` コメントがなく、また 4 行目の `[mysql]" >> /etc/my.cnf` はコピペミスによる無効な INI 構文です（正しくは `[mysql]`）。
> - `skip-character-set-client-handshake` は新しいバージョンの MariaDB では非推奨となっているため、`character-set-client-handshake = FALSE` の使用を推奨します。また、`/var/lib/mysqltmp` をマウントしていない場合、独自の `tmpdir` 設定によりパスが存在せず起動に失敗する可能性があります。

3. <font size="+1" color="Green"><code><span style="color:#e06c75"><del>sudo docker-compose -f mariadb.yml up -d</del></span> *(Updated 2026-11-27: Docker Compose v1 の `docker-compose` はメンテナンスが終了しているため、現在の環境では `sudo docker compose -f mariadb.yml up -d` を使用してください)*</code></font>

これはコンテナを作成して起動するためのコマンドです。

4. <font size="+1" color="Green"><code>sudo docker exec -it mariadb bash</code></font>

```bash
# @mariadb container
--------------------------------------------------------------------------------------------------------------------------------
mysql -u root -p                    # 実行後、SQL root パスワードを入力して MariaDB に入る

# LibreNMS 用のアカウントとデータベースを作成し、そのアカウントにこのデータベースの全権限を付与する（コマンドが苦手な場合は phpMyAdmin で行ってもよい）
mysql> CREATE DATABASE librenms CHARACTER SET utf8 COLLATE utf8_unicode_ci;
mysql> CREATE USER 'librenms'@'%' IDENTIFIED BY 'user_librenms_password';
mysql> GRANT ALL PRIVILEGES on librenms.* TO 'librenms'@'%' WITH GRANT OPTION;
mysql> FLUSH PRIVILEGES;
```

> [!info] Updated 2026-11-27
> - MariaDB 11+ コンテナでは `mariadb` CLI コマンドの使用が推奨されています（`mysql` シンボリックリンクは非推奨マークが付いています）。
> - LibreNMS 公式ドキュメントでは、データベースに `utf8mb4` と `utf8mb4_unicode_ci` を使用することが求められています（MySQL/MariaDB における `utf8` は実際には旧式の 3-byte `utf8mb3` です）。

### LibreNMS

1. <font size="+1" color="Green"><code>vi librenms.yml</code></font>

```yml
#librenms.yml
--------------------------------------------------------------------------------------------------------------------------------
version: '3'
services:
  librenms:
    image: librenms/librenms:latest
    container_name: librenms
    command: su - librenms -c "/opt/librenms/librenms-service.py -v"
    environment:
      - TZ=Asia/Taipei
      - PUID=1000
      - DB_HOST=${your_DB_host}
      - DB_PORT=${your_DB_port}
      - DB_NAME=librenms
      - DB_USER=librenms
      - DB_PASSWORD=user_librenms_passwd
      - DB_TIMEOUT=10
      - LIBRENMS_SNMP_COMMUNITY=${Community_name_you_want}
    ports:
      - ${your_Server_ip}:${port_you_want}:8000
    volumes:
      - /var/lib/docker/volumes/librenms/data:/data
    restart: always
```

ここで重要なポイントとして、必ず以下を追加する必要があります。

<font size="+2" color="blue"><code>command: su - librenms -c "/opt/librenms/librenms-service.py -v"</code></font>

これは <font color="blue">librenms</font> というアカウントで <font color="blue"><code>/opt/librenms/librenms-service.py -v</code></font> を実行するという意味です。

こうすることで rrd の権限が正しくなり、問題が起きなくなります（以前これが optional だと思い込んでずっとうまく動かず苦労しました。これは必須条件です…）。

> [!info] Updated 2026-11-27
> - ブロック内の `----` 区切り線に `#` が付いておらず、また `version: '3'` は Docker Compose v2 では非推奨です。
> - 現在の公式 `librenms/librenms` Docker デプロイ構成はマルチコンテナ構成（`librenms` メインサービスに `librenms-service.py` を実行する `dispatcher` sidecar、および `db`、`redis` を組み合わせる形）に変更されており、メインコンテナの `command` を直接上書きすることはなくなっています。

2. <font size="+1" color="Green"><code>sudo docker exec -it mariadb bash</code></font>

```bash
 # MariaDB コンテナに入る
--------------------------------------------------------------------------------------------------------------------------------
mysql -u librenms -p                    # librenms アカウントで MariaDB にログイン

mysql> use librenms;                        # librenms データベースを使用
# データベースのテーブル定義を修正
mysql> ALTER TABLE `notifications` CHANGE `datetime` `datetime` timestamp NOT NULL DEFAULT '1970-01-02 00:00:00' ; 
mysql> ALTER TABLE `users` CHANGE `created_at` `created_at` timestamp NOT NULL DEFAULT '1970-01-02 00:00:01' ;
```

これはデータベースの不具合を修正するためのものです（Validate Config に表示される問題の修正）。

> [!info] Updated 2026-11-27
> 上記の `ALTER TABLE` は、初期に MySQL の `NO_ZERO_DATE` 厳格モードへ対処するための暫定的な回避策に過ぎません。現在の LibreNMS では `lnms migrate` がデータベーススキーマのマイグレーションを自動管理するため、手動でテーブルのデフォルト値を変更する必要はありません。

### おまけ - phpMyAdmin

正直なところあまり出番はありませんが、mysql コマンドが苦手な場合はこの GUI を使って MySQL データベースを操作できます。

非常にシンプルなので、`docker run` コマンドで直接構築すれば大丈夫です。

```bash
# ${your_DB_host} がデフォルトの 3306 の場合
sudo docker run --name phpmyadmin -d -e PMA_HOST=${your_DB_host} -p 8080:80 phpmyadmin/phpmyadmin

# ${your_DB_host} がデフォルトの 3306 でない場合は docker --link で接続することを推奨
sudo docker run --name phpmyadmin -d --link mariadb:db -p 8080:80 phpmyadmin/phpmyadmin
```

ここの 8080 ポートは外部向けなので、好きなポートに変更できます。

> [!info] Updated 2026-11-27
> `--link` は非推奨となった旧来の Docker オプションです。現在の環境ではカスタムブリッジネットワーク（`docker network create`）を作成し、`--network` でコンテナ間を接続してください。

### Nginx 設定

正直なところ、サブディレクトリ形式で運用するためにコンテナ内の `config.php` を書き換えるのは面倒だと感じたので、専用のドメイン名（DN）をもう一つ取得して使うことにしました。

Nginx の設定は通常の Virtual Host 設定そのままで、<span style="color:#e06c75"><del>/etc/nginx/site-enables/</del></span> *(Updated 2026-11-27: Debian/Ubuntu での正しいパスは `/etc/nginx/sites-available/` であり、そこから `/etc/nginx/sites-enabled/` へシンボリックリンクを作成して有効化します)* 配下に `.cnf` ファイルを追加して定義するだけです。

このドメイン名用に certbot の証明書を別途取得しておくことも忘れないでください。

```bash
# librenms.cnf
--------------------------------------------------------------------------------------------------------------------------------
server {
 listen 80;
 server_name librenms.exsample.com;
 return 301 https://$server_name$request_uri;
}
server {
 listen 443 ssl http2;
 server_name librenms.exsample.com;

 ssl_certificate /etc/letsencrypt/live/librenms.exsample.com/fullchain.pem;
 ssl_certificate_key /etc/letsencrypt/live/librenms.exsample.com/privkey.pem;
# include /etc/letsencrypt/options-ssl-nginx.conf;
# ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;


#charset koi8-r;
 #access_log /var/log/nginx/host.access.log main;

client_max_body_size 20M;


location / {
 proxy_pass http://${your_Server_ip}:${port_you_want};            # ここを転送先の IP/ポートに変更
 proxy_set_header Host $host;
 proxy_set_header X-Real-IP $remote_addr;
 proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
 proxy_set_header X-Forwarded-Proto $scheme;
 proxy_set_header X-Forwarded-Protocol $scheme;
 proxy_set_header X-Forwarded-Host $http_host;
 proxy_buffering off;

        }

error_page 500 502 503 504 /50x.html;
 location = /50x.html {
 root /usr/share/nginx/html;
```

> [!info] Updated 2026-11-27
> - サンプル内に `#` の付いていない `----` 区切り線や、スペルミスのドメイン `exsample.com` が含まれており、さらに末尾で `location` と `server` ブロックの閉じ波括弧 `}` が欠落しています。
> - `listen 443 ssl http2;` の書き方は Nginx 1.25.1+ で非推奨となっており、現在は `listen 443 ssl;` と独立したディレクティブ `http2 on;` に分ける必要があります。

1. <font size="+1" color="Green"><code>SSH で ESXi にログイン後</code></font>

```bash
esxcli system snmp get                                    # snmp の状態と設定値を確認
esxcli system snmp set -c YOUR_STRING                    # community を設定
esxcli system snmp set -p 161                            # snmp ポートを設定（基本的には 161 udp を使用）
esxcli system snmp set -L "City, State, Country"        # Location を設定
esxcli system snmp set -C noc@example.com                # 連絡先を設定
esxcli system snmp set -e yes                            # 有効化を設定
```

2. <font size="+1" color="Green">SNMP を読み取れる別のマシンで実行</font>

```bash
snmpwalk -v2c -c ${YOUR_STRING} ${your_server_IP}
```

データが返ってくるか確認できれば完了です。

## まとめ

* LibreNMS 内の `config.php` を編集したくない場合、Community には `public` 以外の文字列を使わない方が後々扱いやすくて便利です。
* これらを有効化した後、はっきりとしたグラフが表示されるまで少なくとも数時間はかかるため、設定直後にデータが出なくても焦らないでください。

> [!info] Updated 2026-11-27
> セキュリティ上の観点から、本番環境や外部ネットワークに面した環境ではデフォルトの `public` SNMP Community 文字列をそのまま使用することは推奨されません。独自の複雑な文字列へ変更するか、認証および暗号化機構を備えた SNMPv3 へアップグレードしてください。

## 廃止理由

* 利用率が低い - 構築後ほとんど使わなかった
* `netdata` などの代替手段があり、しかも Gateway と DHCP サーバーに直接インストールしてしまったため、なおさら出番がなくなった
