# MS SQL-Server docker-compose.yml

```yml
# Docker-compose.yml
version: '3'
services:
  mssql
    image:  mcr.microsoft.com/mssql/server:2019-latest
    container_name: sql-server
    environment:
      - PUID=1000
      - ACCEPT_EULA=Y
#     - MSSQL_PID=<your_product_id | edition_name> (default: Developer)"
      - SA_PASSWORD=<your@Passw0rd>
    ports:
      - 1433:1433
    volumes:
      - /var/lib/docker/volumes/mssql:/var/lib/mssqlql
    restart: always
```

> [!info] Updated 2026-11-27
> このアーカイブ済みの設定ファイルには複数の構文エラーや非推奨パラメータが含まれていますが、履歴対照のために原文のまま残しています：
> - **YAML 構文エラー**：`mssql` サービス名の後ろにコロンが抜けています（正しくは `mssql:`）。
> - **マウントパスの誤り**：Microsoft 公式 SQL Server コンテナのデータディレクトリは `/var/opt/mssql` であり（原文では `/var/lib/mssqlql` と誤記）、また `/var/lib/docker/volumes/...` を直接ベタ書きするのではなく Docker named volume の使用が推奨されます。
> - **Compose V2 仕様**：新しい `docker compose` を使用する場合、トップレベルの `version: '3'` 宣言は不要です。
> - **環境変数とバージョン**：`2019-latest` はすでに旧版であり、SQL Server 2022 以降は `SA_PASSWORD` に代わって `MSSQL_SA_PASSWORD` が使用されます。

### 基本説明

* <span style="color:#e06c75"><del>PUID=1000 SQL-Server は root で実行できないため別途 USER を指定しないと問題が起きやすいのですが、多くの解説記事では指定されておらず、入れなくても問題なく動くのであればこの行は不要です</del></span> *(Updated 2026-11-27: Microsoft 公式の `mcr.microsoft.com/mssql/server` イメージは `PUID` 環境変数に対応していません（これは LinuxServer.io 製イメージの独自仕様です）。非 root ユーザーで実行したい場合は、Compose 側で `user:` を指定し、ディレクトリの権限を合わせて設定する必要があります。)*
* `ACCEPT_EULA=Y`：同意しないと起動しないので実質必須ですが、Microsoft 公式イメージなので変えようがありません。
* `MSSQL_PID`：実は最も重要なパラメータです。起動する SQL Server のエディションを決定するため、企業利用の場合は購入したプロダクトキー（またはエディション名）をここに指定します。
* `SA_PASSWORD`：文字通り、MySQL における root パスワードの定義に相当します。
