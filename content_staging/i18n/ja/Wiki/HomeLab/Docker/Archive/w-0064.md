## Certbot

### インストールと証明書の発行

参考：<span style="color:#e06c75"><del>https://certbot.eff.org/docs/install.html#running-with-docker</del></span> *(Updated 2026-11-27: 公式ドキュメントは [eff-certbot.readthedocs.io](https://eff-certbot.readthedocs.io/en/latest/install.html#running-with-docker) に移行しました)*

```bash
sudo docker run -it --rm --name certbot -v "/etc/letsencrypt:/etc/letsencrypt" -v "/var/lib/letsencrypt:/var/lib/letsencrypt" \
            certbot/certbot certonly
```

特定の IP アドレスごとに異なるドメインを割り当てたい場合は、`-p <任意のIP>:80:80 -p <任意のIP>:443:443` のようにパラメータを追加すれば対応できます。

### 自動更新の設定

crontab に以下を追加するだけです。

```bash
0 0 * * * docker run --rm -v /etc/letsencrypt:/etc/letsencrypt -ti certbot/certbot renew
```

これで完了です。

> [!info] Updated 2026-11-27
> 1. `crontab` は非対話的な実行環境であるため、元のスケジュールコマンドにある `-ti`（特に疑似端末を割り当てる `-t`）があると Docker が `the input device is not a TTY` エラーを出して失敗します。cron 用のコマンドからは `-ti` を削除してください。
> 2. standalone モードで HTTP-01 認証を行う場合、初回発行時にはコンテナが Let's Encrypt からの検証リクエストを受け取れるよう `-p 80:80`（または `--network host`）の指定が必要です。
> 3. 現在のコンテナ構成では、ACME による自動発行・更新機能を内蔵したリバースプロキシ（Traefik、Caddy、Nginx Proxy Manager など）を利用するのが一般的になっています。

## 廃止理由

もう出番がなくなりました……今は Traefik や Nginx Proxy Manager のような SSL 自動発行機能付きのリバースプロキシを使っているため、こういった単体の仕組みは不要になりました。
