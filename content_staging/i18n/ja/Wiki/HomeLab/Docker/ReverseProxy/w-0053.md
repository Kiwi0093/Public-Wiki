## 1. コア概念とアーキテクチャ解説

Traefik のデータフローと設定ロジックは、3 つの主要な抽象コンポーネントで構成されています。

```text
[外部リクエスト (Client)]
        │ (Port 80 / 443)
        ▼
   [EntryPoints]   ─── (web / websecure: 待ち受けるプロトコルとポートを定義)
        │
        ▼
     [Routers]      ─── (Host(`app.example.com`) などの Rule に基づきリクエストを解析)
        │
        ├─► [Middlewares] ─── (中間処理：HTTP→HTTPS リダイレクト、Basic Auth、Rate Limit など)
        │
        ▼
    [Services]      ─── (対応するコンテナ IP と内部ポートへ転送)
        │
        ▼
 [バックエンドコンテナ (Backend App)]
```

- **静的設定 (Static Configuration)**：グローバルな基盤設定（EntryPoints、Providers、証明書リゾルバ ACME）を定義します。起動時に読み込まれ、CLI 引数（`command:`）または静的設定ファイル（`traefik.yml`）をサポートします。

- **動的設定 (Dynamic Configuration)**：ルーティングルール（Routers、Services、Middlewares）を定義します。Provider（ここでは Docker Labels）によって動的に注入されるため、コンテナの再起動や変更時に Traefik 本体 を再起動する必要はありません。

- **SSL 証明書の保存 (`acme.json`)**：Traefik は ACME クライアントを統合しており、Let's Encrypt によって発行されたすべての秘密鍵と証明書は単一の JSON ファイルに保存されます。**このファイルのパーミッションは厳密に `600` に制限する必要があります**。そうでない場合、Traefik はセキュリティ上の理由から読み込みを直接拒否します。

## 2. Traefik v3 コア設定 (Docker Compose)

旧バージョンの v2.5 と比較して、**Traefik v3** では複数のモダン化および簡素化の改善が導入されています。

1. **EntryPoints での HTTP→HTTPS リダイレクトのネイティブサポート**：Routers 側で煩雑な `hostregexp` catch-all や RedirectScheme ミドルウェアを宣言する必要がなくなり、EntryPoint で直接 `redirections` を有効化するだけでグローバルに適用されます。

2. **ACME チャレンジ方式の排他制御**：`httpChallenge` と `tlsChallenge` を同時に有効にすることはできません。いずれか一方を選択します（一般的には 443 ポートのみで完結する `tlsChallenge` が最もシンプルで推奨されます）。

3. **セキュリティ強化**：Dashboard はデフォルトで明示的なミドルウェア認証（BasicAuth など）による保護が必須となり、無保護での直接公開は許可されません。

### ステップ 1：専用ネットワークとマウントディレクトリの作成

各プロジェクトのコンテナと Traefik のネットワークが互いに干渉するのを防ぐため、グローバルに共有する Docker Bridge ネットワークを作成します。

```bash
# Traefik 専用の共有外部ネットワークを作成
docker network create proxy-network

# 証明書保存用ディレクトリを作成し、acme.json の権限を初期化（必ず 600 にする）
mkdir -p /opt/traefik/letsencrypt
touch /opt/traefik/letsencrypt/acme.json
chmod 600 /opt/traefik/letsencrypt/acme.json

# BasicAuth のユーザー名・パスワードを作成（admin / secret123 の例。apache2-utils のインストール、または openssl/htpasswd を使用）
# 形式: username:hashed_password（注意：YAML 内ではエスケープ回避のため $ を $$ と記述する必要があります）
echo $(htpasswd -nb admin secret123)
# 出力例：admin:$apr1$xyz123... -> label に記述する際は admin:$$apr1$$xyz123... に変換
```

### ステップ 2：Traefik 本体 `docker-compose.yml` (v3 設定)

`/opt/traefik/docker-compose.yml` に以下を設定します。

```yaml
services:
  traefik:
    image: traefik:v3.1
    container_name: traefik
    restart: unless-stopped
    security_opt:
      - no-new-privileges:true
    networks:
      - proxy-network
    ports:
      - "80:80"
      - "443:443"
      # デバッグ・Dashboard を直接確認したい場合は 8080 を開放可能。本番環境では内部 Router 経由でアクセスし 8080 マッピングを閉じることを推奨
      # - "8080:8080"
    volumes:
      - /etc/localtime:/etc/localtime:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - /opt/traefik/letsencrypt/acme.json:/letsencrypt/acme.json
    command:
      #### 1. API とダッシュボード (Dashboard) ####
      - --api.dashboard=true
      - --api.insecure=false

      #### 2. ログとデバッグ記録 ####
      - --log.level=INFO
      - --accesslog=true

      #### 3. Docker Provider 設定 ####
      - --providers.docker=true
      - --providers.docker.exposedbydefault=false # デフォルトでは公開せず、明示的に label を付与したコンテナのみプロキシする
      - --providers.docker.network=proxy-network # デフォルトの通信ネットワークを明示的に指定

      #### 4. EntryPoints (ポート定義) ####
      # HTTP (Port 80) - v3 ネイティブ組み込みのグローバル HTTPS リダイレクト
      - --entrypoints.web.address=:80
      - --entrypoints.web.http.redirections.entrypoint.to=websecure
      - --entrypoints.web.http.redirections.entrypoint.scheme=https
      - --entrypoints.web.http.redirections.entrypoint.permanent=true

      # HTTPS (Port 443)
      - --entrypoints.websecure.address=:443

      #### 5. 証明書リゾルバ (Let's Encrypt ACME) ####
      # TLS-ALPN-01 チャレンジを使用（443 ポートで直接検証するため、追加のディレクトリ公開が不要）
      - --certificatesresolvers.myresolver.acme.tlschallenge=true
      - --certificatesresolvers.myresolver.acme.email=your-email@example.com
      - --certificatesresolvers.myresolver.acme.storage=/letsencrypt/acme.json
    labels:
      - "traefik.enable=true"

      # --- Dashboard ルーティング設定 (HTTPS) ---
      - "traefik.http.routers.traefik-dashboard.rule=Host(`traefik.example.com`)"
      - "traefik.http.routers.traefik-dashboard.entrypoints=websecure"
      - "traefik.http.routers.traefik-dashboard.service=api@internal"
      - "traefik.http.routers.traefik-dashboard.tls=true"
      - "traefik.http.routers.traefik-dashboard.tls.certresolver=myresolver"

      # --- Dashboard セキュリティ保護 (BasicAuth ミドルウェア) ---
      - "traefik.http.routers.traefik-dashboard.middlewares=auth"
      # 注意：パスワード文字列内の $ 記号は compose 内で $$ にエスケープする必要があります
      - "traefik.http.middlewares.auth.basicauth.users=admin:$$apr1$$xyz123...YourHash..."

networks:
  proxy-network:
    external: true
```

## 3. プロキシ対象サービス (Upstream Container) の設定ルール

Web サービスをデプロイする際、**ホスト側へ `ports` を公開する必要はありません**。次の 2 つの条件を満たすだけで動作します。

1. 共有外部ネットワーク `proxy-network` に参加する。

2. `labels` を付与し、サービスのドメイン名とターゲットポートを Traefik に伝える。

### 構文構造のロジック

Traefik Labels の階層ルールは次の形式に従います。

```
traefik.<プロトコル>.<コンポーネント種別>.<カスタム識別名>.<具体的なパラメータ>=<値>
```

### 例：Whoami テストサービスおよび独立アプリ（V2ray / Web App など）のデプロイ

```yaml
services:
  whoami:
    image: traefik/whoami
    container_name: test-whoami
    restart: unless-stopped
    networks:
      - proxy-network
    # ports: ["80:80"] の記述は不要。コンテナを完全に内部ネットワークに留めることでホストのセキュリティを向上
    labels:
      # 1. Traefik による検出を有効化
      - "traefik.enable=true"

      # 2. HTTPS Router ルールを定義
      - "traefik.http.routers.whoami.rule=Host(`whoami.example.com`)"
      - "traefik.http.routers.whoami.entrypoints=websecure"

      # 3. TLS 自動証明書取得を有効化
      - "traefik.http.routers.whoami.tls=true"
      - "traefik.http.routers.whoami.tls.certresolver=myresolver"

      # 4. 内部転送ポートを指定（イメージが複数ポートを EXPOSE している場合やカスタムポート使用時は必須）
      - "traefik.http.services.whoami.loadbalancer.server.port=80"

networks:
  proxy-network:
    external: true
```

## 4. よく使われる実用 Middlewares (ミドルウェア) 設定例

Docker Labels 内で、アプリケーションの手前に各種セキュリティやフィルタリングのミドルウェアを接続できます。

### 4.1 セキュリティヘッダー (Security Headers / HSTS)

```yaml
labels:
  - "traefik.http.middlewares.sec-headers.headers.sslredirect=true"
  - "traefik.http.middlewares.sec-headers.headers.stsseconds=31536000"
  - "traefik.http.middlewares.sec-headers.headers.browserxssfilter=true"
  - "traefik.http.middlewares.sec-headers.headers.contenttypenosniff=true"
  - "traefik.http.routers.myapp.middlewares=sec-headers"
```

> [!info] Updated 2026-11-27
> `headers.sslredirect` は **Traefik v3** で正式に削除されたため、v3 の設定ファイルにこのパラメータを残すと起動に失敗します。HTTP から HTTPS へのリダイレクトは、第 2 節で示した EntryPoints のグローバルリダイレクト設定（`--entrypoints.web.http.redirections.entrypoint.*`）または `redirectScheme` ミドルウェアを使用してください。また、`browserxssfilter`（`X-XSS-Protection`）も現代のブラウザでは非推奨となっています。

### 4.2 レート制限 (Rate Limit)

API やログインエンドポイントへのブルートフォース攻撃を防止します。

```yaml
labels:
  # 平均毎秒 100 リクエスト、最大バースト 50 リクエスト
  - "traefik.http.middlewares.my-ratelimit.ratelimit.average=100"
  - "traefik.http.middlewares.my-ratelimit.ratelimit.burst=50"
  - "traefik.http.routers.myapp.middlewares=my-ratelimit"
```

### 4.3 パスプレフィックスの削除 (StripPrefix)

`example.com/api/*` をコンテナに転送する際、自動的に `/api` を取り除きます。

```yaml
labels:
  - "traefik.http.routers.myapi.rule=Host(`example.com`) && PathPrefix(`/api`)"
  - "traefik.http.middlewares.api-strip.stripprefix.prefixes=/api"
  - "traefik.http.routers.myapi.middlewares=api-strip"
```

## 5. 重要なアーキテクチャ原則とトラブルシューティング

### 5.1 SSL オフロード (SSL Offloading)

- バックエンドコンテナ（Nextcloud、WordPress、V2ray など）の**内部では直接 HTTP を実行してください**。コンテナ内で自己署名証明書を使ったり HTTPS を動かしたりしないでください。

- すべての証明書の暗号化・復号は Traefik の境界で一括処理（SSL Offloading）し、コンテナと Traefik の間は内部 Docker ネットワーク経由で純粋な HTTP 通信を行うことで、演算負荷を大幅に下げ、証明書の競合を防ぎます。

### 5.2 証明書取得失敗時の切り分けポイント

| **よくあるエラー現象**                                                         | **根本原因**                     | **対処方法**                                                                                             |
| ------------------------------------------------------------------ | ---------------------------- | ---------------------------------------------------------------------------------------------------- |
| `permissions of /letsencrypt/acme.json are too open`               | ファイル権限が 600 ではない                   | `chmod 600 /opt/traefik/letsencrypt/acme.json` を実行し、Traefik を再起動する。                                       |
| `Cannot obtain certificates: 403 / 400 urn:ietf:params:acme:error` | 外部 Port 80/443 が開通していない、または DNS が未反映 | 外部ファイアウォール／ルーターで 80/443 がホストへ転送されているか、および Public DNS の A レコードが自機のパブリック IP を正しく指しているか確認する。                                             |
| `Bad Gateway (502)`                                                | Traefik がバックエンドコンテナに疎通できない             | 1. バックエンドコンテナが `proxy-network` に参加しているか確認する。<br />2. `loadbalancer.server.port` で指定したポートがコンテナ内部の Listen ポートと一致しているか確認する。 |
| コンテナに複数ポートがあり転送先が混乱する                                                   | イメージに複数の EXPOSE ポートが定義されている            | `traefik.http.services.<name>.loadbalancer.server.port=<port>` で明確に固定する必要がある。                            |
