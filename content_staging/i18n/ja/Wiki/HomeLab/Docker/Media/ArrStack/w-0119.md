## 5. サービス間連携ガイド（内部通信の入力標準）

すべてのサービス（Gluetun に依存する qBittorrent を除く）が同じ `media_net` カスタムネットワーク内にあるため、**コンテナ間はサービス名を使って直接 DNS 通信が可能**です。ホストの IP を入力したり、追加の静的 IP を設定したりする必要はありません。

### 5.1 Prowlarr と FlareSolverr の連携

- Prowlarr で **Settings** -> **Indexers** を開き、**FlareSolverr** の追加をクリックします。

- **Host** に入力：`http://flaresolverr:8191`

- **Tag** に入力：`flaresolverr`（今後 Cloudflare 保護があるサイトに遭遇した際、該当の Indexer にこの Tag を付けるだけで済みます）。

### 5.2 Prowlarr から Sonarr / Radarr / Lidarr への自動同期

**Settings** -> **Apps** を開き、追加をクリックします：

- **Sonarr**：

  - **Prowlarr Server**：`http://prowlarr:9696`

  - **Sonarr Server**：`http://sonarr:8989`

  - **ApiKey**：Sonarr の API Key を入力します。

- **Radarr** と **Lidarr** も同様に、対応するコンテナ名とポート番号を入力します。保存すると、Prowlarr 内のすべてのトレントサイトが各アプリケーションへ自動的に同期されます。

### 5.3 Sonarr / Radarr と qBittorrent の連携

**Settings** -> **Download Clients** を開き、**qBittorrent** を選択します：

- **Host**：`gluetun` を入力（**注意：qBittorrent は Gluetun のネットワークを使用しているため、外部に公開されるホスト名は `gluetun` になります**）。

- **Port**：`4080`

- **Username / Password**：qBittorrent WebUI で設定したユーザー名とパスワードを入力します。

- **Category**：

  - Sonarr に入力：`tv`

  - Radarr に入力：`movies`

  - Lidarr に入力：`music`

### 5.4 Bazarr と Sonarr / Radarr の連携

- **Settings** -> **Sonarr** を開く：
  - **Address**：`sonarr`、**Port**：`8989`、API Key を入力します。
- **Settings** -> **Radarr** を開く：
  - **Address**：`radarr`、**Port**：`7878`、API Key を入力します。

## 6. よくあるトラブルシューティング (Troubleshooting)

### 6.1 qBittorrent のデフォルトパスワードでログインできない（無効な認証情報）

新しいバージョンの LinuxServer qBittorrent コンテナでは、セキュリティ向上のためデフォルトの `adminadmin` が廃止されています：

- **初回パスワードの取得**：`docker compose logs qbittorrent` を実行すると、ログに一度限りのランダム生成された管理者パスワードが出力されます。

- **手動でのパスワードリセット**：ログインできない場合は、以下のコマンドを実行して `adminadmin` にリセットできます：

  ```bash
  # qbittorrent を停止
  docker compose stop qbittorrent
  # /opt/appdata/qbittorrent/qBittorrent/qBittorrent.conf を編集
  # WebUI\Password_PBKDF2 の行を削除してからコンテナを再起動
  docker compose start qbittorrent
  ```

### 6.2 Lidarr で音楽を追加できない、アーティストを検索できない (MusicBrainz エラー)

- **原因**：旧構成で Lidarr を Gluetun の内部に配置していた場合、VPN ノードが MusicBrainz API にブロックされたり、Gluetun の DNS 異常でリクエストがタイムアウトしたりすることがよくありました。

- **対処**：Rev 2.0 アーキテクチャに従い、Lidarr を標準の Docker ネットワークに接続してローカルのブロードバンド経由で外部通信するようにすれば、アーティストのメタデータ照会が固まる問題を解決できます。

### 6.3 ファイルが重複して容量を圧迫し、ディスクが急速に埋まる

- **原因**：Sonarr / Radarr のダウンロードディレクトリマッピングが qBittorrent と一致していないため、Hardlink 機構が機能せず「コピー（Copy）」にフォールバックしています。

- **対処**：各コンテナの volume 設定を確認し、マッピングパスが全体で同一のルートディレクトリになっていること（例：すべて `/data:/data` を使用）を確認したうえで、Sonarr/Radarr の **Settings -> Media Management** で **Use Hardlinks instead of Copy** が有効になっていることを確認してください。
