# Nextcloud と Traefik v3 リバースプロキシの構築

## 1. 基本方針と落とし穴回避のポイント

- **イメージの選定**：
  - 公式の標準イメージ `nextcloud:apache`（または `nextcloud:latest`）の使用を強く推奨します。Apache + PHP-FPM 統合環境が内蔵されており、`X-Forwarded-*` ヘッダーとの互換性が最も成熟しています。
  - **LinuxServer.io 版の Nextcloud は絶対に避けること**：このイメージは Nginx と自己署名 SSL の処理が組み込まれており、外部リバースプロキシの SSL オフロード（SSL Offloading）と深刻な競合を起こします。
- **権限の罠 (UID 33)**：
  - 公式コンテナ内部の実行ユーザーは `www-data` であり、その **UID と GID はいずれも 33** です。ホスト側でマウントするディレクトリの所有権は必ず `33:33` に割り当てる必要があり、そうしないと `.ocdata` やデータディレクトリの読み書きができず起動に失敗します。
- **データディレクトリの分離 (`NEXTCLOUD_DATA_DIR`)**：
  - ユーザーがアップロードするデータは `/var/www/data`（Web ルートディレクトリ `/var/www/html` の外側）に独立してマウントします。これによりセキュリティを確保しつつ、個別のスナップショット取得や外部ディスクボリュームのマウントが容易になります。

## 2. Docker Compose 完全デプロイ構成 (Traefik v3 モダン設定)

### ステップ 1：専用ディレクトリの作成と権限の修正

```bash
# アプリケーションディレクトリと独立したデータ保存ディレクトリを作成
sudo mkdir -p /opt/nextcloud/html
sudo mkdir -p /opt/nextcloud/data

# 所有権をコンテナ内の www-data (UID 33) に付与
sudo chown -R 33:33 /opt/nextcloud/html /opt/nextcloud/data
sudo chmod 750 /opt/nextcloud/data
```

### ステップ 2：`docker-compose.yml` の構成

`/opt/nextcloud/docker-compose.yml` に以下を記述します：

```yaml
services:
  nextcloud:
    image: nextcloud:apache
    container_name: nextcloud
    restart: unless-stopped
    environment:
      - TZ=Asia/Taipei
      # 1. 初期データベース設定（SQLite を使用）
      - SQLITE_DATABASE=nextcloud
      # 2. データディレクトリの独立パス（ネストマウント問題を回避）
      - NEXTCLOUD_DATA_DIR=/var/www/data
      # 3. 初回インストール時に信頼するドメイン（複数の場合はスペース区切り）
      - NEXTCLOUD_TRUSTED_DOMAINS=cloud.example.com
      # 4. 信頼するプロキシのネットワークセグメント（Docker デフォルトセグメント）
      - TRUSTED_PROXIES=172.16.0.0/12 10.0.0.0/8 192.168.0.0/16
      # 5. 外部リクエストを強制的に HTTPS として認識させる（ログイン時の http リダイレクトや CSRF 失敗を防ぐ鍵）
      - OVERWRITEPROTOCOL=https
      - OVERWRITECLIURL=https://cloud.example.com
      - OVERWRITEHOST=cloud.example.com
      # 6. PHP 実行環境のリソース上限調整
      - PHP_MEMORY_LIMIT=1024M
      - PHP_UPLOAD_LIMIT=16G
    volumes:
      - /opt/nextcloud/html:/var/www/html
      - /opt/nextcloud/data:/var/www/data
    networks:
      - proxy-network
    labels:
      - "traefik.enable=true"

      # --- [Router 基本設定] ---
      - "traefik.http.routers.nextcloud.rule=Host(`cloud.example.com`)"
      - "traefik.http.routers.nextcloud.entrypoints=websecure"
      - "traefik.http.routers.nextcloud.tls=true"
      - "traefik.http.routers.nextcloud.tls.certresolver=myresolver"
      # ミドルウェアリストのアタッチ
      - "traefik.http.routers.nextcloud.middlewares=nc-dav,nc-wellknown,nc-headers"
      # コンテナ内部の Apache の 80 番ポートへ転送するよう明示的に指定
      - "traefik.http.services.nextcloud.loadbalancer.server.port=80"

      # --- [Middleware 1: CalDAV / CardDAV リダイレクト] ---
      - "traefik.http.middlewares.nc-dav.redirectregex.regex=^https://(.*)/\\.well-known/(card|cal)dav(.*)"
      - "traefik.http.middlewares.nc-dav.redirectregex.replacement=https://$${1}/remote.php/dav$${3}"
      - "traefik.http.middlewares.nc-dav.redirectregex.permanent=true"

      # --- [Middleware 2: Webfinger / Nodeinfo リダイレクト (新バージョンの黄色い警告を解消)] ---
      - "traefik.http.middlewares.nc-wellknown.redirectregex.regex=^https://(.*)/\\.well-known/(webfinger|nodeinfo)(.*)"
      - "traefik.http.middlewares.nc-wellknown.redirectregex.replacement=https://$${1}/index.php/.well-known/$${2}$${3}"
      - "traefik.http.middlewares.nc-wellknown.redirectregex.permanent=true"

      # --- [Middleware 3: セキュリティヘッダーと HSTS] ---
      - "traefik.http.middlewares.nc-headers.headers.stsSeconds=31536000"
      - "traefik.http.middlewares.nc-headers.headers.stsIncludeSubdomains=true"
      - "traefik.http.middlewares.nc-headers.headers.stsPreload=true"
      - "traefik.http.middlewares.nc-headers.headers.contentTypeNosniff=true"
      - "traefik.http.middlewares.nc-headers.headers.browserXssFilter=true"

networks:
  proxy-network:
    external: true
```

サービスを起動します：

```bash
docker compose up -d
```

## 3. システム初期化後の「追加設定」と警告の完全解消

Web UI 上で管理者アカウントの作成を完了した後、「管理設定」→「概要」へ進み、警告が出ている場合は以下の手順で対処してください：

### 3.1 警告の解消：「メモリキャッシュが設定されていません (Memcache)」

公式イメージには `APCu` モジュールがコンパイル済みですが、設定ファイルで明示的に指定する必要があります：

1. `/opt/nextcloud/html/config/config.php` を編集し、`$CONFIG = array (` ブロック内に以下を追加します：

   ```php
      'memcache.local' => '\OC\Memcache\APCu',
   ```

2. PHP CLI でも APCu を有効にします（バックグラウンド Cron 実行時のエラーを防ぐため）：

   `/opt/nextcloud/html/.user.ini` を新規作成または編集し、以下を追加します：

   ```ini
   apc.enable_cli=1
   ```

3. コンテナを再起動して反映させます：

   ```bash
   docker compose restart nextcloud
   ```

### 3.2 警告の解消：「データベースに不足しているインデックス」または「BigInt カラム未変換」

コンテナ内の `occ` コマンドを直接使用して自動修復します：

```bash
# 不足しているデータベースインデックスを補完
docker compose exec --user 33 nextcloud php occ db:add-missing-indices

# ファイルキャッシュの BigInt カラムを変換
docker compose exec --user 33 nextcloud php occ db:convert-filecache-bigint
```

### 3.3 稼働後のドメイン追加やリバースプロキシ調整（Compose は変更しない！）

コンテナの初回構築後、環境変数は `config.php` を上書きしなくなります。後日ドメインを追加したり信頼済み IP を追加したりする場合は、`occ` を直接使用してください：

```bash
# 2 つ目のドメインを追加 (例: cloud2.example.com)
docker compose exec --user 33 nextcloud php occ config:system:set trusted_domains 2 --value="cloud2.example.com"

# 信頼済みプロキシセグメント (Trusted Proxies) の追加・変更
docker compose exec --user 33 nextcloud php occ config:system:set trusted_proxies 0 --value="172.16.0.0/12"
docker compose exec --user 33 nextcloud php occ config:system:set trusted_proxies 1 --value="10.0.0.0/8"
```

## 4. バックグラウンド定期タスク設定：Cron vs. Systemd Timer

Nextcloud デフォルトの **AJAX モード** はユーザーが Web ページをクリックすることでメンテナンスタスクを実行するため、閲覧速度が低下するだけでなく、夜間に誰もアクセスしない時間帯はスケジュールが完全に停止してしまいます。

まず Web UI 上で切り替えを完了させてください：

「管理設定」→「基本設定」→ バックグラウンドジョブを **「Cron (推奨)」** に変更します。続いて環境に応じてホスト側で **オプション A** または **オプション B** のいずれかで定期トリガーをデプロイします。

### オプション A：従来の Crontab を使用（設定が簡単で軽量・高速）

1 行のコマンドで完結させたい、余計な設定ファイルを作りたくないホストに適しています。

1. ホスト上で root の crontab を開きます：

   ```bash
   sudo crontab -e
   ```

2. 以下のスケジュールを追加します（5 分ごとに 1 回実行）：

   ```cron
   */5 * * * * docker compose -f /opt/nextcloud/docker-compose.yml exec -T --user 33 nextcloud php -f /var/www/html/cron.php > /dev/null 2>&1
   ```

   - **`-T`**：TTY の割り当てを無効化し、非対話型環境での `the input device is not a TTY` エラー出力を防ぎます。
   - **`--user 33`**：コンテナ内の `www-data` (UID 33) 権限で強制的に実行し、キャッシュディレクトリの権限が root によって汚染されるのを防ぎます。

### オプション B：Systemd Timer を使用（モダンなディストリビューション推奨・本番環境向け標準）

Photon OS、Debian、Ubuntu、Rocky Linux などのモダンなディストリビューションに適しています。起動遅延、タイムアウト保護、`journalctl` によるログの一元管理、さらに `Persistent=true` による停止・再起動後の自動キャッチアップ実行機構を備えています。

#### ステップ 1：タスクを実行する Service ユニットを作成

`/etc/systemd/system/nextcloud-cron.service` を作成します：

```ini
[Unit]
Description=Nextcloud Background Cron Job
Requires=docker.service
After=docker.service

[Service]
Type=oneshot
User=root
WorkingDirectory=/opt/nextcloud
# which docker の結果に合わせてパスを調整してください（通常は /usr/bin/docker）
ExecStart=/usr/bin/docker compose exec -T --user 33 nextcloud php -f /var/www/html/cron.php
TimeoutSec=600

[Install]
WantedBy=multi-user.target
```

#### ステップ 2：定期トリガーを行う Timer ユニットを作成

`/etc/systemd/system/nextcloud-cron.timer` を作成します（ファイル名は `.service` と一致させる必要があります）：

```ini
[Unit]
Description=Run Nextcloud Cron every 5 minutes

[Timer]
# 起動後 5 分遅延させて初回トリガーを実行し、システム起動時のピークを回避
OnBootSec=5min
# その後 5 分ごとに実行
OnUnitActiveSec=5min
# 電源オフで実行タイミングを逃した場合、次回起動後に即座に補完実行する
Persistent=true

[Install]
WantedBy=timers.target
```

#### ステップ 3：読み込み、テスト、および Timer の起動

```bash
# 1. systemd 設定を再読み込み
sudo systemctl daemon-reload

# 2. service を手動で 1 回実行して動作状態をテスト
sudo systemctl start nextcloud-cron.service

# 3. 単発実行のログ出力を確認
journalctl -u nextcloud-cron.service -n 20 --no-pager

# 4. タイマーを有効化し、OS 起動時の自動起動を設定
sudo systemctl enable --now nextcloud-cron.timer

# 5. タイマーの次回トリガーまでのカウントダウンを確認
systemctl list-timers nextcloud-cron.timer
```

## 5. SQLite のメンテナンスとパフォーマンスチューニング

SQLite を採用した軽量構成向けの設定です：

- **WAL (Write-Ahead Logging) を有効化して同時処理性能を向上**：

  SQLite はファイルロック機構を採用しているため、複数デバイスから同時にアップロードするとタイムアウトが発生しやすくなります。`/opt/nextcloud/html/config/config.php` を編集し、配列内に以下を追加します：

  ```php
  'sqlite.journal_mode' => 'WAL',
  ```

- **ワンコマンドでの完全バックアップ**：

  SQLite のデータベース実体は <span style="color:#e06c75"><del>/opt/nextcloud/data/owncloud.db</del></span> *(Updated 2026-11-27: 本記事の設定どおり `SQLITE_DATABASE=nextcloud` とした場合、実体ファイル名は `/opt/nextcloud/data/nextcloud.db` になります。未指定またはデフォルト名のまま運用している場合のみ `owncloud.db` となります)* にあり、バックアップ時はデータディレクトリと設定ファイルを直接アーカイブするだけで完了します：

  ```bash
  sudo tar -czvf /opt/backup/nextcloud_$(date +%F).tar.gz \
    /opt/nextcloud/data \
    /opt/nextcloud/html/config/config.php
  ```

  > [!warning]
  > SQLite の WAL モードを有効化している場合やコンテナが稼働中の場合、稼働中のデータベースファイルに対して直接 `tar` を実行するとスナップショットの不整合が起きる可能性があります。バックアップ前にメンテナンスモードを有効化し（`docker compose exec --user 33 nextcloud php occ maintenance:mode --on`）、アーカイブ完了後に解除（`--off`）することを推奨します。

## 6. 一般的なトラブルシューティング早見表 (Quick Troubleshooting)

| **異常現象** | **根本原因** | **対処方法** |
| :--- | :--- | :--- |
| **ログイン後にログイン画面へ戻される（ループログアウト / CSRF 失敗）** | `OVERWRITEPROTOCOL=https` が不足しており、Session Cookie が非セキュアなプロトコルと判定されている | Compose に `OVERWRITEPROTOCOL=https` を追加して `docker compose up -d` でコンテナを再作成し、ブラウザの Cookie を削除する。 |
| **`.ocdata` 不足エラー** | ホスト側ディレクトリの所有者が UID 33 ではない | `sudo chown -R 33:33 /opt/nextcloud/data` を実行する。 |
| **スマホアプリでカレンダーや連絡先を同期できない** | Traefik の `nc-dav` リダイレクトが機能していない | `https://<domain>/.well-known/caldav` にアクセスし、`/remote.php/dav/` へ自動リダイレクトされるか確認する。 |
| **大容量ファイルのアップロードが中断される** | PHP のアップロード上限に制限されている | 環境変数 `PHP_UPLOAD_LIMIT=16G` を確認するか、`.user.ini` で `upload_max_filesize = 16G` および `post_max_size = 16G` を設定する。 |
