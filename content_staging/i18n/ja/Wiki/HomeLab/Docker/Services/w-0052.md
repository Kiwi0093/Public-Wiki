# vlmcsd ローカル KMS サービス構築と今後の動向分析

## 1. コアメカニズムとエディション制限

- **KMS ライセンス認証の本質**：KMS ライセンスの有効期間は **180 日間** で、クライアントは 7 日ごとに KMS サーバーへ自動更新リクエストを送信します。サーバーがオンラインであれば、更新のたびに 180 日間にリセットされます。
- **サポート対象エディションの制限**：
  - **Windows**：**ボリュームライセンス版（Volume）および Pro、Enterprise、Education、Windows Server のみが対象**です。Home エディションには KMS クライアントコンポーネントが含まれていないため、直接認証することはできません（先に Pro へアップグレードする必要があります）。
  - **Office**：**ボリュームライセンス版（Office LTSC / Volume License）のみが対象**です。通常のリテール版（Retail / Click-to-Run 家庭向け）や Microsoft 365 サブスクリプション版は KMS で直接認証できないため、Office Deployment Tool (ODT) を用いてボリュームライセンス版をインストールする必要があります。
- **GVLK (Generic Volume License Key)**：Microsoft が公式に公開している汎用ボリュームライセンスキーであり、システムに「ローカルネットワーク内の KMS サーバーへ認証を問い合わせる」よう指示する役割のみを持ち、海賊版シリアルキーではありません。

## 2. Docker Compose によるサーバー側デプロイ

`vlmcsd` はリソース消費が極めて少なく（メモリ使用量は通常 5MB 未満）、標準 KMS プロトコルポートの **TCP 1688** を待ち受けるだけで動作します。

### ステップ 1：専用ディレクトリの作成

```bash
mkdir -p /opt/vlmcsd
cd /opt/vlmcsd
```

### ステップ 2：`docker-compose.yml` の設定

```yaml
services:
  vlmcsd:
    image: mikolatero/vlmcsd:latest
    container_name: vlmcsd
    restart: unless-stopped
    ports:
      - "1688:1688"
```

サービスを起動し、ログを確認します。

```bash
docker compose up -d
docker compose logs -f
```

## 3. Windows クライアントのライセンス認証手順

**管理者権限 (Administrator)** でコマンドプロンプト（CMD）<span style="color:#e06c75"><del>または PowerShell</del></span> *(Updated 2026-11-27: 以下の例では CMD 専用の `::` コメント構文を使用しているため、CMD で実行してください。PowerShell を使用する場合は `::` を `#` に変更する必要があります)* を開きます。

```bat
:: 1. (選用) 清除原有綁定的序號
slmgr.vbs /upk

:: 2. 安裝對應版本的微軟官方 GVLK 金鑰
slmgr.vbs /ipk <GVLK-KEY>

:: 3. 指向你的 vlmcsd 伺服器 IP 或內網主機名稱
slmgr.vbs /skms <DOCKER_HOST_IP>:1688

:: 4. 觸發連線啟用
slmgr.vbs /ato

:: 5. 查看詳細授權狀態與過期倒數計時
slmgr.vbs /dlv
```

## 4. Office ボリュームライセンス版 (LTSC) の展開と認証

リテール版の Office は KMS へ直接認証できないため、ボリュームライセンス版をインストールする必要があります。

### ステップ A：Office Deployment Tool (ODT) の取得と設定

1. Microsoft 公式サイトから **Office Deployment Tool (ODT)** をダウンロードします。
2. **[Office Customization Tool](https://config.office.com/deploymentsettings)** オンライン設定ページを開きます。
   - アーキテクチャ選択：`64 ビット`
   - 製品選択：**Office LTSC Professional Plus (Volume License / ボリュームライセンス)**（Office LTSC 2021 または 2024 など）
   - ライセンスおよびライセンス認証：**KMS** を選択
   - 言語：`繁體中文 (台灣)`（必要に応じて日本語 `日本語 (日本)` などを選択）
3. 設定ファイルをエクスポートして `configuration.xml` と命名し、ODT（`setup.exe`）を展開した同じディレクトリに配置します。

### ステップ B：ダウンロードとインストール

該当ディレクトリで管理者権限の CMD を実行します。

```bat
:: 1. 預先下載安裝檔案
setup.exe /download configuration.xml

:: 2. 執行本機靜默安裝
setup.exe /configure configuration.xml
```

### ステップ C：`OSPP.VBS` を用いたライセンス認証

Office のインストール先パスに移動します（インストールしたビット数に応じて選択してください）。

```bat
:: 64 位元 Office：
cd "C:\Program Files\Microsoft Office\Office16"

:: 32 位元 Office (若裝在 64 位元 Windows)：
cd "C:\Program Files (x86)\Microsoft Office\Office16"
```

以下のコマンドを順に実行します。

```bat
:: 1. 設定 KMS 伺服器位址
cscript ospp.vbs /sethst:<DOCKER_HOST_IP>

:: 2. (若未帶入金鑰) 手動指定該產品 GVLK
cscript ospp.vbs /inpkey:<OFFICE-GVLK-KEY>

:: 3. 立即執行連線啟用
cscript ospp.vbs /act

:: 4. 檢視授權狀態與剩餘天數
cscript ospp.vbs /dstatus
```

## 5. 主なエラーコードとトラブルシューティング (Troubleshooting)

|**エラーコード**|**説明**|**対処方法**|
|---|---|---|
|`0xC004F074`|KMS サーバーに接続できない|Docker コンテナの稼働状態を確認し、ポート 1688 がホスト側のファイアウォールでブロックされていないか確認します。|
|`0xC004F038`|KMS カウント不足（Count not sufficient）|Microsoft の仕様では Windows は 25 台、Server は 5 台以上のカウントが必要です。`vlmcsd` は上限値をエミュレートしていますが、このエラーが出る場合はイメージが古いかカウンターが破損しているため、イメージを更新してください。|
|`0xC004F015`|キーが無効、またはエディション非対応|現在インストールされているのが Retail 版または Home 版であり、Volume ライセンス版ではありません。GVLK の置き換え、またはボリュームライセンス版の再インストールが必要です。|

## 6. Microsoft 公式の動向 vs. ローカル KMS (vlmcsd) の今後

企業の IT アーキテクチャがリモートワークとクラウドネイティブへ全面移行する中、Microsoft は近年従来のライセンス認証アーキテクチャに対して抜本的な戦略転換を進めており、ローカル KMS ツールの実用シーンにも直接的な影響を与えています。

### 6.1 Microsoft 公式の脱 KMS 化トレンド (De-KMS)

1. **ID ベースのサブスクリプション認証 (Subscription-based Activation) への全面移行**：
   - 企業向けでは、Microsoft は **Microsoft Entra ID（旧 Azure AD）** と **Microsoft Intune** を強力に推進しています。
   - 最新の Windows 11/10 デバイスでは、ユーザーが M365（E3/E5 または A3/A5）アカウントでサインインするだけで、OS が Pro 版から Enterprise 版へシームレスにホットアップグレードされます。KMS サーバーの構築も GVLK の入力も一切不要です。
2. **ハイブリッドワークによるオンプレミス KMS の維持困難**：
   - 従来の KMS は 180 日ごとに社内ネットワーク上の KMS ホストと通信する必要があります（通信できない場合は猶予期間に入り未認証状態へ戻ります）。ハイブリッドワーク（Work from Anywhere）環境下では VPN 経由での社内 KMS 接続が IT 部門の大きな負担となるため、Microsoft は企業に対してオンプレミス KMS を廃止しクラウド認証へ移行するよう促しています。
3. **Office の SaaS 化 (Microsoft 365 Apps)**：
   - Microsoft は買い切り型の LTSC（Long-Term Servicing Channel）の位置づけとサポート期間を縮小し続けており（例：サポート期間を従来の 10 年から 5 年へ短縮）、クラウド連携の新機能を M365 サブスクリプションユーザー限定にしています。これにより、KMS に依存する Office ボリュームライセンス版の地位は徐々に周辺化しつつあります。

### 6.2 vlmcsd などのツールの今後と限界

|**評価観点**|**現状と今後の見通し**|
|---|---|
|**短期的な展望（一定の需要は存続）**|**エアギャップ（Air-gapped）された閉域網、産業制御ネットワーク、検証用 HomeLab、仮想化クラスター（Proxmox / ESXi）、およびオンプレミスの Windows Server 環境**においては、`vlmcsd` は依然として非常に高い利便性と代替不可能な価値を持ち、インターネット非接続の VM を正常に認証して検証機能を維持できます。|
|**機能制限（機能面のギャップ）**|`vlmcsd` で認証した Office は従来のオフライン機能しか利用できず、**Microsoft サーバー側の認証を要する高度なクラウド機能（Copilot AI 統合、Excel クラウドデータ型、リアルタイム共同編集など）は一切利用できません**。|
|**プロトコル保守・アップグレードのリスク**|Microsoft が新しい Windows / Windows Server をリリースする際、KMS 通信プロトコルのバージョンや RPC 検証機構を変更する可能性があります。オープンソースコミュニティによる `vlmcsd` のメンテナンスが停止したり新しい署名方式への対応が遅れたりした場合、将来の次世代 OS（Windows 12 など）では互換性が失われ機能しなくなるリスクがあります。|
|**デジタルライセンス (HWID) ツールとの競合**|個人ユーザーの領域では、近年コミュニティの多くが Microsoft 公式のアクセシビリティアップグレード経路やデジタル権利移行の仕組み（HWID / MAS など、マザーボードのハードウェアハッシュを直接 Microsoft クラウドサーバーに登録して恒久的なデジタルライセンスを取得する方法）へ流れており、180 日ごとの定期更新が必要な KMS ツールは一般デスクトップ環境では大きく置き換えられています。|
