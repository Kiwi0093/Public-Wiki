SNMP (Simple Network Management Protocol) は、ネットワーク機器（ルーター、スイッチ、ファイアウォールなど）やサーバー（Linux / FreeBSD）の状態監視およびメトリクス収集に広く使われているアプリケーション層プロトコルです。

## 一、 SNMP の基本概念と動作アーキテクチャ

SNMP は **MIB (Management Information Base)** と呼ばれるデータベースを保持することで監視メトリクスを整理しており、各メトリクスには一意の **OID (Object Identifier、オブジェクト識別子)** が割り当てられています。

- **動作メカニズム：**
    - **GET / GETNEXT：** 管理側 (NMS) から監視対象ホスト（Agent）に対して能動的に値を問い合わせます。
    - **TRAP / INFORM：** インターフェースのリンクダウンやハードウェアアラートなどの異常が発生した際、監視対象ホストから管理側へ能動的に通知を送信します。
- **主なバージョンの違い：**
    - **SNMPv1 / SNMPv2c：** 認証に平文の Community String（コミュニティ名：`public` や `private` など）を使用するためセキュリティが低く、盗聴されやすい問題があります。
    - **SNMPv3：** 完全な暗号化とユーザー認証の仕組みを導入しており（<span style="color:#e06c75"><del>MD5/SHA 認証および DES/AES 暗号化</del></span> *(Updated 2026-11-27: MD5 と DES はすでに安全ではないため、現在の実務では SHA-256／SHA-512 認証と AES 暗号化を使用すべきです)* に対応）、本番環境では全面的にこのバージョンを利用することが強く推奨されます。

## 三、 Linux と FreeBSD における SNMP サーバー側の構築 (`Net-SNMP`)

監視リクエストに応答できるようにするには、サーバー側に SNMP Agent (`snmpd`) をインストールして設定する必要があります。

### 1. パッケージのインストール

- **Linux (Ubuntu / Debian / RHEL)：**

    ```bash
    sudo apt install snmpd snmp
    # または RHEL/CentOS の場合
    sudo dnf install net-snmp net-snmp-utils
    ```

- **FreeBSD（pkg 経由）：**

    ```bash
    sudo pkg install net-snmp
    ```

    _(FreeBSD では `/etc/rc.conf` に `snmpd_enable="YES"` を追記し、`sudo service snmpd start` を実行してサービスを起動する必要があります)_

### 2. 設定ファイル例 (`/etc/snmp/snmpd.conf`)

セキュリティを確保するため、平文の Community ではなく最初から **SNMPv3** のアカウントとパスワードを設定することをおすすめします：

```bash
# SNMPv3 専用の読み取り専用アカウント (myuser) を作成し、認証と暗号化を設定
rouser myuser authPriv -V systemview

# authPass と privPass のパスワードを設定（パスワードは 8 文字以上必須）
createUser myuser SHA "MyAuthPassword123" AES "MyPrivPassword123"
```

> [!info] Updated 2026-11-27
> 1. **FreeBSD の設定ファイルパス**は `/usr/local/etc/snmp/snmpd.conf` です（`/etc/snmp/snmpd.conf` ではありません）。
> 2. 平文パスワードを含む `createUser` 行を `/etc/snmp/snmpd.conf` に恒久的に残しておくべきではありません。標準的な手順では、いったん `snmpd` サービスを停止した上で `net-snmp-create-v3-user` コマンドを使用するか、あるいは永続化状態ファイル（Linux では一般的に `/var/lib/snmp/snmpd.conf`、FreeBSD では `/var/net-snmp/snmpd.conf`）に `createUser` を記述します。起動時に `snmpd` がこれをハッシュ化された `usmUser` へ自動変換し、平文パスワードを削除します。
> 3. `rouser ... -V systemview` を指定する場合は、設定ファイル内に `systemview` が定義されていることを確認してください（Debian／Ubuntu のデフォルトでは通常 `systemonly` になっており、そのままでは認可エラーになります）。また、認証と暗号化のアルゴリズムは `SHA-256` と `AES` の使用を推奨します。

設定完了後、サービスを再起動します：

```bash
# Linux
sudo systemctl restart snmpd

# FreeBSD
sudo service snmpd restart
```

## 四、 よく使う手動デバッグ・テストツール

監視システムから正常にデータを取得できない場合は、ターミナル上で直接 `Net-SNMP` 提供のクライアントツールを使って切り分けを行えます：

- **`snmpwalk` を使って OID ツリー全体をスキャン：**

    ```bash
    # SNMPv3 テスト例
    snmpwalk -v3 -l authPriv -u myuser -A MyAuthPassword123 -X MyPrivPassword123 127.0.0.1 .1.3.6.1.2.1.1
    ```

- **`snmpget` を使って特定の単一メトリクス（例：システム稼働時間 sysUpTime）を取得：**

    ```bash
    snmpget -v3 -l authPriv -u myuser -A MyAuthPassword123 -X MyPrivPassword123 127.0.0.1 .1.3.6.1.2.1.1.3.0
    ```

## 五、 現代的な監視システムとの連携ソリューション

従来の SNMP ポーリング（Polling）は大規模インフラではパフォーマンスのボトルネックになりやすいため、現代の運用では以下のツールと組み合わせるのが一般的です：

1. **Prometheus SNMP Exporter：**

    クラウドネイティブ環境向けに、専用の Exporter を介して従来のネットワーク機器の SNMP データを収集し、Prometheus 互換フォーマットへ変換した上で Grafana と組み合わせて見やすいダッシュボードを描画します。

2. **LibreNMS / Zabbix：**

    ネットワーク機器の自動検出やパフォーマンス監視を行うオールインワンシステムです。膨大な機器 MIB データベースを内蔵しており、スイッチのポートごとのトラフィックグラフ描画やアラート通知を自動で行えます。
