**Linux（Manjaro）における PicGo-Core の実践インストール**

Linux（Manjaro / Arch など）環境では、ネットでよく見かける GUI 版の `picgo-appimage` を**インストールしないよう**注意してください。MarkText の画像アップロードプラグインは、その GUI 版のバックグラウンドプロセスを直接認識して連携することができません。必ず Node.js ベースのコマンドラインコアである **PicGo-Core** を使用する必要があります：

- **グローバルインストールコマンド：**

  ```bash
  sudo npm install picgo -g
  ```

  *(注：グローバル環境の権限を完全に確保し、書き込みパスのエラーを防ぐため `sudo` を使用する必要があります。)* *(Updated 2026-11-27: nvm／fnm などのバージョンマネージャを使用している場合や、root 権限によるグローバルディレクトリの汚染を避けたい場合は、ユーザーディレクトリへのインストールまたは npm prefix の設定を利用し、`sudo` を付けない方法を推奨します)*

- **初期化と画像ホスティング設定：**

  対話式の設定ウィザードを実行します。GitHub を画像ホスティング先にする例：

  ```bash
  picgo set uploader
  ```

  案内に従って関連パラメータ（`repo` リポジトリ名、`token` アクセストークン、`path` 保存先パスなど）を順に入力します。

- **指定した画像ホスティングの有効化：**

  設定が完了したら、**必ず次のコマンドを実行**して設定を正式に適用します：

  ```bash
  picgo use uploader
  ```

- **MarkText 側のプラグイン連携：**

  MarkText の設定（Preferences）を開き、画像アップロード設定で `picgo` にチェックを入れます。設定が正しければ、画像を貼り付けたり読み込んだりした際に、裏側でコマンドライン経由の自動アップロードが走ります。

**Obsidian での PicGo 連携活用**

「貼り付け即アップロード」のリアルタイム編集を重視する MarkText と異なり、Obsidian はデフォルトではローカルの Markdown ファイルとフォルダ（Vault）を核としています。Obsidian でも PicGo によるクラウド画像ホスティングへの自動アップロード体験を得たい場合は、通常コミュニティプラグインを通じて実現します：

1. **プラグインのインストール：**

   Obsidian の「コミュニティプラグイン（Community Plugins）」から **Image Auto Upload Plugin** または **PicGo Integration** を検索してインストールします。

2. **PicGo 実行ファイルパスの指定：**

   該当プラグインの設定画面で、PicGo Path に先ほど npm でグローバルインストールした実行ファイルのパス（例：`/usr/bin/picgo`、または `which picgo` で確認したパス）を指定します。

3. **動作の仕組み：**

   Obsidian 内にスクリーンショットや画像を貼り付けると、プラグインが自動的にシステムの `picgo` コマンドを呼び出して画像を GitHub クラウドへプッシュし、Markdown 内のローカル絶対パスをリモート画像ホスティングの CDN リンクへ自動置換してくれます。これにより、複数デバイス間でノートを同期しても画像が見つからずリンク切れになることがなくなります。
