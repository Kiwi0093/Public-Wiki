## 一、 初手：`sudo pip install` は絶対に、何があっても使わない

Linux や macOS において、最も恐ろしい悲劇のひとつが `sudo pip install <パッケージ>` を直接叩くことです。

1. **システムコアの汚染：** OS 自体（Ubuntu の `apt` や RHEL の `dnf` など）の足回りは特定の Python パッケージに強く依存しています。`sudo pip` で強制的に上書き・アップグレードすると、システムのパッケージマネージャーが一発で壊れる可能性が極めて高いです。
2. **PEP 668 の制限：** モダンなディストリビューション（Debian 12、Ubuntu 23.04 以降など）はすでにシステムレベルでグローバルな pip インストールを**禁止**しています。仮想環境を使わずに実行すると、`error: externally-managed-environment` が返されて拒否されます。

**現代の標準的な作法：必ず仮想環境 (Virtual Environment)** または専用ツールを使用すること。

## 二、 基本メンテナンス：標準の `venv` と `pip`

サードパーティ製ツールを一切入れずに使える、Python 3 標準の最もオーソドックスな方法です。パッケージはプロジェクトディレクトリに紐づき、互いに干渉しません。

**1. 仮想環境の作成と有効化**

```bash
# プロジェクトディレクトリ配下に .venv という名前の仮想環境を作成
python3 -m venv .venv

# 仮想環境を有効化 (Linux / macOS)
source .venv/bin/activate
# (有効化すると、ターミナルのプロンプト先頭に (.venv) というラベルが付きます)

# 仮想環境から抜ける
deactivate
```

**2. パッケージのインストールと管理 (仮想環境を有効化した状態で)**

```bash
# パッケージのインストール (ここでは sudo は不要かつ厳禁)
pip install requests

# パッケージのアップグレード
pip install --upgrade requests

# パッケージの削除
pip uninstall requests
```

**3. 環境のコード化：`requirements.txt`**

```bash
# 現在の環境にインストールされているパッケージと正確なバージョン番号を一覧として書き出す
pip freeze > requirements.txt

# 新しいマシン上で、依存パッケージを一括復元インストールする
pip install -r requirements.txt
```

## 三、 グローバル CLI ツールの決定版：`pipx` (Python 界の brew / npx)

プロジェクト開発ではなく、**グローバルなコマンドラインツール**（よく使う `ansible`、<span style="color:#e06c75"><del>`docker-compose`</del></span> *(Updated 2026-11-27: Docker Compose v1 の Python パッケージはメンテナンスが終了し、現在は Docker ネイティブの Go プラグイン `docker compose` に移行したため、pip/pipx 経由ではインストールしません)*、`httpie`、`glances` など）を入れたい場合、`venv` は手間がかかり、`sudo pip` はシステムを壊してしまいます。そんなときは **`pipx`** を使いましょう。

`pipx` は各ツールごとに「専用の隔離された仮想環境」を裏側で自動作成し、実行ファイルだけをグローバルな PATH にリンクしてくれます。

**1. pipx のインストール**

```bash
# Ubuntu / Debian
sudo apt install pipx
pipx ensurepath
```

**2. pipx を使ったツールのインストール**

```bash
# システムの Python 環境を汚さず安全に ansible をグローバルインストール
pipx install ansible

# オンデマンド実行 (npx に相当)、一時的にツールを動かして使い捨てにする
pipx run cowsay "Hello Python!"

# pipx 経由でインストールしたツールを更新
pipx upgrade ansible
# すべて更新
pipx upgrade-all
```

## 四、 容量のクリーンアップとキャッシュ管理

`pip` はパッケージのダウンロードやビルド時に `~/.cache/pip` へファイルをキャッシュするため、放っておくとディスク容量を圧迫する原因になります。

```bash
# キャッシュがどれくらいの容量を使っているか確認
pip cache info

# すべてのキャッシュを削除
pip cache purge

# 特定のパッケージのキャッシュを削除
pip cache remove requests
```

## 五、 Dockerfile 最適化のベストプラクティス (`--no-cache-dir`)

Alpine の `apk --no-cache` と同様に、Docker コンテナをビルドする際は、pip に容量を食うキャッシュファイルを残させてはいけません。

**本番環境向け Dockerfile の例：**

```Dockerfile
COPY requirements.txt .

# --no-cache-dir は必須。これだけでイメージサイズを数十〜数百 MB 削減できます
RUN pip install --no-cache-dir -r requirements.txt

COPY . .
```

## 六、 究極の追加枠：モダンな超高速代替案 `uv` 🌟

Node.js の `fnm` や `pnpm` のような圧倒的なスピードが好みなら、いま Python 界で話題沸騰中の注目株 **`uv`** をぜひ知っておくべきです。

Astral 社が **Rust** で開発した Python パッケージ＆環境マネージャーで、`pip` と `venv` を 1:1 で置き換える設計になっており、**速度は pip の 10〜100 倍**、さらにグローバルキャッシュ（pnpm に似た仕組みでディスク容量を節約）もサポートしています。

**1. uv のインストール**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**2. 日常コマンドをシームレスに置き換える** いつもの `pip` の習慣をそのまま `uv pip` に変えるだけで、異次元の速さを体感できます：

```bash
# 仮想環境を作成 (python -m venv より数十倍高速)
uv venv

# 環境を有効化
source .venv/bin/activate

# 超高速でパッケージをインストール
uv pip install requests

# リストから超高速インストール
uv pip install -r requirements.txt
```

_(CI/CD パイプラインのビルドやコンテナイメージの構築を頻繁に行う DevOps にとって、`uv` への移行は待ち時間を劇的に短縮してくれます。)_
