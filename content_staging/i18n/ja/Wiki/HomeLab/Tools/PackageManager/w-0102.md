## 1. はじめに：なぜ Linux で Homebrew を使うのか？

従来 Homebrew は macOS の定番ツールでしたが、現在は Linux サポート（旧称 Linuxbrew）も非常に成熟しています。

**最大のメリット：`sudo` 権限がないサーバーでの解決策。** 会社や大学の共有サーバー（特に古くからある CentOS 7 や旧版 RHEL）で作業する際、システム標準のパッケージは古びており、かといって `apt` や `yum` で新しいソフトウェアを入れるための root 権限もない、という状況がよくあります。Homebrew はこの問題を完璧に解決してくれます。最新版の CLI ツール（`git`、`python`、`node`、`fzf`、`ripgrep` など）をすべて自分の「ホームディレクトリ」配下にインストールでき、基盤システムを汚したり干渉したりすることが一切ありません。

## 2. 導入：Root 権限なしでの環境インストール

公式の自動インストールスクリプトは、デフォルトでは `sudo` を使って `/home/linuxbrew/.linuxbrew` へのインストールを試みます。root 権限がない場合、スクリプトは自動的にフォールバックし、自分のホームディレクトリ配下（通常は `~/.linuxbrew`）にインストールします。

**1. 公式インストールスクリプトの実行**

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

_(実行中に sudo パスワードの入力を求められた場合は、そのまま Enter キーを押してスキップすれば自動的にホームディレクトリへのインストールに切り替わります)_

**2. 環境変数の設定（極めて重要）** インストール完了直後はまだ Homebrew が有効にならないため、環境変数へ登録する必要があります。インストール完了時の最終画面に表示される案内に従い、以下の内容を `~/.bashrc` または `~/.zshrc` に追記してください：

```bash
# シェル起動時に Homebrew の環境変数を自動で読み込む（bash の場合）
echo 'eval "$(/home/あなたのアカウント/.linuxbrew/bin/brew shellenv)"' >> ~/.bashrc
source ~/.bashrc
```

**3. インストールの確認**

```bash
brew doctor
```

`Your system is ready to brew.` と表示されれば、完全に自分専用の強力なパッケージマネージャーを手に入れたことになります！

## 3. 基本メンテナンス：日常のパッケージ管理

Homebrew のコマンド構文は非常に直感的で、ユーザーディレクトリにインストールされているため、すべてのコマンドで `sudo` を付ける**必要がありません**。

**1. ソフトウェアのインストールとアンインストール**

```bash
# パッケージを検索
brew search <キーワード>

# パッケージをインストール
brew install <パッケージ名>

# パッケージをアンインストール
brew uninstall <パッケージ名>

# 自分で「明示的にインストール」したパッケージのみを一覧表示（依存パッケージを除き、環境棚卸しに非常に便利）
brew leaves
```

**2. システムとソフトウェアの更新**

```bash
# Homebrew 本体とリモートパッケージ一覧を更新
brew update

# インストール済みパッケージをすべて最新版へアップグレード
brew upgrade

# 特定のパッケージのみアップグレード
brew upgrade <パッケージ名>
```

## 4. ディスク容量の解放：キャッシュの削除

Homebrew はビルド時やビルド済みバイナリ（Bottle）のダウンロード時に `~/.cache/Homebrew` へキャッシュを保存するため、使い続けるとそれなりの容量を消費します。

```bash
# 安全なクリーンアップ：古いバージョンのキャッシュのみ削除し、最新版は保持
brew cleanup

# ディープクリーンアップ：最新版のキャッシュも含めてすべて削除（-s = scrub）
brew cleanup -s

# 現在 Homebrew が占有しているディスク容量を確認
brew info
```

## 5. 応用テクニックとトラブル回避ガイド

### 1. 古いシステムにおける C ライブラリの依存関係問題を解決する (gcc / glibc)

非常に古いサーバー環境では、brew で新しいソフトウェアをインストールして実行しようとした際に `lib64/libc.so.6: version 'GLIBC_2.28' not found` のようなエラーに遭遇することがあります。これは OS 標準の C ライブラリが古すぎることが原因です。Homebrew の解決策は非常に力技かつ効果的で、**ホームディレクトリ配下に新しいバージョンの gcc 一式を自前でインストールします！**

```bash
# コンパイルエラーや実行時エラーが出たら、brew でモダンな gcc を明示的にインストールする
brew install gcc
```

インストール後、Homebrew が管理するソフトウェアは自動的にこの新しいライブラリを参照するようになるため、基盤システムの制約を受けなくなります。

### 2. 環境のコード化：Brewfile（IaC の実践）

複数のサーバーや開発マシンを頻繁に行き来する場合、毎回何十個ものツールを `brew install` し直すのは非常に大変です。Homebrew には `requirements.txt` や `package.json` に相当する **Brewfile** という仕組みが標準で備わっています。

- **現在の環境をエクスポート：**

  ```bash
  # 現在インストールされているすべてのパッケージ一覧を Brewfile というファイルに出力
  brew bundle dump
  ```

- **新しいマシンでワンコマンド復元：** この `Brewfile` を新しいマシンにコピーし、同じディレクトリで以下を実行します：

  ```bash
  # Homebrew が Brewfile を自動で読み込み、記載されたパッケージをすべてインストール
  brew bundle
  ```

これは root 権限を持たない開発者にとって、慣れ親しんだ個人開発環境（Dotfiles 哲学）を素早く複製するための切り札となります。
