以下に、Linux のディストリビューション横断サンドボックス 3 大形式における本質的な違いと実践的な操作方法をまとめました：

## 一、 3 大形式の本質と特徴一覧

|**形式**|**主な推進主体**|**基本哲学**|**動作メカニズム**|**メリット**|**デメリット / 課題**|
|---|---|---|---|---|---|
|**Flatpak**|Red Hat / コミュニティ|デスクトップ GUI アプリに特化|共有 Runtime に依存、Bubblewrap サンドボックス隔離|権限管理が極めて優秀、分散型リポジトリ (Flathub)、起動が高速|CLI ツールのサポートが弱く、主にデスクトップアプリ向け|
|**Snap**|Canonical (Ubuntu)|オールラウンド (デスクトップ + サーバー)|squashfs マウントに依存、AppArmor サンドボックス隔離|サーバーバックエンド / Daemon に対応、自動更新機構が強力|コールドスタートがやや遅い、中央集権型 (Canonical 公式ストアのみ)、`lsblk` が loop デバイスで埋まる|
|**AppImage**|オープンソースコミュニティ (probono)|究極の単一ファイル、ポータブルでインストール不要|依存関係を含んだ読み取り専用イメージ、FUSE 経由で直接実行|ダウンロードしてすぐ実行可能、Root 不要、システムを一切汚さない|公式の統一更新機構がない、デスクトップ統合 (ショートカット / アイコン) は手動対応が必要|

## 二、 Flatpak：モダンな Linux デスクトップ GUI アプリの第一選択

Flatpak は現在、Fedora、Arch、Debian などのコミュニティにおけるデスクトップ環境の事実上の標準となっています。パッケージは主に [Flathub](https://flathub.org/) に集約されており、権限管理も非常に厳格です（デフォルトではホームディレクトリすら読み取れません）。

### 1. はじめの一歩：インストールと Flathub リポジトリの有効化

ほとんどのモダンなデスクトップディストリビューションには標準搭載されていますが、未導入の場合は手動でインストールできます：

```bash
# Arch: sudo pacman -S flatpak
# Debian/Ubuntu: sudo apt install flatpak

# 最大のソフトウェアリポジトリである Flathub を追加 (必須)
flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
```

### 2. 基本操作

Flatpak のソフトウェアは、通常 Java に似た「リバースドメイン名」で命名されています（例：`org.mozilla.firefox`、`com.spotify.Client`）。

```bash
# ソフトウェアを検索
flatpak search <ソフトウェア名>

# ソフトウェアをインストール (フルネームまたはキーワードで候補から選択可能)
flatpak install flathub com.spotify.Client

# ソフトウェアを実行 (通常はアプリメニューにアイコンが自動登録されますが、ターミナルから起動する場合)：
flatpak run com.spotify.Client

# すべての Flatpak アプリと Runtime を一括更新
flatpak update -y

# ソフトウェアをアンインストール
flatpak uninstall com.spotify.Client
```

### 3. 必須のクリーンアップと権限調整テクニック

- **未使用 Runtime の削除 (ディスク容量の解放)：**

    Flatpak をアップグレードすると、古い Runtime（GNOME/KDE 実行環境など）が残ってディスクを圧迫することがあります：

    ```bash
    flatpak uninstall --unused
    ```

- **権限変更の神ツール Flatseal：**

    Flatpak はデフォルトでサンドボックス隔離されているため、エディター（VSCode や GIMP など）をインストールした際に「別ドライブのフォルダが読めない」「USB メモリを認識しない」といったことが起こります。そんな時は **Flatseal** をインストールしましょう：

    ```bash
    flatpak install flathub com.github.tchx84.Flatseal
    ```

    このグラフィカルツールを開けば、スマートフォンのアプリ権限設定のように、ネットワーク、ファイルシステム、カメラ、Wayland/X11 ディスプレイへのアクセス可否をアプリごとにワンクリックで切り替えられます。

## 三、 Snap：Ubuntu 直系、デスクトップとサーバーの両刀使い

Snap は Canonical が開発した技術です。デスクトップアプリだけでなく、**システムの Daemon やサーバーソフトウェア（Nextcloud、Docker、Certbot など）を直接パッケージングできる**点が最大の特徴です。

### 1. 基本操作

```bash
# ソフトウェアをインストール
sudo snap install <ソフトウェア名>

# ⚠️ 重要オプション：クラシックモード (--classic)
# システム深部へのアクセスが必要な開発ツール (VSCode、Go、Node.js など) はサンドボックスを無効化してインストールする必要があります：
sudo snap install code --classic

# 検索と詳細確認
snap find <キーワード>
snap info <ソフトウェア名>

# ソフトウェアを更新 (Snap はデフォルトでバックグラウンド自動更新を行いますが、手動で強制実行も可能)
sudo snap refresh

# ソフトウェアをアンインストール
sudo snap remove <ソフトウェア名>
```

### 2. 容量ダイエット術 (古いバージョンの snap を整理)

Snap はアップグレード失敗時のロールバックに備えて各ソフトウェアの「旧バージョン」を保持するため、`/var/lib/snapd/snaps/` が大量のディスク容量を消費してしまいます。

保持するバージョン数（デフォルトは 3）を 2 つだけに変更できます：

```bash
sudo snap set system refresh.retain=2
```

## 四、 AppImage：真の単一実行ファイル「ポータブルアプリ」

AppImage は Windows 時代の「インストール不要のグリーンソフト (.exe)」のような存在です。すべてのプログラムコード、ライブラリ、依存関係を 1 つの `.AppImage` ファイルに丸ごと封入しています。

### 1. 使い方 (極めてシンプル)

1. GitHub Release や公式サイトから `xxx.AppImage` をダウンロードします。
2. 実行権限を付与します：

    ```bash
    chmod +x xxx.AppImage
    ```

3. ダブルクリックで直接実行するか、ターミナルから次のように入力します：

    ```bash
    ./xxx.AppImage
    ```

4. **不要になったら？** そのファイルをそのままゴミ箱に捨てるだけで完全にアンインストール完了です。システムにライブラリなどのゴミは一切残りません。

### 2. ハマりポイント対策：必須の FUSE サポート

近年の多くの Linux（Ubuntu 22.04+ や最小構成システムなど）では旧バージョンの FUSE がデフォルトでインストールされておらず、AppImage 実行時に `dlopen(): error loading libfuse.so.2` というエラーが出ることがあります。

この問題に遭遇した場合は、対応する互換パッケージを追加インストールしてください：

- **Ubuntu / Debian：** <span style="color:#e06c75"><del>sudo apt install libfuse2</del></span> *(Updated 2026-11-27: Ubuntu 24.04+ および Debian 13+ では `t64` 移行に伴い、パッケージ名が `sudo apt install libfuse2t64` に変更されました)*
- **Arch：** `sudo pacman -S fuse2`
- **Fedora：** `sudo dnf install fuse-libs`

### 3. 上級向け便利ツール：AppImageLauncher (デスクトップショートカット問題の解決)

AppImage 最大の欠点は、単なる 1 つのファイルであるため、システムのアプリケーションメニュー（Application Menu）に自動で登録されず、アイコンも付かない点です。

過去によく使われていたコミュニティ製ツールが **[AppImageLauncher](https://github.com/TheAssassin/AppImageLauncher)** です：

- インストールしておくと、新しい `.AppImage` ファイルをダブルクリックするたびに「システムに統合しますか？」というダイアログが表示されます。
- 「Yes」を選ぶと、所定のディレクトリに自動で整理・配置し、アプリケーションメニューに標準的なデスクトップショートカットとアイコンを作成してくれるため、ネイティブソフトに近い体験が得られます。

> [!info] Updated 2026-11-27
> `AppImageLauncher` は上流での頻繁なメンテナンスが長期間停止しており、一部の新しいディストリビューションではインストールや依存関係の問題が発生する場合があります。利用できない場合、モダンなデスクトップ環境では Flatpak 経由でインストールできる **Gear Lever**（`flatpak install flathub it.mijorus.gearlever`）を使って AppImage を管理・統合するのがおすすめです。
