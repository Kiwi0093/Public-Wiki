# XigmaNAS SSH サービスの修復とパスワードレス (Public Key) ログイン設定

> <img src='https://img.shields.io/badge/Status-Active-A8FF24?style=for-the-badge&labelWidth=100' height='38' />

![FreeBSD](https://img.shields.io/badge/FreeBSD-Supported-green?style=plastic&logo=freebsd) 

## 1. SSH サービスが起動しない問題の修復 (Error Code 1)

### 症状

- WebGUI から SSH サービスを起動しようとすると失敗し、`Error Code 1` が表示される。
- ターミナルで手動で Host Key (`ssh-keygen -A`) を生成しても、WebGUI に戻って保存をクリックすると、サービスが即座にクラッシュしてしまう。

### 診断

Console で以下のコマンドを実行して SSH 設定ファイルをテストし、エラー出力を強制表示させます：

```bash
/usr/sbin/sshd -t -f /var/etc/ssh/sshd_config 2>&1
```

`sshd: no hostkeys available -- exiting.` と出力された場合、基盤の `config.xml` に記録されている秘密鍵が破損または消失しており、WebGUI が設定を適用するたびに誤った鍵でシステムを上書きしてしまっていることを意味します。

### 解決策

WebGUI を通じて、システムに新しい Host Keys を強制的に再生成・記録させる必要があります。

1. WebGUI に入り、**Services -> SSH** へ移動します。
2. 下にスクロールして **Private Keys** セクションを見つけます。
3. 中にある 4 つのテキストボックス（**RSA, DSA, ECDSA, Ed25519**）の内容を**すべて空**にします。*(Updated 2026-11-27: OpenSSH 10.0 以降では DSA 鍵のサポートが完全に削除されているため、新しいバージョンの XigmaNAS 画面では RSA、ECDSA、Ed25519 のみが残っている場合があります)*
4. ページ最下部までスクロールし、**Save and Restart** をクリックします。
5. システムが空の値を検知すると、自動的に新しい Host Keys を生成して `config.xml` に書き込み、SSH サービスが正常に起動するようになります。

## 2. パスワードレスログインの設定 (`authorized_keys` の永続化)

### シナリオの説明

XigmaNAS で **Embedded（組み込み）** モードを採用している場合、システムのルートディレクトリ (`/`) はメモリ上 (RAM Disk) に配置されています（`mount | grep ' / '` で `/dev/md0` が表示されることで確認できます）。これは次を意味します：

- デフォルトでは `~/.ssh` ディレクトリが存在しません。
- `ssh-copy-id` で書き込んだ `/root/.ssh/authorized_keys` は再起動すると即座に消えてしまいます。

この問題を解決するには、起動用の物理 USB メモリ (`/cf` パーティション) に公開鍵を保存し、SSH サービスがその物理ファイルを直接読み込むように指示する必要があります。

### ステップ 1：USB 起動ドライブのロック解除と公開鍵の書き込み

デフォルトでは、USB パーティション (`/cf`) は読み取り専用保護状態 (Read-Only) になっています。先に読み書き可能モードへ切り替える必要があります。

1. **読み書き可能 (Read-Write) としてマウント：**

   ```bash
   mount -u -w /cf
   ```

2. **鍵ディレクトリを作成し、権限を設定：**

   ```bash
   mkdir -p /cf/conf/ssh_config
   chmod 700 /cf/conf/ssh_config
   ```

3. **公開鍵を書き込み：** エディタを使って Ansible コントロールノードまたはクライアントの公開鍵（`id_ed25519.pub` または `zeon.key.pub`）をファイルに貼り付けます。

   ```bash
   vi /cf/conf/ssh_config/authorized_keys
   ```

4. **ファイル権限を設定：** （権限が誤っていると SSH が鍵の読み込みを拒否します）

   ```bash
   chmod 600 /cf/conf/ssh_config/authorized_keys
   ```

5. **再び読み取り専用 (Read-Only) にロック：** 頻繁な書き込みによる破損を防ぐため USB メモリを保護します。

   ```bash
   mount -u -r /cf
   ```

### ステップ 2：WebGUI 設定の変更

XigmaNAS の SSH サービスに対し、メモリを迂回して USB メモリから直接設定を読み込むように指示します。

1. WebGUI に入り、**Services -> SSH** へ移動します。
2. **Permit root login** にチェックが入っていることを確認します（root での自動化操作が必要な場合）。
3. 一番下にある **Extra options** テキストボックスまでスクロールします。
4. 以下のパラメータを貼り付けます：

   ```text
   AuthorizedKeysFile /cf/conf/ssh_config/authorized_keys
   ```

5. **Save and Restart** をクリックします。

### 接続テスト

接続元のエンドポイントからテストを実行し、パスワードなしで直接システムに入れることを確認します：

```bash
ssh -i ~/.ssh/ssh.key root@<XigmaNAS_IP>
```
