#### Mirror list の設定

```bash
#Modify Mirrorlist to setting country
echo -n "${COLOR1}Please Select the country you want to set for mirror list\n${NC}${COLOR_H1}C)China\nT)Taiwan\n*)whatever..I don't care\n${NC}"
while :
do
	read COUNTRY
	case $COUNTRY in
		C)
			echo -e "${COLOR2}Set China${NC}"
			sed -i '/Score/{/China/!{n;s/^/#/}}' /etc/pacman.d/mirrorlist
			break

			break
			;;
	esac
done
echo -e "${COLOR2}Completed${NC}"
```

Arch Linux には組み込みの `pacman-mirrors` コマンドがないため、公式の方法に従って `sed` で `/etc/pacman.d/mirrorlist` を編集し、*mirror list* の内容を設定しています

後から追加されている `pacman -Syyu` は、主にミラーリスト更新後の反映を行うために実行しているコマンドです

*Update 2021/06/15: 視認性を高めるため、すべての選択肢にカラータグを追加*

> [!info] Updated 2026-11-27
> 現在の Arch Linux Live ISO では標準で `reflector` を使用して `/etc/pacman.d/mirrorlist` を生成するため、`# Score` 形式のコメントは含まれなくなっており、この `sed` によるフィルタリングルールは機能しません。

#### Fdisk & Mount

```bash
#Fdisk
echo -e "${COLOR1}Partition your HDD please create sda1 for Data and sda2 for Swap.${NC}"
fdisk /dev/sda
echo -e "${COLOR2}Partition Setup Completed${NC}"

#Format
echo -e "${COLOR1}Format /dev/sda1 as EXT4 format${NC}"
mkfs.ext4 /dev/sda1
echo -e "${COLOR2}EXT4 formatting Completed${NC}"
echo -e "${COLOR1}Format /dev/sda2 as Linux Swap${NC}"
mkswap /dev/sda2
echo -e "${COLOR2}Swap Formatting Completed${NC}"
echo -e "${COLOR1}Mount /dev/sda1 to /mnt${NC}"
mount /dev/sda1 /mnt
echo -e "${COLOR2}Completed${NC}"
echo -e "${COLOR1}Mount Swap${NC}"
swapon /dev/sda2
echo -e "${COLOR2}Completed${NC}"
```

ここが、このスクリプトを汎用スクリプトにできない主な理由の一つです。ここの **_format_** 部分で HDD パーティション分割後の構成とマウント先がハードコーディングされているため、柔軟性が失われています

さらに、このスクリプトを使用する環境がすべて **_VMware ESXi_** 上への *Archlinux guest* インストールであったため、他のパーティションツールの代わりにシンプルな `fdisk` を採用しています。そのため、この時点で後続の `grub` のインストール先も、現在主流の *UEFI* ではなく *MBR* に固定される形になっています

スクリプトでは最も一般的ではあるものの効率面で最適とは言えない ext4 をシステムフォーマットとして採用しています。お好みに応じて自由に変更してください

#### インストール

```bash
#Install
echo -e "${COLOR1}Starting Install Archlinux into /mnt${NC}"
echo -e "${COLOR1}Please select your CPU vendor and Linux Kernel you want:\n${NC}${COLOR_H1}1)Intel+Linux\n2)Intel+Linux-LTS\n3)Amd+Linux\n4)Amd+Linux-LTS\n5)Linux-LTS Kernel\n*)Whatever, Normal Linux Kernel is good enough to me\n${NC}"
while :
do
	read CPU
	case $CPU in
	1)
		echo -e "${COLOR2}Linux Kernel＋Intel${NC}"
		pacman -Syyu
		pacstrap /mnt base linux linux-firmware vim zsh curl netctl intel-ucode grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	2)
		echo -e "${COLOR2}Linux-LTS Kernel＋Intel${NC}"
		pacman -Syyu
		pacstrap /mnt base linux-lts linux-firmware vim zsh curl netctl intel-ucode grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	3)
		echo -e "${COLOR2}Linux Kernel＋Amd${NC}"
		pacman -Syyu
		pacstrap /mnt base linux linux-firmware vim zsh curl netctl amd-ucode grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	4)
		echo -e "${COLOR2}Linux-LTS Kernel＋Amd${NC}"
		pacman -Syyu
		pacstrap /mnt base linux-lts linux-firmware vim zsh curl netctl amd-ucode grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	5)
		echo -e "${COLOR2}Linux-LTS Kernel${NC}"
		pacman -Syyu
		pacstrap /mnt base linux-lts linux-firmware vim zsh curl netctl grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	*)
		echo -e "${COLOR2}Linux Kernel${NC}"
		pacman -Syyu
		pacstrap /mnt base linux linux-firmware vim zsh curl netctl grub dnsutils open-vm-tools vim net-tools openssh
		break
		;;
	esac
done
echo -e "${COLOR2}Completed${NC}"
```

このインストール処理は Live CD のシステム上から HDD に対してパッケージをインストールするため、**_pacman_** コマンドではなく **_pacstrap_** コマンドを使って指定した場所へパッケージをインストールする必要があります

`pacstrap /<location> package1 package2 ....`

このコマンドを活用することで、本来は arch-chroot に入ってからインストールするプログラムのうち共通部分をあらかじめここでまとめてインストールしてしまいます。すべてのプログラムをこの段階で入れて問題ないかはまだ検証していませんが、systemd の動作には影響しないはずです

> [!info] Updated 2026-11-27
> 1. 公式 Arch Wiki では Live ISO 環境での `pacman -Syyu` の実行は推奨されていません（メモリの cowspace を圧迫したり、Live 環境のパッケージ不整合を引き起こす恐れがあるため。署名鍵の更新のみが必要な場合は `pacman -Sy archlinux-keyring` を使用します）。
> 2. パッケージ `dnsutils` は Arch Linux において `bind` へ改名されました。また、`net-tools` および `netctl` も旧世代の仕組みであり、現在の環境では `iproute2` と `NetworkManager` または `systemd-networkd` の組み合わせが推奨されます。
> 3. 元のコマンドでは `vim` が 2 回重複して記述されています。

#### 新システム用の fstab 作成

```bash
#fstab
echo -e "${COLOR1}Starting Gernerate fstab${NC}"
genfstab -U -p /mnt >> /mnt/etc/fstab
echo -e "${COLOR2}Completed${NC}"
```

Arch Linux には HDD 分割後に新システムへ fstab を自動生成するインストーラが存在しないため、`genfstab` コマンドで生成した内容を直接 HDD 側の */etc/* 配下に出力します

> [!info] Updated 2026-11-27
> 新バージョンの `arch-install-scripts` に含まれる `genfstab` はデフォルトで仮想ファイルシステムを除外するようになり、`-p` オプションは廃止されました。現在の標準的な使い方は `genfstab -U /mnt >> /mnt/etc/fstab` です。

#### zsh の設定を新システムへコピー

```bash
#Copy Zsh
echo -e "${COLOR1}Starting Copy ZSH setting file to new Archlinux${NC}"
cp -Rv /etc/zsh /mnt/etc/
echo -e "${COLOR2}Completed${NC}"
```

個人的には Arch Linux Live CD にデフォルトで入っている zshrc の設定スタイルがかなり気に入っているため、インストール時に設定ファイルをそのまま自動コピーするようにしています。これにより、このスクリプトで構築したすべての Arch Linux 環境で統一されたシェルスタイルを使えるようになります。

#### 取得するインストールスクリプトを選択して arch-chroot へ入る

```bash
echo -n "${COLOR1}Please select which type you want${NC}${COLOR_H1}\na)Simple Server\nb)Nextcloud Server\nc)V2Ray Server\nd)V2Ray Gateway\n*)I'm the best! let me do by my own!!\n${NC}"
while :
do
	read SCRIPT
	case $SCRIPT in
		a)

			break

		c)

			break
			;;

			echo -e "${COLOR2}V2Ray Gateway${NC}"
			arch-chroot /mnt /bin/zsh <(curl -L -s https://Kiwi0093.github.io/script/arch_v2ray_gate.sh)

```

Arch Linux のインストール手順は以下の流れになっています：

> まず Live CD の OS 上で HDD の準備を行い、ネットワーク経由で新しい Arch Linux システムを HDD にインストールします。続いて新しいシステム環境へ chroot し、新システム側の環境を使って初期設定やブート構成などを行ったうえで完全に抜け出し、再起動して HDD から起動することで、新しいシステムのインストールが完了します。

そのため、arch-chroot へ入った後に用途別のスクリプトを自動実行する選択肢を用意し、あるいはそのまま arch-chroot に入ってユーザーが手動で作業できるようにもしています。

*Update 2021/06/15: 不要になったため Kiwi's Private Router の選択肢を削除*

> [!info] Updated 2026-11-27
> `*)` のデフォルト分岐が `arch-root` と誤記されています（正しいコマンドは `arch-chroot /mnt /bin/zsh`）。また、`Kiwi0093.github.io/script/` 配下の関連サブスクリプトはいずれも退役し無効となっています。
