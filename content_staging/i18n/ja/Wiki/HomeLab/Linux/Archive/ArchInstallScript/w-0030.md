##### MAC アドレス入力による NIC 名の定義

```bash
#Set Mac Address
echo -e "${COLOR1}Define your NIC by Mac address${NC}"

read OUTSIDE
echo 'SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="'${OUTSIDE}'", NAME="EXT0"' > /etc/udev/rules.d/10-network.rules
```

* この設定では固定の **MAC アドレス** を紐づけることで、外部側と内部側のネットワークインターフェースをそれぞれ **`EXT0`** と **`INT0`** にリネームしています。

* IP アドレスは `192.168.0.0/16` のプライベートネットワーク範囲内で設定してください。

##### iptables 設定と systemd

```bash
# iptable script
echo -e "${COLOR1}Create Iptable start script${NC}"
echo "#Natd" > /etc/iptables/iptable.sh
echo "iptables -t nat -A POSTROUTING -s 192.168/16 -j MASQUERADE" >> /etc/iptables/iptable.sh
chmod 750 /etc/iptables/iptable.sh
echo -e "${COLOR2}Finished.${NC}"

# systemd
echo -e "${COLOR1}Create Systemd Service${NC}"
echo "[Unit] > /etc/systemd/system/iptables.service
echo "Description=iptables rules >> /etc/systemd/system/iptables.service
echo " " >> /etc/systemd/system/iptables.service
echo "[Service]" >> /etc/systemd/system/iptables.service
echo "ExecStart=/bin/sh /etc/iptables/iptable.sh" >> /etc/systemd/system/iptables.service
echo " " >> /etc/systemd/system/iptables.service
echo "[Install]" >> /etc/systemd/system/iptables.service
echo "WantedBy=multi-user.target" >> /etc/systemd/system/iptables.service
systemctl enable iptables.service
echo -e "${COLOR2}Finished.${NC}"
```

> [!info] Updated 2026-11-27
> 1. 元のスクリプトでは `echo "[Unit]` と `echo "Description=iptables rules` の 2 行で末尾のダブルクォート `"` が欠落しており、そのまま実行すると構文エラーになります。
> 2. 現代の Arch Linux では、自作の `iptables` シェルスクリプトや `netctl` によるネットワーク管理の代わりに、`nftables`（`nftables.service` との組み合わせ）や `systemd-networkd` / `NetworkManager` を直接使用することが推奨されます。

#### root パスワードの変更と一般アカウントの作成

```bash
#Root Password

#add User

echo "${YOURID} ALL=(ALL) ALL" >> /etc/sudoers
echo -e "${COLOR2}Completed${NC}"
```

> [!info] Updated 2026-11-27
> `useradd -m -g root` は一般ユーザーのプライマリグループを `root` に設定してしまうため、実運用上は推奨されません。通常は `-g root` を省略して `-G wheel` でユーザーを `wheel` グループに追加し、`visudo`（または `/etc/sudoers.d/`）を通じて `%wheel` 権限を有効化します。

`screen`、`v2ray`、`certbot`、<span style="color:#e06c75"><del>`python3-certbot-nginx`</del></span> *(Updated 2026-11-27: これは Debian/Ubuntu のパッケージ名であり、Arch Linux で対応するパッケージは `certbot-nginx` です。また、上記の実際のコマンドには `screen` と `v2ray` しか含まれておらず、Arch Linux では部分更新による破損を防ぐため `-Sy` ではなく `pacman -Syu` を使用すべきです)* をインストールします。`config.json` を直接含めたくなく、他人のワンクリックインストールスクリプトをそのまま流用したくもなかったため、ここでは基本パッケージのインストールのみにとどめ、残りの設定は関連ドキュメントを参照して手動で行う形にしています。

#### Bootloader のインストール

```bash
#install Bootloader
echo -e "${COLOR1}Install grub Boot Loader into /dev/sda${NC}"
grub-install --target=i386-pc /dev/sda
grub-mkconfig -o /boot/grub/grub.cfg
echo -e "${COLOR2}Completed${NC}"
```

> [!info] Updated 2026-11-27
> `grub-install --target=i386-pc /dev/sda` は従来の Legacy BIOS + MBR 構成の `/dev/sda` ディスク専用です。現代の UEFI システムの場合は、`--target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB`（および GPT パーティションテーブルと EFI システムパーティション）へ変更する必要があります。
