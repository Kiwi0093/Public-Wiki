#### ネットワーク設定

```bash
#Hostname
echo -e "${COLOR1}Please input your hostname\n${NC}"
read HOSTNAME
echo ${HOSTNAME} > /etc/hostname
echo "127.0.0.1 localhost ${HOSTNAME}" >> /etc/hosts
echo -e "${COLOR2}Completed${NC}"

echo -e "${COLOR1}Define your NIC by Mac address${NC}"
echo -e "${COLOR1}Please input your MAC Address(need to be lowcase):\n${NC}"
read OUTSIDE
echo 'SUBSYSTEM=="net", ACTION=="add", ATTR{address}=="'${OUTSIDE}'", NAME="EXT0"' > /etc/udev/rules.d/10-network.rules
echo -e "${COLOR2}Completed${NC}"

echo -e "${COLOR1}Define your IP for EXT0:${NC}"
echo "Description='EXT0 IP SETTING'" > /etc/netctl/EXT0.service
echo "Interface=EXT0" >> /etc/netctl/EXT0.service
echo "Connection=ethernet" >> /etc/netctl/EXT0.service
echo "IP=static" >> /etc/netctl/EXT0.service
echo -n "${COLOR1}Please input your IP address:\n${NC}"
read EXT_IP
echo "Address=('${EXT_IP}/24')" >> /etc/netctl/EXT0.service
echo -n "${COLOR1}Please input your Gateway IP address:\n${NC}"
read GATE_IP
echo "Gateway='${GATE_IP}'" >> /etc/netctl/EXT0.service
echo -n "${COLOR1}Please input your DNS IP address:\n${NC}"
read DNS_IP
echo "DNS=('${DNS_IP}')" >> /etc/netctl/EXT0.service
echo -e "${COLOR2}Enable EXT0${NC}"
netctl enable EXT0.service
echo -e "${COLOR2}Finished.${NC}"
```

* この設定は固定の **_MAC Address_** を利用して **_NIC Interface_** の名称を **_EXT0_** として定義するものです。
* この設定には `netctl` を使用しています。

> [!info] Updated 2026-11-27
> `netctl` は現在の Arch Linux では旧式のツールとなっており、現在は `systemd-networkd`（`.link` / `.network` の組み合わせ）または `NetworkManager` が主に使われています。また、`netctl` の設定ファイルに `.service` 拡張子は不要であり（`/etc/netctl/EXT0` として `netctl enable EXT0` を実行すべき）、元の書き方では余分な `netctl@EXT0.service.service` が生成されてしまいます。

#### root パスワードの変更とユーザーアカウント作成

```bash
#Root Password
echo -e "${COLOR1}Set your root password${NC}"
passwd
chsh -s /bin/zsh
echo -e "${COLOR2}Completed${NC}"

#add User
echo -e "${COLOR1}Add user account:${NC}"
echo -n "${COLOR1}What ID you want:${NC}"
read YOURID
useradd -m -g root -s /bin/zsh ${YOURID}
passwd ${YOURID}
echo -e "${COLOR2}Completed${NC}"

echo -e "${COLOR1}Add $YOURID into sudo list${NC}"
pacman -Syu sudo
echo "${YOURID} ALL=(ALL) ALL" >> /etc/sudoers
echo -e "${COLOR2}Completed${NC}"
```

> [!info] Updated 2026-11-27
> このセクションのスクリプトには 3 つの問題があります：
> 1. `chsh -s /bin/zsh` および `useradd -s /bin/zsh` を実行する前に `zsh` パッケージをインストールしていないため、ログインできなくなります。
> 2. `useradd -g root` は一般ユーザーのプライマリグループを `root`（GID 0）に設定してしまい、セキュリティ原則に反します。標準的な方法は `useradd -m -G wheel` を使用し、sudoers で `%wheel` を有効化することです。
> 3. `pacman -Syu sudo` に `--noconfirm` がなく、また `>> /etc/sudoers` でメインファイルへ直接追記するのは構文エラーのリスクがあります。`/etc/sudoers.d/` 配下に独立した設定ファイルを作成し、`visudo -c` で検証する方法を推奨します。

> [!info] Updated 2026-11-27
> このセクションのスクリプトには以下の誤りとパッケージ変更があります：
> 1. `chomd 777 yay` はコマンドのタイプミスです（正しくは `chmod`）。
> 2. `/root` ディレクトリ配下で `sudo -u kiwi makepkg -si` を実行すると `/root` の権限不足で失敗するうえ、ユーザー名も前の `${YOURID}` ではなく `kiwi` がハードコードされています（`/tmp/yay` でのビルドを推奨）。
> 3. 現在の Arch Linux 公式リポジトリからは `php-imap` が削除されており（PHP 8.4 以降は PECL／AUR へ移行）、また Arch の `nextcloud` パッケージはバージョン互換性により `php-legacy`／`php-legacy-fpm` に依存するよう変更されていることが多いです。

##### MariaDB

```bash
#Setup service
#setup MariaDB
echo -e "${COLOR1}Start to Setup MariaDB${NC}"
mariadb-install-db --user=mysql --basedir=/usr --datadir=/var/lib/mysql
mkdir -pv /var/lib/mysqltmp
chown mysql:mysql /var/lib/mysqltmp
echo "tmpfs   /var/lib/mysqltmp   tmpfs   rw,gid=mysql,uid=mysql,size=100M,mode=0750,noatime   0 0" >> /etc/fstab
echo "[client]" >> /etc/my.cnf
echo "default-character-set = utf8mb4" >> /etc/my.cnf
echo "" >> /etc/my.cnf
echo "[mysql]" >> /etc/my.cnf
echo "default-character-set = utf8mb4" >> /etc/my.cnf
echo "" >> /etc/my.cnf
echo "[mysqld]" >> /etc/my.cnf
echo "collation_server = utf8mb4_unicode_ci" >> /etc/my.cnf
echo "character_set_server = utf8mb4" >> /etc/my.cnf
echo "tmpdir      = /var/lib/mysqltmp" >> /etc/my.cnf
mount /var/lib/mysqltmp
systemctl enable mariadb.service
sudo -u mysql /usr/bin/mariadbd &

mysql_secure_installation
echo -n "${COLOR1}Please input your Username for Nextcloud Database:\n${NC}"
read NCUSER
echo -n "${COLOR1}Please input your Password for Nextcloud Database User:\n${NC}"
read NCPASSWD
mysql -u root -p -e"CREATE DATABASE nextcloud DEFAULT CHARACTER SET 'utf8mb4' COLLATE 'utf8mb4_general_ci';GRANT ALL PRIVILEGES ON nextcloud.* TO '${NCUSER}'@'localhost' IDENTIFIED BY '${NCPASSWD}';FLUSH PRIVILEGES;"
echo -e "${COLOR2}MariaDB setup compleated${NC}"
```

> [!info] Updated 2026-11-27
> 新しいバージョンの MariaDB では `mysql_secure_installation` と `mysql` が非推奨のエイリアスとなっており、`mariadb-secure-installation` と `mariadb` の使用が推奨されます。設定についても `/etc/my.cnf` への直接上書きや追記ではなく、`/etc/my.cnf.d/` 配下のファイルへ記述するのが推奨されます。また、`arch-chroot` 内で `mariadbd &` を直接バックグラウンド起動しているのは当時の暫定対応であり、システムを再起動して systemd が立ち上がった後にサービスの初期化を行う方が適切です。

##### Nextcloud

```bash
#Setup nextcloud
echo -e "${COLOR1}Set up Nextcloud${NC}"
echo "nexcloud ALL=(ALL) ALL" >> /etc/sudoers
sudo -u nextcloud occ maintenance:install --database mysql --database-name nextcloud --database-host localhost --database-user ${NCUSER} --database-pass=<${NCPASSWD}> --data-dir /var/lib/nextcloud/data/
curl -o /usr/share/webapps/nextcloud/config/config.php https://kiwi0093.github.io/script/Arch/config.php
echo -e "${COLOR2}nexcloud set up compleated${NC}"
```

> [!info] Updated 2026-11-27
> このセクションのスクリプトには合計 4 つの問題があります：
> 1. `nexcloud ALL=(ALL) ALL` はスペルから `t` が 1 文字抜けており、そもそも Web サービス用アカウントに完全な `sudo` root 権限を与えるべきではありません（`root` 権限で `sudo -u nextcloud` を実行するのにこの設定は不要です）。
> 2. `--database-pass=<${NCPASSWD}>` に余計な `< >` の山括弧が入っており、Bash でクォートしない場合は入出力リダイレクトとして解釈され即座に構文エラーになります。
> 3. Arch Linux パッケージ版 Nextcloud が提供するコマンドラッパーは `/usr/bin/occ`（または `php /usr/share/webapps/nextcloud/occ` を使用）であり、書き込み可能な設定ファイルのパスも `/etc/webapps/nextcloud/config/config.php` です。
> 4. すでに無効な `https://kiwi0093.github.io/script/Arch/config.php` から設定ファイルをダウンロードして上書きすると、`occ maintenance:install` が自動生成した `instanceid`、`passwordsalt`、`secret` が消えてしまいます。

> [!info] Updated 2026-11-27
> このセクションの Nginx 設定にもいくつか古い記述や誤りがあります：
> 1. `listen 443 ssl http2;` は Nginx 1.25.1 以降で非推奨となっており、新しいバージョンでは `listen 443 ssl;` と独立した `http2 on;` ディレクティブに書き換える必要があります。
> 2. Arch Linux 公式の `nextcloud` パッケージは `/var/www/nextcloud` ではなく `/usr/share/webapps/nextcloud` にインストールされます。
> 3. `location /` の行で出力先が `/etc/nginx/sitqes-enabled/nextcloud` と誤記されており（パスのタイプミス）、実際に実行すると失敗して `nextcloud` 設定ファイルの末尾が欠落します。
> 4. Certbot で証明書を取得する前にまだ存在しない `/etc/ssl/nginx/${NCDOMAIN}.crt` を指定しているため、Nginx の設定テストが通りません。
> 5. `X-XSS-Protection` ヘッダーは最新のブラウザでは非推奨となっており、新しい Nextcloud の公式サンプルからは削除されています。
