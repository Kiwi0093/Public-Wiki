# systemd-boot 完全攻略と Pacman Hook による自動化

> <img src='https://img.shields.io/badge/Status-Active-A8FF24?style=for-the-badge&labelWidth=100' height='38' />

![Archlinux](https://img.shields.io/badge/Arch_Linux-Supported-green?style=plastic&logo=archlinux)

## 一、 systemd-boot を知る：GRUB より軽量なモダン UEFI ブートローダー

現代の UEFI アーキテクチャにおいて、ますます多くの Arch ネイティブユーザーや `archinstall` スクリプトが **systemd-boot**（旧称 Gummiboot）を採用するようになっています。設定ファイルが巨大で `grub-mkconfig` による再生成に依存する GRUB と比べ、systemd-boot には以下のような利点があります：

- **ネイティブ統合**：systemd に内蔵されており、巨大なブートローダーソフトウェアパッケージを別途インストールする必要がありません。
- **設定のモジュール化**：各カーネルの起動エントリが独立した `.conf` ファイルとなっており、互いに干渉しません。
- **超高速起動**：UEFI ファームウェアのインターフェースを直接呼び出して EFI 実行ファイルを読み込むため、起動時の遅延が極めて低いです。

## 二、 systemd-boot のコア構造と日常管理

systemd-boot のすべての設定ファイルおよびカーネルイメージは EFI システムパーティション（通常 `/boot` または `/efi` にマウントされます。以下は `/boot` を例とします）に格納されています。

### 1. コアファイル・ディレクトリツリー

```text
/boot/
├── EFI/
│   ├── systemd/systemd-bootx64.efi
│   └── BOOT/BOOTX64.EFI
└── loader/
    ├── loader.conf                 # 全域引導設定檔
    └── entries/                    # 開機選單項目存放處
        ├── arch.conf               # 預設 Linux 核心
        └── arch-linux-zen.conf     # Zen 效能核心
```

### 2. カーネル起動エントリファイル例 (`loader/entries/arch-linux-zen.conf`)

```toml
title   Arch Linux (Linux-Zen)
linux   /vmlinuz-linux-zen
initrd  /intel-ucode.img            # 若為 AMD 請改用 amd-ucode.img
initrd  /initramfs-linux-zen.img
options root=UUID=xxxx-xxxx-xxxx rw quiet
```

> [!info] 2026-11-27 更新
> Boot Loader Specification の `.conf` 設定ファイルでは**行頭**が `#` の行のみがコメントとして扱われ、行末（インライン）の `#` コメントはサポートされていません。実際に `/boot/loader/entries/*.conf` へ書き込む際は、`# 若為 AMD...` のような説明を独立した行へ移すか削除し、パス解析エラーによる起動不能を防いでください。

### 3. ブートメンテナンスのコアコマンド：bootctl

日常のメンテナンスで設定ファイルを手動で探し回る必要はまったくなく、`bootctl` を使えば一般的な操作をすべて完結できます：

```bash
# 查看當前引導狀態、預設核心與所有偵測到的啟動項目
bootctl status

# 列出所有可用的開機項目清單
bootctl list

# 一鍵變更預設開機項目（名稱對應 entries 裡的檔名，不需副檔名）
sudo bootctl set-default arch-linux-zen

# 設定開機選單等待時間（例如 3 秒）
sudo bootctl set-timeout 3
```

> [!info] 2026-11-27 更新
> `bootctl set-default` の `ID` 引数には、`bootctl list` で表示される完全なエントリ識別名（`.conf` 拡張子を**含む**）を指定する必要があります（例：`sudo bootctl set-default arch-linux-zen.conf`、またはワイルドカードを用いて `arch-linux-zen*`）。

## 三、 よくある落とし穴：なぜカーネル更新後に起動不能になりやすいのか？

systemd-boot を使用する際、よくあるトラブルのシナリオは次の 2 つです：

1. **systemd パッケージ更新後にブートバイナリが未同期**：システム側で `systemd` をアップグレードしたにもかかわらず、`/boot/EFI/systemd/systemd-bootx64.efi` が古いバージョンのまま残っている。
2. **マルチカーネル切り替え時の initramfs 欠落**：新しいカーネルをインストールまたは削除（例：`linux` と `linux-zen` の切り替え）した際、適時に `mkinitcpio -P` を実行してイメージを再生成しないと、再起動時に UEFI ブートエラーでそのまま停止してしまいます。

## 四、 究極の自動化：Pacman Hook を導入して一挙解決

Arch Linux の哲学において最もエレガントな解決策は、**Pacman Hook** を活用してパッケージのインストールや更新後にバックグラウンドでメンテナンススクリプトを自動トリガーさせ、人為的な実行漏れを根絶することです。

### 1. Hook 1：systemd 更新時にブートローダーを自動アップグレード

`/etc/pacman.d/hooks/95-systemd-boot.hook` を作成します：

```toml
[Trigger]
Type = Package
Operation = Upgrade
Target = systemd

[Action]
Description = Updating systemd-boot in EFI system partition...
When = PostTransaction
Exec = /usr/bin/bootctl update
```

_役割：`systemd` パッケージがアップグレードされるたびにシステムが自動で `bootctl update` を実行し、EFI パーティション内のブートバイナリが常にシステム側と同期された状態を保ち、バージョンの乖離を防ぎます。_

### 2. Hook 2：カーネル更新後の自動保護とステータスチェック

Arch のデフォルトである `90-mkinitcpio-install.hook` が自動でイメージをビルドしてくれますが、カスタムカーネルや DKMS モジュールをよく切り替える場合は、独自のチェック用 Hook `/etc/pacman.d/hooks/99-boot-integrity.hook` を作成しておくと安心です：

```toml
[Trigger]
Type = Package
Operation = Install
Operation = Upgrade
Operation = Remove
Target = linux
Target = linux-zen
Target = linux-lts

[Action]
Description = Verifying bootloader entries integrity...
When = PostTransaction
Exec = /usr/bin/bootctl --dry-run list
```

_役割：いずれかのカーネルのインストール、アップグレード、または削除の後に、ターミナルのバックグラウンドでブートメニュー設定ファイルの整合性を予行確認・検証し、パスが破損している場合は pacman の更新フロー内で直接警告を出力して、シャットダウン前にその場で修復できるようにします。_

> [!info] 2026-11-27 更新
> `bootctl` の `--dry-run`（`-n`）オプションは `unlink` および `cleanup` サブコマンドにのみ適用され、`list` に対しては実質的な効果がありません。そのため直接 `Exec = /usr/bin/bootctl --no-pager list` に書き換えることを推奨します（`list` 自体は読み取り専用コマンドです）。なお、`bootctl list` はエントリファイルの構文と対応するカーネル／initrd ファイルのパスの存在のみを確認し、initramfs イメージ自体の整合性までは検証しません。
