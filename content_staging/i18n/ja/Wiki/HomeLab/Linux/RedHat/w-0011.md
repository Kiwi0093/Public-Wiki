## Installation

ISO イメージをダウンロードしたら、VMware Workstation または VMware ESXi 上で新しい仮想マシンを作成し（ゲスト OS 種別は VMware Photon OS 64-bit または最新の Linux Kernel 64-bit のどちらでも可）、ISO から起動してウィザードに従ってインストールを完了させます。

Photon OS 自体が必要とするメモリやディスク容量はごくわずかですが、リソースの大半は後から動かす Docker コンテナ側で消費されるため、VM 作成時には稼働予定のサービス数に応じて RAM とディスク容量を適切に設計してください。

## Basic Setup

**基本サービスの確認**

`open-vm-tools` などの基本システムサービスが正常に動作しているか確認します。

```bash
systemctl status vmtoolsd.service
```

**アカウント設定**

インストール途中で `root` パスワードを設定しますが、日常運用の安全性を高めるため `useradd` で一般ユーザーを作成しておくこともできます。

```bash
# ユーザーを追加（-m でホームディレクトリ作成、-g で root グループを指定）
useradd -m -g root $(your_id)

# アカウントのパスワードを設定
passwd $(your_id)
```

> [!info] Updated 2026-11-27
> 上記例の `$(your_id)` は Bash ではコマンド置換（Command Substitution）として解釈されてしまうため、実際に実行する際は対象のユーザー名に直接置き換えてください（例：`useradd -m -G wheel <your_id>`）。また、実運用では一般ユーザーのプライマリグループを直接 `root` にするのではなく、`-G wheel` や `sudo` を使って権限昇格を付与することを推奨します。

システム管理では `root` 権限が必要になる場面が多いため、好みに応じて一般アカウントを作成して `su` / `sudo` を併用するか、`/etc/ssh/sshd_config` を変更して `root` の SSH ログインを許可するかを選択してください。

## ネットワーク設定 (systemd-networkd)

インストール直後のデフォルト設定は DHCP です。IP が1つだけでよく、かつ LAN 内の DHCP サーバー側で MAC アドレスによる固定割り当て（予約）を行っている場合はデフォルトのままで問題ありません。OS 側で固定 IP を設定するなどの高度な要件がある場合は、以下の設定ファイルを編集します。

**DHCP の無効化**

`/etc/systemd/network/99-dhcp-en.network` を編集します。

```ini
[Match]
Name=e*

[Network]
DHCP=no    # no に変更して DHCP を無効化
IPv6AcceptRA=no
```

**固定 IP の設定方法**

`/etc/systemd/network/10-static-en.network` を編集します。

```ini
[Match]
Name=ens160                                # NIC 名

[Network]
Address=10.1.10.9/24                       # IP アドレス（複数行書いて複数 IP 定義可能）
Gateway=10.1.10.1                          # Gateway IP
DNS=10.1.10.1                              # DNS IP
# NTP 設定（スペース区切りで複数サーバー指定）
NTP=tock.stdtime.gov.tw watch.stdtime.gov.tw time.stdtime.gov.tw
# IPv6 を無効化
LinkLocalAddressing=no
IPv6AcceptRA=no
```

**ネットワークインターフェース名の設定**

`/etc/systemd/network/10-ethusb0.link` を編集します。

```ini
[Match]
MACAddress=00:00:00:00:00:00               # NIC の MAC アドレス

[Link]
Description=USB to Ethernet Adapter        # NIC の説明
Name=ethusb0                               # インターフェース名
```

複数の NIC がある場合は、それぞれの MAC アドレスとインターフェース名に対応する `.link` および `.network` ファイルを個別に作成してください。

## システム更新とパッケージインストール

> **補足メモ：** Photon OS の標準パッケージマネージャーは実際には `tdnf` です。`yum` にもエイリアスが張られており同様に動作しますが、普段から `tdnf` を直接使う習慣をつけておくと確実です。

```bash
tdnf update -y          # システムパッケージを更新
tdnf install -y vim     # vim をインストール
tdnf search python      # 名称に python を含むパッケージを検索
```

## SMB 共有フォルダのマウント

運用上、Docker の Volume 用ディレクトリを NAS 上のバックアップ／共有ディレクトリにマウントしておくことがよくあります。これには以下のようなメリットがあります。

1. データを一箇所にまとめてバックアップしやすい。
2. Photon OS 仮想マシン自体のディスク使用量を抑えられる。
3. NAS 上のファイルを参照する Docker サービスが直接アクセスできる（例：個人の音楽ファイルをすべて NAS に置いている場合、SMB/CIFS マウントが非常に便利）。

まず Photon OS に `tdnf` で `cifs-utils` をインストールします。

```bash
tdnf install -y cifs-utils
```

次に認証情報ファイル `/root/secret` を作成します。

```ini
username=sushi    # SMB ユーザー名
password=yummy    # SMB パスワード
```

> セキュリティ確保のため、`/root/secret` のパーミッションは `0400` に変更しておくことを推奨します（`chmod 0400 /root/secret`）。

続いて `/etc/fstab` にマウント設定を追記します。

```text
\\winbox\getme /mnt/win cifs user,uid=500,rw,noauto,suid,credentials=/root/secret 0 0
```

> [!info] Updated 2026-11-27
> Linux の `/etc/fstab` に CIFS 共有パスを記述する際はスラッシュ `//winbox/getme` を使用してください（バックスラッシュ `\\` は fstab 内でエスケープ文字として解釈され、解析エラーの原因になります）。また、近年の NAS では環境に応じて `vers=3.0` などの SMB バージョン指定が必要です。さらに、下記の独立した systemd service を使う方法以外にも、現在では `/etc/fstab` のマウントオプションに `_netdev,x-systemd.automount` を追加するだけでネットワーク準備完了後に自動マウントさせることも可能です。

**systemd を使った起動時自動マウント**

以前 `autofs` を試した際は Photon OS 上でうまく動作せず、`/etc/fstab` で直接 `auto` マウントを試したときも起動時にネットワーク接続完了前へ処理が走って失敗することがよくありました。そのため、最も安定する方法として systemd service を作成し、ネットワーク確立後にマウントを実行させる構成をとっています。

`/etc/systemd/system/mount-nas.service` を編集します。

```ini
[Unit]
Description=mount CIFS
# ネットワークが完全にオンラインになってから実行
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/bin/mount -a
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
```

ポイントは `After=network-online.target` を設定し、ネットワーク疎通が確立してからマウントを行うことです。作成後、設定をリロードしてサービスを有効化します。

```bash
systemctl daemon-reload
systemctl enable --now mount-nas.service
```

## 応用テクニック：ディスク容量の拡張

実際にしばらく運用していると、どれだけ節約していても仮想マシンに割り当てたディスク容量が足りなくなることがよくあります（私自身すでに 2、3 回経験しています）。以前 Windows VM を使っていた頃は新しい仮想ディスクを追加して別ドライブレターとして割り当てていましたが、Photon OS 環境では既存の `/dev/sda` をそのまま拡張したいケースがほとんどです。

**1. ESXi 上で仮想ディスク容量を増やす**

ESXi の管理画面から該当 VM の設定を編集し、ハードディスク容量を直接増やします。

**2. OS 側で再スキャンし、パーティションを拡張する**

`parted` がまだインストールされていない場合は先にインストールします。

```bash
tdnf -y install parted
```

続いてブロックデバイスの再スキャンを行い、`parted` を起動します。

```bash
# ブロックデバイスを再スキャンし、ESXi で増やした容量を OS に認識させる
echo 1 > /sys/class/block/sda/device/rescan

# parted の対話画面を開く
parted /dev/sda
```

`parted` のプロンプトで順番にコマンドを実行します。

```text
# パーティション一覧を表示。ディスク全体が未割り当てになっている旨の警告と修復確認が出たら f（または fix）を入力
(parted) print

# 拡張対象となるメインのパーティション番号（通常は 1 または 3）を確認し、resizepart で残りの全容量 (100%) を割り当てる
(parted) resizepart 1 100%

# 完了したら parted を終了
(parted) quit
```

**3. ファイルシステムの拡張（File System）**

> **補足メモ：** `resize2fs` の引数にはディスク全体（`/dev/sda`）ではなく、「パーティション」のデバイス名（例：`/dev/sda1`）を指定します。

`resize2fs` を使って、先ほど拡張したパーティションのファイルシステムを拡張します（第 1 パーティションを拡張した場合の例）。

```bash
resize2fs /dev/sda1
```

完了後、`df -H` を実行して容量が正しく増えているか確認してください。
