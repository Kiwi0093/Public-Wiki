# Nix / NixOS 実用コマンドとメンテナンスTipsノート

> <img src='https://img.shields.io/badge/Status-Active-A8FF24?style=for-the-badge&labelWidth=100' height='38' />

![NixOS](https://img.shields.io/badge/NixOS-Supported-green?style=plastic&logo=nixos)

## 1. 基本の考え方：イミュータブルな `/nix/store` と世代（Generations）

Nix の世界には、従来の `/usr/bin` や `/lib` が存在しません。ソフトウェアのインストール、依存関係、設定ファイルはすべて、内容から計算されたハッシュ値を付与されたうえで `/nix/store/` に一括格納されます（例：`/nix/store/1a2b3c...-python-3.10`）。

これにより、2 つの大きなメリットが生まれます：

1. **依存関係地獄（Dependency Hell）からの解放：** ソフトウェア A が Python 3.9 を必要とし、ソフトウェア B が Python 3.10 を必要としていても、両者をシステム内に完璧に共存させ、互いに干渉させずに動かせます。
2. **痛みゼロのロールバック：** システムを変更するたびに新しい「世代（Generation）」が作成されます。アップデートで壊れても、いつでも一瞬で前の世代へ切り戻せます。

_(注：以下のコマンドは「Standalone Nix パッケージマネージャ」と「NixOS オペレーティングシステム」の 2 つのシナリオに分けて説明します。)_

## 2. 基本メンテナンス：インストールとシステム更新

現在の Nix は旧来の `nix-env` コマンドから新しい `nix` コマンドへの移行期にあるため、ここでは最も安定していてよく使われる構文を中心に紹介します。

**1. NixOS のシステム全体更新と適用** NixOS を使っている場合、コマンドで手動でパッケージを入れることはほぼなく、宣言ファイル `/etc/nixos/configuration.nix` を編集して、システムにその状態を「実現」させます：

```bash
# 編輯你的系統設定檔，把需要的套件寫進去
sudo vim /etc/nixos/configuration.nix

# 讓系統根據設定檔，編譯/下載並切換到新狀態
sudo nixos-rebuild switch

# 如果只想要套用狀態測試一下，重開機就恢復原狀 (非常適合測試高風險設定)：
sudo nixos-rebuild test
```

**2. Standalone Nix の日常パッケージ管理** Ubuntu や macOS 上で単に Nix をパッケージマネージャとして使う場合：

```bash
# 搜尋套件 (建議直接用網頁版 search.nixos.org 比較快)
nix-env -qaP <關鍵字>

# 安裝套件 (強烈建議加上 -A 參數從屬性路徑安裝，速度快且精準)
nix-env -iA nixpkgs.<套件名稱>

# 升級所有已安裝的使用者套件
nix-env -u
```

## 3. 環境のクリーンアップとガベージコレクション（Garbage Collection）

これは Nix において**最も重要**なメンテナンス作業です！Nix は不変性（イミュータブル）を基本とするため、デフォルトでは**古いソフトウェアを一切削除しません**（いつでもロールバックできるようにするためです）。放置していると、`/nix/store` があっという間にディスク容量を食い尽くします。

**1. 手動でのガベージコレクション（GC）実行**

```bash
# 找出並刪除目前系統中「沒有被任何世代參照」的孤兒檔案
nix-collect-garbage

# ⚠️ 終極清理 (Deep Clean)：刪除所有舊世代，只保留「當下正在用」的版本
# 注意：下達這行之後，你就無法回滾到以前的狀態了！
nix-collect-garbage -d

# 需要 root 權限清理全系統等級的廢棄物 (NixOS 必做)
sudo nix-collect-garbage -d
```

**2. 自動ガベージコレクションの設定（NixOS 限定）** `configuration.nix` に以下を追記しておくと、システムが毎週自動でゴミ掃除を行い、7 日以上前の古い世代を自動削除してくれます：

```nix
nix.gc = {
  automatic = true;
  dates = "weekly";
  options = "--delete-older-than 7d";
};
```

## 4. 救命ツール：タイムマシンと世代ロールバック（Rollbacks）

これこそ Nix の超強力なキラー機能です。システムを更新したり新しいソフトウェアを入れたりした結果、サービスが起動しなくなったりシステムがクラッシュしたりしても、復旧方法は驚くほどシンプルかつ確実です。

**1. NixOS のシステム全体ロールバック**

```bash
# 列出系統所有的世代與時間戳記
sudo nix-env --list-generations --profile /nix/var/nix/profiles/system

# 發現剛套用的設定爛了，無腦退回上一個世代
sudo nixos-rebuild switch --rollback
```

_(たとえシステムが起動できなくなったとしても、NixOS のブートメニュー（GRUB/systemd-boot）にはデフォルトで過去のすべての世代が表示されるため、一つ前の世代を選んで起動するだけで即座に完全復活します！)_

**2. ユーザーパッケージのロールバック（Standalone Nix）**

```bash
# 列出目前帳號的套件變更歷史
nix-env --list-generations

# 退回上一次操作前的狀態
nix-env --rollback
```

## 5. 高度な切り札：Nix Shell（一度使ったら戻れない機能）

開発や異なる環境の検証、あるいは IaC 自動化フローの管理を頻繁に行う人にとって、`nix-shell` はまさに神ツールです。「使い捨てできるクリーンな環境」を即座に作ってくれます。

**シナリオ：今すぐちょっと Python スクリプトを走らせて Ansible も使いたいけれど、システムにインストールして環境を汚したくはない！**

```bash
# 臨時開啟一個包含 python3 與 ansible 的虛擬終端機環境
nix-shell -p python3 ansible
```

このシェルに入れば、通常どおり `python3` と `ansible` を使えます。そして `exit` と入力してこのターミナルを抜けた瞬間、これら 2 つのソフトウェアは最初から存在しなかったかのようにグローバル環境から姿を消します（ただしダウンロードされたファイル自体は `/nix/store` 内に一時保存され、次回のガベージコレクション時に掃除されます）。

これにより、開発マシンのあちこちに雑多な一時依存パッケージが散らかる問題を見事に解決できます！
