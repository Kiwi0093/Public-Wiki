## 一、 はじめに：apk と Alpine のミニマリズム哲学

Alpine Linux が Docker ベースイメージ（Base Image）の覇者になれた理由は、巨大な GNU ツールチェーン（`glibc` など）を捨て、極めて軽量な `musl libc` と `BusyBox` を採用しているからです。素の Alpine イメージはわずか 5MB 未満しかありません！

それと組み合わせて使われる `apk` も操作ロジックが非常に直感的で、実行速度も爆速です。設定ファイルは主に `/etc/apk/repositories` にあります。

## 二、 基本メンテナンス：日常的なシステムのインストールと更新

Alpine を独立した VM や LXC コンテナとして日常運用する場合の基本コマンドは以下の通りです：

**1. システム更新** `apt` と同様に、先にローカルのインデックスを更新してからアップグレードを実行します：

```bash
# パッケージインデックスを更新
apk update

# インストール済みパッケージをすべてアップグレード
apk upgrade

# 1行でまとめて実行することも可能
apk update && apk upgrade
```

**2. 検索と照会**

```bash
# パッケージを検索
apk search <キーワード>

# インストール済みパッケージの詳細情報を確認
apk info <パッケージ名>

# インストール済みの全パッケージを一覧表示
apk info
```

## 三、 Dockerfile 必須テク：イメージの徹底的な軽量化

Dockerfile を書くときは、先ほどの `apk update` のやり方は**忘れてください**。コンテナビルドのベストプラクティスでは、イメージサイズを最小限に抑えるためのもっと賢いオプションが用意されています。

**1. 神オプション：`--no-cache` (update とキャッシュ削除を同時に代替)** Debian/Ubuntu で Dockerfile を書くとき、キャッシュの残留を防ぐためにこんな長くて見苦しいコマンドを書かされがちです： `apt-get update && apt-get install -y xxx && rm -rf /var/lib/apt/lists/*`

Alpine なら `--no-cache` を付けるだけで、サーバーから最新のインデックスを自動取得してソフトをインストールし、**ローカルディスクにキャッシュやインデックスファイルを一切残さずに** 1 行で完結します：

```dockerfile
# 完璧でクリーン、痕跡を残さないインストール方法
RUN apk add --no-cache curl nginx
```

**2. 仮想グループオプション：`--virtual` (使い捨ての割り箸方式)** これは `apk` 最強のキラー機能です。あるソフトウェア（Python パッケージや C プログラムなど）を「ビルド」する必要があるとき、大量のビルドツール（`gcc`、`make`、`dev` 系パッケージ）のインストールが必要になります。ビルドが終わればそれらは不要になりますが、ひとつずつ `del` するのは非常に面倒です。

`--virtual <任意のグループ名>` を使うと、こうした依存パッケージを一時的に仮想タグで束ねておくことができます：

```dockerfile
# 1. ビルドツールを 'build-deps' という仮想グループにまとめてインストール
RUN apk add --no-cache --virtual .build-deps gcc musl-dev python3-dev make

# 2. ビルドやインストール処理を実行 (例: pip install)
RUN pip install some-complex-package

# 3. 用が済んだらお払い箱：1コマンドで先ほどの 'build-deps' 内のツールをすべて綺麗に削除！
RUN apk del .build-deps
```

> **実践ポイント：** 上記の 3 ステップを `&&` で繋いで Dockerfile の同じ `RUN` 命令内にまとめれば、イメージレイヤー（Layer）に肥大なビルドツールが一切残らず、イメージサイズが驚くほど小さくなります。

## 四、 パッケージのアンインストールと「孤児パッケージ」の整理

`apk` はアンインストール時に「どのソフトからも依存されなくなった孤児パッケージ」をデフォルトで自動チェック・削除してくれるため、他のディストリビューションのように頻繁に autoremove を叩く必要はあまりありません。

**1. パッケージの削除**

```bash
apk del <パッケージ名>
```

**2. 孤児の強制クリーンアップ (念のため)** 手動でファイルを雑に消してしまった場合や、システムを極限までクリーンに保ちたい場合、ネイティブの autoremove コマンドはありませんが、この方法で明示的に記録されていない孤児を洗い出せます：

```bash
# システム依存関係の修復とクリーンアップ（world リストに属さないパッケージはすべて削除される）
apk fix
```

## 五、 応用：リポジトリ (Repository) 管理

Alpine のリポジトリは主に `main`（コアサポート）と `community`（コミュニティ保守）に分かれています。便利な OSS の多くは `community` に入っていますが、初期状態では有効化されていない場合があります。

**1. Community リポジトリの有効化** `/etc/apk/repositories` を編集します：

```bash
vi /etc/apk/repositories
```

以下のような内容が表示されるので、`community` の行の先頭にある `#` コメントを外せば有効になります：

```bash
http://dl-cdn.alpinelinux.org/alpine/v3.18/main
http://dl-cdn.alpinelinux.org/alpine/v3.18/community
```

> [!info] Updated 2026-11-27
> Alpine Linux v3.18 は 2025-05-09 をもってサポート終了（EOL）となっています。`/etc/apk/repositories` を設定する際はホストが現在使用している有効なバージョンブランチ（例：`v3.21` や `latest-stable`）に合わせ、全面的に `https://` プロトコルへ切り替えることを推奨します。

変更後は忘れずに `apk update` を一度実行してください。

**2. 単一パッケージに対して一時的にエッジテスト版リポジトリ (Edge) を指定する** システム全体を不安定なテスト版にアップグレードしたくはないけれど、特定のソフトだけ最新版が急ぎで欲しい場合は、このようにコマンドで一時的にリポジトリを指定してインストールできます：

```bash
# 一時的に edge リポジトリを使用して特定ソフトの最新版をインストール
apk add --no-cache <パッケージ名> --repository=http://dl-cdn.alpinelinux.org/alpine/edge/community
```

> [!info] Updated 2026-11-27
> 現在の Alpine 環境では、通信の安全性を確保するため、上記の URL も `https://dl-cdn.alpinelinux.org/alpine/edge/community` に変更することを推奨します。
