# Gentoo / Portage / Emerge 実践コマンド＆メンテナンスTips ノート

## 一、 はじめの一歩：Portage と USE Flags の哲学

Gentoo でソフトウェアをインストールする場合、システムはデフォルトでソースコードを取得し「その場でコンパイル」します。ここから Gentoo 最大の強みである **USE Flags** が生まれます。USE Flags を定義することで、コンパイルの時点でどの機能を削り、どの機能を追加するか（例：システム全体で Bluetooth サポートを外す、GUI インターフェースを含めないなど）を決定でき、究極の軽量化を実現できます。

グローバル設定ファイルは通常 `/etc/portage/make.conf` にあり、個別パッケージの細かな設定は `/etc/portage/package.use/` に配置します。

## 二、 基本メンテナンス：同期とシステム更新

Gentoo の更新コマンドはユーザーの間で「詠唱呪文」と冗談交じりに呼ばれます。オプションが非常に長いものの、それぞれが重要な意味を持っているためです。

**1. Portage ツリーの同期 (Sync)** まずリモートから最新の「コンパイルスクリプト (ebuilds)」カタログを取得します：

```bash
# 従来の使い方
sudo emerge --sync

# 現在推奨されている使い方 (より高速で複数のリポジトリに対応)
sudo emaint sync -a
```

**2. システム全体の更新 (World Update)** これが Gentoo ユーザーに最も馴染み深い究極のコマンドです：

```bash
sudo emerge --ask --verbose --update --deep --newuse @world
# 通常は次のように省略されます：
sudo emerge -avuDN @world
```

> **オプション解説：**
> 
> - `-a (ask)`：コンパイル前にリストを表示して実行可否を確認します（誤操作防止のため必須）。
> - `-v (verbose)`：詳細情報（USE Flags の変更などを含む）を表示します。
> - `-u (update)`：パッケージを更新します。
> - `-D (deep)`：依存パッケージを含めた依存チェーン全体をチェックして更新します。
> - `-N (newuse)`：USE Flags を変更した場合、影響を受けるパッケージを自動的に拾い上げて「再コンパイル」し、新しい設定を適用します。

**3. 設定ファイルの更新 (Dispatch-conf)** ソフトウェア更新後、グローバル設定ファイルに競合が発生しても Gentoo は自動上書きしません。以下を実行する必要があります：

```bash
sudo dispatch-conf
# または
sudo etc-update
```

`u` を押して新しい設定を適用するか、`z` を押して破棄します。

## 三、 パッケージのインストールと「孤児パッケージ」の削除

**1. パッケージの検索とインストール**

```bash
# パッケージを検索 (標準の search は非常に遅いため、後述の代替ツール eix を紹介します)
emerge --search <キーワード>

# パッケージをインストール (world リストにも記録されます)
sudo emerge -av <パッケージ名>

# ⚠️ 重要テクニック：記録せずにインストール (Oneshot)
# ビルドツールや依存関係を一時的に入れたいが、主要ソフトとして @world に記録したくない場合に使用：
sudo emerge -av --oneshot <パッケージ名>
```

**2. アンインストールと孤児パッケージの削除 (Depclean)** Gentoo の削除ロジックは非常に厳密です。`emerge -C <パッケージ>` (unmerge) で直接強制削除すると、他のソフトの依存関係を壊してシステムが破損しやすくなります。

**標準的かつ安全な削除手順：**

```bash
# 1. 指定したパッケージを @world リストから除外する (他のパッケージが必要としている場合は削除を阻止)
sudo emerge --deselect <パッケージ名>

# 2. 依存関係のクリーンアップ (Depclean) を実行！ @world になく誰からも参照されていない孤児パッケージをすべて綺麗に削除します
sudo emerge --ask --depclean
# 省略形：
sudo emerge -a --depclean
```

> [!info] Updated 2026-11-27
> 補足説明：`emerge --deselect <パッケージ名>` はパッケージを `@world` リストから外すだけであり、その場で逆依存関係のチェックやアンインストールを**行うわけではありません**。実際の依存関係チェックと安全な削除はステップ 2 の `emerge -a --depclean` が担当します（特定のパッケージのみを単独でチェック・削除したい場合は `emerge -a --depclean <パッケージ名>` を使用できます）。

**3. 破損した動的リンクライブラリの再構築 (Preserved-rebuild)** クリーンアップやコアライブラリ（glibc、openssl など）のアップグレード後、一部の古いソフトウェアで `.so` ファイルが見つからなくなることがあります。このコマンドを実行すると、影響を受けたソフトウェアを自動検出し再コンパイルしてくれます：

```bash
sudo emerge @preserved-rebuild
```

## 四、 ディスク容量の解放：ソースコードキャッシュの削除

Gentoo はコンパイル前にすべてのソースコード圧縮ファイル（Tarballs）をダウンロードし、`/var/cache/distfiles/` に蓄積します。放置すると凄まじい容量を食いつぶします。

**1. Gentoolkit のインストール** 公式がメンテナンスしている非常に強力な管理ツール集で、必須です：

```bash
sudo emerge -av app-portage/gentoolkit
```

**2. eclean を使ったキャッシュ削除**

```bash
# 安全な削除：現在インストール済みパッケージのソース圧縮ファイルは残し、期限切れバージョンのみ削除
sudo eclean-dist

# ディープクリーン：容赦なし！ Portage ツリー内の最新バージョン以外はすべて削除 (-d = deep)
sudo eclean-dist -d

# バイナリパッケージ (buildpkg) を作成している場合、古いバイナリパッケージを削除
sudo eclean-pkg -d
```

## 五、 救命ツール：ダウングレード、バージョン固定、Mask

Gentoo では `/etc/portage/package.mask`（ブラックリスト／使用禁止）と `/etc/portage/package.accept_keywords`（テスト版の解禁）によってバージョン制御を行います。

**1. 旧バージョンを指定してインストール (ダウングレード)** 新バージョンにバグがある場合は、`=` でバージョン番号を指定して旧版を強制インストールできます：

```bash
# 先頭の = 記号が必須で、かつ完全なカテゴリパスを指定する必要があります
sudo emerge -av =sys-kernel/gentoo-sources-6.1.60
```

**2. アップグレード防止のためのバージョン固定 (Masking)** 次回の `emerge -avuDN @world` でシステムが勝手に新バージョンへ戻してしまうのを防ぐため、新版を「Mask（マスク）」する必要があります。

`/etc/portage/package.mask` ファイルを編集または新規作成します（同名ディレクトリを作成し、その中にテキストファイルを置くことも可能）：

```bash
# Portage への指示：6.2 以降のバージョンのこのパッケージは一切不要
>=sys-kernel/gentoo-sources-6.2.0
```

設定しておけば、Portage は 6.2 以降が存在しないものとして扱います。

## 六、 上級向け便利ツール (高速化と検索)

**1. Eix：超高速検索ツール** 標準の `emerge --search` は毎回テキストデータベース全体をスキャンするため、耐え難いほど遅いです。必ず `eix` をインストールしてください。

```bash
sudo emerge -av app-portage/eix

# インデックスデータベースを初期化・構築
sudo eix-update

# 超高速でパッケージを検索
eix <キーワード>
```

**2. コンパイルの高速化：MAKEOPTS** 毎回その場でコンパイルするため、ビルド速度は CPU コア数に直結します。必ず `/etc/portage/make.conf` に並列コンパイルを設定しておきましょう：

```toml
# CPU が 16 スレッドの場合、通常はコア数または コア数+1 に設定
MAKEOPTS="-j16 -l16"
```

**3. Ccache：コンパイルキャッシュ** 同じパッケージを何度も再コンパイルする場合（Kernel config を調整したり、USE Flags を変えて試したりする場合など）、`ccache` をインストールして有効化すると、2 回目以降のコンパイル速度が何倍にも向上します。これも Gentoo ユーザー必携の設定です。
