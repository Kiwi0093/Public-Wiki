# WSL（Store 版）のインストールと ArchWSL 初期設定

> <img src='https://img.shields.io/badge/Status-Active-A8FF24?style=for-the-badge&labelWidth=100' height='38' />

![WSL](https://img.shields.io/badge/WSL-Supported-green?style=plastic&logo=linux)

:::tip
Microsoft の WSL（Windows Subsystem for Linux）が Store 版（バージョン 1.0 以上）になってからの最大のメリットは、公式で `systemd` を直接サポートし、GUI アプリ（WSLg）の対応もより充実したことです。この記事では、ゼロから WSL のコア環境を構築し、ディストリビューションを普段使い慣れている Arch Linux（ArchWSL）へ置き換える手順を記録しています。
:::

## 基本環境と動作要件

**Windows システムバージョンの確認**

- **最小要件：** Windows 10 バージョン 2004 以降（Build 19041 以上）または Windows 11。
- **バージョン確認方法：** `Win + R` を押して `winver` と入力すると確認できます。
- **Windows 10 に関する補足：** <span style="color:#e06c75"><del>WSL の最新機能を完全にサポートするため、Windows 10 では基本的に更新プログラム **KB5020030** のインストールが必要です。システムが自動更新されていない場合は、[Microsoft Update Catalog](https://www.catalog.update.microsoft.com/Search.aspx?q=KB5020030) から環境に合わせて検索・ダウンロードしてインストールしてください。</del></span> *(Updated 2026-11-27: KB5020030 は後続の累積更新プログラムに置き換えられており、また Windows 10 は 2025-10-14 にサポート終了（EOL）を迎えたため、Windows 11 をそのまま使用することを推奨します。)*

## WSL のインストール手順

現在 WSL をインストールする方法は 2 通りあります。コマンドで直接行うほうが速くておすすめですが、GUI 画面で操作したい場合はそちらでも構いません：

### 方法 1：クイックコマンドでのインストール（推奨）

管理者権限で PowerShell を開き、以下のコマンドを入力します：

```powershell
wsl --install
```

このコマンドは必要な Windows 機能をすべて自動で有効化し、デフォルトで Ubuntu をインストールします。Ubuntu を入れずに機能だけを有効化したい場合は、`--no-distribution` オプションを付けます。実行後、PC を再起動すれば完了です。

### 方法 2：GUI による従来方式でのインストール

手動で機能を確認したい場合や、Microsoft Store からダウンロードしたい場合は以下の手順で行います：

1. Microsoft Store で **WSL** を検索してインストールします。
2. 「Windows の機能の有効化または無効化」を開きます。
3. 以下の主要コンポーネントに必ずチェックを入れます：

   - <span style="color:#e06c75"><del>**Hyper-V**：これは基本的に有効化が必須です。</del></span> *(Updated 2026-11-27: WSL 2 の実行に完全な Hyper-V 役割の有効化は不要であり、Windows Home エディションにはこの項目自体が存在しません。)*
   - <span style="color:#e06c75"><del>**Windows ハイパーバイザー プラットフォーム**</del></span> *(Updated 2026-11-27: この項目はサードパーティ製エミュレータ／仮想マシン向けのものであり、WSL 2 の必須コンポーネントではありません。)*
   - **Linux 用 Windows サブシステム**：WSL 全体の基本コンポーネントです。
   - **仮想マシン プラットフォーム**：WSL 2 カーネルの動作に有効化が必須です。

4. 設定完了後、PC を再起動します。

## 推奨ツール：Windows Terminal

WSL を利用する際は **Windows Terminal**（こちらも Store からダウンロード可能）との併用を強く推奨します。

> **カスタマイズメモ：** あわせて **Nerd-Fonts** 系のフォントを別途インストールし、Windows Terminal の設定でフォントを変更しておくことを忘れないでください。そうしておけば、後々 WSL 内で `zsh` と `powerlevel10k` などのテーマを使った際も、きれいなアイコンやステータスバーが文字化けせずに表示されます（見た目をカスタマイズした環境では基本的にこのフォントが必須です）。

## カスタムディストリビューション：ArchWSL

WSL に標準で用意されているディストリビューションはどれもあまり好みではないため（主に Debian / Ubuntu 系）、私は **ArchWSL** を使用しています。

- **インストール方法：** <span style="color:#e06c75"><del>とても簡単で、現在は **Microsoft Store** を直接開いて **ArchWSL**（または Arch Linux）を検索し、「入手」をクリックしてインストールできます。インストール完了後にスタートメニューから起動すれば、自動的に初期環境のセットアップが行われます。以前は GitHub から手動でアーカイブをダウンロードして展開する必要がありましたが、現在は Microsoft Store 経由でのインストールと管理が非常に手軽になりました。</del></span> *(Updated 2026-11-27: `yuk7/ArchWSL` は GitHub 上のサードパーティ製プロジェクトであり、Microsoft Store の公式公開アイテムではありません。現在は公式からネイティブの Arch Linux WSL イメージが提供されており、PowerShell で `wsl --install archlinux` を実行するだけで直接インストールできます。)*

## Systemd の状態確認

ストア等から ArchWSL をインストールしたら、WSL 内の `systemd` サポートを確認し、手動で有効化する必要があります。以下の手順に沿って設定してください：

**1. WSL バージョンの確認** Windows の PowerShell または CMD で以下を入力します：

```powershell
wsl --version
```

_バージョン番号が表示され、Store 版（1.0.0 以上）であることを確認します。_

**2. WSL 設定ファイルの確認と編集** ArchWSL のターミナルに入り、`/etc/wsl.conf` ファイルを確認または新規作成して、以下の内容が含まれているようにします：

```ini
[boot]
systemd=true
```

**3. 再起動と検証** Windows PowerShell に戻り、WSL を完全にシャットダウンしてから再起動します：

```powershell
wsl --shutdown
wsl
```

再度 WSL に入った後、次のコマンドを実行して PID 1 のプロセスを確認します：

```bash
ps --no-headers -o comm 1
```

画面に `systemd` と表示されれば成功です！

## 付録：VirtualBox との競合解消（Hyper-V support）

Hyper-V や仮想マシン プラットフォームを有効化すると、VirtualBox を併用している場合に仮想マシンが起動できなくなることがあります。解決方法は簡単で、VirtualBox 側の該当 VM の設定を開き、「システム」->「アクセラレーション」にある **準仮想化インターフェース（Paravirtualization Interface）** を `Hyper-V` に変更するだけです。
