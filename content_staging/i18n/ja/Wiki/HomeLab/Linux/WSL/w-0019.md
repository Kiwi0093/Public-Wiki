WSL では現在、Nested Virtualization（ネストされた仮想化）を有効にすることで、パススルー型のハイパーバイザーとして仮想マシンを実行できます。簡単に言えば、WSL2 自体がすでに Windows Hyper-V 上で動作する仮想マシンであり、この機能を有効にすることで WSL2 の内部でさらに QEMU/KVM 仮想マシンを実行し、「仮想マシンの中で仮想マシンを動かす」ことが可能になります（もちろんパフォーマンスは低下します）。

## 一、Host Setting（Windows ホスト側設定）

**1. WSL カーネルの更新**

WSL が最新バージョンであることを確認するため、Windows の PowerShell で以下を実行します：

```powershell
wsl --update
```

**2. Nested Virtualization を有効化**

> **⚠️ 間違いやすいポイント：** ネストされた仮想化の設定は WSL2 仮想マシンエンジン全体に対するものであるため、Windows 側のグローバル設定ファイル `.wslconfig` に記述する必要があり、WSL 内部の `/etc/wsl.conf` に書いては**いけません**。

Windows のエクスプローラーを開き、`C:\Users\<ユーザー名>\.wslconfig` を編集または新規作成し、以下を追記します：

```ini
[wsl2]
nestedVirtualization=true
```

完了したら、PowerShell で WSL を強制再起動して設定を反映させます：

```powershell
wsl --shutdown
```

## 二、ArchWSL への QEMU/KVM と Virt-Manager のインストール

> [!info] Updated 2026-11-27
> 1. サードパーティ製の `ArchWSL` に加え、Arch Linux は現在公式の WSL2 イメージ（`archlinux-wsl`）を提供しており、Windows から `wsl --install archlinux` で直接インストールできます。
> 2. 下記の `systemctl enable --now libvirtd` を実行する前に、WSL 内部の `/etc/wsl.conf` の `[boot]` セクションで `systemd=true` が設定されており、`wsl --shutdown` で再起動済みであることを確認してください。そうでないと `systemctl` が動作しません。

WSL（Arch Linux）を再起動して起動したら、仮想化関連ツールのインストールを開始します。

**1. コアおよびネットワークパッケージのインストール**

```bash
sudo pacman -S archlinux-keyring qemu-full virt-manager virt-viewer edk2-ovmf dnsmasq vde2 bridge-utils openbsd-netcat libguestfs ebtables iptables virglrenderer
```

> [!info] Updated 2026-11-27
> 1. `ebtables` は Arch Linux 公式リポジトリから削除されており、その機能は `nftables` バックエンドをサポートする `iptables` に置き換えられています。実際に `pacman -S` を実行する際は、`target not found` エラーを防ぐため `ebtables` を外してください。
> 2. 第 4 節の VirtioFS 共有フォルダ機能を使用する場合は、`virtiofsd` パッケージも併せてインストールしてください（QEMU から独立したパッケージに分離されています）。

**2. TPM 2.0 エミュレーションパッケージのインストール（Windows 11 ゲストを実行する場合）**

```bash
sudo pacman -S swtpm
```

**3. Libvirt サービスの起動と設定**

```bash
# 啟動並設定開機自啟 libvirtd
sudo systemctl enable --now libvirtd

# 啟動預設的虛擬網路 (NAT)
sudo virsh net-start default

# 設定虛擬網路開機自動啟動
sudo virsh net-autostart default
```

**4. アカウント権限の調整**

Virt-Manager を開くたびに root パスワードを入力しなくて済むように、現在のユーザーを関連グループに追加します：

```bash
sudo usermod -a -G libvirt $USER
sudo usermod -a -G libvirt root
sudo usermod -a -G kvm $USER
sudo usermod -a -G kvm root
```

> [!info] Updated 2026-11-27
> `root` アカウント自体はすでに完全なシステム権限を持っているため、`usermod -a -G libvirt root` や `usermod -a -G kvm root` を実行する必要はありません。一般ユーザー `$USER` のみを `libvirt` と `kvm` グループに追加し、再ログイン（または WSL の再起動）を行えば十分です。

**5. Polkit ルールの設定（パスワードなし管理）**

`/etc/polkit-1/rules.d/50-libvirt.rules` を編集します：

```javascript
/* Allow users in kvm group to manage the libvirt daemon without authentication */
polkit.addRule(function(action, subject) {
    if (action.id == "org.libvirt.unix.manage" &&
        subject.isInGroup("kvm")) {
            return polkit.Result.YES;
    }
});
```

すべての変更が完了したら、サービスを再起動して権限を適用します（最も確実なのは WSL から一度ログアウトして再ログインするか、`wsl --shutdown` を実行することです）：

```bash
sudo systemctl restart libvirtd
```

## 三、Guest OS 設定（2 層目の Arch Linux を例として）

Virt-Manager で Guest OS（仮想マシン）をインストールしたら、画面の自動リサイズやクリップボード共有を実現するために、VMware Tools に相当するゲスト拡張パッケージをインストールする必要があります。

**1. QEMU および SPICE ゲストエージェントのインストール**

**Guest OS（仮想マシン内部）** で以下を実行します：

```bash
sudo pacman -S spice-vdagent qemu-guest-agent xf86-video-qxl
```

X11 デスクトップ環境を使用している場合、ウィンドウの自動スケーリングを有効にするために AUR から `x-resize` をインストールできます：

```bash
yay -S x-resize
```

> **💡 Service Enable に関する疑問：** ネット上の古い解説の多くではこれらのサービスを `systemctl enable` すると書かれています。しかし現在、`spice-vdagent` は通常デスクトップ環境（GNOME / KDE / XFCE などの autostart）によって自動起動され、`qemu-guest-agent` は socket 経由でトリガーされます。そのため対応する service ファイルが見つからなかったり、手動で enable する必要がなかったりするのは正常であり、再起動後に機能が正常に動作していれば問題ありません。

## 四、Shared Folder のマウント（VirtioFS）

VirtioFS を使用すると、Guest OS から Host（ここでは WSL を指す）のフォルダへネイティブかつ高効率にアクセスできます。

**1. Virt-Manager ハードウェア設定**

1. まず Guest OS をシャットダウンします。
2. Virt-Manager ウィンドウ上部に並んでいる「電球」アイコン（仮想ハードウェアの詳細を表示）をクリックします。
3. 左下の **Add Hardware（ハードウェアを追加）** をクリックします。
4. **Filesystem（ファイルシステム）** を選択します：
   - **Driver:** `virtiofs` を選択
   - **Source path:** WSL 内のディレクトリを入力（例：`/home/kiwi/host` ※事前に WSL 側でこのフォルダを作成しておいてください）
   - **Target path:** マウントタグ（Mount Tag）となるラベル名です。任意の名前を設定できます（例：`host`）
5. 「完了」をクリックして仮想マシンを起動します。

> [!info] Updated 2026-11-27
> VirtioFS を使用する前に、Virt-Manager 仮想マシン設定の **Memory** ページで **Enable shared memory** にもチェックを入れておく必要があります。チェックを入れないと、仮想マシン起動時に `virtiofs requires shared memory` エラーが発生します。

**2. Guest OS 側でのマウント**

**手動マウントのテスト：**

```bash
# -t virtiofs <Target Path 標籤> <Guest OS 內的掛載點>
sudo mount -t virtiofs host /home/kiwi/host
```

**`/etc/fstab` に記述して起動時に自動マウント：**

手動マウントに問題がないことを確認したら、Guest OS 内の `/etc/fstab` を編集して以下の行を追加します：

```text
# Shared Folder with HOST (WSL)
# <Target標籤>  <掛載點>           <格式>      <參數>                       <dump> <pass>
host            /home/kiwi/host   virtiofs   rw,noatime,_netdev           0      2
```

> **注意：** `_netdev` オプションを付けることで、ネットワークおよび外部デバイスモジュールが読み込まれた後にマウントが実行されるようになり、起動時のハングを防ぐことができます。

> [!info] Updated 2026-11-27
> 6 列目の `pass`（`fsck` チェック順序）は `2` ではなく `0`（つまり `0 0`）に設定することを推奨します。`virtiofs` は仮想共有ファイルシステムであり、システム内に対応する `fsck.virtiofs` チェックツールが存在しないためです。
