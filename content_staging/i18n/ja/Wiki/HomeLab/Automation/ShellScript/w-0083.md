## 1. Shell 特殊制御文字クイックリファレンス

| **記号**                     | **名称**             | **主な機能と挙動の解説**                                    | **実践コマンド例**                                                                      |
| -------------------------- | ------------------ | ------------------------------------------------ | ------------------------------------------------------------------------------- |
| **`$`**                    | 変数展開記号             | 変数に対応する値を抽出する。環境変数や特殊変数（`$?`、`$$` など）にも使用              | `echo $USER`<br />`echo $?` _(直前のコマンドの終了ステータスコードを返す)_                                         |
| **`#`**                    | コメント記号               | 行頭または空白の後の `#` はコメントを示し、Shell はそれ以降の文字列を無視する                 | `# これはコメントです`<br />`mkdir app # ディレクトリを作成`                                                  |
| **`\`**                    | エスケープ文字 (Escape)      | 直後に続く単一文字の特殊な意味を打ち消し、リテラル文字として扱う。行末では改行継続文字として機能                  | `echo \$PATH`<br />`rm -f filename\ with\ space.txt`                              |
| **`\|`**                   | パイプ記号 (Pipe)        | 左側のコマンドの「標準出力 (stdout)」を右側のコマンドの「標準入力 (stdin)」へ渡す     | `cat access.log \| grep "404" \| wc -l`                                         |
| **`;`**                    | コマンド区切り文字              | 複数のコマンドを順番に連続実行する（前のコマンドの成否に関わらず次のコマンドを実行）                  | `cd /opt; ls -la; df -h`                                                        |
| **`&`**                    | バックグラウンド実行制御           | コマンドをバックグラウンド（Background）で実行し、現在の端末プロンプトを即座に解放する               | `python3 server.py &`<br />`nohup ./backup.sh &`                                  |
| **`/`**                    | パス区切り文字            | Linux 仮想ファイルシステムツリー構造におけるディレクトリ階層の区切り文字。最上位の単独の `/` はルートディレクトリを指す        | `/var/log/docker.log`                                                           |
| **`>`**                    | 出力リダイレクト (上書き)         | 標準出力を指定ファイルに書き込む。**ファイルが既に存在する場合は直接上書きする**                     | `echo "token=123" > config.env`                                                 |
| **`>>`**                   | 出力リダイレクト (追記)         | 標準出力を指定ファイルに書き込む。上書きせず**ファイルの末尾に追記する**                 | `date >> /var/log/deploy.log`                                                   |
| **`<`**                    | 入力リダイレクト              | 指定ファイルの内容をコマンドの標準入力として渡す（キーボード入力の代わり）                        | `mysql -u root -p db < backup.sql`                                              |
| **`<<`**                   | ヒアドキュメント (Here-Document)      | 複数行のテキストブロックを標準入力として定義し、指定した終了タグ（例：`EOF`）まで読み込む             | `cat << 'EOF' > test.txt`<br />`hello`<br />`EOF`                                   |
| **`' '`**                  | シングルクォート (強いクォート)          | **文字を完全にそのまま（リテラル）維持**し、内部の変数やエスケープ記号を一切展開しない             | `echo '$USER'` _(出力: `$USER`)_                                                  |
| **`" "`**                  | ダブルクォート (弱いクォート)          | ほとんどの文字をそのまま維持するが、**変数（`$`）、コマンド置換（`$()`）、エスケープ（`\`）の展開は許可する** | `echo "Hi, $USER"` _(出力: `Hi, admin`)_                                          |
| **`$( )`** または **`` ` ` ``** | コマンド置換               | 括弧内のコマンドを優先実行し、その実行結果（stdout）を元の位置に展開する                 | `TODAY=$(date +%F)`<br />`tar -czvf "backup-$TODAY.tar.gz" /data`                 |
| **`( )`**                  | サブシェル (Subshell) | 独立してフォーク（Fork）された子プロセス内でコマンド群を実行する。内部でのディレクトリ移動や変数変更は外側に影響しない         | `(cd /tmp && rm -rf *)` _(実行終了後も現在の Shell は元のディレクトリに留まる)_                                 |
| **`{ }`**                  | コマンドグループ / ブレース展開          | 1. 現在の Shell 内でコマンドをグループ化して実行（スペースとセミコロンが必要）。<br />2. シーケンスや文字列の一括展開。 | `{ echo 1; echo 2; }`<br />`mkdir -p /opt/{app,db,config}`<br />`cp app.yml{,.bak}` |

## 2. ワイルドカード (Wildcards / Globbing) クイックリファレンス

ワイルドカードは主にコマンド実行前に Shell によって展開され（Pathname Expansion）、**ファイル名やパスのマッチング**に使用されます：

| **ワイルドカード**                       | **マッチ規則**       | **正確な挙動の解説**                       | **実践例**                                                               |
| ------------------------------ | -------------- | -------------------------------- | ---------------------------------------------------------------------- |
| **`*`**                        | 0 文字以上の任意の文字列     | ファイル名内の任意の長さの文字列にマッチ（隠しファイルの先頭ドット `.` は含まない）     | `ls *.log` _(.log で終わるすべてのファイルを一覧表示)_<br />`rm -rf /tmp/cache*`                  |
| **`?`**                        | **任意の 1 文字ちょうど** | 必ず 1 文字のみにマッチする（0 文字や 2 文字以上にはマッチしない） | `ls file?.txt` _(`file1.txt`、`fileA.txt` にはマッチするが、`file10.txt` にはマッチしない)_        |
| **`[abc]`**                    | 集合内の任意の 1 文字        | 角括弧内に列挙された文字のいずれか 1 文字にマッチ                   | `ls report_[abc].pdf` _(`report_a.pdf`、`report_b.pdf` などにマッチ)_           |
| **`[0-9]`**                    | 文字コード範囲内の任意の 1 文字      | ASCII / 文字コードの連続範囲内にある任意の 1 文字にマッチ          | `ls img_[0-9].png` _(0 から 9 までの単一数字にマッチ)_<br />`ls [a-z]*.md` _(小文字のアルファベットで始まるファイル)_ |
| **`[!abc]`**<br />_(または `[^abc]`)_ | 除外集合 (否定)      | 角括弧内で指定された文字を**含まない**任意の 1 文字にマッチ           | `ls file[!0-9].txt` _(`fileA.txt` にマッチし、`file1.txt` は除外)_                  |

## 3. 上級エンジニア必須：混同しやすい境界条件と細部 (Tips)

### 3.1 論理演算子 `&&` と `||`

- **`cmd1 && cmd2` (AND)**：`cmd1` が**正常終了（終了コード = 0）**した場合のみ、続けて `cmd2` を実行します。
- **`cmd1 || cmd2` (OR)**：`cmd1` が**失敗（終了コード ≠ 0）**した場合のみ、`cmd2` を実行します。
- **定番の例**：

    ```bash
    docker compose pull && docker compose up -d || echo "デプロイ更新に失敗しました！"
    ```

### 3.2 ワイルドカードと正規表現 (Regex) の違い

- **Shell ワイルドカード (Globbing)**：Shell によって解釈され、ディスク上の**ファイル名**に直接対応します。
    - `*` は「任意の文字列」を表します。
    - `?` は「任意の 1 文字」を表します。
- **正規表現 (Regex)**：特定のツール（`grep`、`sed`、`awk`、`python` など）によって解釈され、**テキスト内容**のマッチングに使用されます。
    - `*` は「直前の文字の 0 回以上の繰り返し」を表します。
    - `.` は「任意の 1 文字」を表します。
    - `.*` の組み合わせがワイルドカードの `*` に相当します。

### 3.3 ブレース展開 (Brace Expansion) の効率的な活用法

ループを書かずに、中括弧 `{}` を使って連続した文字列やファイルを一括生成できます：

```bash
# 1. node_01 から node_10 までのディレクトリを一括作成
mkdir -p node_{01..10}

# 2. バックアップファイルを素早く作成（cp nginx.conf nginx.conf.bak と同等）
cp nginx.conf{,.bak}

# 3. 2 次元マトリックス展開（a1, a2, b1, b2 を生成）
echo {a,b}{1,2}
```
