## 1. 変数定義と代入のルール

- **基本定義**：

    ```bash
    VAR_NAME="value"      # イコール（=）の両側にスペースを入れてはいけません
    echo "${VAR_NAME}"    # 境界の混同を防ぐため、常に中括弧 ${} で囲むことを推奨します
    ```

- **コマンド出力の代入 (Command Substitution)**：

    ```bash
    CURRENT_USER=$(whoami)
    BACKUP_DATE=$(date +%F)
    ```

- **変数のスコープ**：
    - 通常の宣言はローカル変数（現在のプロセスのみ有効）となります。
    - `export VAR_NAME` を用いて環境変数として宣言することで、フォーク（Fork）された子プロセスへ引き継ぐことができます。

## 2. 特殊自動変数と位置パラメータ クイックリファレンス

| **変数名**        | **意味の説明**                       | **挙動の解説とエンジニアが押さえるべき詳細**                                       | **実践例**                                                  |
| --------------- | ------------------------------ | ------------------------------------------------------ | --------------------------------------------------------- |
| **`$?`**        | 直前のコマンドの終了ステータスコード (Exit Code)        | `0` は実行成功、0 以外（`1`, `2`, `127` など）は実行失敗または異常を示す           | `systemctl restart nginx`<br />`[ $? -eq 0 ] && echo "OK"`  |
| **`$$`**        | 現在の Shell プロセスの Process ID (PID)  | 並列実行時の競合を避けるため、スクリプトが一意の一時ファイル名を作成する際によく使われる                                 | `TMP_FILE="/tmp/run_$$.tmp"`                              |
| **`$!`**        | 最後にバックグラウンド実行されたプロセスの PID              | `&` でバックグラウンドに送った直近のプロセス ID を取得し、後から `wait` で監視する際に便利                    | `python3 job.py &`<br />`JOB_PID=$!`                        |
| **`$-`**        | 現在の Shell で有効になっているフラグ (Flags)        | 現在のシェルの実行オプション（`h`、`B`、`i` などの対話モードフラグ）を表示する                | `echo "$-"`                                               |
| **`$0`**        | 現在の Shell スクリプトのファイル名またはパス              | 実行時に入力されたコマンドパス（例：`./deploy.sh` や `/opt/deploy.sh`）         | `SCRIPT_DIR=$(dirname "$0")`                              |
| **`$1` ~ `$9`** | コマンドライン位置パラメータ (Positional Arguments) | 外部から渡された 1 番目〜9 番目の引数を順番に受け取る（10 番目以降は `${10}` を使用）                      | `./backup.sh /data /mnt/nas`<br />`# $1=/data, $2=/mnt/nas` |
| **`$#`**        | スクリプトに渡された引数の総数                     | スクリプト冒頭で引数の数が十分かを検証する際によく使われる                                      | `[ $# -lt 2 ] && exit 1`                                  |
| **`$*`**        | 渡されたすべての引数の集合 (結合文字列)               | ダブルクォート `"$*"` で囲むと、すべての引数が `$IFS`（デフォルトは空白）で 1 つの文字列に連結される：`"$1 $2 $3"`  | `echo "All args: $*"`                                     |
| **`$@`**        | 渡されたすべての引数の集合 (独立配列)               | **ループ処理や引数転送で最も多用される**。ダブルクォート `"$@"` は各引数を独立した文字列として保持する：`"$1" "$2" "$3"` | `for arg in "$@"; do ... done`                            |

## 3. 代表的な Bash 組み込み環境変数

|**変数名**|**説明**|**典型的な用途**|
|---|---|---|
|**`$BASH_ENV`**|非対話型 Shell の起動時に自動で読み込まれる設定ファイルのパス|CI/CD 自動化スケジュール環境への変数注入|
|**`$CDPATH`**|`cd` コマンド実行時の検索対象ディレクトリ一覧（コロン区切り）|深い階層ディレクトリへの素早い移動|
|**`$LINENO`**|現在実行中のコード行番号|ログ追跡とデバッグ：`echo "Error at line $LINENO"`|
|**`$LINES` / `$COLUMNS`**|現在の端末画面の高さ（行数）と幅（列数）|端末 UI / プログレスバーの横幅自動調整|
|**`$PPID`**|現在のプロセスの親プロセス ID (Parent Process ID)|誰がこのスクリプトを呼び出したかを確認|
|**`$RANDOM`**|0 〜 32767 の間のランダムな整数を生成|ランダムなパスワードやポート番号の生成：`PORT=$((10000 + RANDOM % 10000))`|
|**`$SECONDS`**|スクリプト起動から現在までの累計経過秒数|スクリプトの所要時間計測：`echo "経過時間: ${SECONDS}s"`|
|**`$SHELL`**|ユーザーのデフォルト Shell の絶対パス|デフォルト Shell の確認（通常は `/bin/bash`）|
|**`$TMOUT`**|無操作時の自動ログアウト時間（単位：秒）|セキュリティ強化：一定時間アイドル状態が続くと端末接続を自動切断|

## 4. 空変数と未設定変数の処理 (Parameter Expansion)

Shell スクリプトにおいて、値が代入されていない変数をそのまま使用すると予期しない挙動（最悪の場合、`rm -rf /${DIR}` によるルートディレクトリの誤削除のような大惨事）を引き起こす可能性があります。Bash のパラメータ展開構文を使うことで、デフォルト値の設定や安全なエラー停止をスマートに実装できます：

| **構文形式**           | **条件判定**         | **処理の挙動**                                 | **実践例**                                         |
| ------------------ | ---------------- | ---------------------------------------- | ------------------------------------------------ |
| **`${var:-word}`** | `var` が空または未設定     | **一時的に** `word` を返り値として使用し、`var` 自体の内容は**変更しない** | `PORT=${CUSTOM_PORT:-8080}`<br />_(未指定時のデフォルトを 8080 に設定)_  |
| **`${var:=word}`** | `var` が空または未設定     | **`word` を `var` に代入した上で**、その新しい値を使用する            | `${DATABASE_NAME:=homelab}`<br />_(未設定時に自動定義して変数に保存)_ |
| **`${var:?word}`** | `var` が空または未設定     | `word` のエラーメッセージを stderr に出力し、**即座にプログラムを強制終了する**   | `DIR=${1:?"対象ディレクトリパスを指定してください！"}`<br />_(引数不足時は即座に中断)_       |
| **`${var:+word}`** | `var` が**設定済みかつ非空** | 一時的に `word` に置き換えて返す。空の場合は空文字を返す（存在チェック用）          | `[ -n "${DEBUG:+x}" ] && echo "Debug on"`        |

> **ヒント**：コロンを省略した場合（例：`${var-word}`）、`var` が**完全に未宣言 (Unset)** の場合にのみ発動します。コロンを付けた場合（`${var:-word}`）は、**未宣言**と**宣言済みだが値が空文字列 `""`** の両方が対象になります。日常的なスクリプトではコロン付きの記述を推奨します。

## 5. 入力型変数：`read` コマンドの高度な使い方

`read` コマンドは端末で処理を一時停止し、ユーザーのキーボード入力を読み取るために使用します：

```bash
# 基本的な書き方
echo -n "プロジェクト名を入力してください: "
read PROJECT_NAME
echo "入力された値: ${PROJECT_NAME}"

# 推奨されるモダンな1行記述 (-p プロンプト、-t タイムアウト、-s パスワード非表示の組み合わせ)
# 1. プロンプト文字列付き (-p)
read -p "データベース名を入力してください: " DB_NAME

# 2. パスワード非表示入力 (-s、画面への表示を抑制)
read -sp "接続パスワードを入力してください: " DB_PASSWORD
echo "" # パスワード入力完了後に手動で改行

# 3. タイムアウトによる自動スキップ (-t、例として 10 秒待機)
read -t 10 -p "実行を続行しますか？(y/N): " CONFIRM
CONFIRM=${CONFIRM:-N} # タイムアウトで未入力の場合はデフォルトで N とする
```

## 6. コマンド置換と安全な条件判定の実践

外部コマンドの出力を変数に格納した後、比較判定を行う際は必ずフェイルセーフな記述を行ってください：

```bash
#!/usr/bin/env bash

# 1. 現在の実行ユーザー名を取得
CURRENT_USER=$(whoami)

# 2. 安全な条件判定 (互換性と機能性が最も高い [[ ]] 構文を推奨)
if [[ "${CURRENT_USER}" == "root" ]]; then
    echo "成功：現在 root 権限で実行されています"
else
    echo "警告：このスクリプトは root 権限で実行する必要があります (現在のユーザー: ${CURRENT_USER})" >&2
    exit 1
fi

# 3. 重要なパス変数の検証（未定義による誤削除を防ぐ防御的プログラミング）
TARGET_DIR="${1:-}"

# rm -rf / を防ぐための厳格なチェック
if [[ -z "${TARGET_DIR}" ]]; then
    echo "エラー：クリーンアップ対象ディレクトリが指定されていません！" >&2
    exit 1
fi

echo "一時フォルダをクリーンアップしています: ${TARGET_DIR}..."
```
