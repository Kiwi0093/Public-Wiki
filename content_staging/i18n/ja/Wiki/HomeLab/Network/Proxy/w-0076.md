## 2. DNS レコードと Cloudflare の重要設定

ドメイン管理サービス（Cloudflare を例とします）で、VPS のパブリック IP を指す A レコードを 3 つ追加します：

```text
panel.yourdomain.com   A   <VPS_IP>   DNS Only (または Proxied を有効化し Full SSL と併用)
reality.yourdomain.com A   <VPS_IP>   DNS Only (オレンジ雲は必ずオフにすること。TCP ネイティブハンドシェイクが壊れます)
cdn.yourdomain.com     A   <VPS_IP>   Proxied  (オレンジの雲を有効化し、実 IP を隠蔽)
```

### Cloudflare ダッシュボード確認事項

- **SSL/TLS モード**：**Full** または **Full (Strict)** に切り替えます（Cloudflare から Traefik の 443 へ接続した際の 520/521 エラーを防ぐため）。
- **Network**：**WebSockets** が有効（オン）になっていることを確認します。

## 3. Docker Compose デプロイ設定

`/opt/3x-ui/docker-compose.yml` に定義を作成し、Traefik が属する外部ブリッジネットワーク `proxy-network` に 3X-UI を接続します：

```yaml
services:
  3x-ui:
    image: ghcr.io/mhsanaei/3x-ui:latest
    container_name: 3x-ui
    restart: unless-stopped
    environment:
      - XRAY_VMESS_AEAD_FORCED=false
    volumes:
      - /opt/3x-ui/db:/etc/x-ui
      - /opt/3x-ui/cert:/root/cert
    networks:
      - proxy-network
    labels:
      - "traefik.enable=true"

      # =========================================================================
      # 1. 3X-UI Web パネル (独立ドメイン panel.yourdomain.com -> 内部 2053)
      # =========================================================================
      - "traefik.http.routers.xui-panel.rule=Host(`panel.yourdomain.com`)"
      - "traefik.http.routers.xui-panel.entrypoints=websecure"
      - "traefik.http.routers.xui-panel.tls=true"
      - "traefik.http.routers.xui-panel.tls.certresolver=myresolver"
      - "traefik.http.services.xui-panel.loadbalancer.server.port=2053"

      # =========================================================================
      # 2. VLESS-Reality 直接接続 (独立ドメイン reality.yourdomain.com -> 内部 44300)
      # =========================================================================
      # ポイント：HostSNI で接続先名を判定し、passthrough=true で Traefik による復号を禁止
      - "traefik.tcp.routers.xui-reality.rule=HostSNI(`reality.yourdomain.com`)"
      - "traefik.tcp.routers.xui-reality.entrypoints=websecure"
      - "traefik.tcp.routers.xui-reality.tls.passthrough=true"
      - "traefik.tcp.services.xui-reality.loadbalancer.server.port=44300"

      # =========================================================================
      # 3. VLESS-WS + CDN 救済ルート (独立ドメイン cdn.yourdomain.com -> 内部 44301)
      # =========================================================================
      # Traefik が TLS 終端を担当し、平文の WebSocket トラフィックを Xray へ転送
      - "traefik.http.routers.xui-ws.rule=Host(`cdn.yourdomain.com`)"
      - "traefik.http.routers.xui-ws.entrypoints=websecure"
      - "traefik.http.routers.xui-ws.tls=true"
      - "traefik.http.routers.xui-ws.tls.certresolver=myresolver"
      - "traefik.http.services.xui-ws.loadbalancer.server.port=44301"

networks:
  proxy-network:
    external: true
```

コンテナを起動します：

```bash
docker compose -f /opt/3x-ui/docker-compose.yml up -d
```

## 4. 3X-UI インバウンドノード (Inbounds) 設定詳細

ブラウザで `https://panel.yourdomain.com` を開いて管理パネルにログインし、**Inbounds（インバウンド一覧）** から 2 つのノードを追加します：

### 4.1 インバウンド 1：VLESS-Reality（内部ポート 44300）

- **Remark**：`Reality-Direct-44300`
- **Protocol**：`vless`
- **Listening IP**：`0.0.0.0`
- **Port**：**`44300`**（Compose の TCP サービスで指定したポート番号と一致させる）
- **Flow**：`xtls-rprx-vision`
- **Security**：`Reality`
- **uTLS**：`chrome`
- **Dest**：<span style="color:#e06c75"><del>reality.yourdomain.com:443（または swdist.apple.com:443）</del></span> *(Updated 2026-11-27: Reality の `Dest`／新版 3X-UI の `Target` には、同じ `HostSNI` を経由してローカルの `44300` ポートへ戻ってくる `reality.yourdomain.com:443` を指定してはいけません。未認証の探索接続がループしてしまいます。TLS 1.3 と HTTP/2 に対応した外部の実在サイト（`swdist.apple.com:443` など）、またはローカルの別の独立した仮想ホストの HTTPS ポートを指定してください)*
- **Server Names (SNI)**：**`reality.yourdomain.com`**（**Traefik Labels の `HostSNI` と完全に一致させること**）
- **Private Key / Public Key**：クリックして生成し、公開鍵（Public Key）を控えておく
- **Short IDs**：クリックして生成

### 4.2 インバウンド 2：VLESS-WS + CDN 救済ルート（内部ポート 44301）

- **Remark**：`WS-CDN-Rescue-44301`
- **Protocol**：`vless`
- **Listening IP**：`0.0.0.0`
- **Port**：**`44301`**（Compose の HTTP サービスで指定したポート番号と一致させる）
- **Network**：`ws`
- **Path**：`/ray-ws-stream`
- **Security**：**`none`**（**重要：Traefik の境界で TLS 証明書の復号が完了しているため、コンテナ側では絶対に TLS を有効にしないこと**）

## 5. クライアント設定リファレンス

内部で待ち受けるポートが `44300` でも `44301` でも、**外部のクライアント側で入力するサーバーポート番号はどちらも標準の `443` になります**。

### 5.1 Reality クライアント設定（直接接続・高速）

```text
vless://<UUID>@reality.yourdomain.com:443?type=tcp&security=reality&pbk=<PUBLIC_KEY>&fp=chrome&sni=reality.yourdomain.com&sid=<SHORT_ID>&flow=xtls-rprx-vision#Reality-Direct
```

- **Address**：`reality.yourdomain.com`
- **Port**：`443`
- **Security**：`reality`
- **SNI**：`reality.yourdomain.com`
- **Flow**：`xtls-rprx-vision`

### 5.2 WS + CDN クライアント設定（遮断対策・救済用）

```text
vless://<UUID>@cdn.yourdomain.com:443?type=ws&security=tls&sni=cdn.yourdomain.com&path=%2Fray-ws-stream#CDN-Rescue
```

- **Address**：`cdn.yourdomain.com`（遮断された場合は Cloudflare の最適化 IP に置き換え可能）
- **Port**：`443`
- **Security**：`tls`
- **SNI / Host**：`cdn.yourdomain.com`
- **Path**：`/ray-ws-stream`

## 6. トラブルシューティングの重要チェック項目

1. **Reality ハンドシェイクのタイムアウト (Timeout)**：
   - Cloudflare で誤って `reality.yourdomain.com` のオレンジ雲を有効にしていないか確認してください。このドメインは**必ずグレー雲 (DNS Only) のまま**にする必要があります。
   - クライアントに入力した SNI が Traefik Label の `HostSNI` と完全に一致しているか確認してください。
2. **WS ノードで 502 Bad Gateway が発生する**：
   - 3X-UI 管理画面で 44301 インバウンドの `Security` を誤って `tls` にしていないか確認してください。外側の Traefik で TLS 終端を行っているため、コンテナ側は `none` に設定する必要があります。
3. **パネルにログインできない**：
   - Traefik の ACME 証明書取得状況を確認し、`panel.yourdomain.com` の Let's Encrypt 証明書が正常に発行されているか確かめてください。
