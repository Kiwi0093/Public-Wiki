GitHub Pages で Docusaurus ベースの Wiki / Blog をホストする場合、デフォルトではプロジェクトサイトがリポジトリ名を冠したサブパス（例：`https://kiwi0093.github.io/Public-Wiki/`）として公開されます。

サイトを独立したサブドメイン（例：`https://blog.kiwireich.com/`）のルートサイトとしてアクセスできるようにしたい場合、**その GitHub Pages プロジェクトに直接カスタムドメイン（Custom Domain）を紐づけるのが最もシンプルな方法**です。この方法なら GitHub リポジトリ名を変更する（`kiwi0093.github.io` にリネームする）必要がなく、旧トップページにも影響を与えずに、プロジェクトをカスタムドメインのルートパス `/` に自動でマウントできます。

---

## 1. 基本フローとアーキテクチャの変化

* **移行前**：`https://kiwi0093.github.io/Public-Wiki/`（プロジェクト型サイト。アセットやルーティングがすべて `/Public-Wiki/` プレフィックスに依存）。
* **移行後**：`https://blog.kiwireich.com/`（独立ドメインサイト。アセットやルーティングがルートディレクトリ `/` へ回帰）。
* **運用上のメリット**：
  * 元のリポジトリ名 `Public-Wiki`（または `Public_wiki`）はそのまま維持される。
  * 既存の `kiwi0093.github.io` リポジトリに影響を与えず、`/old/` へ退避させるような破壊的変更が不要。
  * ルートディレクトリのルーティングが自然に成立し、クロスプラットフォームでの静的アセット参照や階層パスのズレを解消できる。

---

## 2. 操作手順

### ステップ A：DNS の CNAME レコードを設定する

メインドメイン（`kiwireich.com`）を管理している DNS コントロールパネル（Cloudflare やホスティング先 DNS サービスなど）にログインし、サブドメインの CNAME 転送設定を追加します：

| レコードタイプ (Type) | ホスト名 (Name / Host) | ターゲットアドレス (Target / Value) | TTL | Proxy 状態 (Cloudflare 使用時) |
| :--- | :--- | :--- | :--- | :--- |
| **CNAME** | `blog` | `kiwi0093.github.io` | 自動 / Auto | **DNS のみ (DNS only / 灰色の雲)** |

> **ヒント**：Cloudflare で DNS を管理している場合、初回バインド時は Proxy をオフ（灰色の雲）にしておくことを推奨します。Cloudflare のエッジキャッシュや SSL 終端機構が、GitHub システムによる Let's Encrypt 証明書の自動発行を妨げるのを防ぐためです。

---

### ステップ B：Docusaurus 設定ファイル (`docusaurus.config.js`) を修正する

ドメインが変更され、パスもサブフォルダからルートパスへ変わるため、サイトのベース URL とベースパスをあわせて修正する必要があります：

Wiki プロジェクトのルートディレクトリにある `docusaurus.config.js`（または `docusaurus.config.ts`）を編集します：

```javascript
module.exports = {
  // サイトのメイン URL を指定したカスタムサブドメインに変更
  url: '[https://blog.kiwireich.com](https://blog.kiwireich.com)',

  // 【重要修正】：従来の '/Public-Wiki/' からルートディレクトリ '/' へ変更
  baseUrl: '/',

  // GitHub Pages デプロイ関連の設定 (現状維持で構いません)
  organizationName: 'kiwi0093',
  projectName: 'Public-Wiki',
  trailingSlash: false,

  // ... その他のテーマ、ナビゲーションバー、プラグイン設定はそのまま維持 ...
};
```

> [!info] Updated 2026-11-27
> 上記サンプル 3 行目の `url` フィールドが誤って Markdown リンク構文（`'[https://blog.kiwireich.com](https://blog.kiwireich.com)'`）になっていました。実際の設定では純粋な URL 文字列 `'https://blog.kiwireich.com'` を入力してください。そうしないと Docusaurus のビルド時に URL 形式の検証に失敗してエラーになります：
> ```javascript
> url: 'https://blog.kiwireich.com',
> ```

### ステップ C：静的な `CNAME` 宣言ファイルを作成する（CI/CD による上書き防止）

GitHub Pages にカスタムドメインを紐づけると、公開ブランチ（`gh-pages` など）のルートディレクトリに `CNAME` という名前のファイルが書き込まれます。プロジェクトを GitHub Actions などの自動化ツールでビルドしている場合、ビルドのたびに `./build` で公開ブランチが上書きされるため、Web 管理画面から手動で入力したドメイン設定が消えてしまいます。

そこで、`CNAME` を Docusaurus の静的アセットディレクトリ（`static/`）に含めておけば、ビルド処理で自動的に出力ルートディレクトリへコピーされます：

1. プロジェクトの `static/` フォルダ直下に `static/CNAME` ファイルを作成します（注意：拡張子なし）。
2. ファイル内容にはカスタムドメイン名だけを 1 行記述します：

```text
blog.kiwireich.com
```

### ステップ D：変更をプッシュして GitHub Actions をトリガーする

設定と静的ファイルをコミットし、GitHub へプッシュします：

```bash
git add docusaurus.config.js static/CNAME
git commit -m "feat: configure custom domain blog.kiwireich.com and set baseUrl to root"
git push origin main
```

プッシュ後、GitHub リポジトリの **Actions** タブを確認し、自動デプロイワークフローが正常に完了したことを確認します。

### ステップ E：GitHub リポジトリ設定画面での確認と HTTPS 強制有効化

1. GitHub 上の `Public-Wiki` リポジトリを開きます。
2. **Settings** ➔ 左側メニューの **Pages** をクリックします。
3. **Custom domain** 欄を確認します：
   - この時点で自動的に `blog.kiwireich.com` が入力されているはずです（未入力の場合は手動で入力して **Save** をクリックします）。
4. **DNS チェックと証明書の発行**：
   - システムが自動的に **DNS check** を実行します。チェックを通過すると、GitHub が該当ドメイン向けの TLS/SSL 証明書を申請・発行します（通常 5〜15 分程度かかります）。
5. 証明書の発行が完了したら **Enforce HTTPS** にチェックを入れ、すべての非暗号化 HTTP トラフィックが自動的に HTTPS へリダイレクトされるようにします。
