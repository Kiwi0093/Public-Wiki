# Hexo と GitHub Pages によるブログ構築アーキテクチャ紹介

> <img src='https://img.shields.io/badge/Status-Obsolete-red?style=for-the-badge&labelWidth=100' height='38' />

## 目的

[Hexo](https://hexo.io/zh-tw/) + [GitHub Pages](https://pages.github.com/) を利用して、個人用の Blog + Wiki 環境を構築します。

## 基本アーキテクチャ

![Construction](https://raw.githubusercontent.com/Kiwi0093/graph/master/img/Blog_wiki_construction.PNG)

### 解説

ここでは GitHub Pages の以下の特性を利用しています。

- `<Username>.github.io` というリポジトリの <span style="color:#e06c75"><del>master</del></span> *(Updated 2026-11-27: GitHub のデフォルトブランチは現在 `main` に変更されており、新しい GitHub Pages では任意のブランチの指定や GitHub Actions 経由での直接デプロイにも対応しています)* 内の `index.html` から `https://<Username>.github.io/` という有効な URL が生成されます。
- その他のリポジトリでは、GitHub Pages によって `gh-pages` ブランチ内の `index.html` から `https://<username>.github.io/<其他repo>/` という有効な URL が生成されます。

そのため、Blog 用の Web ページは `<username>.github.io` リポジトリのメインブランチへ生成してメインサイトとし、別のテーマを使いたい Web ページは別リポジトリの `gh-pages` ブランチへ生成してサブサイトとして運用することができます。

Hexo コマンドで特定の `_config.yml` を指定して 2 つを同居させる方法もありますが、原理的には上記の構成と同じであり、Hexo Wiki と Hexo Blog を同じディレクトリ内に置いて Git 同期管理を統合できるという違いがあるだけです。
