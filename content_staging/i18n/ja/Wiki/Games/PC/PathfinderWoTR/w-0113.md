# 『パスファインダー：ラース・オブ・ザ・ライチャス』セーブデータ中核構造解析（party.json）

> <img src='https://img.shields.io/badge/Status-Active-A8FF24?style=for-the-badge&labelWidth=100' height='38' />

> [!tip]
> 『ラース・オブ・ザ・ライチャス』では、`party.json` がセーブデータ全体の中核を成しており、パーティ内の全キャラクター（主人公、NPC 仲間、傭兵、各種コンパニオン）のあらゆるデータが記録されています。その基盤となる JSON 構造を理解することは、高度な編集（カスタム外見や複数ペットのバインドなど）を行うための基礎となります。

## 🏗️ 1. 基本セーブデータ構造 (Basic Structure)

`party.json` を開くと、ファイル全体が 1 つの巨大なオブジェクトでラップされているのが分かります。各キャラクターは `m_EntityData` 配列（Array）内の独立したブロックとして格納されています。

```json
{
    "SceneName": "<cross-scene>",
    "HasEntityData": false,
    "m_EntityData": [
        { キャラクター A の完全データ },
        { キャラクター B の完全データ },
        { キャラクター C の完全データ }
    ]
}
```

> 💡 **高速検索のコツ**：
> 
> 膨大なファイル内では、`"m_GroupId": "<directly-controllable-unit>"` を検索キーワードとして使用することをおすすめします。これにより、プレイヤーが直接操作可能な中核キャラクターのブロックを素早く特定できます。

## 🧩 2. キャラクターエンティティの分解 (UnitEntityData)

各キャラクターのブロックは `UnitEntityData` として宣言されています。以下は、そのブロック内で最も重要な 5 つの第 1 階層ノードです：

| **ノード名** | **内容説明** |
| --- | --- |
| **`UniqueId`** | **キャラクター固有の識別 ID**。キャラクターブロックの最下層（例：`"e51cd2f4-f8e6-..."`）に位置し、主従バインドを行う際に極めて重要です。 |
| **`Parts`** | **追加コンポーネント領域**。キャラクターの 3D モデル外見（Doll）、ペットの主従関係（Pet/Master）、バフ状態などを管理します。 |
| **`Facts`** | **能力領域**。キャラクターの特技（Feats）やアビリティ（Abilities）がすべてここに保存されます。 |
| **`Descriptor`** | **中核記述領域**。キャラクターの名前、性別、2D ポートレート、基本ステータス（Stats）、アライメントを定義します。 |
| **`Position`** | **座標**。現在のマップ上におけるキャラクターの X/Y/Z 絶対位置です。 |

## 🔗 3. 主従関係のバインド (Parts: Pet & Master)

システムにコンパニオン／ペットを認識させるには、`Parts` ブロック内で「双方向バインド」を行う必要があります。

### 主人側 (Master) の設定

主人には `UnitPartPetMaster` コンポーネントが必要です。複数のコンパニオンを追加したい場合は、`"m_Pets"` 配列にコンパニオンの UUID を順次追加します。

```json
{
    "$type": "Kingmaker.UnitLogic.Parts.UnitPartPetMaster, Assembly-CSharp",
    "m_Pets": [
        { "m_Ref": "コンパニオンAの-UUID" },
        { "m_Ref": "コンパニオンBの-UUID" },
        { "m_Ref": "コンパニオンCの-UUID" }
    ],
    "m_ExPets": []
}
```

### コンパニオン側 (Pet) の設定

コンパニオンには `UnitPartPet` コンポーネントが必要で、主人の UUID を逆参照するように指定します。

```json
{
    "$type": "Kingmaker.UnitLogic.Parts.UnitPartPet, Assembly-CSharp",
    "m_MasterRef": {
        "m_Ref": "主人の-UUID"
    },
    "Type": "MythicSkeletalChampion"
}
```

**WotR でサポートされている 3 大ペットタイプ (`Type`)：**

- `AnimalCompanion`（通常の動物の相棒）
- `MythicSkeletalChampion`（神話スケルトン・チャンピオン）
- `DragonAzataCompanion`（アザータ神話の道専用のドラゴン相棒）

## 👗 4. 外見とペーパードールシステム (Parts: Doll Data)

キャラクターの 3D モデル外見は `UnitPartDollData` コンポーネントによって制御されます。コンパニオンの外見（特にスケルトンのバリエーションなど）を置き換える場合は、通常ここを編集します。

| **パラメーター名** | **設定の影響と説明** |
| --- | --- |
| **`EquipmentEntityIds`** | **外見パーツ UUID 配列**。頭部、身体、髪型、ヒゲなど各部位のモデルコードを含みます。ゲーム全体のパーツ一覧表があれば、ここの文字列を直接書き換えて外見を変更できます。 |
| **`EntityRampIdices`** | **カラー定義**。Key（パーツ UUID）と Value（カラー番号コード）の対応によって、肌色・髪色・細部の色を決定します。 |
| **`Gender`** | **外見性別**。モデルが男性骨格と女性骨格のどちらを使用するか（`Male` / `Female`）を決定します。 |
| **`RacePreset`** | **種族プリセット**。基本体型や種族の特徴（エルフの耳、ドワーフの身長など）を決定します。 |
| **`ClothesPrimaryIndex`** / **`Secondary`** | **衣装のメイン／サブカラー**。ゲーム内のカラーパレットコード（整数値）に対応します。 |

## 👤 5. 中核属性の宣言 (Descriptor)

`Descriptor` はシステムがキャラクターの状態を識別する場所です。編集したいコンパニオンを探す際、最初に名前を確認するのがここです。

| **パラメーター名** | **設定の影響と説明** |
| --- | --- |
| **`CustomName`** | **表示名**。ゲーム内で表示される名前で、日本語や中国語などの入力にも対応しています（例：`"烏緹卡"`）。 |
| **`m_CustomPortraitId`** | **2D ポートレート ID**。ゲームフォルダ内のカスタムポートレート（Custom Portrait）名に対応します。 |
| **`CustomGender`** | **システム性別**。ゲーム内テキストの代名詞（He/She）や一部の装備制限に影響します。前述の 3D 外見性別とは直接連動していないため、個別に設定できます。 |
| **`Alignment`** / **`Faction`** | アライメントおよび勢力（ファクション）の判定です。 |

## ⚠️ 6. JSON 編集のミス防止ルール (Modding Rules)

セーブデータの手動編集は構文エラーによるロード時クラッシュを起こしやすいため、以下の鉄則を必ず守ってください：

### ID と参照について (`$id` & `$ref`)

- **`$id`（識別番号の発行）**：Owlcat エンジンは独立した各 JSON ノードに `$id`（例：`"$id": "2457"`）を割り当てます。この数値は**ファイル内の他の `$id` と絶対に重複してはなりません**。他からブロックをコピーしてきた場合は、重複しない任意の数値（例：`"992457"`）に適宜変更してください。連番にする必要はありません。
- **`$ref`（識別番号の呼び出し）**：すでに宣言されたノードをシステムが参照する際は、`"$ref": "2471"` を使用します。前方の `$id` を書き換えた場合は、それを参照している `$ref` がないかあわせて確認してください。

### 記号の致命的なミス

1. **クォーテーションは必須**：すべての文字列とキー名はダブルクォーテーション `""` で囲む必要があります。
2. **末尾のカンマ**：同階層の要素間はカンマ `,` で区切る必要がありますが、**配列またはオブジェクトの「最後の要素」の後ろには絶対にカンマを付けてはいけません**。
3. **括弧のペアリング**：波括弧 `{}` はオブジェクト（Object）、角括弧 `[]` は配列（Array）の定義に使います。1 つでも欠けるとパースに失敗します。Notepad++ の JSTool などを利用してフォーマットチェックを行うことを強く推奨します。
