## 基本的な手順

新規作成したキャラクターから直接すべての従者を生成する方法はまだ検証していないため、第 1 版では自動生成される最初の 1 体目（`MythicSkeletonCompanion`）を除き、残りの 3 体は傭兵をベースに改造する方がシンプルでおすすめです。

推奨される操作手順は以下の通りです：

1. ToyBox を使用して `MythicSkeletonCompanion` の Feat を追加する（いずれのクラス分岐でも可）。
2. ゲーム内で好みの外見とポートレートを持つ従者用キャラクターを新規作成する。
3. セーブデータの JSON を編集し、作成した好みのキャラクターの外見ブロック（Section）とポートレートを対応する従者データ内に貼り付ける。
4. ゲーム内で追加の傭兵を 3 人雇用する。
5. 残りの 3 つの `MythicSkeletonCompanion` Feat を追加する。
6. ~~Save ファイルを編集して対応する傭兵の UniqueId を Feat に紐付ける~~、`m_pet` を設定し、さらに Master の定義にこれら 3 体の `UniqueId` を追加する。

   `*` 最新の確認では、Master と Pet の関係のみを定義すれば十分であることが分かっています。

### 傭兵を他の 3 体の MythicSkeletonCompanion に変換する方法

#### Feat データ形式（編集不要になりました）

```json

                        "$id": "109",
                        "$type": "Kingmaker.UnitLogic.Feature, Assembly-CSharp",
                        "m_Context": {
                            "AssociatedBlueprint": "048456cce79943f4c9c9eec1aa5ce9a0",
                            "m_OwnerRef": "e51cd2f4-f8e6-4956-93a7-86281cd5e92a",
                            "m_Params": null
                        },
                        "Blueprint": "048456cce79943f4c9c9eec1aa5ce9a0",
                        "UniqueId": "e731dd8b-31cc-4114-9dd5-650a8672ddf0",
                        "AttachTime": "12:00:47.3910000",
                        "IsActive": true,
                        "Components": {
                            "$AddPet$858ef2c0-f8cf-41f4-af45-0bb06f90fa00": {
                                "$type": "Kingmaker.EntitySystem.EntityFactComponentDelegate`2+ComponentRuntime[[Kingmaker.EntitySystem.Entities.UnitEntityData, Assembly-CSharp, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null],[Kingmaker.UnitLogic.FactLogic.AddPetData, Assembly-CSharp, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null]], Assembly-CSharp, Version=0.0.0.0, Culture=neutral, PublicKeyToken=null",
                                "m_Data": {
                                    "$id": "110",
                                    "SpawnedPetRef": "b27cd89c-a8b0-4a1c-a5f0-379c5e5fd9c3",
                                    "Disabled": false
                                }
                            }
                        }
                    },
```

基本的にはその Feat を追加していれば、セーブデータ内で対応する UUID を検索するだけで該当の Section を見つけることができます（上記のような構造のブロックは 1 つしか存在しません）。

以前の方法では、傭兵（または対象キャラクター）の UUID を `"SpawnedPetRef"` フィールドに貼り付けていました（2 つ目以降に追加した Feat ではこの値が `null` になります）。

#### Part 関係設定

##### 従者にする側の Part Section

```json
#在m_part內加上
{
      "$id": "2459",
      "$type": "Kingmaker.UnitLogic.Parts.UnitPartPet, Assembly-CSharp",
      "m_MasterRef": {
              "m_Ref": "e51cd2f4-f8e6-4956-93a7-86281cd5e92a"						
                     },
      "Type": "MythicSkeletalChampion"										
},
```

`m_MasterRef` 配下の `m_Ref` には、主人（Feat の所有者）の UUID が正しく入力されているか確認してください。

##### 主人側の Part Section

```json
#在m_part內加上
{
        "$id": "10",
        "$type": "Kingmaker.UnitLogic.Parts.UnitPartPetMaster, Assembly-CSharp",
        "m_Pets": [
                     {
               "m_Ref": "b27cd89c-a8b0-4a1c-a5f0-379c5e5fd9c3"					
                     },
                     {
               "m_Ref": "46694232-fba8-4a18-8daa-1a1c933290e2"
                     },
                     {
               "m_Ref": "14547546-c716-4e63-9a5c-d8126e9c01f6"
                     },
                     {
               "m_Ref": "2577f7e3-a782-439d-90df-eaa70a440af4"
                     }
                  ],
          "m_ExPets": []
}
```

上記の例に従って `m_Pets` 配列に各従者の `m_Ref` 定義を追加することで、複数の従者を主人キャラクターに正しく紐付けることができます。
