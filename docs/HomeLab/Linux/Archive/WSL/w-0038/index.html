ArchWSL 與 WSLg 早期環境設定與常見問題封存筆記

提示

現在 WSLg 基本上已經內建在 WSL 安裝內，所以不再需要弄個 GWSL 來進行設定。 順便記錄一下 ArchWSL 的一些設定以免忘記。

Updated 2026-11-27

本篇為早期第三方 yuk7/ArchWSL 封存筆記；目前 Microsoft 與 Arch Linux 已提供官方 WSL 映像（可使用 wsl --install archlinux 安裝）。

Basic Setting​

基本上沒打算用 GUI 的同學只需要弄這塊就好了：

Archlinux-keyring​

# 初始化keyring
sudo pacman-key --init
# Poplutae keyring
sudo pacman-key --populate
# 套用及更新 (若需要調整mirrorlist，可以先修改/etc/pacman.d/mirrorlist)
sudo pacman -Syu

這一步驟是 ArchWSL 必備的，不然沒有正確的 keyring 什麼都沒辦法裝。

/etc/wsl.conf​

# 使用systemd
[boot]
systemd=true
# 設定預設的使用者
[users]
default=<username>
Updated 2026-11-27

上方設定檔中的 [users] 為錯誤區段名稱，會被 WSL 忽略；正確寫法須為單數 [user]：

[user]
default=<username>

yay​

# 需要先安裝上go, git, base-devel
cd <what ever you like>
git clone https://aur.archlinux.org/yay.git
cd yay
makepkg -si

yay 為目前安裝 AUR 最方便的工具，所以強烈建議裝上。

GUI (WSLg)​

X server​

參考資料：

  • Bug of WSL Preview - Empty /mnt/wslg/.X11-unix & /tmp/.X11-unix Directory
# 檢查Display為:0
echo $DISPLAY
:0

# 檢查/mnt/wslg/.X11-unix存在，以及是否為 /tmp/.X11-unix -> /mnt/wslg/.X11-unix
ls -la /mnt/wslg
ls -la /tmp

#若/mnt/wslg/.X11-unix存在但沒有link到/tmp/.X11-unix
sudo rm -r /tmp/.X11-unix
ln -s /mnt/wslg/.X11-unix /tmp/.X11-unix

然後測試你的 GUI 軟體是否可以正確地執行，若可以執行就下一步；若不行...請翻文件...

/etc/tmpfiles.d/wslg.conf
---

# TYPE    PATH        Mode    UID    GID Age    Argument
L+    /tmp/.X11-unix    -        -    -    -    /mnt/wslg/.X11unix
Updated 2026-11-27
  1. 手動建立軟連結時應加上 sudo（sudo ln -s /mnt/wslg/.X11-unix /tmp/.X11-unix）。
  2. 上方 wslg.conf 最後一欄的目標路徑少了一個點，正確應為 /mnt/wslg/.X11-unix（而非 .X11unix）；且檔案內容不應包含開頭的檔名與 ---。
  3. 新版 WSL / WSLg 已修正此 systemd 啟動清理 /tmp/.X11-unix 的問題，通常不需再手動建立此設定檔。

在 PowerShell 執行 wsl --shutdown 然後重新進入 WSL 就可以了。

dolphin + breeze (Optional)​

Dolphin 是 KDE 的檔案管理器（類似 Windows 的檔案總管 Explorer），只裝 Dolphin 會有缺圖示的問題發生，所以要裝上 KDE 的主題 breeze 才會正常：

yay -S breeze dolphin

Remmina + freerdp (Optional)​

這是個很好用的 RDP client，不過 Remmina 只是個前端介面，要裝上 freerdp 才能 RDP 到其他 RDP server：

yay -S remmina freerdp

Brave (Optional)​

總要有瀏覽器...不然 GUI 要幹嘛：

yay -S brave-bin

Fcitx (Optional)​

基本上因為我們不會在WSL內安裝完整的桌面環境所以在挑選Fcitx的時候只能用Fcitx4的版本所以不要假會去裝Fcitx5... (Updated 2026-11-27: Fcitx 4 已停止維護並從多數發行版套件庫移除，現行 WSLg 環境已可正常使用 Fcitx 5。) 詳細的內容我放在其他的wiki內，請參考 (Updated 2026-11-27: 中/日文輸入法設定)
