VMware Photon OS 安裝與系統設定

提示

由於打算把所有的網路服務逐步改為 Docker 容器化部署，因此決定將底層系統換成 VMware 針對容器特化的輕量級 Linux 發行版——Photon OS。

Installation​

下載 ISO 映像檔後，在 VMware Workstation 或 VMware ESXi 上建立新的虛擬機（作業系統類型選擇 VMware Photon OS 64-bit 或最新的 Linux Kernel 64-bit 皆可），以光碟開機並依畫面精靈完成安裝即可。

Photon OS 本身所需的記憶體與硬碟空間極小，但主要資源會消耗在後續執行的 Docker 容器上，因此建立虛擬機時請依預計部署的服務數量合理規劃 RAM 與硬碟容量。

Basic Setup​

確認基本服務

確認基礎系統服務（例如 open-vm-tools）是否正常運作：

systemctl status vmtoolsd.service

帳號設定

安裝過程中即會設定 root 密碼；為了日常操作安全性，可再透過 useradd 建立一般使用者帳號：

# 增加使用者 (-m 建立家目錄, -g 指定 root 群組)
useradd -m -g root $(your_id)

# 替你的帳號設定密碼
passwd $(your_id)
Updated 2026-11-27

上述範例中的 $(your_id) 在 Bash 中會被解析為指令替換（Command Substitution），實際執行時請直接代換為目標使用者名稱（例如 useradd -m -G wheel <your_id>）。此外，實務上建議透過 -G wheel 或 sudo 賦予提權能力，避免將一般使用者的主群組直接設為 root。

由於系統管理仍常需要 root 權限，可依個人習慣決定要建立一般帳號並搭配 su / sudo 使用，或是修改 /etc/ssh/sshd_config 以允許 root 透過 SSH 登入。

網路設定 (systemd-networkd)​

安裝完成後的系統預設為啟用 DHCP。若僅需單一 IP 且區域網路內已有 DHCP Server 搭配 MAC Address 保留位址控管，則可維持預設；若有固定 IP 等進階需求，請修改下列設定檔。

關閉 DHCP

編輯 /etc/systemd/network/99-dhcp-en.network：

[Match]
Name=e*

[Network]
DHCP=no    # 改為 no 以關閉 DHCP
IPv6AcceptRA=no

固定 IP 設定方法

編輯 /etc/systemd/network/10-static-en.network：

[Match]
Name=ens160                                # 網卡名稱

[Network]
Address=10.1.10.9/24                       # IP 位址，可重複多行定義多個 IP
Gateway=10.1.10.1                          # Gateway IP
DNS=10.1.10.1                              # DNS IP
# NTP 設定，以空白隔開多組 Server
NTP=tock.stdtime.gov.tw watch.stdtime.gov.tw time.stdtime.gov.tw
# 關閉 IPv6
LinkLocalAddressing=no
IPv6AcceptRA=no

設定網路介面名稱

編輯 /etc/systemd/network/10-ethusb0.link：

[Match]
MACAddress=00:00:00:00:00:00               # 網卡 MAC 位址

[Link]
Description=USB to Ethernet Adapter        # 網路卡說明
Name=ethusb0                               # 介面名稱

若有多張網卡，只需分別建立對應的 .link 與 .network 檔案並指定各自的 MAC 位址與介面名稱即可。

系統更新與安裝套件​

修正筆記： Photon OS 底層預設的套件管理工具其實是 tdnf。雖然執行 yum 時系統也有做 alias 可以相通，但建議養成習慣直接使用 tdnf。

tdnf update -y          # 升級系統套件
tdnf install -y vim     # 安裝 vim
tdnf search python      # 搜尋名稱包含 python 的套件

掛載 SMB 分享資料夾​

實務上通常會先將 Docker 的 Volume 資料夾掛載至 NAS 上的備份／共享目錄，這樣做有以下好處：

  1. 便於集中備份資料。
  2. 減少 Photon OS 虛擬機本身的硬碟空間佔用。
  3. 讓需要讀取 NAS 檔案的 Docker 服務能直接存取（例如個人音樂檔案皆存放於 NAS，透過 SMB/CIFS 掛載十分方便）。

先在 Photon OS 上使用 tdnf 安裝 cifs-utils：

tdnf install -y cifs-utils

接著建立憑證檔 /root/secret：

username=sushi    # SMB 帳號
password=yummy    # SMB 密碼

建議將 /root/secret 權限調整為 0400 以確保安全性（chmod 0400 /root/secret）。

再將掛載設定加入 /etc/fstab：

\\winbox\getme /mnt/win cifs user,uid=500,rw,noauto,suid,credentials=/root/secret 0 0
Updated 2026-11-27

在 Linux /etc/fstab 中撰寫 CIFS 共享路徑時應使用正斜線 //winbox/getme（反斜線 \\ 在 fstab 中會被視為跳脫字元導致解析異常），且現代 NAS 通常需依環境加上 vers=3.0 等 SMB 版本參數。此外，除了下方的獨立 systemd service 做法外，現代亦可直接在 /etc/fstab 掛載選項加入 _netdev,x-systemd.automount 來確保網路就緒後自動掛載。

使用 systemd 開機自動掛載

先前曾嘗試過 autofs（在 Photon OS 上實測無效），也試過直接在 /etc/fstab 使用 auto 掛載，但開機時掛載時機早於網路連線就緒而經常失敗。因此最穩定的做法是建立 systemd service，明確指定於網路連通後再執行掛載。

編輯 /etc/systemd/system/mount-nas.service：

[Unit]
Description=mount CIFS
# 確保網路真正連線後再執行
After=network-online.target
Wants=network-online.target

[Service]
Type=oneshot
ExecStart=/bin/mount -a
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target

關鍵在於設定 After=network-online.target，確保系統完成連網後才執行掛載。設定完成後重新載入並啟用服務：

systemctl daemon-reload
systemctl enable --now mount-nas.service

延伸技巧：磁碟擴容​

實際運行一段時間後，即使再節省空間，當初配置給虛擬機的硬碟容量仍很有可能不敷使用（個人已經遇過兩三次）。過去使用 Windows VM 時通常會再新增一顆虛擬硬碟並掛載為新磁碟機代號；但在 Photon OS 環境下，多數情況下會希望直接擴展原本的 /dev/sda。

1. 在 ESXi 調整虛擬硬碟容量

直接至 ESXi 後台編輯虛擬機設定並調大硬碟容量即可。

2. 進入系統重新掃描並擴展分割區

若系統尚未安裝 parted，先執行安裝：

tdnf -y install parted

接著重新掃描磁碟變更並開啟 parted：

# 重新掃描區塊裝置，讓系統偵測到 ESXi 新增的空間
echo 1 > /sys/class/block/sda/device/rescan

# 進入 parted 互動介面
parted /dev/sda

進入 parted 後依序執行：

# 列出分割區；若系統提示尚未套用全部磁碟空間並詢問是否修正，請輸入 f（或 fix）
(parted) print

# 確認主要使用的分割區編號（通常為 1 或 3），再使用 resizepart 分配全部空間 (100%)
(parted) resizepart 1 100%

# 完成後離開 parted
(parted) quit

3. 擴展檔案系統（File System）

修正筆記： resize2fs 後方應接「分割區」裝置名稱（例如 /dev/sda1），而非整顆硬碟（/dev/sda）。

使用 resize2fs 擴展該分割區的檔案系統（假設方才擴容的是第 1 個分割區）：

resize2fs /dev/sda1

完成後可使用 df -H 確認容量是否已成功擴展！
