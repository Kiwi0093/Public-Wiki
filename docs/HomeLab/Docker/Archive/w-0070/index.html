使用 Docker 部署 phpBB 網路論壇（已封存）

提示

論壇還是用 phpBB via Docker，簡單、省事、方便。

作法​

docker-compose.yml 內容​

version: '2'
services:
  mariadb:
    image: docker.io/bitnami/mariadb:10.3
    environment:
      - ALLOW_EMPTY_PASSWORD=yes
      - MARIADB_USER=bn_phpbb
      - MARIADB_DATABASE=bitnami_phpbb
    volumes:
      - /var/lib/docker/volumes/phpbb/mariadb:/bitnami/mariadb
  phpbb:
    image: docker.io/bitnami/phpbb:3
    ports:
      - 192.168.131.2:8082:8080
    environment:
      - PHPBB_DATABASE_HOST=mariadb
      - PHPBB_DATABASE_PORT_NUMBER=3306
      - PHPBB_DATABASE_USER=bn_phpbb
      - PHPBB_DATABASE_NAME=bitnami_phpbb
      - ALLOW_EMPTY_PASSWORD=yes
    volumes:
      - /var/lib/docker/volumes/phpbb/phpbb:/bitnami/phpbb
    depends_on:
      - mariadb
Updated 2026-11-27

上述歷史配置存在幾項過時或不建議的寫法，僅保留作為封存參考：

  1. 頂層 version: '2' 屬性在現代 Docker Compose v2（docker compose）中已棄用，應省略 version 直接從 services: 開始。
  2. bitnami/mariadb:10.3 已達 EOL 停止維護，且 Bitnami 免費舊版映像檔後續已遷移至 bitnamilegacy 並調整維護策略；實務上應改用官方 mariadb:11 或其他長期維護映像檔，且切勿設定 ALLOW_EMPTY_PASSWORD=yes。
  3. 不建議將 bind mount 直接指向 /var/lib/docker/volumes/...（該路徑為 Docker Engine 內部管理的 Named Volumes 目錄），應改掛載至 /opt/phpbb/... 等獨立宿主機路徑。

老實說當時已經跑了另一個 MariaDB，理論上可以整合在一起，但為了省事就直接另外多跑一個 MariaDB 容器；若採這種做法，記得容器名稱與連接埠不要重複。

不過這份 Compose 檔預設沒有將資料庫連接埠對外映射，因此即使獨立執行也能維持資料庫的網路隔離安全性。

注意事項​

個人對 Bitnami 映像檔的權限習慣並不是很喜歡：容器啟動後，通常必須調整 /var/lib/docker/volumes/phpbb 目錄的權限。

因為該映像檔預設以 UID=1001 執行，不是使用 chown 1001，就是直接用 chmod 777 (Updated 2026-11-27: 實務上切勿使用 chmod 777，會造成嚴重安全風險；應改以 chown -R 1001:1001 精準賦予容器 UID 權限)，否則服務會因沒有寫入權限而無法正常啟動。

廢棄原因​

  • 實際上沒有在使用，主要是現在即時通訊軟體（IM）太發達，親友之間的日常溝通幾乎不會特地架設傳統論壇。
