SSH 金鑰認證與連線設定基礎

提示

現在要求使用 Key Pair 驗證的 SSH 環境越來越多，無論是 Git、Ansible 或 Oracle Cloud 的 VM 都要求透過金鑰連線，因此將相關常用指令與設定整理於此。

參考資料​

  • GTW - SSH 公開金鑰認證：不用打密碼登入 Linux 設定教學，安全又方便
  • MIS腳印 - Windows 使用 SSH 金鑰免密碼登入 Linux
    • Windows 工具：PuTTY、PuTTYgen

產生 Key Pair​

Linux / FreeBSD 終端機產生金鑰​

基本指令是使用 ssh-keygen，搭配常用參數可自訂金鑰長度、演算法與輸出檔名：

# Basic from man ssh-keygen
ssh-keygen [-q] [-a rounds] [-b bits] [-C comment] [-f output_keyfile] [-m format] [-N new_passphrase] [-O option] [-t dsa | ecdsa | ecdsa-sk | ed25519 | ed25519-sk | rsa] [-w provider] [-Z cipher]
     ssh-keygen -p [-a rounds] [-f keyfile] [-m format] [-N new_passphrase] [-P old_passphrase] [-Z cipher]
     ssh-keygen -i [-f input_keyfile] [-m key_format]
     ssh-keygen -e [-f input_keyfile] [-m key_format]
     ssh-keygen -y [-f input_keyfile]
     ssh-keygen -c [-a rounds] [-C comment] [-f keyfile] [-P passphrase]
     ssh-keygen -l [-v] [-E fingerprint_hash] [-f input_keyfile]
     ssh-keygen -B [-f input_keyfile]
     ssh-keygen -D pkcs11
     ssh-keygen -F hostname [-lv] [-f known_hosts_file]
     ssh-keygen -H [-f known_hosts_file]
     ssh-keygen -K [-a rounds] [-w provider]
     ssh-keygen -R hostname [-f known_hosts_file]
     ssh-keygen -r hostname [-g] [-f input_keyfile]
     ssh-keygen -M generate [-O option] output_file
     ssh-keygen -M screen [-f input_file] [-O option] output_file
     ssh-keygen -I certificate_identity -s ca_key [-hU] [-D pkcs11_provider] [-n principals] [-O option] [-V validity_interval] [-z serial_number] file ...
     ssh-keygen -L [-f input_keyfile]
     ssh-keygen -A [-a rounds] [-f prefix_path]
     ssh-keygen -k -f krl_file [-u] [-s ca_public] [-z version_number] file ...
     ssh-keygen -Q [-l] -f krl_file file ...
     ssh-keygen -Y find-principals [-O option] -s signature_file -f allowed_signers_file
     ssh-keygen -Y check-novalidate [-O option] -n namespace -s signature_file
     ssh-keygen -Y sign -f key_file -n namespace file ...
     ssh-keygen -Y verify [-O option] -f allowed_signers_file -I signer_identity -n namespace -s signature_file [-r revocation_file]

# 基本上會用的function大概就是幾個而已
-b 定義編碼長度, rsa預設是3072,其實很夠用了
-t 編碼方式, 有dsa | ecdsa | ecdsa-sk | ed25519 | ed25519-sk | rsa可以挑,一般教學都是推薦用rsa
-C 這個Comment可以定義對應的Email address
-f 可以定義out put的key pair名稱

一般常見的建立方式如下：

ssh-keygen -b 4096 -t rsa -f <server_or_service_name>

執行後會在 ~/.ssh/ 內產生 <server_or_service_name>（私鑰）與 <server_or_service_name>.pub（公鑰）兩個檔案。

Updated 2026-11-27
  1. dsa（-t dsa）自 OpenSSH 9.8 起預設停用，並已於 OpenSSH 10.0（2025）正式移除支援，請勿再使用。
  2. 現代實務普遍推薦改用 ed25519（例如 ssh-keygen -t ed25519 -f <server_or_service_name>），金鑰更短、安全性高且運算更快；僅在必須相容極舊版 OpenSSH 伺服器時才退回使用 4096 位元的 rsa。

Windows（使用 PuTTYgen）​

流程基本相同：在右下角設定好位元數與金鑰類型後，點擊 Generate 即可產生 Private Key 與 Public Key。

Linux 環境轉換 PPK 為 PEM​

若在 Linux 桌面環境（如 Manjaro）需要直接連線，Manjaro 安裝 putty 後即會一併包含 puttygen；若使用 Ubuntu / Debian，還需額外安裝工具套件：

# 安裝 PuTTY 工具
apt install putty-tools

安裝完成後即可將 .ppk 轉為 OpenSSH 使用的 .pem 格式：

# 把 .ppk 檔轉成 .pem 檔供 ssh client 直接使用
puttygen yourkey.ppk -O private-openssh -o yourkey.pem

轉好後即可使用下列指令登入（請確保私鑰權限為 600）：

# 使用 pem 登入
ssh -i /your/key/file user@hostname.or.ip

Public Key @ Server side​

將公鑰部署到遠端伺服器有兩種常見做法：

Simple Copy & Paste​

直接將公鑰內容貼到目標帳號的 ~/.ssh/authorized_keys，可使用 vi 編輯或透過指令附加：

cat <server_or_service_name>.pub >> ~/.ssh/authorized_keys

不過實務上常懶得先手動上傳 <server_or_service_name>.pub 到目標主機，因此較少採用這種方式。

PuTTYgen 金鑰轉換（PEM 轉 PPK）​

由於傳統 PuTTY 無法直接讀取一般的 .pem 私鑰檔，若要從 Windows 透過 PuTTY 連線到 sshd，可匯入轉存為 .ppk 格式：

讀取私鑰後，可設定保護密碼（Passphrase）：

輸入自訂密碼後選擇 Save private key 存成 .ppk 檔即可。

ssh-copy-id​

ssh-copy-id -i ~/.ssh/<server_or_service_name>.pub USER@HOST

ssh-copy-id 預設會讀取 ~/.ssh/id_rsa.pub，因此使用自訂檔名時須透過 -i 指定公鑰路徑。上傳完成並確認可免密碼登入後，即可到伺服器端修改 sshd_config 關閉密碼登入。

伺服器端設定（sshd_config）​

除了 Client 端的金鑰準備，Server 端的 /etc/ssh/sshd_config 通常也需一併強化安全設定：

# 禁止Root帳號透過ssh登入
PermitRootLogin no
# 基本上都會建議設定要拒絕root的遠端登入,但是碰上使用ansible的時候就會覺得除了root帳號直接拿來用以外的方法都很麻煩...所以這裡要慎選

# 接受Public Key認證方式
PubkeyAuthentication yes

# 預設的Public Key位置檔名
AuthorizedKeysFile      .ssh/authorized_keys
# 這個其實是可以修改的,不過我都不會去改他

# 不使用Build-in的密碼認證系統也禁止空白密碼
PasswordAuthentication no
PermitEmptyPasswords no

# 禁止使用密碼認證登入
ChallengeResponseAuthentication no
UsePAM no

# 特定User的設定(這個整段只能放在sshd_config的最後面
Match <User1>, <User2>, ...
# 然後定義這些User的設定, 例如
    PasswordAuthentication yes
# 這樣就只有User1跟User2可以用密碼登入其他都不行
Updated 2026-11-27
  1. ChallengeResponseAuthentication 自 OpenSSH 8.7 起已棄用，新版應改為 KbdInteractiveAuthentication no。
  2. Match 區塊必須指定條件關鍵字且逗號分隔清單不可含空白，正確寫法為 Match User user1,user2（原範例 Match <User1>, <User2> 缺少 User 關鍵字且含空白，會導致 sshd 設定語法錯誤）。
  3. 在現代 Linux（如搭配 systemd）環境下，建議維持 UsePAM yes 以確保帳號會話與資源限制正常運作，僅關閉 PasswordAuthentication no 與 KbdInteractiveAuthentication no 即可停用密碼登入。

客戶端連線指令（SSH）​

基本連線指令如下：

ssh USER@HOST

若要指定特定私鑰檔案，則加上 -i 參數：

ssh -i /location/private_key USER@HOST

因為 SSH 認證是以私鑰為憑據，只要在常用的客戶端主機上妥善存放同一把私鑰並設定正確權限，即可順利進行連線。
