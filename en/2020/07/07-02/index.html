Escaping the GFW - V2Ray Server Setup Summary

July 7, 2020 · 15 min read
info

info

This article was reposted from the old site archive.

V2Ray—this is arguably the main reason I started writing this blog, because it is a specialized skill only needed when living inside the Great Firewall. Generally, technical documentation is in English, yet ironically, documentation related to bypassing internet censorship is almost exclusively in Simplified Chinese...

Because this area of knowledge is quite niche, I felt inspired to record the methods and results I researched so I wouldn't have to look everything up from scratch every time—and, if possible, automate these steps to reduce the effort required.

Originally, the article under this title was meant to consolidate everything up to the "update IV" version of VPS V2Ray Server setup and configuration. However, thinking about it carefully, I hadn't really covered the finer configuration details (since the V2Ray official website explains them very clearly, and once I have a working config I rarely rewrite it from scratch and mostly just reuse it). So I'll include a bit about the configuration here as well, though the official website's documentation is still better.

Prerequisites

VPS​

Even though many people rent VPS instances for general purposes, specializing one solely for bypassing the firewall is probably something only netizens behind the GFW do, so you can find plenty of reviews online. Personally, since I've always thought online freedom should be a given, I tend to be stingy when choosing a VPS—picking the cheapest, barely-usable option. In practice, I just pick the lowest price available; machine performance doesn't matter (though KVM does)...

  • Anynode - This is my main machine. I'm on the $20 USD/year plan with 500 GB of monthly traffic, which is more than enough as a primary VPS for personal use.
  • Hostenos - A cheap and generous option at $21 USD for two years, with unlimited traffic and only a 100M speed cap. Very suitable if you want to generously share with others or burn through bandwidth without worrying about traffic limits (though 500 GB for one person is practically unlimited anyway...).
  • Bandwagonhost - BandwagonHost is actually a very convenient choice. Their early VPS offerings already came with a one-click ShadowSocks installation service, and recently they also launched Just my socks. Though a bit off-topic, anyone who doesn't want to set things up themselves can consider this option to save hassle.

Linux Distro for VPS​

Since we're picking cheap VPS hosts, it's naturally unrealistic to run anything with a GUI or Windows—we can only run a pure CLI OS. Among them, the easiest to get started with is probably FreeBSDLinux. Everyone has their own preferences, so just pick one whose commands you're comfortable with from what your VPS provider offers. Because of my own preferences, I mostly choose distros that use the apt package manager, such as Ubuntu or Debian. However, after being converted by Arch, I've become especially fond of rolling-release systems (even though for server stability it really should be the other way around). So here I'll use Debian as the baseline. For those using a different distro... please mentally translate the commands yourselves.

Domain (Optional)​

You'll need this if you plan to use WebSocket+TLS+Web for obfuscation. Strictly speaking, you also need to apply for an SSL certificate, but Caddy can handle the SSL part for you, making it very simple. You just need to prepare a domain—either a free one or a purchased one will do.

Cloudflare Account (Optional)​

You only need this if you plan to add another layer of obfuscation on top of WebSocket+TLS+Web, betting that the firewall won't block all routes to your VPS web port. The principle is using CDN forwarding to bypass blocks and keep the connection alive, mainly betting that a company as large as Cloudflare won't have all its IPs blocked. Of course, if you don't like Cloudflare, you can use another CDN, though Cloudflare's free tier is quite tempting.

Finally, the more obfuscation layers you add, the slower the connection speed becomes—there's no way around that. You'll need to balance speed and reliability according to your own needs.

Planned Tools​

  • Browser - Needed to perform initial VPS setup via the web control panel.
  • PuTTY or Linux Terminal - Simply put, an SSH client you're comfortable with.
  • vi, vim, or any editor you like - There will be a lot of file editing, and since we almost never download files to edit in a GUI environment, it's best to use a CLI text editor. I personally prefer the vi family...

References​

Installation

Basic System Installation​

  1. In your browser's VPS management panel, select your preferred Linux distro and install the OS. I chose Debian.

  2. Once installed, configure your SSH (via web terminal or whatever method is available).

  3. Log into your VPS using your preferred SSH client.

  4. Change your password for future login management:

passwd
  1. Update the system:
#Debain or Ubuntu
sudo apt update && apt upgrade

#Archlinux
sudo pacman -Syu

  1. Install the required programs - Vim, V2Ray, Caddy:

    #Debain or Ubuntu
    sudo apt install vim
    bash <(curl -L -s https://install.direct/go.sh)
    echo "deb [trusted=yes] https://apt.fury.io/caddy/ /" | sudo tee -a /etc/apt/sources.list.d/caddy-fury.list
    sudo apt update
    sudo apt install caddy

    #Archlinux
    sudo pacman -Sy yay
    yay -Sy vim v2ray caddy2

When I wrote the original blog post, Caddy hadn't officially transitioned to Caddy2 yet, but since the Caddy official site announced that Caddy V1 is now under limited support, updating to V2 was only a matter of time.

Arch definitely looks cleaner and neater (pure personal bias).

Auto-Install Script - Apt-based (Debian/Ubuntu)​

#!bash

#變數定義
COLOR='\033[1;35m'
NC='\033[0m'

echo -e "${COLOR}Update Ubuntu System${NC}"
apt-get -y update
apt-get -y upgrade

echo -e "${COLOR}Install V2ray${NC}"
bash <(curl -L -s https://install.direct/go.sh)

echo -e "${COLOR}Set Auto Monthy Update V2ray${NC}"
echo '59 3    1 * *   root    bash <(curl -L -s https://install.direct/go.sh)'  >> /etc/crontab

echo -e "${COLOR}Install BBR${NC}"
bash <(curl -L -s https://github.com/teddysun/across/raw/master/bbr.sh)

echo -e "${COLOR}Install Caddy${NC}"
wget "https://github.com/caddyserver/caddy/releases/download/v2.1.1/caddy_2.1.1_linux_amd64.deb"
dpkg -i ./caddy_2.1.1_linux_amd64.deb"

echo -e "${COLOR}Setup  Caddy${NC}"
mkdir /etc/caddy
chown -R root:www-data /etc/caddy
mkdir /etc/ssl/caddy
chown -R www-data:root /etc/ssl/caddy
chmod 0770 /etc/ssl/caddy
mkdir /var/www
chown www-data:www-data /var/www
ufw allow http
ufw allow https
apt install libcap2-bin
setcap cap_net_bind_service=+ep /usr/local/bin/caddy
echo '<h1>Hello World!</h1>' | sudo tee /var/www/index.html

#Making Caddyfile for Caddy2
echo -e "${COLOR}Configure your Caddy setting${NC}"
echo -n "Please Enter your Domain name:"
read domain
echo "$domain" { > /etc/caddy/Caddyfile
echo tls { >> /etc/caddy/Caddyfile
echo "protocols tls1.2 tls1.3" >> /etc/caddy/Caddyfile
echo ciphers TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384 TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256 >> /etc/caddy/Caddyfile
echo curves x25519 >> /etc/caddy/Caddyfile
echo } >> /etc/caddy/Caddyfile
echo @v2ray_websocket { >> /etc/caddy/Caddyfile
echo path /ray >> /etc/caddy/Caddyfile
echo header Connection *Upgrade* >> /etc/caddy/Caddyfile
echo header Upgrade websocket >> /etc/caddy/Caddyfile
echo } >> /etc/caddy/Caddyfile
echo -n "Please Enter your V2Ray port"
read PORT
echo reverse_proxy @v2ray_websocket localhost:$PORT >> /etc/caddy/Caddyfile
echo } >> /etc/caddy/Caddyfile

echo -e "${COLOR}Setup V2ray${NC}"
echo -n "${COLOR}Please Enter where you put the file:${NC}"
read link
echo -n "${COLOR}Please Enter the file name:${NC}"
read conffile
wget $Link/$conffile
mv -f  ./$conffile /etc/v2ray/config.json

echo -e "${COLOR}Please enter information as required, and press Ctl+c when Caddy running well${NC}"
caddy run -conf=/etc/caddy/Caddyfile

echo -e "${COLOR}Rebooting your VPS for normal operation${NC}"
reboot

Auto-Install Script - Pacman/yay-based (Arch Linux)​

Before using this, you need to install and configure sudo. I'll fold this step into the Arch Linux installation script later; the method is as follows:

pacman -Syu sudo
echo <user_NAME> ALL=(ALL) ALL >> /etc/sudoers

This script must be run as root. Midway through, it will ask you to enter a non-root account—the one you added to sudoers. It's only this troublesome because Arch Linux doesn't allow running yay as root.

#變數定義
COLOR='\033[1;35m'
NC='\033[0m'

echo -e "${COLOR}Update Arclinux System${NC}"
pacman -Syu

echo -e "${COLOR}Install yay for Archlinux${NC}"
git clone https://aur.archlinux.org/yay.git
cd yay
makepkg -si

echo -e "${COLOR}Need None Root account to run yay${NC}"
echo -n "Please Enter your none root account"
read YOURID
su $YOURID
echo -e "${COLOR}Install V2ray, Caddy2${NC}"
yay -Syu v2ray caddy2
exit

echo -e "${COLOR}Install BBR${NC}"
bash <(curl -L -s https://github.com/teddysun/across/raw/master/bbr.sh)

echo -e "${COLOR}Setup  Caddy${NC}"

mkdir /etc/ssl/caddy
chown -R http:root /etc/ssl/caddy

chown http:http /var/www
curl -s https://raw.githubusercontent.com/mholt/caddy/master/dist/init/linux-systemd/caddy.service -o /etc/systemd/system/caddy.service

systemctl enable caddy.service
ufw allow http
ufw allow https

V2Ray​

Honestly, V2Ray is a great piece of software. Fundamentally, it is a framework rather than just a single communication protocol. Even though its configuration is relatively complex, once you understand how it works, even if VMess stops working later on, another useful protocol like VMess2 will likely be wrapped into the V2Ray framework so you can keep using it.

Currently, as a network traffic routing tool, V2Ray already includes the following capabilities:

  • Intercepting all local UDP port 53 packets and forwarding them to a specific IP and port to implement DNS functionality.

  • Routing all traffic entering a certain port via a chosen protocol to a designated IP machine to act as a proxy (a "ladder").

Even if you don't use it as a proxy ladder, V2Ray could also serve as a firewall for your home network—for example, preventing kids from accessing sites they shouldn't visit (though you can just do that directly with a firewall without going to all this trouble).

For V2Ray configuration details, you can refer to the New V2Ray Plain-Language Guide. It is very detailed and practical—you can basically just copy it, tweak a few values, and start using it.

In the current environment, it is recommended to use WebSocket+TLS+Web paired with a CDN like Cloudflare. There are plenty of tutorials online for reference.

Caddy​

Comparing Caddy v2 installation methods, using yay on Arch-based distros is still much simpler. On Debian/Ubuntu-based systems, following the official instructions didn't allow installing via apt properly at the time, so I ended up installing via the .deb package from GitHub. The downside is having to update the package version in the auto-install script whenever a new release comes out.

Another difference is that on Arch-based systems the config file is /etc/caddy/caddy.conf, whereas when installed via .deb it remains /etc/caddy/Caddyfile.

Keep this in mind during later use so you don't run into issues.

Caddy2 Configuration​

This configuration file is adapted directly from the New V2Ray Plain-Language Guide:

# Caddy v2 (recommended)

<mydomain.me> {
    log {
        output file /etc/caddy/caddy.log
    }
    tls {
        protocols tls1.2 tls1.3
        ciphers TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384 TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256
        curves x25519
    }
    @v2ray_websocket {
        path /<your_path>
        header Connection *Upgrade*
        header Upgrade websocket
    }
    reverse_proxy @v2ray_websocket localhost:<your_port_Number>
}

Replace <mydomain.me> with your domain without <>.

Replace <your_path> with your V2Ray WebSocket path without <>.

Replace <your_port_Number> with your V2Ray port number without <>.

You can copy everything else as-is.

Strictly speaking, since I only just adopted Caddy v2 while writing this post, I'm not too familiar with its config format myself—I recommend checking the Caddy Documentation.

Client-Side (Gateway) Setup Guide​

Qv2ray - Windows & Linux & macOS​

This is a Qt-based GUI for V2Ray. You generally use it together with V2ray-Core. V2ray-Core updates frequently, though it usually maintains compatibility with the previous three versions, so it's rarely an issue.

Windows​

choco upgrade qv2ray v2ray -y

This single line installs everything—just open it and configure your settings.

Linux (Arch Linux / Manjaro)​

yay -Syu qv2ray v2ray

And that's it for installation.

Linux (Others)​

There is an AppImage file on the official GitHub releases page that you can download and run directly.

macOS​

I can't afford one so I don't know, though there's a .dmg file on the official GitHub releases page—you should just be able to download and install it directly.

For related instructions, please refer to the Official Qv2ray Documentation.

BifrostV - Android​

Just tap to install. For those who can't access Google Play, you'll have to find a way to get the APK—for instance, you can set up a V2Ray proxy on Windows and have your phone/tablet connect through it to install.

As for phones without Google Play Services... we'll save that topic for another day if the opportunity arises.

For usage instructions, check out this guide written by a GFW-bypass expert.

Shadowrocket - iOS​

As long as you don't use a Mainland China Apple Store account, you should be able to buy this app directly on the App Store (yes, it's the only paid one here, though iPhone users usually don't mind spending a few bucks).

For friends in China who have no other choice, you can only use this unorthodox workaround rely on kind-hearted folks. However, third-party sharing methods easily lead to other installation issues that I'm not an expert at troubleshooting.

You'll have to figure those out on your own, fellow seekers of the Way...
