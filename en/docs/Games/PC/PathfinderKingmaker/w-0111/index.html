Pathfinder: Kingmaker Save Editing Companion (Pet) Appearance and Model Guide

tip

After modifying appearances, the pet's upgrade mechanism is still recognized by the system as a Pet and will not have independent experience points. It is recommended to use the Bag of Tricks mod to assist with experience and leveling management.

📂 1. Save Location and Essential Tools​

Be sure to back up your original saves before making any modifications.

  • Save Path:

    C:\Users\{Username}\AppData\LocalLow\Owlcat Games\Pathfinder Kingmaker\Saved Games

    (Note: AppData is a hidden system folder. You need to enable "Show hidden items" in File Explorer or type the path directly into the address bar.)

  • File Format: The .zks save files are actually standard ZIP archives. Extract them directly using any decompression software.

  • Recommended Editing Tool: Notepad++ with the JSTool Plugin is strongly recommended.

  • Opening the JSON file and using JSTool's JSFormat feature automatically aligns the compacted JSON content into an easily readable tree structure.

📄 2. Core File Description​

After extracting the .zks archive, you will see many files. The two core files for modifying appearance are:

File NameContent Description
party.jsonPrimary modification target. Records detailed information for "all characters" in the party (including the protagonist, NPC teammates, and pet companions). Changing companion races and appearances is done here.
player.jsonPrimarily records progress and personal status messages for the protagonist.

📊 3. party.json Key Parameter Dictionary​

In party.json, all settings for each character are packaged within a large block (section) called "Descriptor". Here are the core parameters controlling appearance and identity:

Parameter Name (Key)Setting Impact & Description
"CustomName"Character Name. The best anchor point for locating a specific character (e.g., search for "Kiwi Von Hohenzollen" to find the character you want to modify).
"CustomGender"Gender. Usually set to "Male" or "Female".
"LeftHandedOverride"Left-handed setting. Boolean (true / false).
"m_CustomPortrait"Custom Portrait. Specifies the 2D portrait folder ID used by the character (e.g., "aa28").
"Doll"Paperdoll System (3D Model). Complete block controlling character race, face shape, hair, and accessories.
"Blueprint"Character Blueprint (UUID). Defines the unique identifier of the character within the game system.

🛠️ 4. Modification SOP (Replacing Companion Appearance)​

Because directly writing UUIDs and appearance parameters by hand is extremely error-prone, follow this "borrowing a corpse to bring the soul back" replacement workflow:

Step 1: Generate Legal New Appearance Data​

  1. Open the game and use the system's character creation tool (or recruit a new mercenary) to craft the desired "ideal companion appearance and portrait."
  2. Save the game after entering, generating a temporary new save file.
  3. Extract party.json from this new save, locate the new character's "Blueprint", "Doll" block, and "m_CustomPortrait" block, and copy them to another text file for backup.

Step 2: Transfer Data to Target Save​

  1. Extract party.json from the "main progress save" you want to modify.
  2. Search for the name of the companion you want to modify (using "CustomName") to locate that companion's "Descriptor" block.
  3. Replace the companion's original corresponding blocks with the copied "Doll" and "m_CustomPortrait".

Step 3: Handle Internal Reference IDs $id (Extremely Important)​

In the JSON structure, there will be many system-generated serial number tags (e.g., "$id": "644").

  • Must Not Duplicate: All values with "$id" in the block you copied must not duplicate any other $id in the entire party.json file.
  • Solution: Feel free to change the numbers of these $ids (e.g., change them to "999644"), as long as they are unique within this file; they do not need to be in sequential order.

🔗 5. Master-Pet Binding Logic (Linkage Check)​

The game system relies on UUIDs to verify "who is whose pet." If this link is broken, the pet will become masterless or disappear from the party entirely. After modifying, be sure to check the following correspondences:

In the "Master's" Descriptor block:

"m_Pet": {
    "m_UniqueId": "Must fill in the pet character's UUID here"
}

In the "Pet (Companion's)" Descriptor block:

"Master": {
    "m_UniqueId": "Must fill in the master character's UUID here"
}

(Note: UUIDs must never conflict with built-in NPC UUIDs in the game, which is why Step 1 recommends using in-game tools to create a new character to obtain a safe UUID.)

⚠️ 6. Known Issues and Side Effects (Troubleshooting)​

  • Emperor's New Clothes BUG: The 3D paperdoll models replaced using this method will appear without clothes in-game.
  • Current Hypothesis: "ClothesPrimaryIndex" and "ClothesSecondaryIndex" inside the "Doll" block only define colors, while the actual declaration block for "wearing equipment and clothes" is missing or not correctly applied. If the equipment binding block (Equipment Definition) is found in the saves later, this entry will be updated.
