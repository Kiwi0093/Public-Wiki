SNMP (Simple Network Management Protocol) and System Monitoring Tools

info

This article was automatically translated by Google "Gemini". The author does not guarantee its accuracy or wording.

SNMP (Simple Network Management Protocol) is an application-layer protocol widely used for status monitoring and metric collection on networking equipment (such as routers, switches, firewalls) and servers (Linux / FreeBSD).

1. SNMP Core Concepts and Operational Architecture​

SNMP organizes monitoring metrics by maintaining a database called a MIB (Management Information Base), where each metric corresponds to a unique OID (Object Identifier).

  • Operation Mechanism:
    • GET / GETNEXT: The management system (NMS) actively queries monitored hosts (Agents) for values.
    • TRAP / INFORM: When system anomalies occur (such as interface link-downs or hardware alerts), the monitored host proactively sends notifications outward.
  • Major Version Differences:
    • SNMPv1 / SNMPv2c: Uses plaintext Community Strings (such as public or private) for authentication, resulting in low security and high vulnerability to interception.
    • SNMPv3: Introduces complete encryption and authentication mechanisms (supporting MD5/SHA authentication and DES/AES encryption (Updated 2026-11-27: MD5 and DES are insecure; modern practices should switch to SHA-256 / SHA-512 authentication and AES encryption)). It is strongly recommended to adopt this version in production environments.

3. SNMP Server Deployment on Linux and FreeBSD (Net-SNMP)​

Servers must install and configure the SNMP Agent (snmpd) to respond to monitoring requests.

1. Install Packages​

  • Linux (Ubuntu / Debian / RHEL):

    sudo apt install snmpd snmp
    # or RHEL/CentOS
    sudo dnf install net-snmp net-snmp-utils

  • FreeBSD (via pkg):

    sudo pkg install net-snmp

    (On FreeBSD, add snmpd_enable="YES" to /etc/rc.conf and run sudo service snmpd start to start the service)

2. Configuration File Example (/etc/snmp/snmpd.conf)​

To ensure security, it is recommended to directly adopt SNMPv3 to configure accounts and passwords, avoiding plaintext communities:

# Create an SNMPv3 dedicated read-only account (myuser) with authentication and encryption configured
rouser myuser authPriv -V systemview

# Set authPass and privPass passwords (passwords must be at least 8 characters long)
createUser myuser SHA "MyAuthPassword123" AES "MyPrivPassword123"
Updated 2026-11-27
  1. FreeBSD configuration file path is /usr/local/etc/snmp/snmpd.conf (not /etc/snmp/snmpd.conf).
  2. createUser containing plaintext passwords should not remain in /etc/snmp/snmpd.conf long-term. The standard practice is to stop the snmpd service first, use the net-snmp-create-v3-user command, or write createUser to a persistent state file (commonly /var/lib/snmp/snmpd.conf on Linux and /var/net-snmp/snmpd.conf on FreeBSD). Upon startup, snmpd will automatically convert it into hashed usmUser entries and clear the plaintext passwords.
  3. Ensure systemview is defined in the configuration file for rouser ... -V systemview (Debian/Ubuntu defaults are typically systemonly), otherwise authorization errors will occur. It is also recommended to use SHA-256 and AES for authentication and encryption algorithms.

Restart the service after configuration:

# Linux
sudo systemctl restart snmpd

# FreeBSD
sudo service snmpd restart

4. Common Manual Debugging and Testing Tools​

When monitoring systems fail to fetch data properly, you can use client tools provided by Net-SNMP in the terminal to troubleshoot:

  • Use snmpwalk to scan the entire OID tree:

    # SNMPv3 test example
    snmpwalk -v3 -l authPriv -u myuser -A MyAuthPassword123 -X MyPrivPassword123 127.0.0.1 .1.3.6.1.2.1.1

  • Use snmpget to retrieve a single specific metric (e.g., system uptime sysUpTime):

    snmpget -v3 -l authPriv -u myuser -A MyAuthPassword123 -X MyPrivPassword123 127.0.0.1 .1.3.6.1.2.1.1.3.0

5. Modern Monitoring Integration Solutions​

Traditional SNMP polling often encounters performance bottlenecks when dealing with large-scale infrastructures. Modern operations typically combine the following tools:

  1. Prometheus SNMP Exporter:

    Tailored for modern cloud-native architectures, it fetches SNMP data from traditional networking equipment via a dedicated exporter, converts it into Prometheus-compatible formats, and integrates with Grafana to render exquisite dashboards.

  2. LibreNMS / Zabbix:

    Full-featured network automatic discovery and performance monitoring systems with built-in massive device MIB databases, capable of automatically graphing switch port traffic and sending alerts.
