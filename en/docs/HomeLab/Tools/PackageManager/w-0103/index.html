Node.js Modern Package and Environment Management Practical Notes

info

This article was automatically translated by Google "Gemini". The author does not guarantee its accuracy or wording.

I. Getting Started: Never Install Node.js Using System Native Commands​

In Linux (apt/dnf) or macOS, running sudo apt install nodejs or sudo npm install -g xxx directly is strictly discouraged. This leads to two severe consequences:

  1. Outdated Versions: System repositories usually lag behind by several major versions.
  2. Permission Hell: You will constantly encounter EACCES permission errors when installing global packages, forcing you to run npm with sudo, which is a major security and environment cleanliness faux pas.

Modern Standard Practice: Use a Version Manager

  • Classic Choice: NVM (Node Version Manager) Well-established and most popular. Installation command:

    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

    Common commands:

    nvm install 20       # Install Node.js v20 (LTS)
    nvm use 20           # Switch to v20
    nvm alias default 20 # Set default version
    nvm ls-remote        # View all installable versions

  • Blazing Fast Newcomer: fnm (Fast Node Manager) 🌟 Written in Rust, dozens of times faster than nvm, doesn't slow down terminal startup, and natively supports cross-platform. Highly recommended for new setups:

    # Install via script
    curl -fsSL https://fnm.vercel.app/install | bash

    # Common commands are almost identical to nvm
    fnm install 20
    fnm default 20
Updated 2026-11-27

The NVM installation version (v0.39.7) and Node.js v20 referenced in the original text are outdated (Node.js 20 reached End-of-Life EOL in April 2026). In practice, check the official NVM GitHub Releases for the latest installation version, and prefer --lts (e.g., nvm install --lts, fnm install --lts) or current LTS versions (such as Node.js 22 / 24).

II. The Three Pillars of Modern Package Managers: npm / yarn / pnpm​

Once you have Node.js, you face a choice of package managers:

  1. npm (Node Package Manager): Built-in default, standard and solid.
  2. Yarn: Developed by Facebook, once dominant due to speed and lockfiles, but confusion currently surrounds the v1 and v2+ generations.
  3. pnpm (Performant npm): 🌟 Strongly recommended for modern development! It utilizes a "Hard link" mechanism, storing identical packages only once on the entire disk. If your computer has 10 projects using React, npm duplicates them 10 times, whereas pnpm stores only 1 copy and links to it. Extremely disk-space efficient with lightning-fast installation speeds.

Enabling/Installing pnpm: Newer Node.js versions have corepack built-in by default to manage these tools:

# Enable corepack and prepare pnpm
corepack enable pnpm
Updated 2026-11-27

Starting from Node.js 25, official distributions no longer bundle corepack by default. If running corepack results in a command-not-found error, please use the official pnpm standalone installation script (curl -fsSL https://get.pnpm.io/install.sh | sh -), or install it first via npm install -g corepack before enabling.

(Note: Basic commands below focus on the industry-standard npm, but parameter logic is mostly compatible with pnpm)

III. Basic Maintenance: Project-Level Package Management​

In Node.js, packages are typically tied to project directories using package.json as the configuration file.

1. Initialization and Installation

# Initialize a new project (generates package.json)
npm init -y

# Install all dependencies in batch based on package.json
npm install
# (For pnpm, simply run pnpm install or pnpm i)

# Install a specific package and save to dependencies (required for production)
npm install axios

# Install a package and save to devDependencies (development only, e.g., eslint, typescript)
npm install -D typescript

2. Removal and Updates

# Remove a package and automatically update package.json
npm uninstall axios

# Check which packages in the current project are outdated
npm outdated

# Upgrade packages to the latest minor version allowed by package.json
npm update

IV. The Anti-Pollution Savior: npx​

In the past, we often installed command-line tools (such as Vue CLI, Create React App, TypeScript compiler) globally: npm install -g create-react-app (Not recommended)

The modern standard practice is to use npx (Node Package Execute). It fetches and runs the latest CLI tools directly from the cloud on-demand without local installation, discarding them cleanly afterward:

# Temporarily download and run the latest version of create-react-app, cleaning up after use
npx create-react-app my-project

# If typescript is already installed internally in your project (local package), you can invoke it directly with npx
npx tsc --init
Updated 2026-11-27

create-react-app was officially deprecated by the React team in February 2025. For new React projects, please use npm create vite@latest or modern frameworks recommended by the official team (such as Next.js or React Router).

V. Space Cleanup: Rescuing Flooded Disks​

The notorious node_modules is a disk space killer, consuming tens to hundreds of gigabytes over time.

1. Clean npm Global Cache Compressed archives downloaded each time remain in the cache; sometimes resolving package corruption issues (e.g., npm ERR! cb() never called) can also be achieved with this trick:

npm cache clean --force

2. One-Click Removal of node_modules Across All Projects (Disk Savior) If you have a collection of legacy projects, you can use the open-source third-party tool npkill. It uses a super-fast text-based graphical interface to help you find all node_modules across your entire computer and wipe them with the spacebar.

# Run on-demand via npx without polluting the environment
npx npkill

VI. Advanced: Docker and CI/CD Best Practices (npm ci)​

When writing Dockerfiles or setting up GitLab CI / GitHub Actions automated deployment, never use npm install.

In production environments, you must ensure that installed versions match development 100%. npm install sometimes tries to be clever and stealthily upgrades minor versions.

The Only Specified Production Command:

npm ci

Characteristics of npm ci (Clean Install):

  1. Strictly reads the locked versions in package-lock.json, guaranteeing 100% consistency.
  2. Forcefully deletes existing node_modules prior to execution, ensuring a clean environment.
  3. Throws an error and terminates if package.json and lock files mismatch, rather than silently modifying the lock file.
  4. Installation speed is typically twice as fast as npm install.

Dockerfile Example:

COPY package*.json ./
# npm ci is strongly recommended for production environments
RUN npm ci --only=production
COPY . .
Updated 2026-11-27

--only=production has been marked as deprecated in newer npm versions; it is recommended to use RUN npm ci --omit=dev instead.
