SSH Key Authentication and Connection Setup Basics

tip

An increasing number of SSH environments now require key pair authentication (whether for Git, Ansible, or Oracle Cloud VMs). This guide compiles commonly used commands and settings.

  • GTW - SSH Public Key Authentication Tutorial: Passwordless Linux Login, Secure and Convenient
  • MIS Footprint - Windows Passwordless Login to Linux Using SSH Keys
    • Windows Tools: PuTTY, PuTTYgen

Generating Key Pairs​

Generating Keys in Linux / FreeBSD Terminal​

The basic command is ssh-keygen, where common parameters allow you to customize key length, algorithm, and output file name:

# Basic from man ssh-keygen
ssh-keygen [-q] [-a rounds] [-b bits] [-C comment] [-f output_keyfile] [-m format] [-N new_passphrase] [-O option] [-t dsa | ecdsa | ecdsa-sk | ed25519 | ed25519-sk | rsa] [-w provider] [-Z cipher]
      ssh-keygen -p [-a rounds] [-f keyfile] [-m format] [-N new_passphrase] [-P old_passphrase] [-Z cipher]
      ssh-keygen -i [-f input_keyfile] [-m key_format]
      ssh-keygen -e [-f input_keyfile] [-m key_format]
      ssh-keygen -y [-f input_keyfile]
      ssh-keygen -c [-a rounds] [-C comment] [-f keyfile] [-P passphrase]
      ssh-keygen -l [-v] [-E fingerprint_hash] [-f input_keyfile]
      ssh-keygen -B [-f input_keyfile]
      ssh-keygen -D pkcs11
      ssh-keygen -F hostname [-lv] [-f known_hosts_file]
      ssh-keygen -H [-f known_hosts_file]
      ssh-keygen -K [-a rounds] [-w provider]
      ssh-keygen -R hostname [-f known_hosts_file]
      ssh-keygen -r hostname [-g] [-f input_keyfile]
      ssh-keygen -M generate [-O option] output_file
      ssh-keygen -M screen [-f input_file] [-O option] output_file
      ssh-keygen -I certificate_identity -s ca_key [-hU] [-D pkcs11_provider] [-n principals] [-O option] [-V validity_interval] [-z serial_number] file ...
      ssh-keygen -L [-f input_keyfile]
      ssh-keygen -A [-a rounds] [-f prefix_path]
      ssh-keygen -k -f krl_file [-u] [-s ca_public] [-z version_number] file ...
      ssh-keygen -Q [-l] -f krl_file file ...
      ssh-keygen -Y find-principals [-O option] -s signature_file -f allowed_signers_file
      ssh-keygen -Y check-novalidate [-O option] -n namespace -s signature_file
      ssh-keygen -Y sign -f key_file -n namespace file ...
      ssh-keygen -Y verify [-O option] -f allowed_signers_file -I signer_identity -n namespace -s signature_file [-r revocation_file]

# Basically, only a few functions are commonly used:
-b Defines encoding bit length; RSA defaults to 3072, which is generally sufficient.
-t Encryption type: choices include dsa | ecdsa | ecdsa-sk | ed25519 | ed25519-sk | rsa. Most tutorials recommend rsa.
-C Defines a corresponding email address in the comment.
-f Defines the output key pair name.

A common creation method is as follows:

ssh-keygen -b 4096 -t rsa -f <server_or_service_name>

Executing this generates two files inside ~/.ssh/: <server_or_service_name> (private key) and <server_or_service_name>.pub (public key).

Updated 2026-11-27
  1. dsa (-t dsa) has been disabled by default since OpenSSH 9.8 and was officially removed in OpenSSH 10.0 (2025). Please do not use it anymore.
  2. Modern practice generally recommends switching to ed25519 (e.g., ssh-keygen -t ed25519 -f <server_or_service_name>), which offers shorter keys, higher security, and faster computation. Fall back to 4096-bit rsa only when compatibility with extremely legacy OpenSSH servers is required.

Windows (Using PuTTYgen)​

The process is basically the same: set the bit count and key type in the bottom right corner, then click Generate to create the Private Key and Public Key.

Converting PPK to PEM in Linux Environment​

If you need to connect directly from a Linux desktop environment (such as Manjaro), installing putty on Manjaro includes puttygen out of the box. If using Ubuntu / Debian, an additional tool package is required:

# Install PuTTY tools
apt install putty-tools

Once installed, you can convert .ppk to .pem format for OpenSSH usage:

# Convert .ppk file to .pem file for direct use by ssh client
puttygen yourkey.ppk -O private-openssh -o yourkey.pem

After conversion, you can log in using the following command (ensure private key permissions are set to 600):

# Log in using pem
ssh -i /your/key/file user@hostname.or.ip

Public Key @ Server Side​

There are two common practices for deploying public keys to a remote server:

Simple Copy & Paste​

Directly paste the public key content into the target account's ~/.ssh/authorized_keys by editing with vi or appending via command:

cat <server_or_service_name>.pub >> ~/.ssh/authorized_keys

However, in practice, people often find manually uploading <server_or_service_name>.pub to the target host tedious, so this method is less frequently used.

PuTTYgen Key Conversion (PEM to PPK)​

Since traditional PuTTY cannot directly read standard .pem private key files, if you want to connect to sshd from Windows via PuTTY, you can import and save as .ppk format:

ssh-copy-id​

ssh-copy-id -i ~/.ssh/<server_or_service_name>.pub USER@HOST

ssh-copy-id reads ~/.ssh/id_rsa.pub by default, so when using a custom file name, you must specify the public key path using -i. Once uploaded and passwordless login is confirmed, you can modify sshd_config on the server to disable password login.

Server-Side Configuration (sshd_config)​

In addition to client-side key preparation, the server's /etc/ssh/sshd_config usually needs tightened security settings as well:

# Disallow root account to log in via ssh
PermitRootLogin no
# It is generally recommended to disable remote root login, but when using ansible, methods other than directly using the root account can feel cumbersome... choose carefully here.

# Accept Public Key authentication method
PubkeyAuthentication yes

# Default Public Key location file name
AuthorizedKeysFile      .ssh/authorized_keys
# This can actually be modified, but I generally leave it untouched.

# Disable built-in password authentication system and empty passwords
PasswordAuthentication no
PermitEmptyPasswords no

# Disable password authentication login
ChallengeResponseAuthentication no
UsePAM no

# Specific User settings (this entire block must be placed at the very end of sshd_config)
Match <User1>, <User2>, ...
# Then define settings for these Users, e.g.
    PasswordAuthentication yes
# This ensures only User1 and User2 can log in with passwords, while others cannot.
Updated 2026-11-27
  1. ChallengeResponseAuthentication has been deprecated since OpenSSH 8.7; newer versions should use KbdInteractiveAuthentication no instead.
  2. The Match block must specify a condition keyword and comma-separated lists must not contain spaces. The correct syntax is Match User user1,user2 (the original example Match <User1>, <User2> lacked the User keyword and contained spaces, leading to sshd configuration syntax errors).
  3. In modern Linux environments (such as those using systemd), it is recommended to keep UsePAM yes to ensure user sessions and resource limits function correctly, and simply turn off PasswordAuthentication no and KbdInteractiveAuthentication no to disable password logins.

Client Connection Command (SSH)​

The basic connection command is:

ssh USER@HOST

To specify a specific private key file, append the -i parameter:

ssh -i /location/private_key USER@HOST

Since SSH authentication relies on the private key, as long as you properly store the same private key on your frequently used client hosts and set the correct permissions, you can connect smoothly.
