LibreNMS Network Monitoring System Docker Deployment Log (Archived)

tip

A long, long time ago, I used MRTG + SNMP to generate traffic graphs, but over the years in China my home servers gradually dropped to a bare-minimum "as long as it runs" standard, so I stopped bothering with it. Recently, during a major cleanup, I wanted to set up something similar again and picked LibreNMS.

References​

Mokmoe's Notes - Docker LibreNMS Installation Log (incl. MariaDB, phpMyAdmin)

His post is actually very detailed—you can just follow it directly—though I've still written down my slightly adjusted approach below.

Basic Setup​

MariaDB​

  1. vi mariadb.yml 
# mariadb.yml
--------------------------------------------------------------------------------------------------------------------------------
services:
  mariadb:
    image: mariadb:latest
    container_name: mariadb
    environment:
      - MYSQL_ROOT_PASSWORD=${your_DB_root_Passwd}
      - TZ=Asia/Taipei
    ports:
      - ${your_DB_host}:${your_DB_port}:3306
    volumes:
      - /var/lib/docker/volumes/mariadb/data:/var/lib/mysql
      - /var/lib/docker/volumes/mariadb/mariadbcustom.cnf:/etc/mysql/conf.d/custom.cnf
    restart: unless-stopped
Updated 2026-11-27
  • The ---- separator line inside the code block lacks a # comment prefix; pasting it directly into YAML will cause a parse failure.
  • MYSQL_ROOT_PASSWORD has been replaced by MARIADB_ROOT_PASSWORD in MariaDB 11+.
  1. vi /var/lib/docker/volumes/mariadb/mariadbcustom.cnf 
# /var/lib/docker/volumes/mariadb/mariadbcustom.cnf 
--------------------------------------------------------------------------------------------------------------------------------
[client]
default-character-set = utf8mb4

[mysql]" >> /etc/my.cnf
default-character-set = utf8mb4

[mysqld]
skip-character-set-client-handshake
collation_server = utf8mb4_unicode_ci
character_set_server = utf8mb4
tmpdir      = /var/lib/mysqltmp

This defines the defaults for MariaDB so everything uses UTF-8 Unicode.

Updated 2026-11-27
  • The ---- separator line in the block lacks a # comment prefix, and line 4 [mysql]" >> /etc/my.cnf is a copy-paste error resulting in invalid INI syntax (it should be [mysql]).
  • skip-character-set-client-handshake is deprecated in newer MariaDB versions; use character-set-client-handshake = FALSE instead. Also, if /var/lib/mysqltmp is not mounted, the custom tmpdir may fail to start if the path does not exist.
  1. sudo docker-compose -f mariadb.yml up -d (Updated 2026-11-27: Docker Compose v1 docker-compose is end-of-life; on modern environments use sudo docker compose -f mariadb.yml up -d instead)

This creates and runs the container.

  1. sudo docker exec -it mariadb bash 
# @mariadb container
--------------------------------------------------------------------------------------------------------------------------------
mysql -u root -p                    # Enter your SQL root password after running this to enter MariaDB

# Create the account and database for LibreNMS and grant full privileges on this database to the account; if you dislike CLI commands, you can also do this in phpMyAdmin
mysql> CREATE DATABASE librenms CHARACTER SET utf8 COLLATE utf8_unicode_ci;
mysql> CREATE USER 'librenms'@'%' IDENTIFIED BY 'user_librenms_password';
mysql> GRANT ALL PRIVILEGES on librenms.* TO 'librenms'@'%' WITH GRANT OPTION;
mysql> FLUSH PRIVILEGES;
Updated 2026-11-27
  • In MariaDB 11+ containers, the mariadb CLI command is recommended instead (the mysql symlink is marked deprecated).
  • Official LibreNMS documentation requires the database to use utf8mb4 and utf8mb4_unicode_ci (utf8 in MySQL/MariaDB is actually the legacy 3-byte utf8mb3).

LibreNMS​

  1. vi librenms.yml 
#librenms.yml
--------------------------------------------------------------------------------------------------------------------------------
version: '3'
services:
  librenms:
    image: librenms/librenms:latest
    container_name: librenms
    command: su - librenms -c "/opt/librenms/librenms-service.py -v"
    environment:
      - TZ=Asia/Taipei
      - PUID=1000
      - DB_HOST=${your_DB_host}
      - DB_PORT=${your_DB_port}
      - DB_NAME=librenms
      - DB_USER=librenms
      - DB_PASSWORD=user_librenms_passwd
      - DB_TIMEOUT=10
      - LIBRENMS_SNMP_COMMUNITY=${Community_name_you_want}
    ports:
      - ${your_Server_ip}:${port_you_want}:8000
    volumes:
      - /var/lib/docker/volumes/librenms/data:/data
    restart: always

A crucial step here is that you must add:

command: su - librenms -c "/opt/librenms/librenms-service.py -v"

This means running /opt/librenms/librenms-service.py -v as the librenms user.

That way its RRD permissions will be correct, otherwise there will be issues (I previously believed this was optional and couldn't get it working—it is mandatory...).

Updated 2026-11-27
  • The ---- separator line in the block lacks #, and version: '3' is deprecated in Docker Compose v2.
  • Modern official librenms/librenms Docker deployments have moved to a multi-container stack (the main librenms service paired with a dispatcher sidecar running librenms-service.py, plus db and redis), rather than overriding command directly on the main container.
  1. sudo docker exec -it mariadb bash 
 # Enter the mariadb container
--------------------------------------------------------------------------------------------------------------------------------
mysql -u librenms -p                    # Log in to MariaDB with the librenms account

mysql> use librenms;                        # Select the librenms database
# Modify database schema defaults
mysql> ALTER TABLE `notifications` CHANGE `datetime` `datetime` timestamp NOT NULL DEFAULT '1970-01-02 00:00:00' ; 
mysql> ALTER TABLE `users` CHANGE `created_at` `created_at` timestamp NOT NULL DEFAULT '1970-01-02 00:00:01' ;

This fixes database issues (fixing issues reported in Validate Config).

Updated 2026-11-27

The ALTER TABLE statements above were only an early workaround for MySQL's NO_ZERO_DATE strict mode; modern LibreNMS manages database schema migrations automatically via lnms migrate, so manually altering table defaults is unnecessary.

Bonus - phpMyAdmin​

Honestly, you rarely need this, but for people who dislike mysql CLI commands, you can use this graphical interface to manage the MySQL database.

Because it is very simple, you can just create it directly with a docker run command:

# If your ${your_DB_host} uses port 3306
sudo docker run --name phpmyadmin -d -e PMA_HOST=${your_DB_host} -p 8080:80 phpmyadmin/phpmyadmin

# If your ${your_DB_host} is not on the default 3306, it is recommended to connect via docker --link
sudo docker run --name phpmyadmin -d --link mariadb:db -p 8080:80 phpmyadmin/phpmyadmin

Here port 8080 is exposed externally and can be changed to whatever you want.

Updated 2026-11-27

--link is a deprecated legacy Docker flag; in modern environments, create a custom bridge network (docker network create) and connect containers via --network.

Nginx Configuration​

Honestly, modifying config.php inside the container to serve it under a subdirectory seemed like too much trouble, so I went and registered a dedicated domain name for it instead.

The Nginx configuration is just a standard virtual host setup: simply add a .cnf file under /etc/nginx/site-enables/ (Updated 2026-11-27: On Debian/Ubuntu, the correct path is /etc/nginx/sites-available/, then enable it via a symlink into /etc/nginx/sites-enabled/) to define it.

Remember to also request a Certbot certificate for this domain name.

# librenms.cnf
--------------------------------------------------------------------------------------------------------------------------------
server {
 listen 80;
 server_name librenms.exsample.com;
 return 301 https://$server_name$request_uri;
}
server {
 listen 443 ssl http2;
 server_name librenms.exsample.com;

 ssl_certificate /etc/letsencrypt/live/librenms.exsample.com/fullchain.pem;
 ssl_certificate_key /etc/letsencrypt/live/librenms.exsample.com/privkey.pem;
# include /etc/letsencrypt/options-ssl-nginx.conf;
# ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;


#charset koi8-r;
 #access_log /var/log/nginx/host.access.log main;

client_max_body_size 20M;


location / {
 proxy_pass http://${your_Server_ip}:${port_you_want};            # Change this to the target IP/port to forward to
 proxy_set_header Host $host;
 proxy_set_header X-Real-IP $remote_addr;
 proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
 proxy_set_header X-Forwarded-Proto $scheme;
 proxy_set_header X-Forwarded-Protocol $scheme;
 proxy_set_header X-Forwarded-Host $http_host;
 proxy_buffering off;

        }

error_page 500 502 503 504 /50x.html;
 location = /50x.html {
 root /usr/share/nginx/html;
Updated 2026-11-27
  • The example contains an un-commented ---- separator line, a misspelled domain exsample.com, and is missing the closing curly braces } for the location and server blocks at the end.
  • listen 443 ssl http2; is deprecated in Nginx 1.25.1+; modern syntax splits it into listen 443 ssl; and a separate http2 on; directive.

VMware ESXi 6.5​

References​

Sugarcane at Dusk (blog.xuite.net)

Stars Appear When It Gets Dark (sc8log)

  1. After logging into ESXi via SSH 
esxcli system snmp get                                    # Check SNMP status and current settings
esxcli system snmp set -c YOUR_STRING                    # Set your community string
esxcli system snmp set -p 161                            # Set your SNMP port; 161 UDP is standard
esxcli system snmp set -L "City, State, Country"        # Set your location
esxcli system snmp set -C noc@example.com                # Set your contact email
esxcli system snmp set -e yes                            # Enable SNMP
  1. Run on another machine that can query SNMP 
snmpwalk -v2c -c ${YOUR_STRING} ${your_server_IP}

Just verify that data is returned.

Updated 2026-11-27

VMware ESXi 6.5 has reached End of Life (EOL), and the referenced blog.xuite.net service was permanently shut down on 2023-08-31.

Conclusion​

  • If you don't want to modify config.php inside LibreNMS, it's easiest not to use a community string other than public so discovery is simpler.
  • It takes at least a few hours after enabling these before clear graphs appear—don't panic, you won't get data immediately right after configuration.
Updated 2026-11-27

For security reasons, keeping the default public SNMP community string is not recommended in real-world or internet-facing environments; use a custom complex string or upgrade to SNMPv3 with authentication and encryption.

Reason for Deprecation​

  • Low usage — I barely used it after setting it up.
  • There are alternatives like netdata, and since I also installed it directly on the Gateway and DHCP hosts, LibreNMS became even less useful.
