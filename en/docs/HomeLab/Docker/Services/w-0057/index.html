Nextcloud Deployment with Traefik v3 Reverse Proxy

1. Core Concepts and Pitfall Avoidance​

  • Image Selection:
    • Strongly prefer the official standard image nextcloud:apache (or nextcloud:latest). It bundles an integrated Apache + PHP-FPM environment and has the most mature compatibility with X-Forwarded-* headers.
    • Strictly avoid LinuxServer.io's Nextcloud image: That image ships with a pre-installed Nginx and self-signed SSL workflow, which seriously conflicts with SSL offloading at an external reverse proxy.
  • Permission Trap (UID 33):
    • Inside the official container, the process runs as www-data, whose UID and GID are both 33. Host-mounted directories must be owned by 33:33; otherwise startup will fail because .ocdata or the data directory cannot be read or written.
  • Data Directory Separation (NEXTCLOUD_DATA_DIR):
    • Mount user-uploaded data separately at /var/www/data (outside the web root /var/www/html). This both improves security and makes it easy to snapshot or mount external disk volumes independently.

2. Complete Docker Compose Deployment (Modern Traefik v3 Config)​

Step 1: Create Dedicated Directories and Fix Permissions​

# Create the application directory and a separate data storage directory
sudo mkdir -p /opt/nextcloud/html
sudo mkdir -p /opt/nextcloud/data

# Grant ownership to www-data (UID 33) inside the container
sudo chown -R 33:33 /opt/nextcloud/html /opt/nextcloud/data
sudo chmod 750 /opt/nextcloud/data

Step 2: docker-compose.yml Configuration​

Configure /opt/nextcloud/docker-compose.yml:

services:
  nextcloud:
    image: nextcloud:apache
    container_name: nextcloud
    restart: unless-stopped
    environment:
      - TZ=Asia/Taipei
      # 1. Initial database configuration (using SQLite)
      - SQLITE_DATABASE=nextcloud
      # 2. Separate data directory path (avoids nested mount issues)
      - NEXTCLOUD_DATA_DIR=/var/www/data
      # 3. Trusted domains on initial install (space-separated for multiple)
      - NEXTCLOUD_TRUSTED_DOMAINS=cloud.example.com
      # 4. Trusted proxy subnets (Docker default subnets)
      - TRUSTED_PROXIES=172.16.0.0/12 10.0.0.0/8 192.168.0.0/16
      # 5. Force external URLs to be recognized as HTTPS (key to preventing http redirects on login and CSRF failures)
      - OVERWRITEPROTOCOL=https
      - OVERWRITECLIURL=https://cloud.example.com
      - OVERWRITEHOST=cloud.example.com
      # 6. PHP runtime quota tuning
      - PHP_MEMORY_LIMIT=1024M
      - PHP_UPLOAD_LIMIT=16G
    volumes:
      - /opt/nextcloud/html:/var/www/html
      - /opt/nextcloud/data:/var/www/data
    networks:
      - proxy-network
    labels:
      - "traefik.enable=true"

      # --- [Basic Router Settings] ---
      - "traefik.http.routers.nextcloud.rule=Host(`cloud.example.com`)"
      - "traefik.http.routers.nextcloud.entrypoints=websecure"
      - "traefik.http.routers.nextcloud.tls=true"
      - "traefik.http.routers.nextcloud.tls.certresolver=myresolver"
      # Attach middleware chain
      - "traefik.http.routers.nextcloud.middlewares=nc-dav,nc-wellknown,nc-headers"
      # Explicitly forward to port 80 of Apache inside the container
      - "traefik.http.services.nextcloud.loadbalancer.server.port=80"

      # --- [Middleware 1: CalDAV / CardDAV Redirect] ---
      - "traefik.http.middlewares.nc-dav.redirectregex.regex=^https://(.*)/\\.well-known/(card|cal)dav(.*)"
      - "traefik.http.middlewares.nc-dav.redirectregex.replacement=https://$${1}/remote.php/dav$${3}"
      - "traefik.http.middlewares.nc-dav.redirectregex.permanent=true"

      # --- [Middleware 2: Webfinger / Nodeinfo Redirect (clears newer yellow warnings)] ---
      - "traefik.http.middlewares.nc-wellknown.redirectregex.regex=^https://(.*)/\\.well-known/(webfinger|nodeinfo)(.*)"
      - "traefik.http.middlewares.nc-wellknown.redirectregex.replacement=https://$${1}/index.php/.well-known/$${2}$${3}"
      - "traefik.http.middlewares.nc-wellknown.redirectregex.permanent=true"

      # --- [Middleware 3: Security Headers & HSTS] ---
      - "traefik.http.middlewares.nc-headers.headers.stsSeconds=31536000"
      - "traefik.http.middlewares.nc-headers.headers.stsIncludeSubdomains=true"
      - "traefik.http.middlewares.nc-headers.headers.stsPreload=true"
      - "traefik.http.middlewares.nc-headers.headers.contentTypeNosniff=true"
      - "traefik.http.middlewares.nc-headers.headers.browserXssFilter=true"

networks:
  proxy-network:
    external: true

Start the service:

docker compose up -d

3. Post-Initialization Configuration and Resolving All Warnings​

After creating the admin account in the web UI, go to "Administration settings" → "Overview". If any warnings appear, resolve them directly as follows:

3.1 Clearing the Warning: "No memory cache has been configured (Memcache)"​

The official image already comes with the APCu module compiled in, but it must be enabled manually in the configuration file:

  1. Edit /opt/nextcloud/html/config/config.php and add inside the $CONFIG = array ( block:

       'memcache.local' => '\OC\Memcache\APCu',

  2. Enable APCu for PHP CLI as well (to prevent errors when running background cron jobs):

    Create or edit /opt/nextcloud/html/.user.ini and add:

    apc.enable_cli=1

  3. Restart the container to apply:

    docker compose restart nextcloud

3.2 Clearing Warnings: "Missing database indices" or "BigInt columns not converted"​

Run the occ command inside the container to fix them automatically:

# Add missing database indices
docker compose exec --user 33 nextcloud php occ db:add-missing-indices

# Convert filecache columns to BigInt
docker compose exec --user 33 nextcloud php occ db:convert-filecache-bigint

3.3 Adding Domains or Adjusting Reverse Proxies After Startup (Do Not Edit Compose!)​

Once the container is initialized, environment variables no longer overwrite config.php. If you need to add domains or trusted proxy IPs later, use occ directly:

# Add a second domain (e.g., cloud2.example.com)
docker compose exec --user 33 nextcloud php occ config:system:set trusted_domains 2 --value="cloud2.example.com"

# Add or update trusted proxy subnets (Trusted Proxies)
docker compose exec --user 33 nextcloud php occ config:system:set trusted_proxies 0 --value="172.16.0.0/12"
docker compose exec --user 33 nextcloud php occ config:system:set trusted_proxies 1 --value="10.0.0.0/8"

4. Background Job Scheduling: Cron vs. Systemd Timer​

Nextcloud's default AJAX mode relies on users clicking web pages to trigger maintenance tasks, which both slows down browsing and halts scheduled jobs completely overnight when nobody is active.

First switch the setting in the web UI:

Go to "Administration settings" → "Basic settings" → set Background jobs to "Cron (Recommended)". Then choose either Option A or Option B on the host to deploy the periodic trigger.

Option A: Traditional Crontab (Simple, Lightweight, Fast)​

Best for hosts where you want a quick one-liner without creating extra unit files.

  1. Open the root crontab on the host:

    sudo crontab -e

  2. Add the following schedule (runs every 5 minutes):

    */5 * * * * docker compose -f /opt/nextcloud/docker-compose.yml exec -T --user 33 nextcloud php -f /var/www/html/cron.php > /dev/null 2>&1
    • -T: Disables TTY allocation so non-interactive runs don't fail with the input device is not a TTY.
    • --user 33: Forces execution as www-data (UID 33) inside the container, preventing cache directory permissions from being polluted by root.

Option B: Systemd Timer (Recommended for Modern Distros, Production-Grade Standard)​

Suitable for modern distributions such as Photon OS, Debian, Ubuntu, and Rocky Linux. Provides boot delay, crash timeout protection, unified logging via journalctl, and automatic catch-up after downtime via Persistent=true.

Step 1: Create the Service Unit That Runs the Job​

Create /etc/systemd/system/nextcloud-cron.service:

[Unit]
Description=Nextcloud Background Cron Job
Requires=docker.service
After=docker.service

[Service]
Type=oneshot
User=root
WorkingDirectory=/opt/nextcloud
# Adjust the path based on `which docker` output (typically /usr/bin/docker)
ExecStart=/usr/bin/docker compose exec -T --user 33 nextcloud php -f /var/www/html/cron.php
TimeoutSec=600

[Install]
WantedBy=multi-user.target

Step 2: Create the Timer Unit That Triggers the Service​

Create /etc/systemd/system/nextcloud-cron.timer (the name must match the .service file):

[Unit]
Description=Run Nextcloud Cron every 5 minutes

[Timer]
# Delay first run by 5 minutes after boot to avoid startup spikes
OnBootSec=5min
# Run every 5 minutes thereafter
OnUnitActiveSec=5min
# Run immediately on next boot if a scheduled run was missed while powered off
Persistent=true

[Install]
WantedBy=timers.target

Step 3: Load, Test, and Enable the Timer​

# 1. Reload systemd configuration
sudo systemctl daemon-reload

# 2. Manually trigger the service once to test execution
sudo systemctl start nextcloud-cron.service

# 3. Inspect log output for the single run
journalctl -u nextcloud-cron.service -n 20 --no-pager

# 4. Enable the timer and start it immediately at boot
sudo systemctl enable --now nextcloud-cron.timer

# 5. Check countdown to the next timer trigger
systemctl list-timers nextcloud-cron.timer

5. SQLite Maintenance and Performance Tuning​

For lightweight deployments using SQLite:

  • Enable WAL (Write-Ahead Logging) to Improve Concurrency:

    SQLite uses file-level locking, which can cause timeouts when multiple devices upload simultaneously. Edit /opt/nextcloud/html/config/config.php and add to the array:

    'sqlite.journal_mode' => 'WAL',

  • One-Command Full Backup:

    The SQLite database file is located at /opt/nextcloud/data/owncloud.db (Updated 2026-11-27: When using SQLITE_DATABASE=nextcloud as configured in this guide, the actual filename is /opt/nextcloud/data/nextcloud.db; it is owncloud.db only when unspecified or left at the default name). To back up, simply archive the data directory and config file:

    sudo tar -czvf /opt/backup/nextcloud_$(date +%F).tar.gz \
      /opt/nextcloud/data \
      /opt/nextcloud/html/config/config.php
    warning

    If SQLite WAL mode is enabled or the container is still running, running tar directly on active database files may produce an inconsistent snapshot. Enable maintenance mode before backing up (docker compose exec --user 33 nextcloud php occ maintenance:mode --on), then disable it afterward (--off).

6. Quick Troubleshooting​

SymptomRoot CauseResolution
Redirects back to login page after logging in (login loop / CSRF failure)Missing OVERWRITEPROTOCOL=https, causing the session cookie to be treated as insecure protocolAdd OVERWRITEPROTOCOL=https to Compose, recreate the container with docker compose up -d, and clear browser cookies.
.ocdata missing errorHost directory is not owned by UID 33Run sudo chown -R 33:33 /opt/nextcloud/data.
Mobile app cannot sync calendar and contactsTraefik nc-dav redirect is not taking effectVisit https://<domain>/.well-known/caldav and verify it automatically redirects to /remote.php/dav/.
Large file uploads abortRestricted by PHP upload limitsCheck the PHP_UPLOAD_LIMIT=16G environment variable, or set upload_max_filesize = 16G and post_max_size = 16G in .user.ini.
