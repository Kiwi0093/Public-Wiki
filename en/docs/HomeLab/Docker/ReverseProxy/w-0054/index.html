Nginx Proxy Manager (NPM) Setup, Internal Redirection, and Maintenance

1. Database Selection: SQLite vs. MariaDB​

NPM stores Proxy Hosts, Redirections, and user account information in its backend.

  • SQLite (Strongly Recommended): Modern NPM versions include built-in SQLite by default. Unless you have multi-node load balancing or clustering requirements, using SQLite eliminates external relational database dependencies entirely, saving memory and greatly reducing maintenance complexity.

  • MariaDB / MySQL: If your environment already features a centralized DB (such as a shared LibreNMS or WordPress pool) or has high availability requirements, you can switch via environment variables.

2. Docker Compose Deployment (Lightweight SQLite)​

It is recommended to create an independent, global Docker network (e.g., npm-network) so that other backend containers can easily join this network and communicate directly via Container Names, without requiring any physical port mapping on the host.

Step 1: Create Pre-requisite Directories and Custom Network​

# Create shared network (if not already created)
docker network create npm-network

# Create persistent data directories
mkdir -p /opt/npm/data
mkdir -p /opt/npm/letsencrypt

Step 2: docker-compose.yml Configuration​

Define the service in /opt/npm/docker-compose.yml:

services:
  npm:
    image: jc21/nginx-proxy-manager:latest
    container_name: nginx-proxy-manager
    restart: unless-stopped
    ports:
      - "80:80"      # HTTP forwarding and ACME challenges
      - "81:81"      # Web management dashboard
      - "443:443"    # HTTPS forwarding
    volumes:
      - /opt/npm/data:/data
      - /opt/npm/letsencrypt:/etc/letsencrypt
    networks:
      - npm-network

networks:
  npm-network:
    external: true

Start the service:

docker compose up -d

3. Initial Setup and Login​

  1. Access via browser: http://<Host_IP>:81

  2. Default Credentials: Email: admin@example.com / Password: changeme (Updated 2026-11-27: Modern NPM versions prompt you to create an administrator account directly upon first opening the WebUI, bypassing default credentials. Default credentials are only applicable to legacy versions and require a mandatory password change upon first login)

    • Email: admin@example.com

    • Password: changeme

  3. Upon initial login, the system mandates changing the administrator name, email, and password. Please store your new credentials securely.

4. Core Architecture Highlight: Internal Container Name Redirection (Zero-Port Mapping)​

Beyond exposing services externally, NPM's most elegant usage in internal environments (paired with internal DNS like AdGuard Home, Pi-hole, or Unbound) is forwarding directly using the "Container Name" as the destination.

Core Operational Logic​

  1. Same Docker Network: Docker features a built-in Embedded DNS Server (127.0.0.11). As long as two containers share a custom bridge network (e.g., npm-network), they can resolve each other's internal IP addresses directly using container names.

  2. Backend Containers Need No Port Mapping: Backend containers (such as Emby, Jellyfin, Vaultwarden) do not need to expose ports to the host via ports: at all; they only need to listen on internal ports inside the container. This prevents host port conflicts and significantly reduces the internal attack surface.

Backend Application Configuration Example (Emby)​

services:
  emby:
    image: amir20/clash # or any other image; using emby as an example here
    container_name: emby
    restart: unless-stopped
    # Crucial: No ports: - "8096:8096" mapping required at all
    networks:
      - npm-network

networks:
  npm-network:
    external: true
Updated 2026-11-27

image: amir20/clash in the example above was a misattribution (amir20 is actually the developer of Dozzle, and Clash is not a media server). For actual Emby deployments, use the official image emby/embyserver:latest or lscr.io/linuxserver/emby:latest.

NPM Web Interface Configuration (Proxy Host)​

  1. Navigate to Hosts -> Proxy Hosts -> Add Proxy Host.

  2. Fill out the Details tab:

    • Domain Names: emby.internal.local (resolved to the NPM host IP in internal DNS)

    • Scheme: http

    • Forward Hostname / IP: emby (enter the container name directly)

    • Forward Port: 8096 (enter the container's internal listen port)

    • Check Block Common Exploits and Websockets Support (if the application requires real-time communications).

5. Certificate Management: Custom SSL and Let's Encrypt​

Many mistakenly believe NPM can only renew certificates through the UI via Let's Encrypt, but NPM fully supports importing existing local certificates (Custom Certificates):

5.1 Importing Existing / Wildcard Certificates (Custom Certificate)​

If you have already obtained certificates on the host or via acme.sh / DNS API:

  1. Go to SSL Certificates -> Add SSL Certificate -> Select Custom.

  2. Name the certificate (e.g., My-Wildcard-Cert).

  3. Paste or upload files:

    • Certificate Key: Paste private key content (*.key).

    • Certificate: Paste the full certificate chain (fullchain.pem or a file combining the certificate body and intermediate CA).

  4. Save, and select the custom certificate from the dropdown in the Proxy Host's SSL tab.

5.2 Automatic Let's Encrypt Generation via NPM​

  • HTTP-01 Challenge: Enter domain names directly; requires port 80 to be accessible from the public internet.

  • DNS-01 Challenge (Wildcard Certificate Recommended): Check Use a DNS Challenge, select your DNS provider (e.g., Cloudflare), and enter your API Token to automatically issue *.example.com wildcard certificates.

6. Historical Pitfalls and Common Reverse Proxy Troubleshooting​

6.1 Calibre-Web Layout Breaking or Redirection Failure Under Subpaths / Reverse Proxy​

Applications like Calibre-Web are sensitive to reverse proxy headers and script names. Solution: In the NPM Host settings under Custom Locations -> Add the corresponding path, click the gear icon (advanced settings), and paste the following Nginx header directives:

proxy_bind $server_addr;
proxy_set_header Host $http_host;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Scheme $scheme;
proxy_set_header X-Script-Name /${your_location};

6.2 Portainer-CE Sub-location Pitfalls​

  • Root Cause: Portainer-CE frontend Angular/Vue resource paths use absolute paths relative to root /. Embedding it under subpaths like /portainer causes numerous JS/CSS 404 errors, and WebSockets (/api/websocket/...) are easily disrupted.

  • Best Practice: It is strongly recommended not to use subpaths; always mount virtual hosts using independent subdomains (e.g., portainer.internal.local).

  • Important Configuration: When reverse proxying Portainer, ensure Websockets Support is checked in NPM, otherwise the web terminal (Console / Exec) will disconnect immediately.

6.3 Root Path (Host /) Homepage Navigation​

If a domain name points directly to NPM without matching any host, it displays NPM's default "Congratulations" page.

  • Practical Tip: Create a dashboard container (such as Homepage, Dashy, or Heimdall) and set up a default fallback or primary domain Proxy Host in NPM pointing to that dashboard container to serve as your HomeLab entry navigation homepage.

7. Traefik vs. Nginx Proxy Manager Quick Selection Guide​

Comparison MetricNginx Proxy Manager (NPM)Traefik (v3)
Primary FocusGraphical management, intuitive operations, traditional Nginx extensionsCloud-Native, declarative configuration, microservice edge routing
Configuration EntryWeb UI (stored in DB)Docker Labels or static/dynamic YAML/TOML
Auto-DiscoveryManual Host and Port addition via UIAuto-monitors docker.sock, automatically brings up containers on startup
External Non-Docker ServicesExtremely friendly (supports entering physical host IP:Ports arbitrarily in UI)Requires writing extra dynamic configuration files via File Provider
Learning CurveExtremely low, 5 minutes to get startedModerate, requires understanding Router / Middleware / Service concepts
Best ScenarioInternal DNS redirection, small projects, mixed non-containerized bare-metal environmentsPure Docker / K8s environments, high-dynamic container stacks, unattended automated deployments
