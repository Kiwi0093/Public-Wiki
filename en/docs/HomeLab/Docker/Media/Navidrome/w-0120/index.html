Bash Shell Variable Management, Special Automatic Variables, and Empty Variables

info

This article was automatically translated by Google "Gemini". The author does not guarantee its accuracy or wording.

1. Variable Definition and Assignment Conventions​

  • Basic Definition:

    VAR_NAME="value"      # Absolutely no spaces are allowed on either side of the equals sign
    echo "${VAR_NAME}"    # It is recommended to always wrap with curly braces ${} to prevent boundary ambiguity

  • Command Output Assignment (Command Substitution):

    CURRENT_USER=$(whoami)
    BACKUP_DATE=$(date +%F)

  • Variable Scope:

    • Declared as a local variable by default (restricted to the current process).
    • Declared as an environment variable via export VAR_NAME so it can be inherited by forked child processes.

4. Handling Empty and Unset Variables (Parameter Expansion)​

In shell scripts, using unassigned variables directly can easily lead to unexpected behaviors (or even disasters like root directory deletion via rm -rf /${DIR}). Using Bash parameter expansion syntax allows you to safely and gracefully set default values or exit defensively:

Syntax FormatCondition CheckHandling BehaviorPractical Examples
${var:-word}var is empty or unsetTemporarily uses word as the return value, does not change the actual content of var.PORT=${CUSTOM_PORT:-8080}
(Defaults to 8080 when unspecified)
${var:=word}var is empty or unsetAssigns word to var, and subsequently uses the new value.${DATABASE_NAME:=homelab}
(Automatically defines and stores in the variable when unset)
${var:?word}var is empty or unsetPrints the word error message to stderr and immediately forces termination of the program.DIR=${1:?"Please provide the target directory path!"}
(Aborts execution immediately if argument is missing)
${var:+word}var is set and non-emptyTemporarily replaces it with word; returns empty value if it is empty (used for existence checks).[ -n "${DEBUG:+x}" ] && echo "Debug on"

Tip: Omitting the colon (e.g., ${var-word}) triggers only when var is completely unset (Unset); including the colon (${var:-word}) covers both unset and set to an empty string "" cases. Using the colon syntax is recommended for all routine scripts.

5. Input Variables: Advanced Usage of the read Command​

The read command is used to pause in the terminal and read user keyboard input:

# Basic syntax
echo -n "Please enter project name: "
read PROJECT_NAME
echo "You entered: ${PROJECT_NAME}"

# Recommended modern single-line syntax (combining -p prompt, -t timeout, -s password hiding)
# 1. With prompt string (-p)
read -p "Please enter database name: " DB_NAME

# 2. Hidden password input (-s, prevents printing password to screen)
read -sp "Please enter connection password: " DB_PASSWORD
echo "" # Manually print newline after password input

# 3. Timeout auto-skip (-t, e.g., wait 10 seconds)
read -t 10 -p "Confirm to continue execution? (y/N): " CONFIRM
CONFIRM=${CONFIRM:-N} # Defaults to N if no input before timeout

6. Command Substitution and Safe Conditional Judgment Practice​

After storing external command output into a variable, make sure to wrap it defensively when performing comparisons:

#!/usr/bin/env bash

# 1. Capture current executor identity
CURRENT_USER=$(whoami)

# 2. Safe conditional judgment (recommended [[ ]] structure, most complete compatibility and features)
if [[ "${CURRENT_USER}" == "root" ]]; then
    echo "Success: Currently executing with root privileges"
else
    echo "Warning: Must execute this script with root privileges (current user: ${CURRENT_USER})" >&2
    exit 1
fi

# 3. Check critical path variables (defensive programming, avoiding undefined accidental deletion)
TARGET_DIR="${1:-}"

# Strict validation to avoid rm -rf /
if [[ -z "${TARGET_DIR}" ]]; then
    echo "Error: Cleanup directory not specified!" >&2
    exit 1
fi

echo "Cleaning up temporary folder: ${TARGET_DIR}..."
