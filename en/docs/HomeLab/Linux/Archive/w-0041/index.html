Oracle Linux 8 (OCI) Automated Initialization and Docker Deployment Script

info

This article was automatically translated by Google "Gemini". The author does not guarantee its accuracy or wording.

tip

My OCI architecture underwent a major overhaul later on, so this kind of all-in-one initialization script is no longer needed. As a result, this tool is obsolete and has been archived.

tip

Thanks to the generous Oracle Always Free VMs, I spun up a few VMs to run services; however, the free tier had limited OS image options, so I standardized on Oracle Linux 8 at the time.

Basic Requirements​

  • Create an additional account: Serves as a backup/rescue account.
  • Disk expansion: Expand the OS image partition to match the actual Boot Volume size (the default image is only about 50 GB, while a single free-tier instance can be configured with up to a 100 GB Boot Volume, so expansion is required).
  • Update system packages.
  • Basic installation: Install tools such as docker-ce, docker-compose (Updated 2026-11-27: Docker Compose v1 is end-of-life; modern setups should install docker-compose-plugin and use the docker compose v2 command instead).
  • Basic configuration: Pull configuration files via git clone and complete system initialization.

Updated 2026-11-27

This archived script contains several outdated practices and syntax errors and is preserved solely for historical reference:

  • Docker Compose v1 retirement: The script downloads the end-of-life docker-compose 1.29.2 binary from GitHub Releases and runs docker-compose; modern setups should install docker-compose-plugin and use the docker compose (v2) command instead. Additionally, version: '3' / version: '3.3' and links: inside Compose YAML are deprecated in v2 (services on the same network can communicate directly by service name).
  • Script syntax and configuration errors:
    • Lines 46–47 and elsewhere mistakenly use an undefined lowercase ${nc} (whereas uppercase NC='\e[0m' is declared above), causing terminal color resets to fail.
    • In v2ray.yml, the restart: unless-stopped line for the traefik service is misindented under the labels: block instead of at the service level, which causes Compose parsing errors.
    • After generating v2ray.yml, Please input the Domain for Trafik Dashboard is printed twice.
    • Uses end-of-life (EOL) traefik:v2.5, and enables both httpchallenge and tlschallenge simultaneously (only one is needed).
  • System and security recommendations: useradd -m -g root directly assigns root as the rescue account's primary group and manually copies a private key inside the script, posing significant privilege and security risks; modern practice recommends using a separate group with usermod -aG wheel to grant sudo access and authenticating via SSH public keys. Furthermore, yum on Oracle Linux 8+ is actually an alias for dnf, and the external file downloaded by the script (https://kiwi0093.github.io/script/OL8/default) is also an early archived dependency.

Basically, it updates the system, installs common tools, and deploys the Portainer Agent and Watchtower containers by default. Since I host the Portainer Master in my home lab environment, every node other than that host only needs to run the Agent.

Revision Notes​

When I use these Oracle Linux 8 hosts myself, I normally just run git clone on my private repo to spin up services. However, considering others might also use this script—and most of them need to run V2Ray (sigh... the GFW...)—I added logic to deploy V2Ray-related services directly:

  • WebSocket + TLS requires an SSL certificate, so Traefik is bundled as a foundational component.
  • Because Traefik sits at the front end, instead of using V2Ray's built-in HTTP handling directly to accept packets, an Nginx layer is wrapped around it as a reverse proxy.
  • Due to how Traefik works, be sure to configure DNS before starting the service; otherwise, if the service starts before DNS resolves properly, you will hit a Let's Encrypt error that locks out that domain name for at least 30 days (Updated 2026-11-27: Should be "Let's Encrypt"; furthermore, the failed-validation rate limit is 5 failures per hostname per hour, locking out for roughly 1 hour rather than 30 days)...
  • Because I was too lazy to write complex input validation, entering anything other than an exact Yes or No puts you into an infinite loop (and it's case-sensitive too~~~~).

Conclusion​

At the end of the day, it all comes down to a single command:

sudo su
bash <(curl -L -s https://kiwi0093.github.io/script/OL8/setup.sh)
Updated 2026-11-27

This remote installation script has been archived and retired following architectural changes. In addition, sudo su starts a new interactive root subshell, so if you copy and paste both lines at once, the second line bash <(...) will not run inside that su session. On modern systems, use sudo when you need root privileges for a single command, and avoid executing remote scripts directly without inspecting them or verifying their checksums.
