Docusaurus モダン静的ドキュメントサイト構築ガイド

1. アーキテクチャ全体像とディレクトリ構成​

標準的な Docusaurus サイトは、ドキュメント (docs)、ブログ (blog)、およびカスタム React ページ (src/pages) で構成されます。

my-website/
├── docs/                   <-- Markdown / MDX 技術ドキュメント (サイドバーのツリー構造)
│   ├── intro.md
│   └── tutorial/
├── blog/                   <-- タイムライン記事 (Blog モード、オプションで無効化可能)
├── static/                 <-- 静的アセット (画像、favicon、robots.txt)
├── src/
│   ├── css/custom.css      <-- カスタムスタイル (ダーク/ライトモード変数の上書きに対応)
│   └── pages/index.js      <-- トップページ (Landing Page)
├── docusaurus.config.js    <-- コアグローバル設定ファイル (サイト名、ルーティング、プラグイン)
├── sidebars.js             <-- サイドバー構造定義
└── package.json            <-- 依存関係管理および起動スクリプト

2. クイック初期化と基本コマンド​

2.1 プロジェクトの作成​

公式推奨の classic テンプレートの使用をおすすめします。

# Node.js 18+ を使用してプロジェクトを作成
npx create-docusaurus@latest my-website classic

cd my-website

2.2 ローカル開発とビルド​

# ローカルのリアルタイムプレビューサーバーを起動 (デフォルト Port: 3000、HMR ホットリロード対応)
npm start

# 静的ビルド成果物を生成 (build/ ディレクトリに出力、本番環境公開用)
npm run build

# ビルド後の静的ファイルをローカルでプレビュー
npm run serve

3. コア設定詳解 (docusaurus.config.js)​

設定ファイルでは、サイト全体のベース URL、ナビゲーションバー（Navbar）、フッター（Footer）、およびデフォルトプラグインを定義します。

// @ts-check
const {themes} = require('prism-react-renderer');

/** @type {import('@docusaurus/types').Config} */
const config = {
  title: 'My HomeLab Wiki',
  tagline: '自動運用とセルフホストサービス技術マニュアル',
  favicon: 'img/favicon.ico',

  // 本番環境 URL 設定
  url: 'https://wiki.example.com',
  baseUrl: '/',

  // GitHub Pages デプロイ時に使用 (GH Pages 以外では任意の値で可)
  organizationName: 'my-org',
  projectName: 'my-wiki',

  onBrokenLinks: 'throw',         // リンク切れ検出時にビルドを中断 (CI/CD でのミス防止)
  onBrokenMarkdownLinks: 'warn',

  i18n: {
    defaultLocale: 'zh-Hant',     // デフォルト言語：繁体字中国語
    locales: ['zh-Hant', 'en'],
  },

  presets: [
    [
      'classic',
      /** @type {import('@docusaurus/preset-classic').Options} */
      ({
        docs: {
          sidebarPath: './sidebars.js',
          routeBasePath: 'docs',  // ドキュメントのルートパス。'/' に変更するとサイト全体が純粋なドキュメントサイトになる
          editUrl: undefined,     // 「このページを編集」ボタンを無効化 (プライベートリポジトリ向け)
        },
        blog: false,              // 純粋な Wiki ナレッジベースとして使う場合は false でブログを無効化できる
        theme: {
          customCss: './src/css/custom.css',
        },
      }),
    ],
  ],

  themeConfig:
    /** @type {import('@docusaurus/preset-classic').ThemeConfig} */
    ({
      navbar: {
        title: 'HomeLab Wiki',
        logo: {
          alt: 'Site Logo',
          src: 'img/logo.svg',
        },
        items: [
          {
            type: 'docSidebar',
            sidebarId: 'tutorialSidebar',
            position: 'left',
            label: 'ドキュメント',
          },
          {
            href: 'https://github.com/my-org/my-wiki',
            label: 'GitHub',
            position: 'right',
          },
        ],
      },
      colorMode: {
        defaultMode: 'dark',      // デフォルトでダークモードを採用
        respectPrefersColorScheme: true,
      },
      prism: {
        theme: themes.github,
        darkTheme: themes.dracula,
        additionalLanguages: ['bash', 'yaml', 'docker', 'nginx', 'json'], // シンタックスハイライトの拡張
      },
    }),
};

module.exports = config;
Updated 2026-11-27

Docusaurus v3.9 以降、トップレベル設定の onBrokenMarkdownLinks は非推奨（v4 で削除予定）となっており、markdown.hooks.onBrokenMarkdownLinks へ移行することが推奨されています。

markdown: {
  hooks: {
    onBrokenMarkdownLinks: 'warn',
  },
},

4. ドキュメント構造とサイドバー管理 (sidebars.js)​

サイドバーには「自動生成 (Auto-generated)」と「手動宣言 (Manual)」の 2 つのモードがあります。ドキュメント数が多い Wiki では、自動生成モードを採用し、ディレクトリ構造と Markdown Frontmatter で並び順を制御することを強く推奨します。

4.1 サイドバーの自動生成 (sidebars.js)​

// @ts-check
/** @type {import('@docusaurus/plugin-content-docs').SidebarsConfig} */
const sidebars = {
  tutorialSidebar: [
    {
      type: 'autogenerated',
      dirName: '.', // docs/ ディレクトリ配下のすべてのフォルダとファイルを自動再帰スキャン
    },
  ],
};

module.exports = sidebars;

4.2 ドキュメント Frontmatter コアヘッダー制御​

各 Markdown ファイルの先頭に YAML メタデータを記述することで、サイドバーでの表示名や並び順の重みを精密に制御できます。

---
id: uptime-kuma-guide
title: Uptime Kuma 監視マニュアル
sidebar_label: Uptime Kuma 監視      # サイドバーに表示する短縮名
sidebar_position: 1                 # 並び順の重み (数字が小さいほど上位に表示)
description: クロスホストコンテナ監視とステータスページ構築
tags:
  - Docker
  - Monitoring
---

# Uptime Kuma 監視マニュアル本文...

4.3 ディレクトリグループ名の制御 (_category_.json)​

docs/ 内のサブフォルダにサイドバー上の表示名を設定するには、そのフォルダ内に _category_.json を配置します。

{
  "label": "メディアストリーミングスタック",
  "position": 2,
  "link": {
    "type": "generated-index",
    "description": "Navidrome、Emby、および Lidarr の連携ガイドを網羅しています。"
  }
}

5. MDX 拡張構文の実践​

Docusaurus では、Markdown 内で直接アドモニション（Admonitions）や React UI コンポーネントを使用できます。

5.1 アドモニション（警告・ヒントブロック）(Admonitions)​

:::tip[実用テクニック]
NFS で音楽ライブラリをマウントする際、`_netdev` オプションを付けると起動時のハングアップを防げます。
:::

:::warning[注意事項]
SQLite データベースを CIFS/SMB ネットワークドライブ上に配置しないでください。
:::

:::danger[重大な警告]
データ削除を実行する前に、必ずスナップショットバックアップを取得してください！
:::

5.2 コードブロックのタブ切り替え (Code Tabs)​

異なる OS やツール間でのコマンド対比を表示するのに適しています。

import Tabs from '@theme/Tabs';
import TabItem from '@theme/TabItem';

<Tabs>
  <TabItem value="photon" label="Photon OS" default>

```bash
tdnf -y install cifs-utils
```

  </TabItem>
  <TabItem value="debian" label="Debian / Ubuntu">

```bash
apt-get update && apt-get install -y cifs-utils
```

  </TabItem>
</Tabs>

6. ローカル全文検索エンジンの統合（外部依存なし）​

Docusaurus 公式ではデフォルトで Algolia が推奨されていますが、内部向けのプライベートナレッジベースを構築する場合、外部クローラーがアクセスできません。コミュニティで最も成熟したオフラインソリューションは @easyops-cn/docusaurus-search-local です。

ステップ 1：オフライン検索プラグインのインストール​

npm install @easyops-cn/docusaurus-search-local

ステップ 2：docusaurus.config.js にプラグインを登録​

// config オブジェクトに themes ブロックを追加：
themes: [
  [
    require.resolve('@easyops-cn/docusaurus-search-local'),
    /** @type {import("@easyops-cn/docusaurus-search-local").PluginOptions} */
    ({
      hashed: true,
      language: ['zh', 'en'],       // 中国語・英語の分かち書き検索に対応
      indexDocs: true,
      indexBlog: false,
      docsRouteBasePath: '/docs',
    }),
  ],
],

設定完了後、npm run build を実行するとローカルで自動的にインデックスファイルが生成され、サイト上部にオフライン検索バーが表示されます。

7. 本番環境デプロイ構成​

Docusaurus はビルド後、純粋な静的ファイル（build/ ディレクトリに出力）となるため、一般的なセルフホスト構成では Docker Nginx コンテナ または Traefik v3 との組み合わせが用いられます。

7.1 Dockerfile マルチステージビルド (Multi-stage Build)​

Dockerfile を作成し、Node コンテナでビルドした成果物を Alpine Nginx で配信することで、イメージサイズを約 20MB に抑えられます。

# Stage 1: Build
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Serve
FROM nginx:alpine
COPY --from=builder /app/build /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
Updated 2026-11-27

node:20-alpine が属する Node.js 20 は 2026-04-30 をもって公式サポート期間（EOL）を終了しました。ビルドステージのベースイメージは、サポート期間内の LTS バージョン（node:22-alpine や node:24-alpine など）へ変更することを推奨します。

対応する nginx.conf：

server {
    listen 80;
    server_name localhost;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静的アセットの Gzip 圧縮を有効化
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml image/svg+xml;
}

7.2 Docker Compose + Traefik v3 統合テンプレート​

services:
  wiki:
    build: .
    container_name: docusaurus-wiki
    restart: unless-stopped
    networks:
      - proxy-network
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.wiki.rule=Host(`wiki.example.com`)"
      - "traefik.http.routers.wiki.entrypoints=websecure"
      - "traefik.http.routers.wiki.tls=true"
      - "traefik.http.routers.wiki.tls.certresolver=myresolver"
      - "traefik.http.services.wiki.loadbalancer.server.port=80"

networks:
  proxy-network:
    external: true

8. よくあるトラブルシューティング (Troubleshooting)​

異常現象根本原因対処方法
npm run build で Docusaurus found broken links! が発生する本文中のページ間リンクのパスが誤っている、または参照しているアンカー（Anchor）が存在しない。ログに出力されたファイル行番号をもとにパスを修正するか、一時的に docusaurus.config.js で onBrokenLinks を 'warn' に変更する。
Markdown に特殊文字が含まれビルドに失敗するMDX パーサーが < や { を JSX タグやコード変数として誤認識している。インラインコードのバッククォートで囲む（例：`<Your_IP>`）か、HTML エンティティ文字参照に置き換える。
中国語文字列が検索にヒットしない検索プラグインに中国語の分かち書き辞書が含まれていない。@easyops-cn/docusaurus-search-local の設定に language: ["zh", "en"] が含まれているか確認する。
ダークモードでカスタムスタイルのレイアウトが崩れるCSS にカラーコードを直接ハードコードしており、グローバル CSS 変数を上書きしていない。src/css/custom.css を編集し、[data-theme='dark'] セレクタ内で --ifm-color-primary などのテーマ変数を上書きする。
