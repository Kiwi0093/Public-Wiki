Docusaurus + GitHub Actions による自動ビルドと GitHub Pages デプロイ

1. 自動デプロイの構成トポロジー​

現在、GitHub Pages は以下の 2 つの公開方式をサポートしています。

  1. GitHub Actions ネイティブ Artifact 公開（推奨）：ビルド成果物（build/）をバイナリアーカイブ形式で GitHub Pages の基盤インフラに直接送信します。リポジトリ内にビルド済みファイルが混在する gh-pages ブランチを別途管理する必要がなく、クリーンかつ極めて高速に実行できます。
  2. 従来のブランチ上書き公開（gh-pages ブランチ）：Action によって gh-pages ブランチを自動作成し、静的成果物をそのブランチへ commit します。

2. 事前準備：リポジトリと docusaurus.config.js の URL 設定の整合​

Docusaurus はビルド時に url と baseUrl に基づいてすべてのアセット（CSS、JS、画像）の絶対パスを厳密に計算します。パス設定の誤りは、GitHub Pages 公開後にスタイルが崩れる（レイアウト崩れ）ことや 404 エラーが発生する最も一般的な原因です。

2.1 URL 設定の計算ルール​

GitHub アカウントが kiwihome、リポジトリ名が kiwi-wiki であると仮定した場合：

  • url：https://kiwihome.github.io（独自ドメインを紐付ける場合は https://wiki.example.com のように独自ドメインを指定）
  • baseUrl：/<リポジトリ名>/（前後に必ずスラッシュが必要。例：/kiwi-wiki/。独自トップレベルドメインを使用する場合は '/' に変更する必要があります）
  • organizationName：GitHub の Organization 名または個人アカウント名
  • projectName：リポジトリ名
  • trailingSlash：末尾のスラッシュの有無を明示的に指定します（false に設定することを推奨。GitHub Pages 上で特定のアンカーリンクの遷移が失敗するのを防げます）

プロジェクトルートディレクトリの docusaurus.config.js を編集します。

// @ts-check

/** @type {import('@docusaurus/types').Config} */
const config = {
  title: 'My HomeLab Wiki',
  tagline: '自動化維運與技術文件庫',
  favicon: 'img/favicon.ico',

  // 核心路徑宣告 (依據專案嚴格替換)
  url: 'https://<USERNAME>.github.io',
  baseUrl: '/<REPO_NAME>/',

  organizationName: '<USERNAME>',
  projectName: '<REPO_NAME>',
  trailingSlash: false,

  onBrokenLinks: 'throw',         // 遇到死連結直接中斷 Build，防止髒資料上線
  onBrokenMarkdownLinks: 'warn',

  // ... 其餘主題與外掛配置保持不變
};

module.exports = config;
Updated 2026-11-27

Docusaurus 3.9 以降では、トップレベルの onBrokenMarkdownLinks オプションは非推奨（Deprecated）とマークされているため、markdown: { hooks: { onBrokenMarkdownLinks: 'warn' } } へ移行して設定することを推奨します。

3. GitHub リポジトリコンソールでの初回権限設定​

Workflow を push する前に、GitHub リポジトリの Web 画面で権限の許可設定を行っておく必要があります。

  1. 対象の GitHub リポジトリを開きます。
  2. 上部ナビゲーションバーの Settings をクリックします。
  3. 左側のメニューから Pages（Code and automation セクション内）を開きます。
    • Build and deployment -> Source：デフォルトの Deploy from a branch から GitHub Actions に切り替えます。
  4. 左側のメニューから Actions -> General をクリックします。
    • Workflow permissions セクションまでスクロールします。
    • Read and write permissions（読み取りおよび書き込み権限）が選択されていることを確認します。
    • Allow GitHub Actions to create and approve pull requests（表示されている場合）にチェックを入れ、Save をクリックします。

4. GitHub Actions ワークフロー設定ファイル​

ローカルのプロジェクトルートディレクトリに .github/workflows/deploy.yml ファイルを作成します。

方式 A：モダンなネイティブ Pages デプロイ（強く推奨、ブランチ汚染なし）​

この構成では GitHub 公式の upload-pages-artifact と deploy-pages モジュールを使用します。Personal Access Token（PAT）を作成する必要はなく、Runner 組み込みの短命な OIDC トークンによって安全にデプロイされます。

name: Deploy Docusaurus to GitHub Pages

on:
  push:
    branches:
      - main # 觸發分支，若專案預設為 master 請自行調整

# 嚴格定義 Workflow 權限
permissions:
  contents: read      # 讀取儲存庫程式碼
  pages: write         # 寫入 GitHub Pages 產物
  id-token: write      # 用於 OIDC 認證完成免金鑰部署

# 避免多個 commit 同時推送時產生並發衝突，自動取消前一個未完成的任務
concurrency:
  group: 'pages'
  cancel-in-progress: false

jobs:
  build:
    name: Build Docusaurus
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          # fetch-depth: 0 代表抓取完整 Git 歷史紀錄
          # 關鍵：若設為 1，Docusaurus 將無法獲取文件的「最後編輯時間」與「作者資訊」
          fetch-depth: 0

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm # 自動快取 ~/.npm 目錄，大幅加速 npm ci 時間

      - name: Install dependencies
        # 使用 npm ci 取代 npm install，依據 package-lock.json 嚴格還原版本
        run: npm ci

      - name: Build website
        # 編譯產生靜態 build/ 目錄
        run: npm run build

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: build/ # 指定 Docusaurus 的編譯輸出目錄

  deploy:
    name: Deploy to GitHub Pages
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
Updated 2026-11-27
  1. 上記 YAML 内のコメント「自動取消前一個未完成的任務（実行中の前回タスクを自動キャンセルする）」は、実際の設定 cancel-in-progress: false と逆の内容になっています。false を指定した場合は、実行中のデプロイタスクが完了するまで後続タスクがキューで待機します（これはデプロイ途中の強制中断を防ぐための GitHub 公式の推奨設定です）。
  2. node-version: 20：Node.js 20 は 2026-04-30 にサポート終了（EOL）となっているため、現行の LTS バージョン（22 や 24 など）への変更を推奨します。

方式 B：従来の gh-pages ブランチへの push（旧構成との互換用）​

組織やプロジェクトの規約上、ブランチ一覧に実体ファイルや commit 履歴を残す必要がある場合は、Docusaurus 公式組み込みの CLI デプロイスクリプトを使用できます。

name: Deploy to gh-pages Branch

on:
  push:
    branches:
      - main

permissions:
  contents: write # 必須具備對倉庫的寫入權限以建立分支

jobs:
  deploy:
    name: Deploy via Docusaurus CLI
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Deploy to gh-pages
        run: |
          git config --global user.name "github-actions[bot]"
          git config --global user.email "github-actions[bot]@users.noreply.github.com"
          npx docusaurus deploy
        env:
          # 使用內建的 GITHUB_TOKEN，無需手動配置 Secret
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
Updated 2026-11-27

node-version: 20：Node.js 20 は 2026-04-30 にサポート終了（EOL）となっているため、現行の LTS バージョン（22 や 24 など）への変更を推奨します。

5. 独自ドメイン (Custom Domain) と HTTPS 設定​

この Wiki に独自のドメイン（例：wiki.example.com）を紐付ける場合の手順です。

ステップ 1：CNAME 静的ファイルの作成​

プロジェクトの static/ ディレクトリ配下に CNAME という名前のプレーンテキストファイル（拡張子なし）を新規作成し、ドメイン名を記述します。

wiki.example.com

static/ 配下に置かれたファイルは、ビルド時にそのまま build/ のルートディレクトリへ自動的にコピーされます。

ステップ 2：docusaurus.config.js の修正​

  url: 'https://wiki.example.com',
  baseUrl: '/',                     // 綁定自訂網域後，baseUrl 必須改回根路徑 '/'

ステップ 3：DNS 設定（Cloudflare / DNS プロバイダを例として）​

DNS 管理画面で CNAME レコードを 1 件追加します。

  • 名前 (Name)：wiki
  • ターゲット (Target)：<USERNAME>.github.io
  • プロキシステータス：Cloudflare を使用している場合、初回証明書発行時は DNS Only（灰色の雲） にしておくことを推奨します。GitHub が Let's Encrypt 証明書を正常に発行し、「Enforce HTTPS」を有効化した後にオレンジ色の雲（プロキシ有効）に切り替えるか検討してください。

6. よくあるトラブルシューティング (Troubleshooting)​

6.1 Action のビルドが失敗し、ログに Docusaurus found broken links! と表示される​

  • 原因：Docusaurus にはデフォルトでビルド時のリンク切れチェック機能があり、Markdown 本文内で存在しないファイル名、誤った相対パス、または存在しない見出しアンカー（#section-title）を参照していると、ビルドが強制中断されます。
  • 対処法：
    1. Action の実行ログを確認します。どのファイルの何行目でリンク切れが発生しているかが明確に出力されます。
    2. 該当パスを修正します。下書き段階のページであれば、その Markdown の Frontmatter に draft: true を追加してビルド対象から除外することもできます。

6.2 デプロイ完了後にサイトへアクセスすると画面が真っ白になり、Console に 404 が大量に出る​

  • 原因：baseUrl と GitHub リポジトリ名が一致していません。たとえばリポジトリ名が my-wiki なのに baseUrl が '/' のままだと、ブラウザは https://<User>.github.io/my-wiki/assets/css/... ではなく https://<User>.github.io/assets/css/... からアセットを取得しようとしてしまいます。
  • 対処法：docusaurus.config.js を確認し、baseUrl: '/<REPO_NAME>/' のように前後にスラッシュが入っていることをチェックします。

6.3 Action で Permission to ... denied to github-actions[bot] エラーが出る​

  • 原因：リポジトリで Actions の書き込み権限が有効になっていません。
  • 対処法：リポジトリの Settings -> Actions -> General -> Workflow permissions へ進み、Read and write permissions に切り替えて Save をクリックします。

6.4 ローカルでは npm start が動くが、Actions の npm run build でメモリ不足 (OOM) が発生する​

  • 原因：ドキュメント数が数百ページ以上に達すると、Node.js のデフォルトヒープメモリ上限（約 1.5GB）が Webpack ビルド処理中に枯渇します。

  • 対処法：Workflow のビルドステップに Node の環境変数を追加してメモリ上限を引き上げます。

        - name: Build website
          run: npm run build
          env:
            NODE_OPTIONS: "--max-old-space-size=4096"
