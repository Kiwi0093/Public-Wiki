SSH 鍵認証と接続設定の基礎

ヒント

現在、Key Pair 認証を必須とする SSH 環境が増えており、Git、Ansible、Oracle Cloud の VM などいずれも鍵による接続が求められます。そのため、関連するよく使うコマンドや設定をここにまとめました。

Key Pair の生成​

Linux / FreeBSD ターミナルでの鍵生成​

基本コマンドは ssh-keygen です。よく使うオプションを組み合わせることで、鍵長、アルゴリズム、出力ファイル名をカスタマイズできます。

# Basic from man ssh-keygen
ssh-keygen [-q] [-a rounds] [-b bits] [-C comment] [-f output_keyfile] [-m format] [-N new_passphrase] [-O option] [-t dsa | ecdsa | ecdsa-sk | ed25519 | ed25519-sk | rsa] [-w provider] [-Z cipher]
     ssh-keygen -p [-a rounds] [-f keyfile] [-m format] [-N new_passphrase] [-P old_passphrase] [-Z cipher]
     ssh-keygen -i [-f input_keyfile] [-m key_format]
     ssh-keygen -e [-f input_keyfile] [-m key_format]
     ssh-keygen -y [-f input_keyfile]
     ssh-keygen -c [-a rounds] [-C comment] [-f keyfile] [-P passphrase]
     ssh-keygen -l [-v] [-E fingerprint_hash] [-f input_keyfile]
     ssh-keygen -B [-f input_keyfile]
     ssh-keygen -D pkcs11
     ssh-keygen -F hostname [-lv] [-f known_hosts_file]
     ssh-keygen -H [-f known_hosts_file]
     ssh-keygen -K [-a rounds] [-w provider]
     ssh-keygen -R hostname [-f known_hosts_file]
     ssh-keygen -r hostname [-g] [-f input_keyfile]
     ssh-keygen -M generate [-O option] output_file
     ssh-keygen -M screen [-f input_file] [-O option] output_file
     ssh-keygen -I certificate_identity -s ca_key [-hU] [-D pkcs11_provider] [-n principals] [-O option] [-V validity_interval] [-z serial_number] file ...
     ssh-keygen -L [-f input_keyfile]
     ssh-keygen -A [-a rounds] [-f prefix_path]
     ssh-keygen -k -f krl_file [-u] [-s ca_public] [-z version_number] file ...
     ssh-keygen -Q [-l] -f krl_file file ...
     ssh-keygen -Y find-principals [-O option] -s signature_file -f allowed_signers_file
     ssh-keygen -Y check-novalidate [-O option] -n namespace -s signature_file
     ssh-keygen -Y sign -f key_file -n namespace file ...
     ssh-keygen -Y verify [-O option] -f allowed_signers_file -I signer_identity -n namespace -s signature_file [-r revocation_file]

# 基本的に使う機能は次の数個だけです
-b 鍵長を指定します。rsa のデフォルトは 3072 で、実用上十分です
-t 暗号方式です。dsa | ecdsa | ecdsa-sk | ed25519 | ed25519-sk | rsa から選べますが、一般的なチュートリアルでは rsa が推奨されています
-C この Comment には対応するメールアドレスなどを指定できます
-f 出力される key pair のファイル名を指定できます

一般的な作成方法は以下の通りです。

ssh-keygen -b 4096 -t rsa -f <server_or_service_name>

実行すると、~/.ssh/ 内に <server_or_service_name>（秘密鍵）と <server_or_service_name>.pub（公開鍵）の 2 つのファイルが生成されます。

Updated 2026-11-27
  1. dsa（-t dsa）は OpenSSH 9.8 からデフォルトで無効化され、OpenSSH 10.0（2025）で正式にサポートが削除されたため、今後は使用しないでください。
  2. 現在の実務では ed25519（例：ssh-keygen -t ed25519 -f <server_or_service_name>）の使用が広く推奨されています。鍵長が短く、安全性が高く、計算も高速です。極めて古いバージョンの OpenSSH サーバーとの互換性が必須な場合にのみ、4096 ビットの rsa にフォールバックしてください。

Windows（PuTTYgen を使用）​

手順は基本的に同じです。右下でビット数と鍵の種類を設定した後、Generate をクリックすると Private Key と Public Key が生成されます。

Linux 環境での PPK から PEM への変換​

Linux デスクトップ環境（Manjaro など）で直接接続する必要がある場合、Manjaro では putty をインストールすると puttygen も同時に含まれます。Ubuntu / Debian を使用している場合は、別途ツールパッケージをインストールする必要があります。

# PuTTY ツールのインストール
apt install putty-tools

インストール完了後、.ppk を OpenSSH で使用する .pem 形式に変換できます。

# .ppk ファイルを ssh client で直接使える .pem ファイルに変換
puttygen yourkey.ppk -O private-openssh -o yourkey.pem

変換後は以下のコマンドでログインできます（秘密鍵のパーミッションが 600 であることを確認してください）。

# pem を使用してログイン
ssh -i /your/key/file user@hostname.or.ip

サーバー側の公開鍵配置（Public Key @ Server side）​

公開鍵をリモートサーバーに配置するには、主に 2 つの方法があります。

シンプルなコピー＆ペースト​

対象アカウントの ~/.ssh/authorized_keys に公開鍵の内容を直接貼り付けます。vi で編集するか、コマンドで追記できます。

cat <server_or_service_name>.pub >> ~/.ssh/authorized_keys

ただし、実務では事前に <server_or_service_name>.pub を対象ホストへ手動アップロードするのが面倒なため、この方法はあまり使われません。

PuTTYgen 鍵変換（PEM から PPK へ）​

従来の PuTTY は一般的な .pem 秘密鍵ファイルを直接読み込めないため、Windows から PuTTY 経由で sshd に接続したい場合は、インポートして .ppk 形式で保存し直すことができます。

秘密鍵を読み込んだ後、保護用のパスフレーズ（Passphrase）を設定できます。

任意のパスワードを入力し、Save private key を選んで .ppk ファイルとして保存すれば完了です。

ssh-copy-id​

ssh-copy-id -i ~/.ssh/<server_or_service_name>.pub USER@HOST

ssh-copy-id はデフォルトで ~/.ssh/id_rsa.pub を読み込むため、任意のファイル名を使う場合は -i で公開鍵のパスを指定する必要があります。アップロードが完了し、パスワードなしでログインできることを確認したら、サーバー側の sshd_config を編集してパスワードログインを無効化できます。

サーバー側設定（sshd_config）​

クライアント側の鍵の準備に加え、サーバー側の /etc/ssh/sshd_config でもセキュリティ設定を強化しておくのが一般的です。

# root アカウントによる ssh ログインを禁止
PermitRootLogin no
# 基本的には root のリモートログイン拒否が推奨されますが、ansible を使う場面では root アカウントをそのまま使う以外の方法がどれも煩雑になりがちなので、ここは慎重に検討してください

# Public Key 認証方式を許可
PubkeyAuthentication yes

# デフォルトの Public Key の場所とファイル名
AuthorizedKeysFile      .ssh/authorized_keys
# ここは変更可能ですが、通常は変更せずにそのまま使います

# 組み込みのパスワード認証システムを使用せず、空パスワードも禁止
PasswordAuthentication no
PermitEmptyPasswords no

# パスワード認証ログインを禁止
ChallengeResponseAuthentication no
UsePAM no

# 特定 User 向けの設定（このセクション全体は sshd_config の末尾にのみ配置可能）
Match <User1>, <User2>, ...
# 続いてそれらの User の設定を定義します。例：
    PasswordAuthentication yes
# これにより User1 と User2 のみパスワードログインが可能になり、その他は不可になります
Updated 2026-11-27
  1. ChallengeResponseAuthentication は OpenSSH 8.7 から非推奨となっており、新しいバージョンでは KbdInteractiveAuthentication no に変更する必要があります。
  2. Match ブロックでは条件キーワードを指定する必要があり、カンマ区切りリストに空白を含めることはできません。正しい記述は Match User user1,user2 です（元の例 Match <User1>, <User2> は User キーワードが欠落しており空白も含まれているため、sshd の設定構文エラーになります）。
  3. 現代の Linux（systemd を併用する環境など）では、アカウントセッションやリソース制限を正常に機能させるため UsePAM yes を維持し、PasswordAuthentication no と KbdInteractiveAuthentication no のみをオフにしてパスワードログインを無効化することが推奨されます。

クライアント接続コマンド（SSH）​

基本的な接続コマンドは以下の通りです。

ssh USER@HOST

特定の秘密鍵ファイルを指定したい場合は、-i オプションを追加します。

ssh -i /location/private_key USER@HOST

SSH 認証は秘密鍵を証明として用いるため、よく使うクライアントホスト上に同じ秘密鍵を適切に保管し、正しいパーミッションを設定しておけば問題なく接続できます。
