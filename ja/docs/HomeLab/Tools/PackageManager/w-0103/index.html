Node.js 現代的パッケージおよび環境管理の実用メモ

一、 はじめに：OS 標準のコマンドで Node.js をインストールしてはいけない理由​

Linux (apt/dnf) や macOS で、sudo apt install nodejs や sudo npm install -g xxx を直接実行するのは避けるべきです。これには 2 つの大きな問題があります：

  1. バージョンが古い： OS の標準リポジトリにある Node.js は、数メジャーバージョン遅れていることがよくあります。
  2. 権限地獄： グローバルにパッケージをインストールするたびに EACCES 権限エラーが発生し、やむなく sudo を付けて npm を実行する羽目になります。これはセキュリティ上も環境管理上も悪手です。

現代の標準的な方法：バージョンマネージャー (Version Manager) を使用する

  • 定番の第一選択：NVM (Node Version Manager) 長年使われており最も普及しています。インストール方法：

    curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

    よく使うコマンド：

    nvm install 20       # Node.js v20 (LTS) をインストール
    nvm use 20           # v20 に切り替え
    nvm alias default 20 # デフォルトバージョンを設定
    nvm ls-remote        # インストール可能な全バージョンを表示

  • 超高速な新星：fnm (Fast Node Manager) 🌟 Rust 製で、nvm より数十倍高速に動作し、ターミナルの起動時間を遅延させません。さらにクロスプラットフォームをネイティブサポートしています。新しい環境ではこちらへの移行を強くおすすめします：

    # スクリプト経由でインストール
    curl -fsSL https://fnm.vercel.app/install | bash

    # 基本コマンドは nvm とほぼ同じ
    fnm install 20
    fnm default 20
Updated 2026-11-27

上記の例にある NVM のバージョン（v0.39.7）および Node.js v20 は現在すでに古くなっています（Node.js 20 は 2026 年 4 月にサポート終了 EOL となりました）。実際には NVM 公式 GitHub Releases で最新バージョンを確認し、--lts（例：nvm install --lts、fnm install --lts）または現行の LTS バージョン（Node.js 22 / 24 など）を使用してください。

二、 現代のパッケージマネージャー三国志：npm / yarn / pnpm​

Node.js を用意したら、次はパッケージマネージャーの選択です：

  1. npm (Node Package Manager)： Node.js に標準搭載されており、堅実です。
  2. Yarn： Facebook が開発し、かつては高速さと lockfile の導入で一世を風靡しましたが、現在は v1 と v2+ の世代交代でやや分かりにくくなっています。
  3. pnpm (Performant npm)：🌟 現代では強く推奨！ 「ハードリンク (Hard link)」の仕組みを利用し、同じパッケージはマシン全体のディスク上に 1 つだけ保存されます。たとえばパソコンに React を使うプロジェクトが 10 個あっても、npm は 10 個分コピーしますが、pnpm は 1 つだけ保存してリンクを張ります。ディスク容量を大幅に節約でき、インストール速度も非常に高速です。

pnpm の有効化／インストール： 比較的新しい Node.js バージョンでは、これらのツールを管理する corepack が標準で同梱されています：

# corepack を有効化して pnpm を準備
corepack enable pnpm
Updated 2026-11-27

Node.js 25 以降、公式ディストリビューションには corepack がデフォルトで同梱されなくなりました。corepack 実行時にコマンドが見つからない場合は、pnpm 公式のスタンドアロンインストールスクリプト（curl -fsSL https://get.pnpm.io/install.sh | sh -）を使うか、先に npm install -g corepack でインストールしてから有効化してください。

(注：以降の基本コマンドは業界で最も一般的な npm を例に説明しますが、オプションの考え方は多くが pnpm と共通です)

三、 基本メンテナンス：プロジェクト内のパッケージ管理​

Node.js では、パッケージは基本的にプロジェクトフォルダ単位で管理され、設定ファイルは package.json になります。

1. 初期化とインストール

# 新しいプロジェクトを初期化（package.json を生成）
npm init -y

# package.json に基づいてすべての依存関係を一括インストール
npm install
# (pnpm の場合は pnpm install または pnpm i を実行)

# 特定のパッケージをインストールして dependencies に記録（本番環境で必要）
npm install axios

# パッケージをインストールして devDependencies に記録（eslint や typescript など開発環境のみで必要）
npm install -D typescript

2. 削除とアップデート

# パッケージを削除して package.json を自動更新
npm uninstall axios

# 現在のプロジェクトで古くなっているパッケージを確認
npm outdated

# package.json で許可されている範囲の最新マイナー／パッチバージョンへ更新
npm update

四、 グローバル汚染を防ぐ強力なツール：npx​

以前は Vue CLI、Create React App、TypeScript コンパイラなどの CLI ツールを使うために、npm install -g create-react-app のようにグローバルインストールするのが一般的でした (非推奨)。

現在の標準的なやり方は npx (Node Package Execute) を使うことです。「インストール不要」でクラウドから最新の CLI ツールを直接取得して実行し、使い終わったら跡形もなく片付けてくれます：

# 最新版の create-react-app を一時的にダウンロードして実行し、完了後にクリーンアップ
npx create-react-app my-project

# プロジェクト内にすでに typescript（ローカルパッケージ）が入っている場合は、npx でそのまま呼び出し可能
npx tsc --init
Updated 2026-11-27

create-react-app は 2025 年 2 月に React 公式から正式に非推奨（Deprecated）と発表されました。新規の React プロジェクトを作成する場合は npm create vite@latest または公式推奨のモダンフレームワーク（Next.js、React Router など）を使用してください。

五、 容量のクリーンアップ：肥大化したディスクを救う​

悪名高い node_modules はディスク容量のキラーであり、放置すると数十〜百 GB 単位で容量を食い潰します。

1. npm グローバルキャッシュの削除 毎回ダウンロードされたアーカイブはキャッシュに残ります。パッケージ破損エラー（npm ERR! cb() never called など）に遭遇した際も、この方法で解決できることがあります：

npm cache clean --force

2. 全プロジェクトの node_modules を一括整理（ディスク救世主） 年季の入ったプロジェクトが大量にある場合、サードパーティのオープンソースツール npkill が便利です。高速な TUI（テキストベースの UI）でマシン内のすべての node_modules をリストアップし、スペースキーでサクッと削除できます。

# npx で都度実行し、環境を汚さない
npx npkill

六、 応用：Docker と CI/CD のベストプラクティス (npm ci)​

Dockerfile を記述したり、GitLab CI / GitHub Actions で自動デプロイを構築したりする際は、絶対に npm install を使ってはいけません。

本番環境では、開発時と「完全に同じ」バージョンのパッケージが入ることを保証する必要があります。npm install は気を利かせてマイナーバージョンなどを勝手に上げてしまうことがあります。

本番環境で唯一指定すべきコマンド：

npm ci

npm ci (Clean Install) の特徴：

  1. package-lock.json で固定されたバージョンを厳密に読み込み、100% の一致を保証する。
  2. 実行前に既存の node_modules を強制的に削除してから入れ直すため、クリーンな環境を保てる。
  3. package.json と lock ファイルの内容が食い違っている場合、lock ファイルを勝手に書き換えるのではなく、即座にエラーを出して停止する。
  4. インストール速度が通常 npm install の 2 倍以上高速。

Dockerfile の例：

COPY package*.json ./
# 本番環境では npm ci の使用を強く推奨
RUN npm ci --only=production
COPY . .
Updated 2026-11-27

--only=production は新しいバージョンの npm では非推奨フラグ（Deprecated）とされているため、代わりに RUN npm ci --omit=dev を使用することをおすすめします。
