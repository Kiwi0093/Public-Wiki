Portainer-CE と Portainer Agent によるマルチノード集中管理

1. アーキテクチャ概要とポートの役割​

Portainer は典型的な Server-Agent アーキテクチャを採用しています。

ポート (Ports) 役割早見表​

  • 9443 (TCP)：モダンな Portainer-CE のデフォルト HTTPS 管理インターフェース（旧版の 9000 は非暗号化 HTTP であり、現行バージョンでは 9443 への全面移行が強く推奨されています）。
  • 9001 (TCP)：Portainer Agent 通信ポート。Agent が管理対象ノード側でこのポートを待ち受け、Server からの接続を受け付けます（双方向 mTLS 暗号化に対応）。
  • 8000 (TCP)：Edge Agent リバーストンネル待ち受けポート（Edge Tunnel Server）。管理対象ノードが NAT 内や外部からの接続を厳格に遮断するファイアウォール配下にある場合、Edge Agent から Server の 8000 番ポートへ向けて能動的にトンネルを確立します。

2. 中央管理側のデプロイ：Portainer-CE Server​

データボリューム、自動再起動、リバースプロキシ統合を管理しやすくするため、docker-compose.yml での運用を推奨します。

ステップ 1：専用ディレクトリと永続化ボリュームの作成​

mkdir -p /opt/portainer/data
cd /opt/portainer

ステップ 2：docker-compose.yml の設定​

services:
  portainer:
    image: portainer/portainer-ce:latest
    container_name: portainer
    restart: unless-stopped
    ports:
      - "9443:9443"  # 官方標準 HTTPS 介面
      - "8000:8000"  # Edge Agent 邊緣通道（若有需要接入內網節點再開）
    volumes:
      - /etc/localtime:/etc/localtime:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - /opt/portainer/data:/data
    networks:
      - portainer-net

networks:
  portainer-net:
    driver: bridge

サービスを起動します：

docker compose up -d

セキュリティタイムアウト機構の注意：Portainer-CE を初回起動した後、5 分以内 にブラウザで https://<Server_IP>:9443 へアクセスし、初期管理者アカウントとパスワードを設定する必要があります。時間切れになると不正な乗っ取りを防ぐためにシステムが強制終了するため、その場合はコンテナを再起動（docker compose restart）してタイマーをリセットしてください。

3. 管理対象ノードのデプロイ：Portainer Agent​

管理下に組み込みたい各 VPS / ノード上に portainer/agent をデプロイします。

3.1 docker-compose.yml によるデプロイ（被管理側 VPS）​

/opt/portainer-agent/docker-compose.yml を作成します：

services:
  agent:
    image: portainer/agent:latest
    container_name: portainer_agent
    restart: always
    ports:
      - "9001:9001"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - /var/lib/docker/volumes:/var/lib/docker/volumes
    # 關閉不必要的特權模式，僅依賴 socket 與 volumes 即可

Agent を起動します：

docker compose up -d

3.2 重要なマウントポイントの説明​

  • /var/run/docker.sock:/var/run/docker.sock：Agent がホストの Docker API を呼び出し、コンテナの稼働状態をリアルタイムで返却したり、管理コマンドを転送したりできるようにします。
  • /var/lib/docker/volumes:/var/lib/docker/volumes：管理側の Web UI で「Volumes」を選択した際、ボリューム内のファイルを直接閲覧・ダウンロード・アップロードできるようにします。

4. Portainer Server 画面でのリモートノード追加 (Environments)​

  1. Portainer Server の Web 画面にログインします。
  2. 左側ナビゲーションバーの Environments -> Add environment をクリックします。
  3. Docker Standalone を選択し、Start Wizard をクリックします。
  4. Portainer Agent を選択します：
    • Name：識別名を入力します（例：VPS-Tokyo-01）。
    • Environment address：リモート管理対象ノードの IP とポート番号を <VPS_IP>:9001 の形式で入力します。
  5. Connect をクリックします。
  6. 接続に成功するとホーム画面の一覧にそのリモート VPS が表示され、クリックするだけでローカルホストを操作するのと同じようにそのマシンの Containers、Images、Networks、Volumes を管理できるようになります。

5. パブリック環境でのセキュリティ強化 (Security Hardening)​

Portainer や Agent をパブリックネットワーク上の VPS に公開する場合、適切な保護を行わないとサーバーの Root 権限を明け渡すのと同じことになります。

5.1 Agent (Port 9001) の接続元 IP を厳格に制限する​

portainer/agent 自体にも接続ペアリング認証がありますが、管理対象側 VPS のファイアウォール（ufw またはクラウドのセキュリティグループ）で、Portainer Server のパブリック IP からのみ 9001 番ポートへのアクセスを許可する よう制限することを強く推奨します：

# 在被控端 VPS 執行（以 UFW 為例）：
sudo ufw default deny incoming
sudo ufw allow ssh
# 僅允許中央 Server IP 存取 9001
sudo ufw allow from <PORTAINER_SERVER_IP> to any port 9001 proto tcp
sudo ufw reload

5.2 固定パブリック IP がない場合の代替策：Edge Agent（能動アウトバウンドモード）​

管理対象が動的 IP や NAT 内にある場合、または 9001 番ポートを外部へ開放したくない場合は、代わりに Edge Agent を使用します：

  1. Server 側で Environment を追加する際に Edge Agent を選択します。
  2. キー（Edge ID / Key）付きの docker run コマンドが自動生成されます。
  3. 管理対象側でそのコマンドを貼り付けて実行すると、被管理側から Server の Port 8000 へ向けて安全なリバース接続が確立されるため、被管理側では 外部からのインバウンドポートを一切開放する必要がありません。

5.3 リバースプロキシ統合 (Traefik v3 / NPM)​

正規の SSL 証明書を取得するために Server 側をリバースプロキシ配下に置く場合は、以下の点に注意してください：

  • WebSocket サポート：Portainer の Web ターミナル（Exec Console）は WebSocket に依存しているため、リバースプロキシ側で接続のアップグレードを保持する必要があります（NPM の場合は必ず Websockets Support にチェックを入れてください）。
  • プロキシ先ポート：NPM / Traefik と Portainer が同じ Docker ネットワーク上にある場合は、http://portainer:9000 へ直接リバースプロキシする（イメージが内部 HTTP を引き続きサポートしている場合）か、自己署名証明書（self-signed）を無視する設定で https://portainer:9443 へリバースプロキシすることを推奨します。
