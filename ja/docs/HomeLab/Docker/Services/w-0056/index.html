Heimdall アプリケーション・ポータルサイトの構築

1. 基本位置づけとアーキテクチャ設計​

  • ポータル・エントリーポイント：イントラネット内に散在する各種ポート（Portainer :9443、LibreNMS :8000、Node-RED :1880、Nextcloud など）を視覚的なカードとして一箇所に集約します。
  • SSL オフロード構成：通常はフロントエンドの NPM / Traefik が HTTPS 証明書を処理するため、Heimdall 自体は外部向けに 443 番ポートを公開する必要が一切なく、内部で 80 番ポートを待ち受けるだけで済みます。これにより証明書管理の負担を省けます。
  • データ永続化：ユーザー設定、カード配置、カスタムアイコン、および内蔵 SQLite データベースはすべてコンテナ内の /config ディレクトリに保存されます。

2. Docker Compose によるモダンなデプロイ​

ステップ 1：永続化ディレクトリの作成と権限設定​

sudo mkdir -p /opt/heimdall/config
sudo chown -R 1000:1000 /opt/heimdall/config

ステップ 2：docker-compose.yml の設定​

/opt/heimdall/docker-compose.yml に以下のように定義します：

services:
  heimdall:
    image: ghcr.io/linuxserver/heimdall:latest
    container_name: heimdall
    restart: unless-stopped
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Asia/Taipei
    volumes:
      - /opt/heimdall/config:/config
    # リバースプロキシ経由の場合は内部ポートのみ公開、または共有ネットワークに直接接続する
    ports:
      - "8081:80"
    networks:
      - proxy-network

networks:
  proxy-network:
    external: true

サービスを起動します：

docker compose up -d

3. リバースプロキシ連携 (NPM / Traefik)​

3.1 Nginx Proxy Manager (NPM) 経由でデフォルトのトップページにする​

  1. NPM で Proxy Host を新規作成します：
    • Domain Names：home.example.com（またはメインドメイン名）
    • Forward Hostname / IP：heimdall（同じ proxy-network に属している場合はコンテナ名をそのまま指定）
    • Forward Port：80
    • Websockets Support と Block Common Exploits にチェックを入れます。
  2. SSL 証明書を取得または割り当て、Force SSL を有効にします。

3.2 Traefik v3 経由 (Labels による宣言)​

Traefik を使用している場合は、docker-compose.yml の heimdall サービスセクションに直接ラベルを追加し、ports: のマッピングを削除できます：

    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.heimdall.rule=Host(`home.example.com`)"
      - "traefik.http.routers.heimdall.entrypoints=websecure"
      - "traefik.http.routers.heimdall.tls=true"
      - "traefik.http.routers.heimdall.tls.certresolver=myresolver"
      - "traefik.http.services.heimdall.loadbalancer.server.port=80"

4. 基本的な使い方と「Enhanced Apps（拡張アプリ）」機能​

Heimdall のカードは単なる静的ショートカットにとどまらず、バックエンド API と連携してリアルタイムデータを表示する機能（Enhanced Apps）に対応しています。

4.1 通常のショートカットカードを追加する​

  1. トップページ右下の「+」ボタン（Add item）をクリックします。
  2. Application Name にサービス名（例：Nextcloud や Portainer）を入力します。
  3. 公式サポートリストから自動補完され、デフォルトのアイコンと背景色が設定されます。
  4. URL（例：https://cloud.example.com）を入力します。

4.2 Enhanced Apps によるリアルタイムステータス表示を有効化する​

API 連携に対応したサービス（Pi-hole、AdGuard Home、qBittorrent、Transmission、Plex、Proxmox など）の場合：

  • カード設定画面の下部に Config セクションが表示されます。
  • 対象アプリの API Key、Token、またはアカウント・パスワードを入力します。
  • 効果：カード上に Pi-hole の「ブロック済み広告数／総クエリ数」、ダウンローダーの「リアルタイムのダウンロード／アップロード速度」、メディアサーバーの「再生中のユーザー数」などが直接表示されるようになります。

5. Heimdall のビジュアルカスタマイズ (Personalization)​

デフォルトの単色背景と大きな四角いタイル表示はやや単調なため、内蔵機能とカスタム CSS を使ってアップグレードできます：

5.1 高解像度壁紙とダークモードの設定​

  1. 右下の歯車アイコン（Settings）をクリックします。
  2. Background Image：4K 壁紙をアップロードします（または Unsplash のランダム壁紙 URL を指定します）。
  3. Background Blur / Opacity：カードの文字が読みにくい場合は、設定画面で背景のぼかし度（Blur）とオーバーレイの暗さを調整できます。
  4. Dark Mode にチェックを入れます。

5.2 コミュニティ製高品質ベクターアイコンの導入 (Dashboard Icons)​

Heimdall の内蔵アイコンの多くは PNG ビットマップ画像であるため、拡大するとぼやけやすい傾向があります。コミュニティが保守しているオープンソースのアイコン集（walkxcode/dashboard-icons など）から対応する SVG / 高解像度 PNG をダウンロードし、カード編集時にカスタムアイコンとして直接アップロードできます。

5.3 Custom CSS を注入してすりガラス風カードを作る (Glassmorphism)​

Heimdall はホストマシン側でのカスタムスタイルシート配置に対応しています。

/opt/heimdall/config/www/custom.css を編集します（存在しない場合は新規作成）：

/* カードを半透明のすりガラス風にする */
.item {
    background: rgba(255, 255, 255, 0.1) !important;
    backdrop-filter: blur(12px) !important;
    -webkit-backdrop-filter: blur(12px) !important;
    border: 1px solid rgba(255, 255, 255, 0.18) !important;
    border-radius: 12px !important;
    box-shadow: 0 8px 32px 0 rgba(0, 0, 0, 0.37) !important;
    transition: transform 0.2s ease, box-shadow 0.2s ease !important;
}

/* マウスホバー時にわずかに浮き上がって拡大 */
.item:hover {
    transform: translateY(-4px) scale(1.02) !important;
    box-shadow: 0 12px 40px 0 rgba(0, 0, 0, 0.5) !important;
}

/* 未ログイン時に右下の不要な編集ボタンを非表示にする（ゲストモードをよりすっきりさせる） */
body:not(.logged-in) #edit-toggle {
    display: none;
}

編集が完了したら、ブラウザーでスーパーリロード（Ctrl + F5）を実行すると反映されます。

6. コミュニティにおける代替ダッシュボード比較​

Heimdall の強みは純粋な Web UI 上のクリック操作だけですべての設定が完了する点にあります。一方で、より高度なシステムのリアルタイム監視や Docker コンテナ状態の自動連携、宣言的（YAML）管理を求める場合は、近年コミュニティで主流の代替ソリューションも検討できます：

ダッシュボード名設定方式リソース消費量主な特徴向いているユーザー
Heimdall純 Web GUI極小 (~30MB)クリック操作中心、内蔵の簡易 API データカード、1 分ですぐ導入可能設定ファイルを書きたくない・直感的な操作を求める軽量ポータル用途
Homepage (gethomepage.dev)純 YAML ファイル低 (~50MB)高いモジュール性、Docker 状態の自動検知、豊富なシステムリソース Widget (CPU/RAM/ディスク)コードでの管理（GitOps / Infrastructure as Code）を好むユーザー
HomarrWeb GUI + ドラッグ&ドロップ中 (~150MB)グリッド上での自由なドラッグ配置、内蔵ファイルマネージャー、トレント検索と Docker 管理レイアウトを高度にカスタマイズしたいユーザー
DashyYAML + Web GUI 双方向やや高 (~200MB)非常に多機能、自作外観テーマ対応、Status Check ヘルスチェック機能高密度な情報表示や細部まで徹底的に制御したい上級者

7. データのバックアップと復元​

Heimdall のすべての設定（ユーザー、カード、背景画像、アップロード済みアイコンを含む）は /config ディレクトリ内に集約されています：

# 設定のバックアップ
sudo tar -czvf /opt/backups/heimdall-$(date +%F).tar.gz -C /opt/heimdall config

# 設定の復元
sudo tar -xzvf /opt/backups/heimdall-*.tar.gz -C /opt/heimdall/
sudo chown -R 1000:1000 /opt/heimdall/config
docker compose restart heimdall
Updated 2026-11-27

上記の復元コマンドに含まれるワイルドカード heimdall-*.tar.gz は、ディレクトリ内に複数のバックアップファイルが存在する場合にマッチして tar が失敗する原因になります。実際に復元する際は単一の正確なファイル名（例：heimdall-2026-09-04.tar.gz）を指定してください。
