*arr 自動化メディア視聴アーキテクチャ概要とストレージ事前準備

シリーズ案内

本シリーズ全 3 回：1. アーキテクチャ概要とストレージ事前準備（本記事） → 2. Docker Compose バックエンド・フロントエンドデプロイ → 3. サービス間連携とトラブルシューティング

1. アーキテクチャ全体像とモダン化への進化​

1.1 主要コンポーネントの役割分担​

自動メディア収集システムは本質的にデータパイプライン（Pipeline）であり、各層のコンポーネントの役割は以下の通りです。

1.2 コミュニティにおける最新の進化と構成見直し (Change Log: Rev 2.0+)​

  1. ダウンローダーのみを VPN 内に隔離し、管理層はすべて通常ネットワークへ解放：

    • 従来のように「すべてのサービスを Gluetun ネットワーク内に押し込む」構成では、Sonarr / Radarr / Lidarr の API リクエスト（MusicBrainz や TheTVDB などの外部メタデータ取得）まで VPN ノードの品質に引きずられてしまいます。VPN ノードの回線が不安定になったり、パブリック IP チェックに失敗したりすると、すべてのメタデータ取得が全面停止してしまいます。

    • 最新の標準解：qBittorrent のみに Gluetun のネットワーク名前空間を共有させ（network_mode: "service:gluetun"）、実際の BT/PT ダウンロード通信だけが VPN を通るようにします。その他の管理用コンテナは標準の Docker カスタム Bridge ネットワークに接続し、「コンテナ名」で直接通信させることで、静的 IP をハードコードする煩雑なメンテナンスから解放されます。

  2. Jackett の代わりに Prowlarr を採用：

    • Jackett は従来型の Indexer プロキシツールです。新世代の Prowlarr は Sonarr / Radarr と同じ LinuxServer / *arr ファミリーであり、ネイティブな統合度がさらに高く、単一画面から設定済みのインデクサーを「ワンクリックですべての Sonarr、Radarr、Lidarr インスタンスへ自動同期」できます。各ツールに Torznab URL と API Key を手動でコピペする必要はもうありません。

  3. ChineseSubFinder の代わりに Bazarr を採用：

    • ChineseSubFinder はすでにメンテナンスが終了しています。現在の最良の代替は Bazarr です。API 経由で Sonarr / Radarr のデータベースを直接監視し、複数の字幕ソース（Zimuku、Shooter、Assrt など）に対応しており、字幕が見つからない場合もバックグラウンドで定期的に自動リトライしてくれます。

2. 事前準備：ストレージ構成、ハードリンク、システム基盤​

2.1 ストレージディレクトリ構造と Hardlink（極めて重要）​

多くの初心者がダウンロードディレクトリを /downloads、メディアディレクトリを /media として別々にマウントしてしまいますが、これでは Docker から見て 2 つの異なるファイルシステムとして認識されてしまいます。ダウンロード完了時、Sonarr / Radarr は**ボリューム間コピー（Copy + Delete）**しか行えず、処理が遅いだけでなくディスク寿命を大きく消耗し、容量も 2 倍消費してしまいます。

ベストプラクティス：ハードリンク (Hardlinks) を実現するために単一のルートディレクトリを統一マウントする

/data
├── torrents         <-- qBittorrent のダウンロード一時保存・シード用ディレクトリ
│   ├── movies
│   ├── tv
│   ├── anime
│   └── music
└── media            <-- Emby / Navidrome が読み込む整理済みメディアライブラリ
    ├── movies       <-- Radarr からハードリンク（ディスク容量の重複消費ゼロ）
    ├── tv           <-- Sonarr からハードリンク
    ├── anime
    └── music        <-- Lidarr からハードリンク

すべてのコンテナ内部で統一して /data:/data をマウントします。ダウンロードが完了すると、システムは inode ポインタ（Hardlink）を作成するだけで 1 秒でインポートが完了し、かつ torrents ディレクトリ内の元ファイルで BT のシードもそのまま継続できます。

2.2 Photon OS で TUN カーネルモジュールをロードする​

Gluetun を動かすには、ホスト側が TUN 仮想ネットワークインターフェースに対応している必要があります。Photon OS ではデフォルトで tun.ko がロードされていません。

# 1. TUN カーネルモジュールを手動でロード
modprobe tun

# 2. ロード成功を確認
lsmod | grep tun

# 3. 起動時の自動ロードを設定
echo tun > /etc/modules-load.d/tun.conf
