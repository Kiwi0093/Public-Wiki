Navidrome 音楽サーバー構築：NAS マウントとリバースプロキシ設定

シリーズ案内

本シリーズ全 2 編：1. NAS マウントとサーバー構築（本記事） → 2. クライアント選定・歌詞自動化・バックアップ

1. 事前準備：Photon OS での NAS 音楽ライブラリマウント (SMB vs. NFS)​

音楽ファイル本体を外部 NAS に保存している場合、そのディレクトリをホスト機へ安全にマウントする必要があります。Linux / Photon OS 環境では、NFS の方が SMB/CIFS よりも CPU 負荷が低く、小さな音声ファイルの読み込み性能に優れています。

方式 A：CIFS / SMB マウント（汎用的な従来方式）​

NAS 側の権限設定が Windows ACL 寄りである場合や、専用のアカウント・パスワードで認証保護したい場合に適しています。

# 1. 必要なパッケージをインストール
tdnf -y install cifs-utils

# 2. 認証情報ファイルを作成（fstab にパスワードを平文で書かないため）
sudo mkdir -p /root/.smbcredentials
sudo bash -c 'cat << EOF > /root/.smbcredentials/nas
username=nas_username
password=nas_secret_password
domain=WORKGROUP
EOF'
sudo chmod 600 /root/.smbcredentials/nas

# 3. ローカルのマウントポイントを作成
sudo mkdir -p /mnt/nas/music

/etc/fstab を編集して以下を追記します：

//192.168.1.50/Music /mnt/nas/music cifs credentials=/root/.smbcredentials/nas,uid=1000,gid=1000,ro,iocharset=utf8,_netdev,nofail 0 0

方式 B：NFS マウント（推奨：高パフォーマンス・Linux ネイティブ対応）​

NFS は Linux ネイティブプロトコルで動作するためオーバーヘッドが小さく済みます。あらかじめ NAS 側で対象フォルダの NFS サービスを有効化し、Photon OS の IP を許可リストに追加してください（読み取り専用 ro および特定 UID/GID への all_squash マッピング設定を推奨）。

ステップ 1：Photon OS に NFS クライアントをインストール​

# NFS サポートパッケージをインストール
tdnf -y install nfs-utils

# rpcbind サービスを起動し自動起動を有効化
systemctl enable --now rpcbind

ステップ 2：NAS 側の NFS エクスポートパスを確認​

NAS が公開している共有フォルダが正常に見えるか確認します：

showmount -e 192.168.1.50
# 出力例：
# /volume1/Music  192.168.1.0/24

ステップ 3：ローカルのマウントポイントを作成​

sudo mkdir -p /mnt/nas/music

ステップ 4：/etc/fstab に起動時自動マウントを設定​

/etc/fstab を編集し、以下の設定を追加します：

192.168.1.50:/volume1/Music /mnt/nas/music nfs nfsvers=4.1,ro,_netdev,nofail,hard,intr,rsize=1048576,wsize=1048576 0 0

  • 主要パラメータの解説：

    • nfsvers=4.1：NFSv4.1 を優先使用します（状態管理が優れておりファイアウォールにも適しています。古い NAS の場合は nfsvers=3 に変更してください）。

    • ro：読み取り専用モードでマウントします。Navidrome は音声ファイルの読み取りのみを行うため、読み取り専用にすることで誤削除やランサムウェア被害を確実に防げます。

    • _netdev：重要なパラメータです。ネットワーク接続完了後にマウントを実行するよう強制し、起動時に NAS が見つからずブートが停止するのを防ぎます。

    • nofail：NAS が再起動中またはオフラインの場合でも、OS はこの項目をスキップして通常起動を継続し、Emergency Mode へ落ちるのを防ぎます。

    • hard,intr：接続が一時的に途切れた場合、即座にエラーで再生を中断するのではなくサーバー復旧を待機します（またユーザーによるリクエストの中断も許可します） (Updated 2026-11-27: Linux Kernel 2.6.25 以降、intr オプションは非推奨となり無効なパラメータとして扱われます。現代のカーネルではデフォルトで SIGKILL による hard マウントの中断のみが許可されています)。

    • rsize/wsize=1048576：転送バッファサイズを 1MB に設定し、ハイレゾ音源（FLAC / DSD）再生時のスループットを大幅に向上させます。

ステップ 5：マウントテスト​

# /etc/fstab 内の全項目をマウントテスト
sudo mount -a

# 正常にマウントされたか確認し中身を表示
df -h | grep /mnt/nas/music
ls -la /mnt/nas/music

CIFS vs. NFS 比較表​

比較軸CIFS / SMBNFS (v4.1) (推奨)
接続認証ユーザーアカウント / パスワード認証クライアントホスト IP ホワイトリスト認証
転送効率プロトコルがやや煩雑で、小ファイルの頻繁な読み込み時に CPU 負荷が高めプロトコルが簡素で、遅延が低くスループットに優れる
権限マッピングマウントオプションで uid=1000,gid=1000 の明示的な指定が必要NAS 側で all_squash を設定し特定ユーザーへ統一マッピング可能
クロスプラットフォーム互換Windows / macOS / Linux すべてで汎用的に利用可能Unix / Linux エコシステム向けに特化

ストレージ分割の鉄則（SMB / NFS いずれの場合も共通）： 音楽ライブラリ /music は NAS 上に配置して問題ありませんが、Navidrome のデータベースディレクトリ /data（SQLite の navidrome.db を含む）は必ずローカル SSD に配置してください。ネットワーク共有ストレージ上に置くと、検索や再生回数書き込みの遅延だけでなく SQLite データベース破損の原因になります。

2. Docker Compose デプロイ構成 (Traefik v3 連携)​

リバースプロキシ設計には、主に以下の 2 パターンがあります：

  1. 独立サブドメイン方式 (推奨)：music.example.com のように URL パスがシンプルで、URL リライトの問題が一切発生しません。

  2. サブパス方式 (Subpath)：example.com/music のような構成で、ND_BASEURL と Traefik の PathPrefix を個別に設定する必要があります。

ステップ 1：ローカル専用ディレクトリの作成​

sudo mkdir -p /opt/navidrome/data
sudo chown -R 1000:1000 /opt/navidrome/data

ステップ 2：docker-compose.yml の設定 (独立サブドメインの例)​

services:
  navidrome:
    image: deluan/navidrome:latest
    container_name: navidrome
    restart: unless-stopped
    user: "1000:1000"
    environment:
      # タイムゾーン設定
      - TZ=Asia/Taipei
      # バックグラウンドスキャン頻度（1時間ごとにディレクトリ変更をスキャン）
      - ND_SCANSCHEDULE=1h
      # ログレベル (debug, info, warn, error)
      - ND_LOGLEVEL=info
      # セッション有効期間
      - ND_SESSIONTIMEOUT=24h
      # 信頼するリバースプロキシの IP サブネット（Docker ネットワーク帯域に対応）
      - ND_REVERSEPROXYWHITELIST=172.16.0.0/12,10.0.0.0/8,192.168.0.0/16
      # トランスコード設定（必要に応じて有効化し、クライアント側で MP3/Opus へのビットレート変換を選択可能にする）
      - ND_ENABLETRANSCODINGCONFIG=true
      # サブパス運用時のみ設定（例: "/music"）。サブドメイン運用の場合は空欄またはこの行を削除
      - ND_BASEURL=
    volumes:
      - /opt/navidrome/data:/data
      - /mnt/nas/music:/music:ro
    networks:
      - proxy-network
    labels:
      - "traefik.enable=true"
      # 1. ルーティングルール
      - "traefik.http.routers.navidrome.rule=Host(`music.example.com`)"
      - "traefik.http.routers.navidrome.entrypoints=websecure"
      - "traefik.http.routers.navidrome.tls=true"
      - "traefik.http.routers.navidrome.tls.certresolver=myresolver"
      # 2. コンテナ内部の 4533 番ポートへの転送を明示的に宣言
      - "traefik.http.services.navidrome.loadbalancer.server.port=4533"

networks:
  proxy-network:
    external: true

3. Nginx / Nginx Proxy Manager 専用設定​

フロントエンドに Nginx または NPM を配置している場合の設定例です：

location /music {
    proxy_pass http://navidrome:4533;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $http_host;
    
    # ストリーミング専用最適化：高ビットレート FLAC/DSD 再生時の音途切れを防ぐためバッファリングを無効化
    proxy_buffering off;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    
    # 長時間再生中の切断を防ぐためタイムアウトを延長
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
