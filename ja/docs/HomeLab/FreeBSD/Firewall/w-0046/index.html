FreeBSD IPFW と Dummynet によるトラフィック制御の実践設定

ヒント

FreeBSD Gateway は ipfw を利用してトラフィック制限機能を実現できます。正常に動作させるには dummynet カーネルモジュールを組み合わせる必要があります。

Dummynet​

動的ロード​

現在ほとんどの環境では Generic Kernel が使用されているため（自分で Kernel を再コンパイルする手間を省けるため）、kldload をそのまま使って dummynet.ko を動的にロードできます。

手動ロード​

kldload dummynet

モジュールがロードされたか確認するには、以下を実行します：

kldstat

このコマンドは動的にロードされたすべての .ko モジュールを一覧表示します。出力に dummynet.ko が含まれていることを確認してください。

起動時の自動ロード​

再起動後も設定が有効になるようにするため、/boot/loader.conf を編集します：

# /boot/loader.conf
dummynet_load="YES"

これにより、次回以降の再起動時に自動的にロードされます。

ipfw システム設定​

/etc/rc.conf で、システム起動時にファイアウォールを有効化する方法とルールスクリプトを読み込む設定を定義します（/etc/ipfw.conf に実行権限があるか、有効な Shell スクリプトであることを確認してください）：

# /etc/rc.conf
firewall_enable="YES"
firewall_script="/etc/ipfw.conf"  # 設定ファイルのパス
firewall_type="unknown"           # 独自のスクリプトを実行することをシステムに通知
natd_enable="NO"                  # natd を起動しない

トラフィック制限の実践例​

/etc/ipfw.conf

ここが最も核となる部分です。インターフェース、ネットワークセグメント、帯域幅の変数定義と、実際のルールを分けてメンテナンスすることをお勧めします：

#!/bin/sh
# ipfw コマンドのパスを定義
IPFW="/sbin/ipfw"

# --- インターフェースを定義 ---
EXT_IF="ext0"
INT_IF="int0"

# --- ネットワークと IP を定義 ---
DMZ_NET="192.168.0.0/24"
GUEST_NET="192.168.2.0/24"
VPN_NET="10.8.0.0/24"       # 修正：元々不足していた定義を補完
P2P1_IP="192.168.0.100"     # 修正：元々不足していた定義を補完
P2P2_IP="192.168.0.101"

# --- 帯域幅の種類と速度を定義 ---
P2P_UP="100KBytes/s"
VPN_UP="500KBytes/s"
RDP_P2P="500KBytes/s"
SERV_UP="350KBytes/s"
GUEST_BAND="30KBytes/s"

# --- ルール開始 ---

# 1. 既存のすべてのルールと pipe をクリア
$IPFW -f flush
$IPFW -f pipe flush

# 2. ローカルループバック (Loopback) トラフィックを許可 (重要：これがないとシステムサービスが通信不能になる)
$IPFW add 10 allow ip from any to any via lo0

# 3. ipfw pipe を使用して各トラフィック制限と番号を定義
$IPFW pipe 1 config bw $VPN_UP
$IPFW pipe 2 config bw $P2P_UP
$IPFW pipe 3 config bw $RDP_P2P
$IPFW pipe 4 config bw $SERV_UP
$IPFW pipe 5 config bw $GUEST_BAND

# 4. pipe を利用してトラフィックルールを定義 (数値が小さいほど優先度が高い)

# VPN トラフィック制限
$IPFW add 20 pipe 1 ip from any to $VPN_NET

# RDP 特定トラフィック (修正：3389 ポートを追加して精度を確保)
$IPFW add 25 pipe 3 tcp from $P2P1_IP to any 3389 in recv $INT_IF

# P2P トラフィック制限
$IPFW add 30 pipe 2 ip from $P2P1_IP to any in recv $INT_IF
$IPFW add 40 pipe 2 ip from $P2P2_IP to any in recv $INT_IF

# Guest ネットワークの速度制限 (送受信どちらも制限)
$IPFW add 110 pipe 5 ip from $GUEST_NET to any
$IPFW add 120 pipe 5 ip from any to $GUEST_NET

# DMZ 送信トラフィック制限 (修正：元のハードコードを置き換えて変数 $EXT_IF を使用)
$IPFW add 210 pipe 4 ip from $DMZ_NET to any via $EXT_IF

# 5. 最後に残りのすべてのトラフィックを許可
$IPFW add 65534 allow ip from any to any

まとめ​

現在、FreeBSD 上の主要なファイアウォールはほとんどが PF（Packet Filter）に移行しており、セキュリティフィルタリングに IPFW 単体を使うケースは減っています。しかし、PF は帯域幅制限の設定において IPFW + dummynet ほど直感的でシンプルではないため、実務では二層ファイアウォールで役割分担する構成が非常に適しています：PF がセキュリティフィルタリングと NAT を担当し、IPFW がトラフィック制御（Traffic Shaping）を専任するという形です。
