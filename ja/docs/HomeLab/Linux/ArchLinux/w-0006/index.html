Arch Linux KDE Plasma Wayland での KRDP リモートデスクトップ設定ガイド

備考

この記事は Google「Gemini」によって自動翻訳されたものであり、筆者は内容の正確性および表現について保証いたしません。

ヒント

VNC は Wayland 環境で使えないので、乗り換えるしかありませんね​

📝 背景と構成の目標​

常時稼働している archdesk について、KDE Plasma 6.8 へのアップグレード後、ネイティブの Wayland ディスプレイサーバーに RDP プロトコルが深く統合されました。より安定した接続と優れた Wayland 表示サポートを得るため、本ガイドでは従来の X11 ベースの TigerVNC を廃止し、krdp + Remmina (FreeRDP) によるモダンなリモートデスクトップ構成へ移行する手順を案内します。

🛠️ 第 1 段階：システムアップグレードと環境クリーンアップ​

1. システムの更新とアップグレード​

システム全体を更新し、最新の Plasma 6.8 と関連する依存パッケージを入手します：

sudo pacman -Syu

2. TigerVNC Server の削除​

後続の RDP サービスとのポート競合やバックグラウンドプロセスの衝突を避けるため、旧バージョンの TigerVNC サーバーと不要になった依存パッケージを削除します：

sudo pacman -Rns tigervnc

ユーザーのホームディレクトリに残っている VNC パスワードや設定ファイルを削除します：

rm -rf ~/.vnc

⚙️ 第 2 段階：最重要ポイント — SDDM 自動ログインの設定​

⚠️ 重要な考え方： krdp は KWin Wayland 内に深く統合された「ユーザーレベル (User Session)」のサービスです。VM の再起動後に SDDM のログイン画面で止まったままでは、Wayland Session がまだ起動しておらず、krdp サーバーも待機状態にならないため、外部から一切接続できなくなります。

1. 自動ログイン (Auto-login) の設定​

archdesk 上で /etc/sddm.conf.d/autologin.conf を作成または編集し、起動後にデフォルトの Wayland Session を自動で読み込むようにします：

[Autologin]
User=kiwi
Session=plasma

2. KWallet (KDE ウォレット) のパスワードポップアップ対策​

自動ログインを設定すると、システムログイン時に平文のパスワードが渡されないため、KDE のデフォルトの KWallet は自動ロック解除されなくなります。

  • 解決策： RDP でデスクトップに接続した後、「KDE ウォレットマネージャー (KWalletManager)」を開き、デフォルトウォレットのパスワードを「空（空白）」に変更します。これにより、以降ブラウザや他のアプリを開いた際のパスワード入力ポップアップを防ぐことができます。
  • （注：この設定は Systemd User Service によってバックグラウンドで常駐する SSH Agent の認証には影響しません）

🚀 第 3 段階：KRDP のインストールと有効化​

1. 必要パッケージのインストール​

KDE ネイティブの RDP サーバーコンポーネント (krdp) と、ローカル側で必要なクライアントツール remmina、およびそれが依存する freerdp プロトコルコアをインストールします：

sudo pacman -S krdp remmina freerdp

2. RDP サービスの起動​

KDE Plasma 6 以降の Wayland 環境では、RDP サーバーが GUI に完全に統合されており、手動で設定ファイルを管理する必要はありません：

  1. 「システム設定 (System Settings)」 を開きます。
  2. 「システム (System)」 → 「リモートデスクトップ (Remote Desktop)」 へ移動します。
  3. 「RDP サーバーを有効にする (Enable RDP server)」 オプションをオンにします。
  4. 画面上でリモート接続専用のユーザー名とパスワードを設定します。
  5. (ファイアウォール確認)：ローカルのファイアウォールで標準の RDP ポート (TCP 3389) が許可されていることを確認します。

💻 第 4 段階：クライアント接続設定 (Remmina)​

接続元のクライアントマシン（自宅の物理 Dell ノート PC、IP 192.168.31.21 / .54 など）で Remmina を開き、新しい接続プロファイルを作成します：

  • プロトコル (Protocol)：RDP - FreeRDP plugin を選択。
  • サーバー (Server)：接続先 archdesk の IP 192.168.31.11 を入力。
  • 認証情報：KDE システム設定で作成した RDP アカウントのユーザー名とパスワードを入力。
  • 色深度と画質：LAN 環境では色深度を True color (32 bpp) に設定するか RemoteFX を有効にすることで、最適なグラフィック描画が得られます。

接続の検証​

sudo reboot を実行して archdesk を再起動します。約 30 秒待った後、ESXi のコンソール画面は一切開かずに、クライアントから直接 RDP 接続を行います。そのままデスクトップに入り、完全な KDE デスクトップが表示されれば、自動ログインと KRDP バックグラウンドサービスがともに正常に動作しています。
