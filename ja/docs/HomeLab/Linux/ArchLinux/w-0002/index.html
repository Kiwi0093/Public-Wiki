Arch 系 Pacman / Yay 実用コマンドとメンテナンス術

一、 はじめに：Yay のインストール方法（Arch 派生ディストリビューション別）​

Arch 系システムでは、公式リポジトリ以外のソフトウェアはすべて AUR (Arch User Repository) に置かれています。yay は Go で書かれた強力なツールで、pacman の構文と互換性があり、AUR からのソフトウェアのダウンロードとビルドをシームレスに行うことができます。

使用している Arch 系ディストリビューションによって、yay のインストール手順は少し異なります：

1. Vanilla Arch Linux（本家 Arch）または ArchWSL (Updated 2026-11-27: サードパーティ製の ArchWSL プロジェクトはアーカイブされました。現在は公式 WSL イメージから wsl --install -d archlinux で直接インストール可能です)

本家 Arch の公式リポジトリには AUR ヘルパーが含まれていないため、初回はソースコードを手動で取得してビルドする必要があります：

# 1. 必須のビルドツールと Git をインストール
sudo pacman -S --needed git base-devel

# 2. yay のソースコードを clone してディレクトリへ移動
git clone https://aur.archlinux.org/yay.git
cd yay

# 3. ビルドしてインストール（-s は依存関係を自動解決、-i はビルド後に自動インストール）
makepkg -si

2. Manjaro

Manjaro は公式のコミュニティリポジトリ *(Updated 2026-11-27: Manjaro は community を extra リポジトリへ統合しました)*に yay を収録しているため、pacman でそのままインストールできます：

# yay 単体でもインストールできますが、今後 AUR パッケージをビルドする際にエラーが出ないよう base-devel も一緒に導入することをおすすめします
sudo pacman -S base-devel yay

3. EndeavourOS / Garuda Linux

すぐに使えることを重視したこの 2 つの Arch 派生ディストリビューションでは、OS インストール時点でデフォルトで yay が導入済みであり、特別な作業は不要です。万が一誤って削除してしまった場合でも、独自リポジトリが設定されているため同様にコマンドひとつで再導入できます：

sudo pacman -S yay

インストールが完了すれば、日常的なパッケージ管理は基本的に pacman を yay に置き換えて実行できます。

二、 基本メンテナンス：パッケージのインストールとシステム更新​

1. システム全体の更新とダウングレード同期

通常は、以下のコマンドで公式パッケージと AUR パッケージを同時に更新します：

yay -Syu

応用知識：yay -Syu と yay -Syyuu の違いは？

  • -Syu（標準アップデート）： -y は最新のパッケージデータベースを同期し、-u は古いパッケージをすべてアップグレードします。日常的な更新で最もよく使うコマンドです。

  • -Syyuu（強制同期およびダウングレード許可）：

    • -yy：ローカルのデータベースが最新かどうかに関わらず、サーバーから強制的にデータベースを再ダウンロードして同期します（ミラーサーバーを変更した直後やデータベースが破損した際に使用します）。
    • -uu：パッケージのダウングレード (downgrade) を許可します。サーバー上のバージョンがローカルより古い場合（例：公式が新版に重大なバグを発見して緊急に旧版へ差し戻した場合など）、u を 2 つ付けることで公式リポジトリの状態に合わせて強制的に旧版へ戻せます。

2. パッケージの検索とインストール

# 特定のパッケージをインストール
yay -S <パッケージ名>

# 正確な名前が分からない場合は、yay にキーワードを渡すと候補一覧が表示されて選択できます
yay <キーワード>

三、 パッケージのアンインストールと「孤立パッケージ」の削除 (Orphans)​

Arch では、pacman -R だけで本体を削除してしまい、そのソフトのために導入された大量の依存パッケージを残してしまうのは避けるべきです。

1. パッケージをきれいに削除する（依存関係もまとめて削除）

ソフトウェアを削除する際は s を付ける習慣をつけましょう。システム全体の設定ファイルもあわせて消したい場合は n も追加します：

sudo pacman -Rns <パッケージ名>
# または
yay -Rns <パッケージ名>

2. 孤立パッケージの削除 (Orphans)

ローリングアップデートやソフトウェアのインストール・アンインストールを繰り返すうちに、どのパッケージからも依存されなくなった「孤立パッケージ（Orphans）」が溜まっていきます。

  • Pacman 標準の方法：

    # すべての孤立パッケージを一括削除
    sudo pacman -Rns $(pacman -Qtdq)

  • Yay 組み込みの便利機能（推奨）： 上記のような長いコマンドを覚える必要はなく、yay には専用のクリーンアップオプションが用意されています：

    yay -Yc

四、 ディスク容量の解放：キャッシュの削除 (Cache)​

アップデートやインストール時にダウンロードされたパッケージファイルは /var/cache/pacman/pkg/ に蓄積され、放置すると非常に大きなディスク容量を消費します。

1. 手動でキャッシュを削除

# 安全なクリーンアップ：「すでにアンインストールされた」パッケージのキャッシュのみ削除
yay -Sc

# 完全なクリーンアップ：「すべての」キャッシュを削除（最も容量を節約できますが、後からローカルの旧版へダウングレードできなくなります）
yay -Scc

2. 応用テクニック：Systemd による自動定期クリーンアップ

paccache -r コマンドを利用します（デフォルトでは最新 3 バージョンを残し、それより古いファイルを削除します）。

注意： 事前に pacman-contrib パッケージをインストールする必要があります (yay -S pacman-contrib)。

サービスファイル /etc/systemd/system/paccache.service を作成します：

[Unit]
Description=Clean-up old pacman pkg cache

[Service]
ExecStart=/usr/bin/paccache -r

タイマーファイル /etc/systemd/system/paccache.timer を作成します：

[Unit]
Description=Clean-up old pacman pkg cache

[Timer]
OnCalendar=monthly    # 毎月 1 回実行するように設定
Persistent=true       # 電源オフ中などに実行タイミングを逃しても次回起動時に補完

[Install]
WantedBy=multi-user.target

タイマーを有効化して起動します：

sudo systemctl enable paccache.timer
sudo systemctl start paccache.timer
Updated 2026-11-27
  1. pacman-contrib をインストールすると、システムにはすでに /usr/lib/systemd/system/paccache.service と paccache.timer（デフォルトで毎週 1 回実行）が組み込まれています。通常は sudo systemctl enable --now paccache.timer を実行するだけでよく、手動でユニットファイルを作成する必要はありません。
  2. 独自に .timer ファイルを記述する場合、systemd のユニットファイルは Key=Value と同じ行の末尾に # によるインラインコメントを記述できません（上記例の OnCalendar=monthly # ... や Persistent=true # ... は構文エラーの原因になります）。コメントは必ず独立した行に記述してください。

五、 救済ツール：パッケージのダウングレード (Downgrade)​

Arch はローリングリリース（Rolling Release）であるため、アップデート後に特定のソフトウェアやカーネルが動かなくなるトラブルに遭遇することがあります。その場合は downgrade ツールを使って前の安定バージョンへ戻します。

1. Downgrade ツールのインストール

このツールは AUR に登録されているため、yay でインストールします：

yay -S downgrade

2. 特定パッケージのダウングレード

特定のパッケージ（例：Firefox や Linux Kernel）が更新後に不具合を起こした場合は、次を実行します：

sudo downgrade <パッケージ名>

実行後の流れとポイント：

  1. ツールが対象パッケージの過去バージョン一覧を表示します。まずローカルキャッシュ（/var/cache/pacman/pkg/）を優先して探し、ローカルにない場合は Arch Linux Archive (A.L.A.) のオンラインアーカイブから取得します。
  2. 戻したいバージョンに対応する「番号」を入力して Enter を押します。
  3. ⚠️ 重要な手順： ダウングレード完了後、ターミナルに add <パッケージ名> to IgnorePkg? [y/N] と表示されます。ここでは強く y を選択することをおすすめします。これによりそのパッケージが pacman の無視リストに追加され、次回 yay -Syu で全体更新しても自動でスキップされ、不具合のある新版へうっかり戻ってしまうのを防げます。

3. ダウングレード固定の解除（IgnorePkg からの削除）

公式から修正版がリリースされ、再びそのソフトウェアをアップデート対象に戻したいときは、/etc/pacman.conf を編集します：

sudo vim /etc/pacman.conf

IgnorePkg = <パッケージ名> の行を見つけ、削除するか先頭に # を付けてコメントアウトして保存すれば、次回のアップデートから通常通り更新されるようになります。
