ManjaroWSL（WSL2）インストールとデスクトップ環境設定（アーカイブ済み）

ヒント

現在の最新の方法では、Microsoft Store から WSL2 と ArchWSL を組み合わせてインストールするだけで完結するため、手順が大幅に簡略化されています。

備考

手元の Windows マシンでインストール権限を取得して WSL を利用できるようになったため、当時 ManjaroWSL を導入した際の作業ログを記録したものです。

Pre-Start​

まず、WSL / WSL2 環境を準備します。

  • 管理者権限で PowerShell を開き、次のコマンドを実行して Windows Subsystem for Linux を有効化します。
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
  • 管理者権限で PowerShell を開き、次のコマンドを実行して Virtual Machine Platform を有効化します。
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
  • WSL-Kernel をダウンロードしてインストールします。
  • デフォルトのバージョンを WSL2 に設定します。
wsl --set-default-version 2
Updated 2026-11-27

現在の Windows 10（2004 以降）および Windows 11 では、wsl --install（および wsl --update）を直接実行するだけで必要なコンポーネントを一括インストール・有効化できるため、手動で dism.exe を実行したり別途 WSL2 Kernel 更新パッケージをダウンロードしたりする必要はありません。

Install & Initialize ManjaroWSL​

Download​

ManjaroWSL はあらかじめパッケージ化されており、当時は Releases ページ から最新の zip ファイルをそのままダウンロードできました。

Updated 2026-11-27

sileshn/ManjaroWSL プロジェクトは現在メンテナンス終了・アーカイブされています。現在の WSL2 で Arch 系環境を利用したい場合は、公式サポートの wsl --install -d archlinux または新しい .wsl イメージインポート機能の利用を推奨します。

配置・インストール​

ダウンロードした zip ファイルを ManjaroWSL システム全体を配置する予定のディレクトリに展開した後、PowerShell を開いて次を実行します。

./Manjaro.exe

自動展開と初期化が完了するまで待ち、もう一度次を実行します。

./Manjaro.exe

Initialize​

画面の案内に従って Resize および New User の作成を行うかどうか選択しますが、当時はどちらも No を選ぶことを推奨していました。理由は以下の通りです。

  • 250GB 以上の容量を使用しないため（また、WSL はデフォルトで Windows のドライブを /mnt/ に自動マウントします）。
  • ユーザーアカウントは後続のスクリプトで一括作成し、あわせて完全な Zsh ターミナルおよび Xfce 環境設定を適用するため。

Configure System​

root 権限で初期化スクリプトを実行します。

bash <(curl -L -s https://kiwi0093.github.io/script/WSL/manjaro.sh)

Script 使用上の注意​

  • 最初に手動で国コードを指定する方が、自動速度測定でミラーサイトを選択するより通常は高速です。
  • 途中で /etc/wsl.conf を vi で編集する画面が開いたら、以下の設定を追加します。
[Users]
# 加入以下資訊
default = <User Name you created and wish to be default>

編集が完了したら :wq を入力して保存・終了します。

Script の解説​

以下は、スクリプト内で実行される主な設定セクションの抜粋です。

Mirrorlist & System Upgrade​

# Basic system configuration
echo -e "${color1}Basic system configuration started${NC}"
echo -e "${color1}Setting your Repo${NC}"
echo -e "${color2}Do you want to set location for the mirror-list?(Y for Location, others for fastest 3 location)${NC}"
while :
do
        read LT
        case $LT in
                Y)
                        echo -e "${color2}Please input location you want(EX, tw for Taiwan, us for USA)\n${NC}"
                        read LT2
                        pacman-mirrors -c $LT2
                        break
                        ;;
                *)
                        pacman-mirrors --fasttrack 3
                        break
                        ;;
        esac
done
echo -e "${color1}Update system${NC}"
pacman -Syyu

主に対話形式の選択肢を提示し、pacman-mirrors と pacman -Syyu を実行する部分です。

Basic Tools Install​

echo -e "${color1}Install Basic tools${NC}"
pacman -S git yay wget curl rsync sshpass zsh manjaro-zsh-config \
ttf-nerd-fonts-symbols ttf-meslo-nerd-font-powerlevel10k \
ttf-meslo-nerd-font-powerlevel10k powerline-fonts \
nerd-fonts-noto-sans-mono vim wireguard-tools systemd-resolvconf htop --noconfirm

このセクションでは、zsh と装飾用フォント／設定のほか、git、yay、rsync、wireguard などのよく使うツールをインストールします。

Xfce4 および Manjaro Theme​

echo -e "${color1}Install Xfce4 for GUI${NC}"
pacman -S xfce4-gtk3 xfce4-goodies xfce4-terminal network-manager-applet \
xfce4-notifyd-gtk3 xfce4-whiskermenu-plugin-gtk3 tumbler engrampa lightdm \
lightdm-gtk-greeter lightdm-gtk-greeter-settings manjaro-xfce-gtk3-settings \
manjaro-settings-manager --noconfirm

この部分は主に Manjaro 公式ドキュメントを参照し、Xfce4 とテーマ関連パッケージをインストールしています。

GUI Tools & 中国語環境​

echo -e "${color1}Install GUI$ tools${NC}"
pacman -S terminator brave-browser tigervnc gnome-pie --noconfirm
echo -e "${color1}Install Chinese Environment${NC}"
pacman -S adobe-source-han-serif-tw-fonts adobe-source-han-serif-hk-fonts \
adobe-source-han-serif-cn-fonts adobe-source-han-sans-tw-fonts \
adobe-source-han-sans-hk-fonts adobe-source-han-sans-cn-fonts \
adobe-source-han-serif-jp-fonts adobe-source-han-sans-jp-fonts \
fcitx fcitx-chewing fcitx-configtool fcitx-mozc fcitx-configtool --noconfirm

ここでは基本的なブラウザ、ターミナル、中国語／日本語フォント、および入力メソッドパッケージをインストールしています。残りは個人設定ファイルのインポートやアカウント作成処理です。

Updated 2026-11-27

上記の過去スクリプトでは、ttf-meslo-nerd-font-powerlevel10k と fcitx-configtool が重複して記載されていました。また、従来の fcitx（v4）は Arch / Manjaro エコシステムにおいて fcitx5（fcitx5-im、fcitx5-chewing、fcitx5-mozc）へ完全に置き換えられています。

Systemd on WSL​

echo -e "${color1}Change your root password & shell to zsh${NC}"
sudo -u $USERN yay -S genie-systemd-git
echo 'genie -i' > /etc/init.wsl
chmod +x /etc/init.wsl
genie -i
genie -c systemctl disable auditd.service
genie -c systemctl disable multipathd.service
genie -c systemctl disable systemd-modules-load.service
genie -c systemctl enable systemd-resolved.service
genie -c systemctl start systemd-resolved.service

当時の検証では、比較的簡単に正常動作する手段は genie-systemd-git のみでした。インストール後にまず genie -i でボトル環境を初期化し、genie -c 経由でコマンド実行や新しいシェルへの移行を行います。

Updated 2026-11-27

WSL 0.67.6 以降、WSL2 は systemd をネイティブサポートしています。現在の環境では /etc/wsl.conf に [boot] と systemd=true を追記して WSL を再起動（wsl --shutdown）するだけで済むため、genie-systemd-git のインストールや上記のようなサービス無効化のワークアラウンドは不要になりました。

Desktop Shortcut の作成​

GWSL を使用して設定します。

  • GWSL Distro Tools → Display/Audio auto exporting を有効化
  • GWSL Distro Tools → LibGL Indirect を有効化
  • 続いて Shortcut Creator を開きます。

  • Shortcut Label：Windows スタートメニューに表示されるショートカット名（任意）。
  • Shortcut Command：Xfce4 を使用する場合は固定で startxfce4 を入力します。
  • Display Mode：完全なデスクトップ環境を表示したい場合は、Single Window または Fullscreen を選択します。
  • Keep Xserver Instance：Display Mode で Fullscreen を選択した場合、この項目を true に設定しないとクラッシュしやすくなります。

設定完了後、まず Test Configuration を押してテストし、問題がなければ Add to Start Menu をクリックします。

Updated 2026-11-27

Windows 11 に標準搭載されている WSLg は Linux GUI（X11 / Wayland）、音声、日本語／中国語入力メソッドの統合をネイティブで提供しているため、一般的な GUI アプリケーションで GWSL などのサードパーティ製 X Server を組み合わせる必要はなくなりました。

まとめ​

正直なところ、最初に WSL を見たときはとても驚き、Manjaro のコミュニティディストリビューションがあると知ってさらに期待が高まりましたが、実際にインストールして使ってみると少しギャップを感じました。理由は以下の通りです。

  • 動作速度が思ったほど滑らかではなく、特にフルデスクトップ環境を起動して作業すると重く感じる。
  • マルチディスプレイ環境で実行したプログラムでは、入力メソッドが正常に切り替えられないことがよくある（デフォルトを Chewing にして Shift で切り替える運用にするくらいしか対策がない）。
  • Desktop モードをしばらく放置するとそのままフリーズして落ちやすく、中のプログラムも巻き添えで終了してしまう。
  • systemd はサードパーティ製ツールでなんとか動作するものの、全体的な安定性はネイティブ環境と比べると明らかな差がある。

そのため、単に Linux シェルでツールを実行したい場合や、特殊な事情で Windows と Linux を同時に使い分ける必要がある場合には WSL は良い選択肢になります。しかし、本格的な Linux Desktop と比較すると力不足は否めず、別の Linux デスクトップ機にリモート VNC 接続する体験にすら及びません。とはいえ、これはもともと特定の状況向けの暫定的な解決策（ワークアラウンド）と言えます。
