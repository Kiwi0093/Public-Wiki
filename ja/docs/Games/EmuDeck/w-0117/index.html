EmuDeck インストールおよびクロスプラットフォーム設定 (Windows / Linux)

1. アーキテクチャ設計：集中型読み取り専用ライブラリとマルチユーザーローカルセーブ分離​

Duo / Sunshine を組み合わせてマルチユーザー同時ストリーミングや家族間での複数アカウント共有を行う場合、最も安定したストレージ構成は「ROM / BIOS は NAS で集中読み取り専用共有、ゲームのセーブデータは各アカウントのローカルに分離」することです。

  • 読み取り専用の集中共有 (NAS / RomM)：ROM と BIOS は NAS 上に配置し、SMB 経由で各端末にマウントします（例：Z:\roms および Z:\bios）。

  • ローカルでのマルチアカウント・セーブデータ分離 (Saves / States)：各ユーザーのゲームセーブデータ（.srm, .sav）およびステートセーブ（Save States）をネットワーク共有ディレクトリへ書き戻すことは厳禁です。セーブデータを共有すると、同じゲームを複数インスタンスや複数人でプレイした際にファイルロック（File Lock）や進行状況の上書きといったトラブルが発生します。

1. NAS 側のディレクトリ構成規約​

リモート NAS の共有ディレクトリは標準的な階層構造に合わせる必要があります。

\\<NAS_IP>\Emulation\          <-- 網路磁碟機根目錄 (映射為 Z:\)
├── bios\                     <-- 各機種 BIOS (如 scph1001.bin 等)
│   └── ...
└── roms\                     <-- 平台資料夾名稱需完全吻合 EmuDeck 規範
    ├── gba\
    ├── ps2\
    └── snes\

2. Windows ローカルでの起動時永続ネットワークドライブ接続 (Z:)​

  1. 「エクスプローラー」➔「ネットワークドライブの割り当て」を開きます。

  2. ドライブ文字に Z: を選択し、フォルダーに \\<NAS_IP>\Emulation を入力します（「サインイン時に再接続する」にチェックを入れます）。

  3. 起動時のネットワーク遅延により Z: が切断状態（赤いバツ印）になりやすい場合は、スタートアップ用バッチファイルを作成します。

@echo off
timeout /t 5 /nobreak >nul
net use Z: \\<NAS_IP>\Emulation /persistent:yes

2. Windows 環境でのインストールと「adb.zip ハング」の解消​

1. インストール先にネットワークドライブを指定すると「adb.zip」で止まる原因​

EmuDeck for Windows のインストーラーは、「事前準備（Prerequisites）」フェーズにおいて Android エミュレータを選択していない場合でも、platform-tools（すなわち adb.zip）を強制的にダウンロードして展開します。インストール先にネットワークドライブ (Z:) を直接指定すると、SMB のファイルハンドル（File Handle）のロック遅延や非同期書き込みの特性により、スクリプトが削除やリトライループ実行時にファイル状態を誤認し、無限待機やプログラムのデッドロックに陥ります。

2. 解決策（2 通りのアプローチ）​

Option A：ローカルにインストールし、ディレクトリジャンクション (Junction) (Updated 2026-11-27: mklink /D で作成されるのはディレクトリシンボリックリンク（Symbolic Link）であり、ネットワークドライブ Z:\ に使用できます。一方 mklink /J のジャンクションはローカルディスクのみ対応しています) でネットワークドライブに接続する（推奨・最も安定）​

インストーラーがリモートパス上で実行する SMB 特権操作を完全に回避するため、先にローカルへインストールしてからシンボリックリンクを作成します。

  1. 残留プロセスの強制終了：管理者権限で PowerShell を開き、バックグラウンドでロックしているプロセスを終了します。

     Stop-Process -Name "adb" -Force -ErrorAction SilentlyContinue
     Stop-Process -Name "EmuDeck*" -Force -ErrorAction SilentlyContinue

  2. チェック中断防止用のダミーファイルを事前作成：

     $paths = @(
         "$env:USERPROFILE\EmuDeck",
         "$env:APPDATA\EmuDeck",
         "$env:TEMP"
     )
     foreach ($p in $paths) {
         if (Test-Path $p) {
             New-Item -ItemType File -Path "$p\adb.zip" -Force -ErrorAction SilentlyContinue
         }
     }

  3. ローカルインストールの実行：

    • EmuDeck インストーラーを起動し、Custom Mode を選択します。

    • インストール先ディレクトリにはローカルドライブ（例：デフォルトの C:\Users\%USERNAME%\Emulation）を選択します。

    • エミュレータ一覧では、Android 関連のエミュレータのチェックをすべて外します。

  4. ディレクトリシンボリックリンク (Symbolic Link) の作成：インストール完了後に EmuDeck を完全に終了し、ローカルに作成された空のフォルダーを削除します。

    • C:\Users\%USERNAME%\Emulation\roms を削除

    • C:\Users\%USERNAME%\Emulation\bios を削除

    管理者権限でコマンドプロンプト（CMD）を開き、ディレクトリシンボリックリンクを作成します。

     mklink /D "C:\Users\%USERNAME%\Emulation\roms" "Z:\roms"
     mklink /D "C:\Users\%USERNAME%\Emulation\bios" "Z:\bios"

    確認方法：C:\Users\%USERNAME%\Emulation\roms を開き、Z:\roms 内のファイルが正常に読み書き・参照できることを確認します。

Option B：settings.json を直接編集して ADB チェックを回避する（Z: に直接インストール）​

どうしても EmuDeck のインストールルートを Z:\ に直接指定したい場合は、設定ファイルを書き換えて ADB と Android モジュールが導入済みであると強制的に宣言し、インストーラーに adb.zip のダウンロード・展開・削除処理をスキップさせることができます。

  1. インストールプロセスの強制終了：Ctrl + Shift + Esc でタスクマネージャーを開き、すべての EmuDeck、PowerShell、cmd.exe、adb.exe を強制終了します。

  2. settings.json を編集してステータスを書き換える：%USERPROFILE%\EmuDeck\settings.json（AppData 側の場合は %APPDATA%\EmuDeck\settings.json）を開き、adb と android の状態を手動で true および skip に設定します。

     {
       "tools": {
         "adb": {
           "installed": true,
           "configured": true
         },
         "platformTools": {
           "installed": true
         }
       },
       "android": {
         "installed": true,
         "configured": true,
         "skip": true
       }
     }

  3. ローカルにダミーツールファイルを配置しキャッシュを削除：PowerShell で以下のコマンドを実行し、ファイル存在チェックを通過させるためのダミーファイルを作成するとともに、引っかかっている圧縮ファイルを削除します。

     # 建立 platform-tools 佔位目錄與偽裝執行檔
     $toolsPath = "$env:USERPROFILE\EmuDeck\tools\platform-tools"
     New-Item -ItemType Directory -Path $toolsPath -Force -ErrorAction SilentlyContinue
     New-Item -ItemType File -Path "$toolsPath\adb.exe" -Force -ErrorAction SilentlyContinue

     # 清除暫存目錄下的 adb.zip 殘留
     Remove-Item "$env:USERPROFILE\EmuDeck\adb.zip" -Force -ErrorAction SilentlyContinue
     Remove-Item "$env:TEMP\adb.zip" -Force -ErrorAction SilentlyContinue

  4. インストールの再開：EmuDeck を右クリックして「管理者として実行」を選択すると、インストーラーは ADB フェーズをスキップし、そのままエミュレータの選択・設定画面へ進みます。

3. マルチアカウント独立セーブ設定（複数ユーザー間の進行データ競合防止）​

EmuDeck はデフォルトでセーブデータをメインディレクトリの saves（例：Z:\Emulation\saves）へ向けるため、セーブデータの保存先を各ユーザーのローカル領域へ強制的に戻す必要があります。

1. RetroArch のセーブデータおよびステートセーブパスのリダイレクト​

RetroArch を起動 ➔「設定 (Settings)」➔「ディレクトリ (Directory)」へ進みます。

  • セーブデータ (Savefile Directory)：ローカルパスに設定します（例：C:\Users\%USERNAME%\EmuDeck\saves\）。

  • ステートセーブ (Savestate Directory)：ローカルパスに設定します（例：C:\Users\%USERNAME%\EmuDeck\states\）。

  • 「コア名ごとにセーブを分類」または「コンテンツディレクトリごとにセーブを分類」を有効にし、ゲームごとのセーブデータが混ざらないようにします。

2. スタンドアロンコンソールエミュレータ（PCSX2、RPCS3、Dolphin など）​

  • PCSX2：Settings ➔ Memory Cards を開き、メモリーカードファイルの保存先がローカルの %APPDATA%\PCSX2\memcards\ または C:\Users\%USERNAME%\Documents\PCSX2\memcards\ になっていることを確認してください。Z:\ を指定することは厳禁です。

  • Dolphin：GC/Wii 仮想メモリーカードはデフォルトでローカルの %USERPROFILE%\Documents\Dolphin Emulator\ に作成されるため、デフォルトのローカルパスのまま維持してください。

3. マルチユーザー個人セーブデータの自動バックアップ（バッチスケジュール）​

個人のローカルセーブデータをリモート NAS にバックアップしたい場合は、各アカウントで独立した定期実行スクリプトを作成できます。

robocopy "C:\Users\%USERNAME%\EmuDeck\saves" "\\<NAS_IP>\Backup\%USERNAME%_Saves" /MIR

4. Linux 環境でのインストール (Arch Linux およびその他のディストリビューション)​

1. Arch Linux​

Arch Linux では、公式インストールスクリプトと Flatpak コンテナ構成を組み合わせて使用することを推奨します。

1. 事前依存パッケージのインストール​

sudo pacman -Syu --needed base-devel git curl flatpak zenity
flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo

2. EmuDeck のダウンロードと起動​

mkdir -p ~/Downloads/EmuDeck && cd ~/Downloads/EmuDeck
curl -L -O https://www.emudeck.com/EmuDeck.desktop
chmod +x EmuDeck.desktop
./EmuDeck.desktop

インストールウィザードで Expert Mode を選択します。保存先ディレクトリにはローカルの /home/<user>/Emulation を指定するか、あらかじめ /etc/fstab でマウントしておいたリモート NFS/SMB ディレクトリを指定します。

<NAS_IP>:/mnt/share/Emulation /mnt/Emulation nfs _netdev,nofail,x-systemd.automount 0 0

2. その他の Linux ディストリビューション​

  • SteamOS (Steam Deck)：Desktop Mode に切り替え、公式サイトから EmuDeck.desktop をダウンロードしてデスクトップに配置して実行します。インストール先に SD カードまたは内蔵ストレージを選択すると、TDP やリフレッシュレート最適化スクリプトが自動的に構成されます。

  • Ubuntu / Debian 系：

     sudo apt update && sudo apt install -y flatpak git curl zenity dialog libfuse2
     flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
     bash -c "$(curl -fsSL https://raw.githubusercontent.com/dragoonDorise/EmuDeck/main/install.sh)"

  • Fedora：

     sudo dnf install -y flatpak git curl zenity
     flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
     bash -c "$(curl -fsSL https://raw.githubusercontent.com/dragoonDorise/EmuDeck/main/install.sh)"

5. Steam ROM Manager (SRM) 登録と注意点​

  1. 実行前に Steam を終了する：ショートカットの生成やアートワークの保存を行う前に、書き込み競合によるキャッシュ上書きを防ぐため、必ず Steam クライアントを完全に終了してください。

  2. Parsers のパス確認：各プラットフォームの ROMs Directory が正しく Z:\roms\<プラットフォーム名> またはローカルのシンボリックリンク先（例：C:\Users\%USERNAME%\Emulation\roms\<プラットフォーム名>）を指していることを確認します。

  3. Parse & Save：Preview ➔ Parse をクリックしてカバーやポスターをダウンロードし、確認後に Save to Steam をクリックしてショートカットを書き込みます。
