『Pathfinder: Kingmaker』セーブデータ編集による動物の相棒（ペット）の外見・モデル変更ガイド

ヒント

外見を変更しても、相棒のレベルアップ機構は引き続きシステム上 Pet として判定されるため、独立した経験値は獲得しません。この問題については、Bag of Tricks MOD を併用して経験値やレベルアップを補助管理することをおすすめします。

📂 1. セーブデータの場所と必須ツール​

編集作業を行う前に、必ず元のセーブデータのバックアップを取ってください。

  • セーブデータのパス：

    C:\Users\{Username}\AppData\LocalLow\Owlcat Games\Pathfinder Kingmaker\Saved Games

    (注：AppData はシステムの隠しフォルダであるため、エクスプローラーで「隠しファイル」を表示する設定にするか、アドレスバーにパスを直接入力して開く必要があります。)

  • ファイル形式：ゲームの .zks セーブファイルは、実際には標準的な ZIP 圧縮ファイル です。解凍ソフトを使ってそのまま展開してください。

  • 推奨エディタ：Notepad++ に JSTool プラグイン（Plug-in） を導入して使用することを強く推奨します。

    • JSON ファイルを開いた後、JSTool 内の JSFormat 機能を使うことで、1 行に圧縮された JSON データを読みやすいツリー構造へ自動整形できます。

📄 2. コアファイルの説明​

.zks 圧縮ファイルを展開すると多数のファイルが現れますが、外見の変更に関わる中核ファイルは次の 2 つです。

ファイル名内容の説明
party.json主な編集対象。パーティ内の「全キャラクター」（主人公、NPC の仲間、動物の相棒を含む）の詳細情報を記録しています。相棒の種族や外見の変更はここで行います。
player.json主に主人公（プレイヤーキャラクター）の進行状況や個人ステータスの情報を記録しています。

📊 3. party.json 主要パラメータ辞書​

party.json では、各キャラクターの全設定が "Descriptor" という大きなブロック（Section）内に格納されています。外見と識別情報を制御する主要パラメータは以下の通りです。

パラメータ名 (Key)設定の影響と説明
"CustomName"キャラクター名。特定のキャラクターを探す際の最も確実な目印です（例："Kiwi Von Hohenzollen" で検索して編集対象を特定します）。
"CustomGender"性別。通常 "Male" または "Female" が設定されます。
"LeftHandedOverride"左利き設定。真偽値（true / false）。
"m_CustomPortrait"カスタムポートレート。そのキャラクターが使用する 2D ポートレートフォルダ ID（例："aa28"）を指定します。
"Doll"ペーパードールシステム (3D モデル)。キャラクターの種族、顔型、髪型、アクセサリーなどを制御する完全なブロックです。
"Blueprint"キャラクターブループリント (UUID)。ゲームシステム内でそのキャラクターを識別する一意の ID を定義します。

🛠️ 4. 編集作業 SOP（相棒の外見差し替え）​

UUID や外見パラメータを直接手書きすると非常にミスが起きやすいため、以下の「別データからの移植」手順に従って差し替えを行ってください。

ステップ 1：正当な新しい外見データの生成​

  1. ゲームを起動し、キャラクター作成ツール（または新規傭兵の雇用）を使って、理想とする「相棒の外見とポートレート」を作成します。
  2. ゲーム本編に入ってセーブし、一時的な新しいセーブファイルを作成します。
  3. この新しいセーブデータの party.json を展開し、新規キャラクターの "Blueprint"、"Doll" ブロック、および "m_CustomPortrait" ブロックを探して、別のテキストファイルにコピーして控えておきます。

ステップ 2：対象セーブデータへのデータ移植​

  1. 編集したい「メイン進行セーブデータ」の party.json を展開します。
  2. 変更したい相棒の名前を検索（"CustomName" を利用）し、その相棒の "Descriptor" ブロックを特定します。
  3. 先ほどコピーした "Doll" と "m_CustomPortrait" で、相棒の元の該当ブロックを上書きします。

ステップ 3：内部参照 ID $id の処理（極めて重要）​

JSON 構造内には、システムが生成した多数の連番タグ（例："id": "644" ではなく "$id": "644"）が存在します。

  • 重複は厳禁：コピーしてきたブロックに含まれるすべての "$id" の値は、party.json 全体の中の他のどの $id とも絶対に重複してはなりません。
  • 対処方法：これらの $id の数値を適当に書き換えて（例："999644" に変更）、ファイル内で一意の値になるようにしてください。連番である必要はありません。

🔗 5. 主人とペットのバインドロジック（連動チェック）​

ゲームシステムは UUID を頼りに「誰が誰のペットか」を判定しています。この紐付けが切れると、ペットは主人なしの状態になるか、パーティから直接消滅してしまいます。編集完了後、必ず以下の対応関係を確認してください。

「主人」の Descriptor ブロック内：

"m_Pet": {
    "m_UniqueId": "這裡必須填入寵物角色的 UUID"
}

「ペット（相棒）」の Descriptor ブロック内：

"Master": {
    "m_UniqueId": "這裡必須填入主人角色的 UUID"
}

(注：UUID はゲーム内蔵の NPC の UUID と絶対に衝突してはなりません。ステップ 1 でゲーム内の作成ツールを使って新規キャラクターを作り、安全な UUID を取得するよう推奨しているのはそのためです。)

⚠️ 6. 既知の問題と副作用 (Troubleshooting)​

  • 裸の王様バグ：この方法で差し替えた 3D ペーパードールモデルは、ゲーム内で表示された際に服を着ていない状態になります。
    • 現在の推測："Doll" ブロック内の "ClothesPrimaryIndex" と "ClothesSecondaryIndex" は色のみを定義しており、実際に「装備や衣服を着用する」宣言ブロックが欠落しているか、正しく適用されていないためと考えられます。今後セーブデータ内で実体装備のバインドブロック（Equipment Definition）が見つかり次第、本項目を更新します。
