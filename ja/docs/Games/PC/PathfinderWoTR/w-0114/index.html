パーティ人数上限の突破：ToyBox 設定と傭兵をペット化するセーブデータ改変

ヒント

『パスファインダー：ラース・オブ・ザ・ライチャス』(WotR) では、ペット（Pet）システムが根底から再構築されました。セーブデータ編集を活用することで、ペット 1 体の制限を突破できるだけでなく、システムロジックの抜け穴を突き、完全なペーパードール（Paper Doll）・独立した装備スロット・レベルアップツリーを備えた「傭兵（Mercenary）」を、パーティ 6 人枠を消費しない「隠しペット」へと変換することも可能です。

💡 核心結論：ToyBox によるパーティ枠の解放 (ベストプラクティス)​

データ破損のリスクを冒してまで、びっしり詰まった JSON ファイルの中で高難度のコード分解と移植を行うくらいなら、最も安全で直接的な正解は、パーティ人数上限をそのまま解除することです。

ゲーム内の ToyBox MOD を有効にすれば、無数のデバッグ時間を節約できます：

  1. ToyBox の Party タブを開きます。
  2. Party Size の上限を探して引き上げます（例：8 人や 10 人に設定）。
  3. 酒場へ行き、通常通り大量の傭兵を雇って軍団を編成します。

メリット分析： システムが正規のクラスレベルアップツリー、独立した装備スロット、戦闘不能からの蘇生判定をすべて自動で処理してくれます。JSON 改変による致命的なバグを完全に回避しつつ、最高度のパーティ編成の自由度と没入感を維持できます。

🔎 ゲーム仕様とファクトチェック (Fact Check)​

それでもゲームの内部的な限界が気になる方のために、検証済みのエンジン仕様を以下にまとめます：

検証テーマエンジン内部の判定と結論
最大 6 体のペットを持てるか？UI と安定性の制約を受ける。内部的には無数のエンティティを保持できますが、パーティ全体の総エンティティ数が 14〜16 体を超えるとパーティ肖像画の表示が崩れ、ターン制モードではタイムラインがフリーズしやすくなります。
複数種類のペットは共存可能？完全に可能。動物の相棒、ミシックのスケルトン・ウォーリアー、アザータのドラゴン（アイヴ）は異なるシステムスロット（Slots）を占有するため、同じ主人のもとに問題なく重複させられます。
各種動物／スケルトンを 1 体ずつ連れ歩けるか？システムに一意性の法則がある。同種の特技を複数無理やり追加するとエンティティ同士が上書きし合ったり、レベルアップ画面がクラッシュしたりします。スケルトン軍団や動物園を作りたい場合は、「傭兵をペット化する手法」に頼る必要があります。
特技なしで強制ペット化した場合のペナルティ主人が対応する特技を持たない状態で無理やり JSON を書き換えると、そのペットの経験値が永久に固定され、振り直し（Respec）時に永久消滅し、さらに死亡後も自動蘇生しなくなります。

⚙️ [技術補足] セーブデータ低レベル改変および傭兵ペット化 SOP​

このセクションは、エンジンの限界に挑み、画面上部のパーティ欄を占有しない構成を追求したいハードコアプレイヤー向けの参考資料です。

ファイルの場所と必須ツール​

  • セーブデータのパス：C:\Users\{Username}\AppData\LocalLow\Owlcat Games\Pathfinder Wrath Of The Righteous\Saved Games
  • セーブデータ形式：.zks ファイルは標準的な ZIP 圧縮ファイルです。改変前には必ずバックアップを取ってください。
  • Windows ツール：Notepad++ と Jstool Plug-in の組み合わせがおすすめです。JSFormat 機能を使って JSON ツリー構造を整形できます。
  • Linux ツール：Notepadqq がおすすめです。ターミナルでの整形コマンド：cat file.json | python -m json.tool > new.json

実装 SOP：乗っ取り移植法 (精密な器官移植)​

レベルアップ UI のクラッシュや振り直し時の消滅バグを避けるため、正規ペットの「戸籍」を借りて、そこに傭兵の「肉体」を載せ替えます。

ステップ 1：戸籍と肉体を用意する

ゲーム内で酒場の主人に話しかけ、見た目とクラスを設定した新しい傭兵を 1 人雇います。ToyBox を開いて Party -> Features に進み、主人に普段絶対使わない動物の特技（例：ムカデ）を強制付与して、システムに正規のペットを 1 体生成させます。マップを切り替えてエンティティをスポーンさせた後、セーブしてゲームを終了します。

ステップ 2：パーティ枠を解放する

.zks セーブデータを解凍し、player.json を開きます。"m_Party" 配列を探し、その傭兵の UUID を配列から削除します。

ステップ 3：データ移植と上書き

party.json を開き、先ほどの「ムカデ（正規ペット）」のブロックを見つけます。

傭兵ブロック内にある "Doll" (3D 外見)、"m_Inventory" (インベントリ)、"m_Slots" (装備スロット)、"Stats" (基礎ステータス) を、ムカデ側の対応ブロックへ上書きコピーします。ムカデの "Blueprint" と "Progression" は絶対に上書きしないでください（動物のレベルアップツリーを残す必要があります）。作業が完了したら、元の傭兵の独立した大ブロックを丸ごと削除します。

ステップ 4：主従の双方向バインド

合成したエンティティ（元のムカデ）の "Descriptor" ブロック内にある "Master" フィールドを探し、主人の UUID を記入します。続いて主人の名前で検索して "m_Pets" 配列を見つけ、合成エンティティの UUID がその中に含まれていることを確認します。JSON を再び .zks に圧縮し直せばゲームを起動できます。

既知の問題とトラブルシューティング (Troubleshooting)​

異常な症状システム上の原因と対処法
ペットが消える、または敵対化する確実に party.json 内の Master バインド失敗か UUID の記入ミスです。システムがそのエンティティを野生生物と判定しています。
傭兵ペットがカットシーンで詰まる特定のイベントシーンではパーティの立ち位置が厳密にチェックされるため、モデルの位置ズレが起きることがあります。Esc でスキップするかマップを切り替えれば回復します。
傭兵ペットのインベントリを開けないUI 判定に異常が出ています。ToyBox を開き、Bag of Tricks タブで Allow Equip Everything と Show Inventory for All にチェックを入れて強制解放してください。
