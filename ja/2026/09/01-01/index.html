久しぶりの更新、近況報告

4月に新しい Blog/Wiki の表示方式を調整して以来、しばらくの間ずっとこれらに触れていませんでした。 ひとつは Vibe Coding に熱中していたこと、もうひとつは仕事が忙しかったことが理由です。

近況報告

おじさんの近況など誰も気にしないとは思いますが、この期間に何をしていたのか、そして今後何をするつもりなのかを日記がてら整理しておこうと思います。

Vibe Coding​

結論から言うと、失敗しました。何か実用的なものが作れなかっただけでなく、Gemini AI Pro の1年プランまで課金してしまいましたが、いくつか残しておきたい気づきがあります。

簡単に言うと、Vibe Coding が失敗した件は全面的に Google のせいにできるわけではありません。ネット上では「Gemini のプログラミング能力はダメだ」などとよく言われていますが、冷静に振り返ると、失敗の主な原因は以下の2点にありました。

  • 作りたいものが明確に定まっていなかった 厳密に言えば、私に創造力が欠けていたのだと思います。いくつか良さそうなアイデアを考えてみたものの、最終的にはどれも費用対効果が悪くて取り組む意味が薄かったり、すでに誰かが書いた優秀なオープンソースプロジェクトがそのまま使えたりすることが判明し、だんだん頭を悩ませて続けるモチベーションがなくなってしまいました。

  • プログラミングの基礎概念が乏しく、AI が大量のコードを書いても読めないし、どこに問題があるかも理解できない この問題はとても顕著でした。プログラムのフレームワーク選定、アーキテクチャ設計、言語の選択、変数の定義方法、複数ターンを重ねた後に AI が破綻しないように制御する方法、そして最初から将来の保守や改修を見据えて設計すること――これらすべてが私の事前計画能力をはるかに超えていました。言い換えれば、AI がどれだけコードを書けても、青写真を描く人間側の頭が空っぽではどうにもならないということです（まあ、これは国家統治や企業経営、プロジェクトマネジメントなど多くの分野にも同じことが言えますが）。

そのため、この分野は現在完全に休止中です。ただ、厳密に言えば、私でもある程度理解できる簡単なシェルスクリプトなどを AI に書いてもらう用途であれば、今でも非常に便利に使えています。

会社関連​

オフィス政治​

何か書くと思いましたか？？ 答えはノーです。こんな場所で仕事上の情報を漏らすほど愚かではありません。ただ感情的な記録として、この時期の仕事に関してはかなり不愉快な記憶が残っている、という脚注だけ残しておきます。

給料泥棒​

これについて厳密に言うと、会社から新しいノート PC が支給された話です。今回のマシンは面白くて、Lenovo Thinkpad P16 Gen3 に NVIDIA RTX PRO 1000 GPU と SSD を2基搭載した構成でした。会社の Windows をセットアップした際に、SSD の1本がマウントもフォーマットもされず管理対象外になっている抜け穴を突いて、そこに今この執筆にも使っている Arch Linux をインストールしました。おかげで職場でも、ずっと WSL に頼りきりにならず仕事用の Arch Linux 環境を使えるようになりました（もっとも会社の Windows 側にも WSL は入っていますが）。

この Arch Linux マシンにまつわる話は、気が向いたら後日もっと詳しく書こうと思います。書かなければそれまでということで。

新しいおもちゃを入手​

要するに、会社で廃棄予定だった Dell Latitude 5411 を安く引き取って持ち帰っただけです。いろいろ悩んだ末に、自分専用の最初の Arch Linux ノート PC として使うことにしました。

今一番力を入れていること​

実のところ、上で挙げたのはここ数ヶ月の些末な出来事にすぎず、最近本気で考えながら進めているのは以下の件です。

ホームエンターテインメント環境の再構築​

以前からずっと、自宅のゲーム環境を徹底的に整理し直したいと考えていました。理想は、リビングにストリーミング端末またはある程度の性能で動作する専用機を置き、重めの PC 大作ゲームは書斎の PC で直接プレイするか、リビングへストリーミングして遊べるようにする構成です。そこで手持ちのマシン（どれも古い機種ですが）を棚卸しして再構築することにしました。

NVIDIA SHIELD TV Pro​

現在、我が家のリビングで動画視聴のメインになっているセットトップボックスです。以前ここに RetroArch と Moonlight を入れて試したことがあります。実験結果は以下の通りです。

  • Moonlight は動作するものの、Sunshine を動かすストリーミング元となるゲーミングマシンへの依存度が非常に高い
  • RetroArch はスーパーファミコン時代までなら問題なく快適に動くものの、ストレージ容量が大きなネックになる

Steam Deck​

私のメイン携帯ゲーム機です。実はこれの Steam アカウントを切り替え、エミュレータ環境も整えたうえで、ドックごとリビングへ移設し、現在の Switch の代わりにしようかと考えています（Switch はコントローラが壊れてしまい……画面にもヒビが入っているため）。 ただ、この案は以下の点で引っかかっています。

  • Steam Deck のエミュレータ性能は PS2 を超えると厳しくなるものの、現時点では私の手元にあるリビング用ゲーム機として最良の選択肢ではある
  • あくまで私個人のおもちゃなので、子どもたちに雑に扱われて壊されたくないという気持ちが強い

Dell Latitude 5411​

ゲーム用途という点では、独立 GPU もなくメモリも 8GB しかないため、正直まったく戦力にならないマシンです。しかしこのマシンが存在するおかげで、これまで Steam Deck が担っていた「ちょっとした Linux デスクトップ」の役割を置き換えることができました。 だからこそ、Steam Deck を他の用途へ回す余裕が生まれたわけです。

MSI GL73​

NVIDIA RTX 2060 Mobile を搭載したこのゲーミングノート PC は、現在私が所有している中で最もゲーム性能が高いマシンであり、OS もゲームに最適な Windows です。

問題点​

理想はとても素晴らしいのですが、現実はあまりに厳しく、手を付け始める前から問題が見つかりました。

一番の大きな問題は、このホームエンターテインメントシステムが「私ひとりだけ」のためのものではない、という点です。現在使える技術や手段のほとんどは、次のような大前提のもとで成り立っています。

ゲームの所有者 ＝ プレイヤー ＝ すべての管理者

子どもも遊ぶことを前提にすると、プレイ時間の制限や遊べるゲームの制限が必要になり、そうなると即座に「Steam ファミリーグループに子ども用アカウントを追加する」という解決策に行き着きます。Steam の機能で子どものプレイ時間とプレイ可能なゲームを管理し、エミュレータ側についてはリビング機体の容量が限られているため最初から厳選したゲームだけを入れておく、という構成です。聞こえは良いのですが、ここで問題が出てきます。もしリビングのマシン自体が高性能でストリーミング不要なら、独立したゲーム機1台で完結するので問題はすべて解決します。しかし、より高いスペックが要求されるゲームを動かすために強力なストリーミング元が必要になった場合はどうでしょうか？

結論から言うと、自宅のネットワーク環境で Steam Deck から Steam Link 経由でゲームを動かすのは、悲惨としか言いようがない状態でした……。 一方で Moonlight/Sunshine 方式にはアカウント制御の仕組みがありません（デスクトップ画面丸ごとのストリーミングになるため）。そのため大作ゲームまで対応させようとすると、結局はストリーミング元のマシンごと子ども向けに用意する必要が出てきます。さらに、自分自身が遊ぶゲームをストリーミングしたい場合はどうするか、どうやってアカウント管理や配信先を分けるか……と問題が一気に面倒になり、実現するにはマシンの台数を増やすしかなくなってしまいます。

これまでの実装進捗​

とりあえず最近は手元の物理 Arch Linux 環境を統一しつつ、設定面では Steam Deck の SteamOS ＋ EmuDeck に近い構成へと統合を進めています。これまで放置して荒れ放題だったエミュレータ関連リソースを整理し直す一方で、将来的に Windows を手放すための布石も打っているところです……。

結論​

もしリビングへのストリーミングという選択肢を諦めるなら、Steam Deck をエミュレータ＋子ども向けおよびリビング向けの Steam ゲーム専用機へと転用することはできます。ただその場合、私自身は携帯機を失うか、子どもたちと本体を共有する形で遊ぶしかなくなります……。 新しいゲーミングマシンを購入するまでのつなぎとしては悪くない妥協案ではありますが、それもこれも「子どもがゲームを遊びやすくなったせいで奥さんに怒られて正座させられたり撤去させられたりしない」ことが大前提なんですけどね……。
